# ADR-012: Owned outputs не коммитятся: блок `.gitignore` пишет `init`

**Status:** Accepted
**Date:** 2026-09-09
**Deciders:** владелец backslop

## Context

Правило «adapter outputs — локальный generated результат» действует с [ADR-006](adr-006-adapter-ownership.md), но нигде не было записано как обязательство проекта-потребителя и ничем не поддерживалось. `init` клал owned outputs и `CLAUDE.md` и не трогал `.gitignore` ни строкой; шаблона `.gitignore` в `templates/` не было вовсе. Слово «gitignore» не встречалось ни в `README.md`, ни в `README.ru.md`, ни в `docs/reference/**`, ни в `templates/**` — единственное упоминание во всём репозитории лежало в закрытой задаче `docs/archive/BS-5-harness-neutral-self-host/result.md:3`, то есть в отчёте о прошлой работе, а не в действующем правиле.

Цена молчания измерена на трёх живых потребителях (BS-20, проверено построчно): `backslop/.gitignore` и `external/promptobus/.gitignore` держали побайтово одинаковый 14-строчный блок в поимённой форме (`.claude/skills/backslop-task/`, `.cursor/rules/backslop-task.mdc` и так далее), `repos/agent-workspace/ati-agents/.gitignore` — другую, glob-форму из четырёх строк, а путь рабочих копий агентов у него игнорировался вовсе не из `.gitignore`, а из машинно-локального `.git/info/exclude`. Три проекта, три разных ответа на один вопрос, и ни один не следует из инструмента.

Гейты `lint` факта «owned output лежит в индексе git» не проверяли.

## Варианты

**Ось 1 — кто держит правило.**

- **1A. `init` пишет блок в `.gitignore`.** Механизм уже есть и уже применяется к другому файлу — `upsertBlock` для `AGENTS.md`. Правило приходит в проект вместе с раскладкой, до первого коммита owned output. Цена: `init` начинает писать файл, которого раньше не касался; для файла с чужим содержимым это дописывание блока в конец.
- **1B. Отдельный гейт `lint` по индексу git.** Owned-output путь, попавший в индекс (`git ls-files --error-unmatch`), — ошибка с перечнем строк для `.gitignore`. Инструмент ничего не пишет. Цена: правило срабатывает уже после того, как файл закоммичен, лечение остаётся ручным, а гейт требует git — в проекте без него он молчит.
- Обе сразу — отвергнуто разделом «Не входит» задачи BS-20: одно правило, один механизм.

**Ось 2 — форма строк, если выбран 1A.**

- **2A. Поимённый список.** По одной строке на скилл и harness — сегодня 12 строк. Список зависит от состава `templates/skills/**` и расходится с ним при каждой правке.
- **2B. Glob по корню harness** — `.claude/skills/backslop-*`. Три строки на три harness, состав скиллов не важен, форма совпадает с фильтром `markedFiles` (`backslop-` первым сегментом пути).

**Ось 3 — `/CLAUDE.md` в блоке.**

- **3A. Всегда при выбранном `claude`.** Просто, но прячет от git пользовательский `CLAUDE.md`, который `ensureClaudeStub` намеренно сохраняет.
- **3B. Только когда на диске лежит наш stub** (`@AGENTS.md` дословно) — то же условие, по которому `cleanupAdapters` признаёт stub своим.

## Decision

**1A + 2B + 3B.** `init` держит в `.gitignore` проекта блок между маркерами `# backslop:start` и `# backslop:end`: по строке `<корень harness>/backslop-*` на каждый выбранный adapter и `/CLAUDE.md`, когда на диске лежит именно наш stub. Корни берутся из общего источника ([lib/adapters-registry.js](../../lib/adapters-registry.js)), поэтому четвёртый adapter не потребует правки этого блока отдельно.

Маркеры комментарием `#`, а не html-комментарием, как в `AGENTS.md`: в синтаксисе `.gitignore` строка `<!-- backslop:start -->` была бы не комментарием, а шаблоном имени файла с пробелами.

Блок заводится, когда есть что игнорировать или когда блок уже был. Проект с `tools: []` — в том числе self-host самого backslop — `.gitignore` не получает: раскладка ничего не генерирует, а заведение файла там, где его не было, сделало бы tracked tree грязным при обычном `init`. Снятие всех adapters оставляет пустой блок с объяснением вместо строк, а не стирает файл.

Отдельный гейт `lint` по индексу git не заводится: правило, приходящее с раскладкой, не нуждается в постфактум-проверке, а проверка индекса тянула бы в `lint` зависимость от git и молчала бы там, где его нет.

## Consequences

- Потребитель получает правило вместе с `init`, а не из чужого репозитория. Три разошедшихся `.gitignore` сами собой не сойдутся: `upsertBlock` дописывает блок рядом, а прежние рукописные строки без маркеров остаются на месте — снимает их человек, увидев дубль. Правку чужих репозиториев BS-20 прямо исключила.
- `init` теперь пишет четвёртый файл проекта помимо конфига, `docs/` и `AGENTS.md`. Это входит в раскладку и описано в [reference/01](../reference/01-layout.md).
- Пользовательские строки `.gitignore` сохраняются: заменяется только содержимое между маркерами. Маркер без пары — отказ с именем файла, как у `AGENTS.md`.
- Факт «owned output закоммичен» инструмент по-прежнему не ловит. Проект, который завёл backslop раньше этого решения и успел закоммитить generated-файлы, чинит это руками: `.gitignore` игнорирование уже отслеживаемого файла не отменяет.
- Собственный `.gitignore` backslop остаётся рукописным: self-host держит `tools: []` и блока не получает, а его строки защищают разработчика, который включил adapter локально. Форма приведена к той же, что генерирует `init`, — иначе в одном репозитории жили бы два ответа на один вопрос. Строка `.claude/worktrees/` к adapter outputs не относится и остаётся отдельно.
