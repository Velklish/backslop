# ADR-038: Гейт комментариев судит и ширину строки: не шире 100 знаков, знак — кодпоинт

**Status:** Accepted
**Date:** 2026-09-24
**Deciders:** владелец — правило и порог 100 (решение по записи BS-75.1 в пачке BS-82); worker BS-82 — как считать знак, место проверки, текст. Владельцем текст не вычитан.

## Context

[ADR-028](adr-028-two-line-comment-rule-and-its-gate.md) судит блок комментария только по числу строк. Абзац, сложенный в две длинные строки, проходит гейт, хотя правило заведено ради токенов, а не ради переводов строки. Раздел «Чего гейт не ловит» этот обход не называл.

Замер на `3b9c82c` по `lib`, `test`, `bin`, `scripts` (54 файла `.js`/`.mjs`): 31 строка блоков комментария шире 100 знаков, в 15 файлах. Самая широкая — 124 знака, `lib/show.js:44`. Тот же счёт и ту же самую широкую строку называет запись BS-75.1 по замеру на `5e5554a`. Свод [BS-75](../archive/LOG.md#bs-75) держал строки в пределах 100 по привычке файла, гейт этого не требовал.

## Варианты

Решение 1 — что считать знаком:

- **1A** — кодпоинт: `[...line].length`. Буква вне BMP — один знак.
- **1B** — единица UTF-16: `line.length`. Буква вне BMP — два знака, глаз видит один.
- **1C** — позиция на экране: табуляция до следующей позиции, широкие знаки CJK — по два. Это ближе к глазу, но требует таблицы East Asian Width и выбора шага табуляции. В дереве обхода нет ни табуляций, ни знаков CJK.

Решение 2 — где живёт проверка:

- **2A** — внутри `longBlocks`: блок с широкой строкой считается длинным. Тогда ширину прощает список долга по личности блока, а поле `length` у такого блока не значит ничего.
- **2B** — соседняя функция `wideLines` в `test/comment-scan.mjs` и отдельный список `wide` в обходе. Список долга этот отказ не читает.

## Decision

**1A + 2B.**

Строка блока шире 100 кодпоинтов — нарушение той же природы, что третья строка блока. Строка блока — та, которую видит `commentBlocks`: `//`, `/* … */` и строки продолжения. Ширина считается по всей строке вместе с отступом: так её видит редактор и так мерил замер. Табуляция — один знак: на `3b9c82c` её нет ни в одном из 54 файлов обхода. Завершающий `\r` в ширину не входит, иначе строка ровно в 100 знаков краснела бы только в checkout с `core.autocrlf=true`.

Второго списка долга нет. Все 31 строку свёл перенос или сокращение в пределах двух строк, и проверка включена уже после свода. Запись файла в `test/fixtures/comment-sweep-pending.json` отказ по ширине не снимает.

Носитель пробы `test/fixtures/comment-debtor.js.txt` получил третий блок: две строки, вторая шириной 101 знак. Обход обязан отвергнуть эту строку и в файле вне списка долга, и в файле из списка.

## Consequences

**Что гейт ловит сверх ADR-028.** Строку блока шире 100 знаков в любом файле обхода. Отказ называет файл, строку и ширину.

**Чего гейт не ловит.**

- **Хвост строки кода.** Как и в ADR-028, комментарий после кода не судится ни по длине, ни по ширине. На `3b9c82c` таких строк шире 100 знаков нет, но правило этого не держит.
- **Код после комментария в той же строке.** `/* … */ code();` и закрывающая строка блока `*/ work();` — строки кода: `commentBlocks` отбрасывает их по `codeAfter`, и ни длина, ни ширина их не судятся. На `3b9c82c` таких строк в 54 файлах обхода нет ни одной, шире 100 знаков — тоже; строк с комментарием после кода — 17, шире 100 — ни одной. Судить ли эту форму — отдельное решение, здесь оно не принято.
- **Ширину строк кода.** Правило только о комментариях.
- **Составной эмодзи.** Последовательность ZWJ или флаг — несколько кодпоинтов, и гейт считает её шире, чем видит глаз. В дереве таких нет.
- **Сокращение, которое выбросило смысл.** Гейт видит ширину, а не прозу. Как и у ADR-028, эту половину держат автор правки и ревьюер.

**Что дороже.** Абзац уже не сложить в две длинные строки. Нюанс, который не помещается в две строки по 100 знаков, сразу уезжает в документацию, а рядом с кодом остаётся указатель.
