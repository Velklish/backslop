# ADR-004: Пин версии в проекте и обновление командой upgrade

**Status:** Superseded in part by [ADR-007](adr-007-npm-pin.md) (источник релизов при npm-форме)
**Date:** 2026-09-03
**Deciders:** Velklish

## Context

Форма установки `npx github:Velklish/backslop` без тега — HEAD ветки `main`: npm 11 при каждом запуске делает `git ls-remote`, сравнивает SHA с кэшем и переклонирует пакет, когда он изменился (улика: `libnpmexec/lib/index.js`, функция `missingFromTree` — для git-спеки сравниваются `node.package.resolved` и `manifest._resolved`). Значит, любая правка шаблонов в `main` меняла поведение всех проектов сразу, без их ведома, а проект не мог зафиксировать версию, с которой работает. Скиллы и блок в `AGENTS.md` обновлялись повторным `init`, но ничто не говорило проекту, что он отстал, и ничего не переводило формат файлов при его смене.

## Варианты

Решение 1 — что записано в проекте:

- **1A** — без пина: `cli` без тега, версия раскладки нигде не хранится.
- **1B** — пин версии в `cli` (`#vX.Y.Z`) и штамп `version` в `backslop.json`, который ставит версия, делавшая раскладку.

Решение 2 — как обновляться:

- **2A** — руками: поправить пин, запустить `init`.
- **2B** — команда `upgrade`: последний тег из источника релизов, пин в `cli` и `gates`, затем `migrate` и `init` уже новой версией, выжимка CHANGELOG между версиями.
- **2C** — скиллы отдельным плагином Claude Code с его механизмом обновления, CLI — отдельно.

## Decision

1B и 2B. `init` пишет пин своей версии и штамп; `upgrade` переставляет пин и запускает новую версию для миграции и раскладки; `lint` предупреждает, когда штамп старее инструмента или расходится с пином, но не краснеет: устаревший скелет работает.

1A оставлял проект во власти чужого коммита. 2A требовал знать, что и в каком порядке запускать. 2C делил поставку на две половины с независимыми версиями и возвращал проблему «одна версия у скиллов и CLI», которой в одном пакете нет по построению.

## Consequences

- Проект обновляется, когда решил сам: `upgrade` — осознанное действие, а не побочный эффект запуска.
- Форма пина стабильна: `npx github:owner/repo#vX.Y.Z`; публикация в npm меняет только её на `npx backslop@X.Y.Z`, источник релизов тогда объявляется полем `source` или выводится из новой формы. — заменено [ADR-007](adr-007-npm-pin.md)
- Всё, что зависит от формата файлов, делает новая версия: `upgrade` может идти из старой, и список миграций живёт вместе с форматом в `migrate`.
- Цена — сеть при каждом запуске всё равно нужна: npx резолвит тег через `ls-remote` даже при попадании в кэш; офлайн-работу даёт только установка пакета в проект или глобально.
