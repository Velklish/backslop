# ADR-010: Бриф worker'у собирается командой, а не руками

**Status:** Accepted
**Date:** 2026-09-09
**Deciders:** владелец, оркестратор захода 2026-09-09

## Context

Скилл `backslop-batch` требовал от оркестратора восьми обязательных пунктов брифа. Из них решение по конкретному заходу — одно: границы правки, кому какие каталоги. Остальные семь либо лежат на диске, либо неизменны по формулировке:

- постановки задач — в файлах задач, читает `scanTasks` ([lib/tasks.js](../../lib/tasks.js));
- `gates`, `prefix` и `cli` — поля `backslop.json`, читает `loadConfig` ([lib/config.js](../../lib/config.js));
- критерий готовности, просьба закоммитить с префиксом, запрет каталогов статусов и `archive/`, находки файлом, порядок мутационной пробы, состав результата — один и тот же абзац из захода в заход.

Команды для этого не было: `COMMANDS` в [bin/backslop.js](../../bin/backslop.js) не называл `brief`, реализации в `lib/` не существовало. Оркестратор набирал текст заново каждому worker'у — и цена этого не в наборе, а в пропусках: пункт, забытый в одном брифе, worker не восполнит, потому что бриф самодостаточен и другого источника у него нет.

## Варианты

**Где живёт текст брифа.**

- **1A. Шаблон в `templates/`, рендер командой.** Текст правится там же, где остальные шаблоны, и английский близнец сторожится существующим `templateParity`. Цена: ещё одна пара файлов в `templates/`.
- **1B. Текст зашит в скилл `backslop-batch`, команда его не знает.** Ничего нового в репозиторий, но правило остаётся текстом, который агент переписывает руками, — то есть задача не решается.

**Что делает команда с готовым текстом.**

- **2A. Только печатает в stdout.** Куда отправить — промпт субагента, первое сообщение сессии, шина — решает оркестратор; транспорт остаётся слотом скилла.
- **2B. Команда сама поднимает worker'а.** Потребовала бы знания harness внутри CLI — прямо против [ADR-003](adr-003-node-stdlib-npx.md) (Node без зависимостей) и против слота «Как поднять worker'а», который держит транспорт вне инструмента.

**Границы правки.**

- **3A. Текстовый аргумент `--neighbour "путь=track"`, повторяемый; без него — заготовка `[TODO]`.** Решение остаётся за оркестратором, но форма записи стандартна.
- **3B. Выводить соседей из веток и worktree.** Инструмент угадывал бы, кто что правит; резка track'ов — решение по заходу, а не факт с диска.

## Decision

1A + 2A + 3A. Команда `brief <N…> [--track "…"] [--neighbour "путь=track"] [--measurements]` рендерит [templates/brief.md](../../templates/brief.md) (и английский близнец) через `renderProjectTemplate`, подставляя заголовок track'а, постановки названных задач с диска, `gates`, `prefix` и `cli` проекта. Печатает в stdout и ничего не отправляет.

Из постановки берутся разделы «Что сделать» и «Не входит» — они задают границы задачи; файл целиком не переносится, его путь назван, и worker его прочитает.

Несуществующий номер — отказ с этим номером, а не частичный бриф: worker прочитал бы пропуск как «задач меньше».

Без `--neighbour` раздел границ остаётся заготовкой `[TODO]` — это сигнал оркестратору, что границы ещё не решены, а не умолчание «всё твоё».

## Consequences

Состав брифа перестаёт быть памятью оркестратора: пункт, забытый в тексте скилла, теперь либо есть в шаблоне, либо его нет ни в одном брифе — и это видно.

Обязательство на следующие правки: изменение состава брифа — правка `templates/brief.md` и английского близнеца одним ходом, иначе `lint` краснеет на `templateParity`. Раздел «Бриф» скилла `backslop-batch` описывает теперь только два решения оркестратора — заголовок и границы; переносить туда обратно перечень обязательных пунктов значит вернуть расхождение между скиллом и тем, что реально печатается.

Команда добавлена в `COMMANDS` и справку — контракт CLI расширен, но не изменён: прежние команды, их флаги и коды возврата не тронуты, состав `status --json` тот же.
