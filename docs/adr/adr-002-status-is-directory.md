# ADR-002: Статус задачи — каталог, приоритет — поле «Порядок»

**Status:** Accepted
**Date:** 2026-09-03
**Deciders:** Velklish

## Context

Исходный процесс, из которого вырос backslop, держал статус задачи в индексе — одном markdown-файле с секциями «В работе», «Очередь», «Отложено», где приоритет задавался порядком строк. Индекс правился при каждом заведении, взятии и закрытии задачи, и параллельные ветки конфликтовали на нём даже при удалении разных соседних строк; строка «следующий свободный номер» конфликтовала всегда. Отдельный каталог для неразобранного (triage) уже был решён там как половинчатая мера.

## Варианты

Решение 1 — где живёт статус:

- **1A** — каталог на каждый статус: `triage/`, `queue/`, `active/`, `deferred/`, `archive/`; индекса в git нет, сводку печатает команда.
- **1B** — каталоги только для `triage` и `active`, очередь и отложенное остаются строками индекса.

Решение 2 — где живёт приоритет очереди без строк индекса:

- **2A** — целое поле «Порядок» в шапке файла, шаг 10; сортировка командой.
- **2B** — файл `queue/ORDER` с номерами по строке.
- **2C** — порядок по номеру задачи, без отдельного приоритета.

## Decision

1A и 2A. Смена статуса — `git mv` одного файла; приоритет — правка одного числа в одном файле или команда `mv --top | --after`. Индекса в репозитории нет; `status` собирает сводку с диска, `status --json` отдаёт её оркестраторам.

1B оставлял общий файл в двух из четырёх переходов. 2B возвращал общий файл, конфликтующий на соседних строках при взятии разных задач. 2C не даёт владельцу развернуть приоритет, а он делает это регулярно.

## Consequences

- Две ветки конфликтуют только тогда, когда двигают или перенумеровывают одну и ту же задачу — и это законный конфликт.
- «Взгляд на очередь» стоит команды, а не открытия файла; блок в `AGENTS.md` говорит об этом прямо, чтобы агент не искал список в README бэклога.
- Поля, которые статус ведёт за собой («Порядок», «Взята», раздел «Отложено»), держит `lint`: без него каталог и содержимое файла разъехались бы молча.
- Между соседними порядками может не остаться целого места; тогда очередь перенумеровывается шагом 10 — команда делает это сама и сообщает.
