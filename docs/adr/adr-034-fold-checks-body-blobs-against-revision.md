# ADR-034: Массовая свёртка сверяет тело с ревизией по блобам и отказывает на расхождении

**Status:** Accepted
**Date:** 2026-09-24
**Deciders:** оркестратор захода 2026-09-24 — ADR заведён по ревью BS-76.5; текст владельцем не вычитан

## Context

[ADR-026](adr-026-archive-folds-to-log.md) велит массовой свёртке проверить `git cat-file` до удаления и записать в строку журнала ревизию тела. Причин пустой ревизии там три: нет git-репозитория, каталог не закоммичен, тела в истории нет.

Ревизию код брал по `task.md`, а `task.md` последним трогает коммит архивации. `result.md` дописывается позже — по ревью, приёмкой, чужими заходами. Первая живая свёртка v0.10.1 (карточка BS-76.5): у ati-agents 116 строк из 773, у promptobus 9 из 312 назвали ревизию, где результат ещё черновик или его нет вовсе, и `show N` печатал её. `cat-file -e` на `task.md` этого не видел: он проверяет, что один файл существует, а не что история держит тот же текст.

## Варианты

- **Решение 1 — что проверяется.**
  - 1A — ревизия по каталогу (`git log -1 -- <каталог>/`), проверка — `cat-file -e` на каждый файл тела. Цена: существование — не равенство. Правка, которую `git status` не видит (`assume-unchanged`, `skip-worktree`), уйдёт вместе с каталогом, а строка пообещает другой текст.
  - 1B — ревизия по каталогу и сверка содержимого: дерево ревизии (`git ls-tree -r`) против `git hash-object` каждого файла каталога из ревизии. Цена: четвёртый ответ на пустую ревизию и два вызова git на каталог.
- **Решение 2 — чем сравнивается.**
  - 2A — сырые байты файла против блоба. Цена: на checkout с `core.autocrlf=true` расходится каждый файл — на диске CRLF, в блобе LF, а `git status` чист.
  - 2B — блоб после чистки git (`hash-object`, та же чистка, что у `git add`). Цена: сверка доверяет фильтрам git так же, как `git status`.

Выбраны 1B и 2B.

## Decision

Ревизия строки журнала — последний коммит, тронувший каталог тела. Постановка, результат и записи пачки обязаны лежать в её дереве, иначе это «тела в истории нет» — прежняя третья причина.

Каждый файл каталога из ревизии сверяется по блобу: `git hash-object` файла на диске против идентификатора в `git ls-tree` ревизии.

Четвёртая причина пустой ревизии — **файл не сверяется с ревизией**: его блоб на диске другой при чистом `git status`, либо `git hash-object` отказал (файл удалён мимо индекса). Массовая свёртка на ней отказывает до первой записи — с именем файла или с причиной от git. Ответ тот же, что на незакоммиченный каталог: убедиться, что история держит тот же текст, было нечем. Одиночная свёртка пишет в строку `—`, и тело едет в заготовку ([ADR-033](adr-033-fold-draft-mandatory-only-without-revision.md)).

Проверка «каталог не закоммичен» зовёт `git status` с `--untracked-files=all`. Иначе `status.showUntrackedFiles=no` прятал бы незакоммиченный `result.md`, и каталог уходил бы веткой «тела в истории нет».

## Consequences

Строка журнала называет ревизию, где тело блоб в блоб то, что удалено. Перемер на архивах потребителей: 773 из 773 и 312 из 312, было 657 и 303.

Файл под `.gitignore` в ревизию не попадает, не сверяется и уходит вместе с каталогом — как и до этого решения.

[ADR-026](adr-026-archive-folds-to-log.md) заменён в части проверки до удаления и числа причин пустой ревизии.
