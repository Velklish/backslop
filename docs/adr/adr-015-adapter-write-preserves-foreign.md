# ADR-015: Запись adapter outputs не переписывает чужой файл на owned-пути

**Status:** Accepted
**Date:** 2026-09-09
**Deciders:** Velklish

## Context

[ADR-006](adr-006-adapter-ownership.md) задаёт владение generated outputs: маркер `<!-- backslop:generated -->` в файле плюс фиксированный legacy-набор путей. Снятие adapter'а идёт по этому предикату (BS-36): чужой файл без маркера на пути шаблона остаётся и назван предупреждением `init`. Запись владения не спрашивала: `renderAdapters` писал каждый файл выбранного adapter'а безусловно, `write` проверял только путь — выход за корень и symlink — и клал содержимое поверх того, что лежало. Тот же файл, который `init --tools none` сохранял и называл вслух, `init --tools claude` затирал молча и без следа. Контракта на этот случай не было: «Decision» и «Consequences» ADR-006 говорят о владении применительно к снятию.

## Варианты

- **Перезапись остаётся штатной и названа вслух.** Дешевле всего, но правило владения действует в одну сторону: файл без маркера защищён от снятия и не защищён от записи, и потеря пользовательского файла зависит от того, выбран ли adapter.
- **Отказ `init` до первой записи**, как у symlink на корне harness (BS-38). После успешного `init` состояние «чужой файл на owned-пути» невозможно. Цена — ещё одна проверка до `saveConfig` и отказ всей раскладки из-за одного файла, который пользователь мог положить намеренно; файл, созданный после `init`, этот вариант всё равно не ловит.
- **Предупреждение с сохранением файла**, симметрично снятию: файл без маркера не переписывается, `init` называет его и проходит; `lint` красит такой файл у выбранного adapter'а, потому что скилл backslop на этом пути не установлен.

## Decision

Третий вариант. `renderAdapters` перед записью читает владение тем же предикатом `isOwnedAdapterFile`, что и снятие: файл на owned-пути без маркера и вне legacy-набора не переписывается и попадает в предупреждение `init` («не переписаны: …»). Symlink и выход за корень остаются отказом до чтения владения: сквозь чужую ссылку backslop не читает и не пишет (ADR-006). Проверка adapter outputs в `lint` считает такой файл ошибкой у выбранного adapter'а — «на пути adapter output чужой файл без маркера»; лечение — убрать или переименовать файл и повторить `init` либо снять adapter. Файл без маркера на owned-пути тем самым пользовательский по определению: свой вариант скилла держат при снятом adapter'е, а не поверх выбранного.

## Consequences

- Запись и снятие читают одно правило владения: чужой файл на owned-пути не теряется молча ни в одном направлении.
- Проект с чужим файлом на owned-пути выбранного adapter'а не проходит `lint`, пока файл не убран или adapter не снят: раскладка без части скиллов не живёт зелёной.
- Снять маркер с generated файла вне legacy-набора — не способ его приватизировать: следующий `init` файл не перепишет, но `lint` покраснеет; файл legacy-набора owned и без маркера и переписывается. Для своего варианта скилла adapter снимается.
- Уточняет ADR-006: владение читается и при записи; охрана пути — symlink и выход за корень — не меняется.
