# ADR-014: Механика посева — команда, отбор — агент и владелец

**Status:** Accepted
**Date:** 2026-09-09
**Deciders:** владелец, оркестратор захода 2026-09-09

## Context

Скилл `backslop-seed` описывает две процедуры как извлечение по улике, но исполнял их агент руками.

Фаза 1, инвентаризация: [references/inventory.md](../../templates/skills/backslop-seed/references/inventory.md) перечисляет фиксированные места — `package.json` scripts, цели `Makefile`/`justfile`/`Taskfile`, шаги `.github/workflows/*.yml` и `.gitlab-ci.yml`, `*.csproj`/`*.sln`, `pyproject.toml`/`setup.cfg`/`tox.ini`; подсистемы — каталоги `src/*`, `services/*`, `apps/*`, `packages/*`, проекты `.csproj`, точки входа. Это обход известных путей, а не понимание содержания.

Фаза 3, шаг 4: по каждой строке таблицы справочника заводится задача «Справочник: …». Формальный цикл с уже существующим `SLUG_RE` ([lib/tasks.js](../../lib/tasks.js)) и проверкой на дубль по имени файла.

Команды для обоих шагов не было: `COMMANDS` в [bin/backslop.js](../../bin/backslop.js) не называл `seed`, реализации в `lib/` не существовало.

Цена ручного исполнения разная у двух шагов. Инвентаризация руками неполна молча: пропущенный источник выглядит как «в проекте этого нет». Посев очереди руками — это цикл, в котором агент на каждом обороте заново решает уже решённое, и повторный проход плодит дубли.

## Варианты

**Что берёт на себя команда.**

- **1A. Только извлечение: перечислить кандидатов с уликами и завести задачи по строкам таблицы.** Суждение остаётся человеку и агенту: какой пункт — настоящий гейт без секретов, сети и БД, какой каталог — настоящая подсистема, какие термины в глоссарий, какие решения в ADR.
- **1B. Команда сама отбирает `gates` и пишет их в `backslop.json`.** Отбор требует знания, что команда не тянет секреты, сеть и базу, — этого из файла не видно. Ошибка тут дороже ручной работы: гейт, который нельзя прогнать на чистом чекауте, ломает сдачу каждой следующей задачи.

**Откуда берётся slug задачи «Справочник: …».**

- **2A. Из цели ссылки в строке таблицы** (`[Приём заказов](orders-api.md)` → `describe-orders-api`). Имя файла раздела уже латинское — иначе ссылка не работает; транслитерация не нужна.
- **2B. Транслитерация русского заголовка строки.** Потребовала бы таблицы соответствий в инструменте и всё равно давала бы спорные варианты, которые агент правил бы руками.

**Разбор YAML в CI-конфигах.**

- **3A. Построчное извлечение: значение `run:`/`script:` на строке и блок ниже по отступу.** Пункт всё равно проверяет человек, а улика — файл и номер строки — ведёт прямо туда.
- **3B. Полноценный разбор YAML.** Потребовал бы зависимости — прямо против [ADR-003](adr-003-node-stdlib-npx.md).

## Decision

1A + 2A + 3A. Команда `seed` в двух режимах, ровно один за запуск:

- `seed --scan [--json]` печатает кандидатов в `gates` и в подсистемы, каждый пункт с путём-уликой. Ничего не пишет и не отбирает.
- `seed --queue-reference` читает таблицу `<docs>/reference/README.md` и заводит `describe-<slug>` в очередь на каждую строку, чей файл раздела ещё не написан. Slug берётся из имени файла-цели, повторный запуск дублей не плодит: задача с этим slug уже видна в статусах и архиве. Строка, из цели которой slug не выходит, называется в выводе — такую задачу заводит агент руками.

Заведение идёт через `lib/new.js`, а не отдельной записью файла: номер, место в очереди и шаблон остаются общими с `new`.

## Consequences

Инвентаризация перестаёт быть полнотой памяти агента: источник, забытый в `references/inventory.md`, теперь либо в коде `seed --scan`, либо его нет ни в одном посеве — и это видно по коду, а не по добросовестности сессии.

Обязательство на следующие правки: список источников живёт в двух местах — в `scanGates`/`scanSubsystems` и в таблицах `references/inventory.md` (и его английском близнеце). Новый источник добавляется в оба, иначе документация обещает то, чего команда не делает.

Разбор CI построчный, и это осознанная граница: команда даёт кандидатов и улики, а не гарантию, что нашла все шаги. Проект со сложным YAML (якоря, шаблоны заданий, матрицы) даст неполный список — читателю об этом говорит сам смысл слова «кандидаты». По той же причине цели `Taskfile` читаются только при отступе в два пробела: он в этом формате обычен, но YAML его не требует.

Контракт CLI расширен, но не изменён: прежние команды, их флаги и коды возврата не тронуты, состав `status --json` тот же.
