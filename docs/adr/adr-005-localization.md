# ADR-005: Язык раскладки — поле `lang` и второй комплект шаблонов

**Status:** Accepted
**Date:** 2026-09-03
**Deciders:** Velklish

## Context

Все шаблоны, скиллы и человеческий CLI были на русском. Для проекта с англоязычной командой блок в `AGENTS.md` агент прочитает, а человек в команде — нет. Переводить содержимое уже существующих `docs/` при смене языка нельзя: это чужой текст. `status --json` читают оркестраторы, и его схема не должна зависеть от языка.

## Варианты

- **Один комплект шаблонов и отдельный переводчик.** Дешевле держать, но перевод живёт вне репозитория и разъезжается с подстановками.
- **Второй комплект `templates/en/` с тем же составом и `{{placeholders}}`.** `lint` репозитория инструмента краснеет, если набор файлов или подстановок разошёлся. Флаг `init --lang` и поле `lang` в `backslop.json`; старый конфиг без поля читается как `ru`.

## Decision

Второй комплект шаблонов и поле `lang`: `ru` или `en`. Русские шаблоны остаются в `templates/**`, английские — в `templates/en/**`. Команды `new`, `adr`, `archive` и повторный `init` берут шаблон по языку конфига. Смена `lang` обновляет генерируемые harness-артефакты и новые файлы, существующие docs и задачи не переводит. Человеческий CLI говорит на языке конфига; вне проекта `help` и ранние ошибки — двуязычные. `status --json` язык не меняет. Поля шапки и разделы задач читаются на обоих языках в одном бэклоге.

## Consequences

- Гейт равенства состава — часть `lint` репозитория инструмента: правка русского шаблона без английского близнеца не проходит.
- README инструмента — английский, русский текст — в `README.ru.md`.
- Смешанный RU/EN backlog — штатный режим, не ошибка.
