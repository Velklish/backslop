# ADR-017: Шаг гейтов в брифе идёт по пинованной версии, а не по запущенной

**Status:** Accepted
**Date:** 2026-09-12
**Deciders:** Velklish

## Context

Блок «Критерий готовности» брифа зовёт раннер: «гейты зелёные числом: `<cli> gates` печатает итог „гейтов N, зелёных N“». Строку команды он собирает из поля `cli` проекта, то есть из **пинованной** версии, а сам текст блока был одинаков для всех версий.

Раннер `gates` появился в v0.5.0 — измерено по тегам: `git show v0.4.0:bin/backslop.js` перечисляет `init, new, mv, archive, adr, status, lint, upgrade, migrate, changelog`, а `v0.5.0` добавляет сразу `brief`, `seed`, `gates`, `tracks`, `merge-changelog`. На проекте, пинованном ниже v0.5.0, требование блока неисполнимо: `npx github:Velklish/backslop#v0.4.0 gates` выходит кодом 1 с `unknown command "gates"`. Ключ `gates` в `backslop.json` при этом есть и несёт команды — то есть декларация живёт, а исполнителя нет.

Так и случилось дважды на `external/promptobus` (прогоны 2026-09-11 и 2026-09-12, [BS-51](../archive/BS-51-gates-command-absent-on-old-pin/task.md)). Оба worker'а обошли одинаково и правильно — прогнали команды ключа по одной с кодом возврата и отказались печатать сводку, которой не было, — но каждый потратил на разбор ход и пришёл к оркестратору с вопросом не по своей задаче.

Бриф при этом рендерит **запущенная** версия: `brief` тоже появился в v0.5.0, и проект на старом пине собирает бриф чужим, более новым CLI. Поэтому «умеет ли раннер» нельзя спрашивать у себя — только у пина.

## Варианты

- **1. Чем определяется шаг.** 1A — версией из пина `cli`. 1B — версией запущенного инструмента. 1C — пробным запуском `<cli> gates --dry-run`.
- **2. Что печатается на старом пине.** 2A — команды ключа `gates` по одной с требованием кода возврата у каждой и прямым запретом выдумывать сводку. 2B — оба маршрута с условием выбора, одинаково для всех версий. 2C — блок молчит о гейтах.

Цена: 1B отвечает на вопрос не о том инструменте — он и есть источник сегодняшней ошибки. 1C стоит сетевого запуска на каждый бриф и превращает генератор текста в команду с побочным эффектом. 2B оставляет разбор worker'у — ровно тот ход, который карточка и считает потерянным. 2C снимает с worker'а обязанность, которую снимать не за что: гейты гонять надо, вопрос только чем.

## Decision

1A + 2A. `lib/brief.js` читает пин через `parseCli(cfg.cli)` и сравнивает его с константой `GATES_SINCE = '0.5.0'`. Пин не ниже — блок зовёт раннер, как раньше. Пин ниже — блок перечисляет команды поля `gates` по одной, требует код возврата у каждой и прямым текстом запрещает выдумывать сводку «гейтов N, зелёных N»: выдуманная сводка хуже отсутствующей, потому что выглядит как гейт.

Пина нет вовсе (self-host `node bin/backslop.js`, глобальная установка, `npx` без тега) — считается, что раннер есть: проект зовёт тот самый CLI, который сейчас рендерит бриф.

Остальные команды блока проверены той же меркой: `new --parent` есть с v0.1.0 (`git show v0.1.0:lib/new.js` — `parent: { type: 'string' }`), `lint` — с v0.1.0. Кроме `gates`, ветвить в блоке нечего.

## Consequences

Константа `GATES_SINCE` — единственное место, где инструмент знает о возрасте своей команды. Появится в блоке вторая команда моложе самой ранней поддерживаемой версии — рядом встанет вторая константа, а не общий реестр «команда → версия»: реестр пришлось бы держать полным ради двух строк.

Проверка идёт по форме пина, которую понимает `parseCli`. Пин в форме, которую он не разбирает, читается как «пина нет» — то есть блок зовёт раннер. Это осознанный fail-open: неизвестная форма чаще означает свежую установку, чем древнюю.

Текст блока теперь зависит от конфигурации проекта, поэтому проба на него идёт в двух редакциях — `test/brief.test.mjs` гоняет обе ветви на одном дереве, меняя `cli` в `backslop.json`.
