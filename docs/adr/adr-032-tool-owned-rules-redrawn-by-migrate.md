# ADR-032: Правила ведения и архива у потребителя принадлежат инструменту: migrate перерисовывает их из шаблона

**Status:** Accepted
**Date:** 2026-09-24
**Deciders:** владелец — решение 2026-09-24 в карточке BS-72 (`upgrade` перерисовывает процессные файлы `docs/` из шаблона своей версии); механизм — оркестратор захода bs-0924-t20260924-115051 (шаг `migrate`); текст — worker bs72, владельцем не вычитан

## Context

Блок `AGENTS.md` у потребителя отсылает агента к правилам: «Правила ведения — `docs/backlog/README.md`». Блок — adapter output, и `upgrade` его перерисовывает. Файл, на который блок показывает, не перерисовывался никогда. `init` кладёт скелет `docs/` один раз и пропускает существующий файл (`lib/init.js:126-137`), а `upgrade` доводит обновление вызовом `init` новой версии. После любого обновления свежий блок и свежие скиллы показывали на текст правил той версии, на которой проект завели ([BS-72](../archive/LOG.md#bs-72)).

Пара `docs/backlog/README.md` и `docs/archive/README.md` несёт процессный текст инструмента. В этом репозитории она рендерится из шаблона 1:1, равенство держит `test/templates.test.mjs`. Соседи по каталогу наполняются проектом осознанно: `GLOSSARY.md`, `README.md`, `ROADMAP.md`, `reference/README.md`, ADR процесса.

## Варианты

**Решение 1 — чей файл (владелец, 2026-09-24).**

- **1A — файл принадлежит инструменту, обновление перерисовывает его из шаблона своей версии.** Цена: местная правка потребителя в паре теряется при обновлении.
- **1B — файл остаётся проектным, расхождение с шаблоном сторожит `lint`.** Правила всё равно не доезжают, а потребитель получает красный гейт, который чинится ручным слиянием.
- **1C — правила уезжают в adapter output, в блок `AGENTS.md`.** Блок грузится в каждую сессию агента, и объём правил оплачивается токенами на каждом запуске.

**Решение 2 — чей код перерисовывает.** Сам `upgrade` исполняется версией из пина проекта, то есть старой. `migrate` и `init` он зовёт уже новой версией, и так с v0.2.0: `git show v0.2.0:lib/upgrade.js`, строки 118–119; `git show v0.10.1:lib/upgrade.js`, строки 170–171. Шаблон «своей версии» есть только у новой.

- **2A — флаг `init`, его передаёт `upgrade`.** Первое обновление с версии без этого решения идёт старым `upgrade`, который флага не знает, и правила не перерисуются. На момент решения так обновляются все потребители. В обратную сторону флаг ломает обновление: новый `upgrade` на цель не новее v0.10.1 (`--to` или незапиненный `npx` из `main` до выпуска) передаёт флаг старому `init`, и тот отказывает. Замер во временном worktree на `v0.10.1`: `init --refresh-rules` — код 1, «Unknown option '--refresh-rules'». Пин к этому шагу уже переставлен.
- **2B — переменная окружения на вызове `init`.** Старая версия её игнорирует (замер: код 0), но дыра первого обновления та же, что у 2A.
- **2C — версионная миграция в `MIGRATIONS` с полем `since`.** Первое обновление она закрывает, но срабатывает один раз. Следующая правка шаблона до потребителя снова не доедет.
- **2D — постоянный шаг `migrate`: при штампе ниже версии инструмента пара перерисовывается из шаблона этой версии.** `migrate` новой версии зовёт любой `upgrade` начиная с v0.2.0, поэтому шаг работает и на первом обновлении, и на каждом следующем. Цена: `migrate`, запущенный человеком, делает то же самое, и это его работа, а не побочный эффект.

## Decision

**1A + 2D.** Перечень файлов — `RULES_DOCS` в [lib/migrate.js](../../lib/migrate.js): `backlog/README.md` и `archive/README.md` каталога `docs`. Шаг идёт при штампе ниже версии инструмента или без штампа. Он рендерит оба файла из шаблона языка проекта с подстановками `cli`, `prefix`, `docs` и именем проекта. Файл переписывается, если расходится с рендером или отсутствует. Вывод называет перерисованные пути строкой «правила ведения и архива из шаблона vX.Y.Z: перерисованы …», а без расхождения печатает «уже совпадают». `--dry-run` печатает план и ничего не пишет. На штампе, равном версии инструмента, шаг молчит.

Два предохранителя срабатывают до первой записи — и до миграций формата, и с `--dry-run` тоже. Первый: если `git status --porcelain` по файлу, который пришлось бы переписать, непуст, `migrate` отказывает и называет файл: «закоммить или откати правку, затем повтори». Отказ устроен как у массового `fold` на незакоммиченном каталоге, и штамп при нём не меняется. В проекте без git проверять нечем: перерисовка идёт, а строка вывода говорит об этом словами «git нет, незакоммиченных правок проверить нечем». Второй: если путь к файлу пары идёт через symlink на любой компоненте под корнем проекта, файл не перерисовывается, и предупреждение называет ссылку. Иначе запись ушла бы за ссылку, в общий файл вне проекта. Прецедент — [ADR-016](adr-016-selected-adapter-roots-symlink.md), но здесь это пропуск, а не отказ: второй файл пары при этом перерисовывается.

`init` не меняется: существующий файл скелета он не трогает, эту пару тоже. Чей файл, говорит потребителю сам шаблон: абзац «Файл принадлежит backslop…» в обоих языковых слоях.

## Consequences

- Правила ведения и архива доезжают до потребителя с каждым обновлением, начиная с первого обновления на версию с этим решением: и через `upgrade`, и через ручной `migrate` после `upgrade --pin-only`.
- Закоммиченная местная правка потребителя в паре теряется при обновлении — по замыслу. Свои правила проект держит вне пары, например в `AGENTS.md` вне блока backslop. Уже разошедшиеся копии перерисовываются первым же обновлением. Перенос из них своего текста не автоматизирован и в BS-72 не входит, но потерю видно в `git diff` после обновления, а прежний текст лежит в истории. Незакоммиченную правку `migrate` не стирает — отказывает. Исключение — проект без git: там правка стирается без следа, и вывод об этом предупреждает.
- Перерисованная пара ссылается на скелет `docs/`: `README.md`, `ROADMAP.md`, `reference/README.md`, `archive/LOG.md`. `migrate` без последующего `init` в проекте без этих файлов оставляет `lint` красным. Замер на фикстуре со штампом 0.8.0 и без `ROADMAP.md` и `reference/README.md`: код 1, три битые ссылки. `upgrade` зовёт `init` сразу после `migrate`, и недостающие файлы скелета создаёт `init`.
- `init` новой версии, запущенный без `migrate`, ставит штамп (`lib/init.js`, блок «Штамп версии») и этим гасит и миграции формата, и перерисовку. Так было и до решения; рецепт `--pin-only` называет `migrate` перед `init`.
- Состав пары — контракт раскладки: расширение состава — новый ADR. Self-host (`tools: []`, `cli` без источника релизов) через `upgrade` не обновляется. Равенство пары с шаблоном там по-прежнему держат правило `AGENTS.md` и `test/templates.test.mjs`.
