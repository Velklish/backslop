## Контекст

Доставка идёт через `npx github:Velklish/backslop` ([ADR-003](../../adr/adr-003-node-stdlib-npx.md)): без реестра, но с клоном при первом запуске и без пина версии. Публикация в npm даёт короткую команду `npx backslop init`, точную версию в проектах и `npm view` для проверки свежести.

## Что сделать

- Поддержка точной npm-формы `npx backslop@X.Y.Z` в разборе пина и `upgrade`; версии по-прежнему берутся из Git tags через `source`.
- Скрипт релиза: чистое дерево, совпадение версии и тега, `npm test`, `lint`, локальный тег, `npm publish`, затем atomic push `main` и тега.
- Безопасные сообщения восстановления после сбоя публикации или push.
- Чеклист релиза в `AGENTS.md` и документации.
- Отдельная задача `BS-2.1` на фактическую публикацию и переключение default CLI.

## Не входит

- Автоматизация релиза в CI: раннера у репозитория нет.
- `npm publish`, создание тега, push, смена версии `0.2.0` и переключение default CLI в этом заходе.

## Проверки

- Unit/e2e проверяют exact npm pin, сохранение npx-флагов и Git `source` для `upgrade`.
- Release tests через fake `git`/`npm` проверяют preflight, порядок операций и сбои без внешних эффектов.
- Tarball устанавливается во временный проект и проходит `version`, `init`, `lint`.
