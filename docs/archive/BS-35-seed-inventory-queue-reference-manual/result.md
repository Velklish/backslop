# BS-35 · Результат

**Закрыта 2026-09-09.** Выполнена. Команда `seed` (`lib/seed.js`, ADR-014) в двух режимах, ровно один за запуск. `seed --scan [--json]` — кандидаты в `gates` (scripts `package.json` по именам test/lint/check/build/typecheck/fmt; цели `Makefile`/`justfile`/`Taskfile`; шаги `.github/workflows/*.yml` и `.gitlab-ci.yml` построчным разбором без YAML-библиотеки, с `run: |` и `script:`; `dotnet build`/`test` по `.csproj`/`.sln`; `pytest`/`ruff`/`mypy` по `pyproject.toml`/`setup.cfg`/`tox.ini`) и в подсистемы (`src/*`, `services/*`, `apps/*`, `packages/*`, проекты `.csproj`, точки входа по фиксированному списку имён, скрипты `bin/*`), каждый с путём-уликой; сборочные и вендорные каталоги (`.venv`, `vendor`, `dist`, `build`, `out`, `target`, `obj`, `bin`-выход сборки, `coverage`, `.tox`, `__pycache__`) пропускаются локальным `walk` — `SKIP_DIRS` mdwalk не тронут. Ничего не пишет и не отбирает: выбор `gates` — за агентом. `seed --queue-reference` — по строкам таблицы `<docs>/reference/README.md` заводит через `lib/new.js` задачи «Справочник: <строка>» в очередь; slug — из цели ссылки, не транслитерацией (имя файла раздела уже латинское по определению; строка без пригодного slug называется и пропускается); написанный раздел и внешняя ссылка пропускаются; повторный запуск дублей не плодит (сверка по slug, включая архив); «Область» посеянной задачи заполняется строкой таблицы со ссылкой на индекс справочника и именем будущего файла спаном; итог называет заведённые и пропущенные как уже посеянные; `--json` с этим режимом — отказ. Скилл `backslop-seed` и `references/inventory.md` (RU/EN) переписаны под команду; `README.md` и `CONTRIBUTING.md` остались ручным источником — вытащить команду из прозы значит понимать, а не извлекать.

**Границы, названные в ADR-014.** Разбор CI и Taskfile построчный: якоря YAML, `extends`, матрицы и четырёхпробельный отступ Taskfile дают неполный список; список сборочных каталогов и имён точек входа — перечни, не правила; локальный `walk` не разворачивает symlink'и, в отличие от `srcFiles`; список источников живёт в коде и в `inventory.md` без гейта на расхождение. «После посева `lint` код 0» в общем случае недостижимо: единственная оставшаяся ошибка — ссылка самой таблицы на ненаписанный раздел, то есть состояние, которое посев и создаёт по замыслу скилла; посеянная задача в выводе `lint` не упоминается, и это закреплено ассертом.
