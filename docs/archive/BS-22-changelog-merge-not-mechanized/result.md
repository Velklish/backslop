# BS-22 · Результат

**Закрыта 2026-09-09.** Выполнена. Команда `merge-changelog --ours <ref> --theirs <ref> [--base <ref>] [--out <файл>]` (`lib/merge-changelog.js`, ADR-018) сливает две редакции CHANGELOG по единицам структуры: только первая секция невыпущенного, выпущенные секции и шапка — от `--ours`; ключ записи — заголовок `- **…**` в пределах секции, подгруппа — та, где запись встретилась первой; порядок подгрупп и записей — ours, затем только-theirs; совпавший заголовок с одинаковым телом — одна запись, с разошедшимися — обе под строкой `<!-- backslop:conflict <заголовок> -->`, и гейт 7 краснеет на дубле, пока агент не выберет; с `--base` запись, снятая ровно одной стороной относительно базы, снимается в обе стороны, без базы сохраняется, а пометка уходит в отчёт; слитый текст — в stdout или `--out`, отчёт (счёт записей, односторонние поимённо, снятые, помеченные пары) — в stderr. Модуль — `lib/merge-changelog.js`, а не `lib/changelog.js`, как называла «Область» карточки: диспетчер резолвит модуль по имени команды, а `changelogSections` переиспользовать не вышло — она выбрасывает секции без номера версии (ту самую невыпущенную) и привязана к CHANGELOG самого инструмента; из готового взят только регэксп `CHANGELOG_ENTRY`, экспортированный из `lib/lint.js` (долг на пересмотр места регэкспа назван в ADR-018). Скилл `backslop-batch` (RU/EN) зовёт команду вместо ручной процедуры из двух редакций; правило BS-12 для прочих общих файлов осталось. Выпущенная секция, которая есть только у `--theirs`, теряется — прямое следствие правила и названо в ADR.
