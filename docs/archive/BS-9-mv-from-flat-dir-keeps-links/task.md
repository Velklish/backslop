# BS-9 · mv файла из плоского docs/backlog/ в каталог статуса не переписывает исходящие ссылки на глубину +1

- **Область:** [02-cli](../../reference/02-cli.md)
- **Создана:** 2026-09-04
- **Зависимости:** нет
- **Взята:** 2026-09-05

## Контекст

Находка worker'а при переходе `ati-agents` на backslop (BL-541 там), 2026-09-05: задачи, лежавшие плоско в `docs/backlog/`, после `git mv` в `docs/backlog/<status>/` получают глубину +1, и относительные ссылки внутри файлов (`../reference/…`, `../archive/…`) рвутся; `mv` инструмента их не переписывает, потому что считает, что между каталогами статусов глубина не меняется. Worker переписал ссылки руками. Случай миграции чужого трекера — ровно тот, где инструмент нужен больше всего.

## Что сделать

- Решение по устройству `archive`: `mv` всегда пересчитывает исходящие ссылки переехавшего файла от старого каталога к новому (`rewriteMovedLinks`); из плоского `docs/backlog/` меняется глубина, между каталогами статусов — ссылка на соседа из прежнего каталога.
- `mv` подбирает файл задачи, лежащий прямо в `docs/backlog/`: `scanTasks` его не видит, и без этого миграция плоского бэклога идёт руками.
- Отдельная команда миграции не нужна.

## Не входит

- Номера плоских файлов в `new`: до раскладки по статусам `lint` красный, и `new` там не зовут.

## Проверки

- `test/commands.test.mjs`: файл `docs/backlog/BS-5-flat.md` со ссылками `../reference/…`, `queue/…`, `../archive/…` после `mv 5 queue` лежит в `queue/` с пересчитанными ссылками, входящая ссылка из ROADMAP поправлена, `lint` зелёный.
