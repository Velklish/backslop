# BS-16 · У прогона `node --test` backslop нет лимита времени, поэтому регрессия в решении `exitCode` вместо `process.exit` (`bin/backslop.js:108`) не красит тест, а вешает весь прогон навсегда

- **Область:** `test/review.test.mjs`, `package.json`, `bin/backslop.js`, [02-cli](../../reference/02-cli.md)
- **Создана:** 2026-09-06
- **Зависимости:** нет
- **Взята:** 2026-09-09

## Контекст

`bin/backslop.js:105-108` — «Код возврата — через exitCode, а не process.exit: выход до сброса stdout режет длинный вывод на размере буфера пайпа, и `status --json` уезжал бы оркестратору битым.» `docs/reference/02-cli.md:23` фиксирует то же решение как контракт: «...код возврата ставится через `exitCode`, закрытый читателем пайп — тихий выход».

Единственная проверка этого решения — `test/review.test.mjs:77`, объявление без опции `timeout`: `test('status --json доезжает целиком через пайп, который читают с задержкой', async () => {`; `:84` — `spawn(process.execPath, [BIN, 'status', '--json'], { cwd: root })`. `package.json:19` — `"test": "node --test"` без `--test-timeout`; у Node ≥ 20 (версия, на которой работает проект) таймаута тестам по умолчанию нет. Единственный явный лимит в наборе — `test/release.test.mjs:163`: `test('packed tarball installs locally and its bin passes version, init and lint', { timeout: 60_000 }, () => {` — форма уже принята в проекте.

Мутационная проба на копии в scratchpad: замена `(code) => { process.exitCode = code; }` на `(code) => { process.exit(code); }` в `bin/backslop.js:108` (ровно решение, которого требует комментарий) — `node --test test/review.test.mjs` не завершился за 90 с (три предыдущих теста в файле зелёные, четвёртый висит), снят снаружи. Тот же прогон с флагом `--test-timeout=15000` дал `✖ … 'test timed out after 15000ms'`, exit 1, остальные тесты доехали. Полный `node --test` на неизменённой копии — 134 теста, 25.9 с, самый долгий тест 5.97 с — десятикратный запас у лимита 60000 мс.

## Что сделать

- `package.json:19` → `"test": "node --test --test-timeout=60000"`
- Собственный лимит самой пробе: `test/review.test.mjs:77` → `test('status --json доезжает целиком через пайп, который читают с задержкой', { timeout: 20000 }, async () => {` — глобальный флаг работает только через `npm test`, прямой `node --test <файл>` его не получает, поэтому это вторая половина починки, а не дубль

## Не входит

- Остальные тесты набора на предмет собственных таймаутов не разбираются — только тест, который ловит именно эту регрессию
- Само решение «exitCode вместо process.exit» не меняется — оно корректно и должно остаться

## Проверки

- Мутация `bin/backslop.js:108` (`exitCode` → `exit`) после правки красит `test/review.test.mjs` строкой с именем теста и «timed out», не виснет
- `npm test` без мутации — 134/134 pass, время в пределах прежних ~26 с
