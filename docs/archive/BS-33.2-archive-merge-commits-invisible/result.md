# BS-33.2 · Результат

**Закрыта 2026-09-09.** Выполнена. Предположение карточки подтверждено замером ровно для правки, сделанной самим merge-коммитом: репозиторий с веткой (`docs/reference/branch-only.md`), коммитом в `main` (`main-side.md`) и merge `--no-ff --no-commit` с добавленным `merge-only.md`; `archive 1 --range <база>..HEAD` печатал `branch-only.md` и `main-side.md`, но не `merge-only.md`. Файлы ветки приходят через её коммиты, которые входят в диапазон, поэтому пропадает только правка самого слияния. Выбран `--cc`: он даёт ровно её. `-m` тащил бы диффом против второго родителя всё, что `main` набрал с точки ветвления, `--first-parent` прятал бы коммиты ветки от выборки по заголовку. Без `--range` merge-коммит в выборку по заголовку `<prefix>-N:` не попадает — названо в справочнике и прибито тестом.

**Проверки.** Тест `archive --range: merge-коммит — файл из ветки и файл, изменённый только слиянием, названы оба` (`test/commands.test.mjs`), `deepEqual` на точный состав с `--range` и без него. Мутационная проба после коммита: снять `--cc` — 2 из 2 красных (этот тест и вложенный тест BS-33.1). На `main` перед приёмкой: `gates` — код 0, гейтов 2, зелёных 2; `npm test` — 226 из 226; `lint` — 0.

**Доки тем же ходом.** [02-cli](../../reference/02-cli.md) — строка `archive`: merge добавляет только правку слияния, файлы ветки — через её коммиты, без `--range` — только по заголовку; [01-layout](../../reference/01-layout.md) — абзац про архив; `CHANGELOG.md`.
