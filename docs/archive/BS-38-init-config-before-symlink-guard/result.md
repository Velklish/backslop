# BS-38 · Результат

**Закрыта 2026-09-09.** Выполнена. `init` проверяет корни harness на symlink до первой записи: `checkAdapterRoots` обходит `.claude/skills`, `.cursor/rules`, `.agents/skills` тем же `ownedPath`, что `markedFiles`, и бракует symlink на любой компоненте пути под корнем проекта, включая сам `.claude`; вызов стоит до `saveConfig` и скелета `docs/`, одинаково для нового и существующего конфига. Текст отказа называет причину и лечение: сквозь чужую ссылку backslop не пишет и не снимает; замени корень обычным каталогом; `--tools none` не поможет — корни проверяются независимо от выбранных adapters. Существо вопроса «self-host с общим harness-каталогом не проходит `init` никогда» не закрыто по «Не входит» карточки: две развилки контракта (symlink с `realpath` внутри проекта как owned-путь; проверка корней adapter'ов вне `tools`) вынесены находкой BS-38.1 и отложены до решения владельца.
