# BS-66 · Результат

**Закрыта 2026-09-22.** Выполнена. Запись `gates` получила необязательную область: вместо строки — объект `{ command, when: [<glob>…] }`, строка осталась формой «гоняется всегда», обратная совместимость держится тестами. Команда, чья область не задета, не запускается и уходит в `skipped` с причиной, к зелёным не прибавляясь. Решение — [ADR-023](../../adr/adr-023-gates-scope-when.md).

**Источник изменённого набора — оба, как решил владелец.** Без `--base` набор берётся из `git status --porcelain`; с `--base <ref>` — из `git diff --name-only <ref>..HEAD` плюс грязное дерево. Источник называется и в человеческом выводе, и в JSON (`scope.source`), потому что по отчёту должно быть видно, чем считалась адресность.

**Три ловушки, найденные изолированным ревью, и ни одна не была видна гейтам.**
1. Пути `git status --porcelain` идут от корня **репозитория**, а корень проекта — ближайший `backslop.json` вверх. В монорепе `when: ["lib/**"]` не сошёлся бы **никогда**, и итог оставался бы зелёным. Закрыто снятием префикса `git rev-parse --show-prefix`, поле `scope.prefix`, тест на настоящей монорепе.
2. Пустой `--base` проходил: `values.base !== undefined` истинно для `""`, а `git diff --name-only "..HEAD"` — это `HEAD..HEAD`, пустой дифф с кодом 0. Прогон вырождался в «только грязное дерево», но отчёт заявлял базу. Попасть туда просто: `--base "$BASE"` с незаданной переменной. Закрыто отказом до первой команды.
3. `--require-clean` без `--base` при объявленных областях — не вероятный, а **достоверный** холостой прогон: флаг требует чистого дерева, значит набор пуст, значит каждая запись с областью пропущена, и это известно до первой команды. Закрыто отказом, и отказ считает по **сырому** набору, а не по форме флагов: `--require-clean --base HEAD` и `--base origin/main` на уже влитой ветке обходили проверку, построенную на флагах.

**Граница между отказом и пропуском.** Пустой сырой дифф — отказ: приёмка ничего не проверила. Непустой дифф, целиком уехавший за пределы проекта, — прогон с честными пропусками и строкой «отброшено N вне проекта»: изменения есть, наших среди них нет. Без этой границы матрица CI монорепы падала бы на каждом нетронутом пакете.

**Проверки.** `node bin/backslop.js gates --require-clean --json` на `8b11791` — exit 0, «гейтов 2, зелёных 2», `skipped 0`, `outOfScope 0`; `lint` код 0, `npm test` код 0, tests 294 / pass 294 / fail 0. Против базы `1330e9e` (281) снятых имён ноль, добавлено тринадцать. Мутационные пробы по новому коду раннера: снято снятие префикса монорепы — код 1, покраснел тест монорепы; обезврежен отказ холостой приёмки — код 1; занулён счёт отброшенных — код 1. Две последние гонялись суженным набором (`test/gates.test.mjs`), и это названо в уликах.

**Живой прогон адресности** — на самом backslop: правка одного `.md` даёт «гейтов 2, зелёных 1, не запущено 1 (вне области 1)», exit 0; тот же конфиг с `--base HEAD~1` гонит `npm test` 294/294.

**Что осталось незакрытым.**
- Пункт «Проверки» карточки про живой прогон **в потребителе** не закрыт и закрыт быть не мог: потребители пинятся тегом, а тега на этот код нет. Прогон на самом backslop показывает механику, но потребителем не является.
- Ловушка пустого набора **без** `--require-clean` закрыта только словами в справочнике и ADR: раннер без этого флага не знает, приёмка идёт или обычный прогон.
- Старый пин ломается на новой форме `gates`: `loadConfig` версии ниже 0.10.0 требует от поля список строк. Названо в ADR-023, проверки нет.

**Доки тем же ходом.** ADR-023 (включая раздел «Система координат» про монорепу), `docs/reference/01-layout.md` (форма записи, диалект glob и ловушка голого `docs`), `docs/reference/02-cli.md` (флаги, отказы, форма пропущенной записи в `--json`), `README.md` и `README.ru.md`, `CHANGELOG.md`. Критерий готовности «гейтов N, зелёных M» перестал быть полным, и это уехало во все три места, где он живёт: шаг 4 managed-блока, бриф worker'а и скиллы `templates/skills/**`. Правку скиллов внёс соседний track этого же захода (коммит `3d77a23`), она приезжает в `main` следующим коммитом.
