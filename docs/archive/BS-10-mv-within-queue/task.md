# BS-10 · mv N queue --top | --after M переставляет задачу, уже стоящую в очереди

- **Область:** [02-cli](../../reference/02-cli.md)
- **Создана:** 2026-09-05
- **Зависимости:** нет
- **Взята:** 2026-09-05

## Контекст

Наблюдение оркестратора 2026-09-05 в external/promptobus (15 track'ов, 33 задачи): `backslop mv 21 queue --after 18` и `mv 545 queue --top` на задаче, которая уже лежит в `queue/`, отвечают «PB-21 is already in queue/» / «BL-545 уже в queue/» и ничего не делают. Улика: `lib/mv.js` — проверка `task.status === target` стоит раньше расчёта места, `test/commands.test.mjs` закрепляет отказ («задача уже в очереди»). README трекера предлагает править поле «Порядок» руками. Дубли «Порядка» после ручной правки `lint` не ловит: `lintStatusFields` проверяет только наличие и целочисленность.

## Что сделать

- `mv N queue --top | --after M` для задачи из `queue/`: файл не двигается, «Порядок» пересчитывается через `placeInQueue` без самой задачи; соседи перенумеровываются шагом 10, когда целого места нет.
- Без флага положения на задаче из очереди — отказ «уже в очереди; место — `--top` или `--after M`».
- `--after` на саму себя — отказ.
- `lint`: два файла в `queue/` с одним «Порядком» — ошибка гейта 4; красная проба в `test/lint.test.mjs`.
- Доки: справочник 02 и 03, README (EN и RU), README трекера в `docs/` и в шаблонах ru/en, CHANGELOG.

## Не входит

- Перестановка внутри других статусов: порядок есть только у очереди.

## Проверки

- `test/commands.test.mjs`: `mv` внутри очереди ставит «Порядок» между соседями и наверх; без флага — код 1; `--after` на себя — код 1; тесная очередь перенумеровывается.
- `test/lint.test.mjs`: дубль «Порядка» краснит гейт.
