# BS-4.1 · mv переписывает входящие ссылки на задачу

## Контекст

Находка при работе над BS-4: `mv 4 active` перенёс файл задачи, а ссылка на него из `docs/ROADMAP.md` осталась на `backlog/queue/…` — `lint` покраснел на собственном репозитории (улика: `node bin/backslop.js lint` после переноса, «docs/ROADMAP.md: битая ссылка backlog/queue/BS-4-upgrade-and-pin.md»). `archive` входящие ссылки переписывает, `mv` — нет, хотя каталог у файла меняется точно так же.

## Что сделать

- `mv` после переноса переписывает входящие ссылки на файл по всему markdown репозитория тем же обходом и той же функцией, что `archive`; исключения — сам файл по старому и новому пути.
- Тест: ссылки из roadmap, соседней задачи и корневого README после `mv` ведут в новый каталог; `lint` зелёный.
- Справочник 02 (строка `mv`), CHANGELOG.

## Не входит

- Перепись ссылок внутри блоков кода отдельно от прозы: унаследовано от `mapLinks`, задокументировано в links.js.

## Проверки

- Тест в `test/commands.test.mjs`; мутационная проба — ограничить обход каталогом `docs/` — краснеет на ссылке из корневого README.
