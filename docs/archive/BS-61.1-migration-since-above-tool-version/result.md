# BS-61.1 · Результат

**Закрыта 2026-09-22.** Выполнена. Инвариант «`since` записи `MIGRATIONS` не выше `TOOL_VERSION`» сторожит тест `test/version.test.mjs`; рантайм-проверок в `migrate` и `lint` не добавлено сознательно. Оба числа приезжают из одного пакета, поэтому у потребителя они разойтись не могут — перекос бывает только в dev-дереве инструмента, между коммитом миграции и бампом версии. Проверка стоит там, где дефект возможен, и не платит за себя у каждого потребителя.

**Проверки.** `node bin/backslop.js gates --require-clean` на `aab1bad` — код 0, «гейтов 2, зелёных 2», tests 284 / pass 284 / fail 0. Мутационная проба: `since` оставшейся записи `0.9.0` → `0.11.0` (с `node --check` и живым импортом) — код 1, 17/15/0, ассерт «миграция „каталог статуса minor/“: since 0.11.0 выше инструмента 0.10.0».

**Доки тем же ходом.** `docs/reference/02-cli.md`: инвариант назван, сказано, что сторожит его тест, а не рантайм. По находке второго прохода ревью там же уточнена цена перекоса — миграция не только печатается должной, но и **исполняется заново** при каждом запуске (`due` пересчитывается по `since`, штамп при равенстве версий не пишется), а `upgrade` зовёт `migrate` каждый раз; отсюда требование к телу миграции быть идемпотентным.
