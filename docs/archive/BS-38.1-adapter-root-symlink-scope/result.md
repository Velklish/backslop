# BS-38.1 · Результат

**Закрыта 2026-09-09.** Выполнена по решению владельца, с ADR-016: `init` проверяет на symlink только корни adapter'ов из `cfg.tools` — `checkAdapterRoots(root, tools, lang)` до первой записи; ссылка на выбранном корне остаётся отказом независимо от цели (внутрь проекта или наружу — вторая развилка отклонена), а отказ называет лечение однозначно: обычный каталог или `--tools` без этого adapter'а (голый `init` состав не меняет и не лечит). Корни невыбранных не проверяются и не чистятся: `cleanupAdapters` пропускает adapter, чей корень лежит за ссылкой. Обход markdown `repoMarkdown`, по которому `mv` и `archive` переписывают ссылки, за ссылку на корне harness тоже не заходит — граница ставится при обходе в `srcFiles` (набор пропусков), а не пост-фильтром, иначе общий `seen` по realpath терял бы файлы проекта при ссылке внутрь него; ссылкой считается любая компонента корня adapter'а (`.claude` или `.claude/skills`) — тем же `symlinkComponent`, что у охраны записи, он переехал в `lib/mdwalk.js`. Обычный symlink на каталог внутри проекта проходится, как раньше; гейт ссылок `lint` harness-каталогов не касается. ADR-016 заменяет часть решения BS-38 и уточняет ADR-006.

**Проверки.** Тест `init: symlink на корне harness — отказ только для выбранного adapter'а, до первой записи` (`test/init.test.mjs`): `.claude → shared` с файлом backslop за ссылкой — `init --tools claude` отказ без записи конфига и скелета; `init`, `init --tools none`, `init --tools cursor` проходят, файл за ссылкой не снят, cursor разложен; ссылка внутрь проекта на выбранном корне — тот же отказ до записи конфига; на существующем конфиге с claude голый `init` отказывает, `--tools none` проходит. Тест `repoMarkdown: за ссылку на корне harness обход не заходит — на .claude и на .cursor/rules; ссылка внутрь проекта файлы проекта не теряет` (`test/mdwalk.test.mjs`, цели ссылок в отдельной песочнице — результат не зависит от порядка `readdir`). Мутационные пробы после коммита: проверять снова все корни — 1 из 1 красный; снять пропуск невыбранного корня за ссылкой в `cleanupAdapters` — 1 из 1 красный; снять границу обхода — 1 из 1 красный; смотреть только первую компоненту корня — 1 из 1 красный; вернуть пост-фильтр вместо границы — 1 из 1 красный в трёх прогонах подряд. На `main` перед приёмкой: `gates` — код 0, гейтов 2, зелёных 2; `npm test` — 238 из 238; `lint` — 0.

**Ревью.** Изолированное ревью (reviewer Claude на шине, три круга). Круг 1: major — `repoMarkdown` ходит сквозь symlink на каталог, и `mv`/`archive` писали бы за ссылку `.claude` (закрыто границей обхода); minor — двусмысленное лечение «без него» (переформулировано, тест на существующем конфиге). Круг 2: major — отсечение пост-фильтром травит общий `seen` (граница перенесена в обход); major — проверялась только первая компонента корня (любая компонента, общий `symlinkComponent`); minor — тест зависел от порядка `readdir` (цели ссылок вынесены), minor — `lint` обходом `repoMarkdown` не пользуется (доки поправлены). Круг 3 — прежние закрыты, два minor по оформлению (комментарий в тесте оторвался от своего теста, дубль фразы про область гейта ссылок в 03-lint) закрыты без четвёртого круга.
