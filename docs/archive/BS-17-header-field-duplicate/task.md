# BS-17 · Шапка задачи: читатель поля берёт последнее вхождение, писатель — первое, и на дублированном «Порядке» `mv N queue --top` рапортует успех, ничего не переставив, а `mv N active` снимает не то вхождение — гейт 4 остаётся зелёным

- **Область:** `lib/tasks.js`, `lib/lint.js`, [01-layout](../../reference/01-layout.md), [03-lint](../../reference/03-lint.md), [02-cli](../../reference/02-cli.md), `test/lint.test.mjs`, `test/commands.test.mjs`
- **Создана:** 2026-09-06
- **Зависимости:** нет
- **Взята:** 2026-09-06

## Контекст

Читатель и писатель одного поля шапки выбирают разные строки. `readFields` (`lib/tasks.js:297-300`) кладёт поля в `Map`: `for (const [, name, value] of fieldLines(splitLines(text))) map.set(name, value);` — эффективно выигрывает ПОСЛЕДНЕЕ вхождение. `setField` (`:318-320`) и `removeField` (`:340-346`) берут `fields.find(([, n]) => aliases.has(n))` — ПЕРВОЕ. `getField` (`:303-309`) вдобавок перебирает алиасы, а не строки текста.

Гейт 4 (`lib/lint.js:147-162`, `lintStatusFields`) слеп к дублю: ранг читается через `orderOf` → `getField` → `readFields`, дубль поля не ловится ни как повтор строки, ни как занятый ранг — `lintStatusFields` знает только про совпадение рангов у РАЗНЫХ файлов (карта `ranked`), не про две строки одного поля в ОДНОМ файле.

Живая проверка (scratch-проект, `init --prefix BS --tools none`, три задачи в очереди с рангами 10/20/30, во вторую строку BS-3 руками вставлена вторая `- **Порядок:** 25` рядом с исходной `- **Порядок:** 30`):
```
$ node bin/backslop.js status
    10  BS-1 · Один
    20  BS-2 · Два
    25  BS-3 · Три          # читается НИЖНЯЯ строка (25), не верхняя (30)

$ node bin/backslop.js mv 3 queue --top
✔ BS-3: queue/ «Порядок» 5   # код 0, «успех»
# в файле верхняя строка стала 5, нижняя осталась 25

$ node bin/backslop.js status
    25  BS-3 · Три          # позиция не изменилась — перестановки не было

$ node bin/backslop.js lint
✔ lint: ошибок нет           # на всех шагах, включая исходный дубль

$ node bin/backslop.js mv 3 active
✔ BS-3: queue/ → active/
$ head -3 docs/backlog/active/BS-3-three.md
# BS-3 · Три
- **Порядок:** 25            # снята была верхняя строка (5), а не эта
```
То есть `mv N queue --top` отчиталось успехом, не переставив задачу, а `mv N active` оставил в перенесённом файле поле «Порядок», хотя [02-cli](../../reference/02-cli.md):13 обещает «из `queue` снимает «Порядок»».

Живая улика есть и в боевом репозитории ati-agents: `git show 89115bd` добавил в `queue/BL-544.1-…md` сразу две строки «Порядок» (190 и 105); `git show 0ae592d` (`mv 544.1 active`) снял только 190, и 105 доехал до `docs/archive/BL-544.1-canary-live-output-not-streamed/task.md:3`. Происхождение дубля в этом случае не установлено — правдоподобны ручная правка или слияние веток; на находку это не влияет, потому что дефект в том, что инструмент такой файл молча принимает и врёт об успехе.

Задача [BS-10](../BS-10-mv-within-queue/task.md) закрыла соседний, но другой случай — два ФАЙЛА с одним рангом; проверки «поле встречается один раз ВНУТРИ файла» там нет (её текст: «Дубли «Порядка» после ручной правки `lint` не ловит: `lintStatusFields` проверяет только наличие и целочисленность» — про два файла, не про две строки одного файла).

## Что сделать

- Свести выборку «своей» строки поля к одному правилу для чтения и записи: первое вхождение среди алиасов (ru/en) ПО ПОРЯДКУ СТРОК файла, а не по порядку алиасов и не по последнему вхождению; `readFields`/`getField` берут ту же строку, что правит `setField`
- `setField` переписывает первое вхождение и удаляет остальные вхождения того же поля (включая другой языковой алиас); `removeField` удаляет все вхождения — тогда дубль схлопывается при первой же команде, и `mv N queue --top` перестаёт врать об успехе
- В гейт 4 (`lintStatusFields`) — проверка «поле шапки (с учётом алиасов) встречается в файле больше одного раза», с номерами строк в тексте ошибки
- Красные пробы: в `test/lint.test.mjs` — рядом с `probe('4. …')` дубль поля внутри одного файла; в `test/commands.test.mjs` — `mv N queue --top` на шапке с дублем меняет эффективный ранг и оставляет одну строку, `mv N active` снимает «Порядок» целиком
- Доки: [01-layout](../../reference/01-layout.md) — правило «поле шапки внутри файла — один раз»; строка гейта 4 в [03-lint](../../reference/03-lint.md)

## Не входит

- Случай «файл вне `queue/` несёт «Порядок»» (снятое поле не удалено при переносе в другой статус, не при дубле) — отдельный вопрос, не часть этой починки
- Расследование происхождения конкретного дубля в BL-544.1 — не установлено и не нужно для фикса: инструмент должен не принимать такой файл молча независимо от того, откуда взялась вторая строка

## Проверки

- На фикстуре с двумя строками одного поля (ru и en алиас) — `lint` красный с номерами обеих строк
- `mv N queue --top` на шапке с дублем — файл после команды несёт одну строку поля с новым значением, и `status` отражает новую позицию
- `mv N active` на такой же шапке — поле «Порядок» отсутствует в перенесённом файле целиком
- Живой прогон команд, воспроизведённый в разборе (`status` → `mv N queue --top` → `status` → `mv N active`), после правки не даёт расхождения между отчётом команды и фактической позицией/содержимым файла
