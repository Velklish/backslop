# BS-29 · Результат

**Закрыта 2026-09-09.** Выполнена. `npm run release -- X.Y.Z --bump` пишет `version` в `package.json` точечной заменой строки, переименовывает верхнюю секцию `CHANGELOG.md` в `## vX.Y.Z — <дата>` (дата — `today()` из `lib/util.js`, тот же календарь, что у BS-8) и ставит штамп `backslop.json` вызовом `node bin/backslop.js init`; все проверки идут до первой записи, в том числе «bump только вверх» по `compareVersions` — иначе `release 0.1.0 --bump` из 0.4.0 оставлял дерево полубампнутым (находка ревью). Гейт 11 `lintReleaseVersions` (`lib/lint.js`, отдельная функция, только в репозитории инструмента): `package.json.version` против штампа; секция `## vX.Y.Z` на выпускаемую версию; пин `github:Velklish/backslop#vX.Y.Z` либо `backslop@X.Y.Z` в `README.md`, `README.ru.md`, `AGENTS.md`, называющий не её, — блоки кода считаются, потому что команда установки в README — живая инструкция. Пины сверяются с `package.json.version`, а не с `defaultCli()`, как буквально просила карточка: во временном проекте пробы `defaultCli()` дал бы версию настоящего инструмента, и гейт стал бы непроверяемым; в self-host оба числа связаны первым пунктом того же гейта. README переведены на обобщённую форму `#v<версия>` — там пин держался на `#v0.2.0` три релиза спустя (слитая BS-41); заодно поправлено описание поведения `init`: пин подставляет та версия, что делала раскладку. Фикстура `test/release.test.mjs` раскладывает `scripts/` и `lib/` во временном корне и получила `"type": "module"` — без него Node перечитывал копии `lib/*.js` как CJS с предупреждением в stderr.

Гейт 11 по пинам на дереве после перевода README на обобщённую форму вакуумный — сторожит будущее; что он не холостой, показывают красные пробы.
