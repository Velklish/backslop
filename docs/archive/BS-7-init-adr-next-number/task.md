# BS-7 · init кладёт ADR процесса следующим свободным номером, если ADR в проекте уже есть

- **Порядок:** 20
- **Область:** [02-cli](../../reference/02-cli.md)
- **Создана:** 2026-09-04
- **Зависимости:** нет

## Контекст

`init` писал `docs/adr/adr-001-process.md` безусловно. В проекте со своими ADR (`ati-agents`: `adr-001-architecture.md` и ещё 38) это давало два файла с номером 001, и первый же `lint` краснел на «номер ADR 1 уже занят» — замер 2026-09-05 на копии дерева. Ход `adr` при этом номер считает правильно.

## Что сделать

- Номер ADR процесса: в пустом `adr/` — 001, иначе следующий свободный; шаблоны ADR и строки таблицы `docs/README.md` берут `{{adrNumber}}`.
- Уже лежащий `adr-NNN-process.md` повторный `init` не дублирует; напоминание про строку таблицы называет созданный файл.

## Не входит

- Строка в существующей таблице `docs/README.md` — по-прежнему руками, как напоминает `init`.

## Проверки

- `init` над `adr-001-architecture.md` и `adr-002-storage.md` создаёт `adr-003-process.md`, повтор не создаёт `adr-004`.
- `init` в пустом проекте: строка таблицы README и файл ADR называют один номер.
