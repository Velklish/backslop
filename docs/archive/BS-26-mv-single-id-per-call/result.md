# BS-26 · Результат

**Закрыта 2026-09-09.** Выполнена. `mv <N…> <статус> [--top | --after M]` принимает несколько номеров: последний позиционный — статус, всё до него — номера. Резолв и все видимые до переноса отказы (задачи нет, в архиве, уже в этом статусе, в `queue/` без флага положения, повтор номера в пакете, `--top`/`--after` при нескольких номерах) идут по всему пакету до первого `git mv`; дальше перенос по одному в порядке аргументов, строка `ok` на каждый, одна сводка перенумерации очереди. Тело переноса — `moveOne`, одиночный вызов не изменился. Очередь читается заново на каждый номер пакета: общий снимок выдал бы уезжающим в `queue` задачам один «Порядок», и команда сама создавала бы ошибку гейта. Атомарна проверка, а не файловые операции: отказ `git mv` на середине пакета так не отменяется — 02-cli говорит это словами. Сводка перенумерации считает сумму длин, а не множество путей, и у суммы стоит комментарий почему: перенумерация возможна только с `--top`/`--after`, а они при пакете — отказ, поэтому за пакет `renumbered` всегда пуст и сумма равна множеству; вариант с множеством был написан по замечанию ревью и откачен как недостижимый код. ADR не заводился: расширение арности обратно совместимо. Сохранение прежнего «Порядка» при выходе из очереди — остаток BS-30, за границами.

**Проверки.** Актуализация подтвердилась дословно, включая живой прогон `mv 1 2 3 active` → «статус «2» неизвестен». Worker: `npm test` — 156 из 156, затем 170 из 170, код 0; `lint` — 0 ошибок.
