# BS-51 · Результат

**Закрыта 2026-09-12.** Выполнена. `brief` собирает шаг гейтов по версии из пина `cli`, а не по запущенной: `parseCli` даёт пин, он сравнивается с `GATES_SINCE = '0.5.0'` — версией, в которой раннер появился. Пин не ниже — блок зовёт `<cli> gates`, как раньше. Пин ниже — блок перечисляет команды поля `gates` по одной, требует код возврата у каждой и прямым текстом запрещает выдумывать сводку «гейтов N, зелёных N»: выдуманная сводка хуже отсутствующей, потому что выглядит как гейт. Пина нет вовсе (self-host `node bin/backslop.js`, глобальная установка, `npx` без тега) — раннер считается доступным: проект зовёт тот же CLI, который рендерит бриф. Решение записано в [ADR-017](../../adr/adr-017-gates-step-follows-the-pin.md).

Остальные команды блока проверены той же меркой, как требовала постановка: `git show v0.1.0:lib/new.js | grep -c parent` → 7, то есть `new --parent` есть с первой версии; `lint` — тоже с v0.1.0. Моложе самой ранней поддерживаемой версии в блоке только `gates`, поэтому ветвление одно.

Дата появления команды снята с тегов, а не с CHANGELOG: `git show v0.4.0:bin/backslop.js` перечисляет `init, new, mv, archive, adr, status, lint, upgrade, migrate, changelog`, `v0.5.0` добавляет `brief`, `seed`, `gates`, `tracks`, `merge-changelog`.

**Проверки.** `node bin/backslop.js gates` — гейтов 2, зелёных 2 (`node bin/backslop.js lint` код 0, `npm test` код 0, тестов 245). Ветви шага проверены обе в `test/brief.test.mjs`: на пине `npx backslop@1.2.3` блок зовёт раннер, на `npx backslop@0.4.0` — не называет `gates` вовсе, перечисляет команды и запрещает сводку. Живой пробой на фикстуре проекта: пин `#v0.4.0` даёт перечисление, `#v0.5.0` — раннер, то есть граница включения стоит на самой версии появления.
