## Контекст

AGENTS.md:11 описывает единственную процедуру релиза: «Релиз — `npm run release -- X.Y.Z` из чистого `main`: …, `npm publish`, atomic push `main` и тега». `scripts/release.mjs:42` принимает ровно один позиционный аргумент (версию) и не имеет флагов (`if (argv.length !== 1 || !/^\d+\.\d+\.\d+$/.test(argv[0]))`); `npm publish` (release.mjs:75, `command('npm', ['publish'])`) стоит безусловно между локальным `git tag` (release.mjs:67) и atomic push `main`+тега (release.mjs:81) — обойти публикацию средствами самого скрипта нельзя.

Абзац AGENTS.md:11 и `scripts/release.mjs` появились одним коммитом `4a5418d` («BS-1, BS-2, BS-3, BS-5…», 2026-09-03 15:25:40) — `git log --diff-filter=A -- scripts/release.mjs` и `git blame -L11,11 AGENTS.md` называют один и тот же коммит. `git tag -l` → `v0.1.0 v0.2.0 v0.3.0 v0.3.1 v0.4.0`; `git merge-base --is-ancestor v0.2.0 4a5418d` подтверждает: v0.1.0 (03:52) и v0.2.0 (12:33) того же дня вышли раньше коммита со скриптом и мандатом — к этой находке они отношения не имеют. А v0.3.0 (2026-09-04 15:12:59), v0.3.1 (2026-09-05 01:03:49) и v0.4.0 (2026-09-05 21:45:18) вышли уже после того, как AGENTS.md стал предписывать единственный путь через скрипт. При этом `npm view backslop version` → `E404 Not Found` — пакет в реестре ни разу не публиковался, то есть все три тега после появления мандата поставлены мимо него.

`docs/backlog/deferred/BS-2.1-npm-publish.md` в статусе «Отложена» (2026-09-03): «Причина: фактическая публикация, tag и push исключены из текущего захода владельцем», «Условие возврата: владелец выбирает release version и подтверждает готовность npm auth/2FA к публикации». Это решение владельца покрывает саму публикацию, но не текст AGENTS.md: он по-прежнему предписывает единственный путь, включающий шаг, признанный преждевременным. Поиск по `docs/backlog` и `docs/archive` не находит отдельной задачи на это расхождение — только исходную BS-2 и саму BS-2.1.

`npm whoami` → `401 Unauthorized` (проверено сейчас) — токен в `~/.npmrc` невалиден, поэтому случайный запуск `npm run release` сегодня технически не опубликует пакет, но упадёт после создания локального тега в состоянии, которое сам скрипт называет «состояние npm registry неизвестно». Это защита по случайности просроченного токена, а не осознанная гарантия — предположение, не проверенный факт: при валидном токене результат первого запуска либо реальная первая публикация пакета, либо тот же отказ после создания тега.

## Что сделать

- Добавить в `scripts/release.mjs` флаг `--no-publish`: пропускает шаг `npm publish` (строка ~75), сохраняя создание локального тега и atomic push `main`+тега.
- `test/release.test.mjs` — тест на `--no-publish` через существующий fake git/npm harness: `npm publish` не вызывается, лог заканчивается на `git push --atomic origin main vX.Y.Z`, код возврата 0.
- AGENTS.md:11 — заменить формулировку так, чтобы текущий (до закрытия BS-2.1) путь назывался `npm run release -- X.Y.Z --no-publish`, а фраза «Default `cli` до первой публикации в npm — GitHub-форма» явно привязана к условию возврата BS-2.1.
- docs/reference/02-cli.md:27 — упомянуть `--no-publish` в описании релизного пути.
- CHANGELOG.md — запись о новом флаге.
