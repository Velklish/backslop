# BS-19.1 · Каталог, названный как файл задачи, роняет lint стеком EISDIR вместо гейта 2

- **Область:** `lib/tasks.js`, `lib/lint.js`, [03-lint](../../reference/03-lint.md)
- **Создана:** 2026-09-09
- **Зависимости:** нет
- **Взята:** 2026-09-09

## Контекст

Находка при работе над BS-19. Гейт 2 (`lib/lint.js:121`) объявляет ветвь «каталог внутри
каталога статуса: задача — один файл», и `docs/reference/03-lint.md:8` обещает то же:
«в каталоге статуса файл не по шаблону имени или подкаталог». Ветвь достижима не для всех имён.

Улика — прямой замер на HEAD `aa36f3b`, проект из `makeProject({ git: false })` с одной задачей
в `queue/`, `node bin/backslop.js lint`:

- каталог `docs/backlog/queue/sub` → `✖ docs/backlog/queue/sub: каталог внутри каталога статуса:
  задача — один файл`, `✖ lint: ошибок 1`, код 1 — гейт отработал;
- каталог `docs/backlog/queue/BS-9-sub.md` (имя проходит `taskFileRe`) → необработанный
  `Error: EISDIR: illegal operation on a directory, read` со стеком `node:fs:435
  binding.readFileUtf8`, код 1.

`scanTasks` читает такой каталог как файл задачи до того, как `lintTasks` доходит до своей ветви,
и отказ выходит стеком, а не диагностикой. Код возврата 1 в обоих случаях, поэтому в гейтах
разница не видна — видна она человеку, который читает вывод.

Проба BS-19 на эту ветвь поэтому использует имя `sub`, а не `BS-9-sub.md`
(`test/lint.test.mjs`, блок BS-19).

## Что сделать

- Решить, чей это предмет: охрана в `scanTasks` (не читать каталог как файл задачи) или порядок
  гейтов в `lintProject`. Правка — одна из двух, не обе.
- Проба: каталог `docs/backlog/queue/BS-9-sub.md` — ожидается текст гейта 2, а не стек.

## Не входит

- Пять проб BS-19 — они закрыты, эта запись только про недостижимость ветви для части имён.

## Проверки

  диагностику гейта 2 и не печатает стек.
