# BS-11 · new считает номер по всем worktree и локальным веткам, а не только по текущему дереву

- **Область:** [01-layout](../../reference/01-layout.md)
- **Создана:** 2026-09-05
- **Зависимости:** нет
- **Взята:** 2026-09-05

## Контекст

Наблюдение захода 2026-09-05 в external/promptobus: `new <slug> --parent 14` в основном дереве оркестратора дал `PB-14.3`, тогда как worker в своём git worktree уже создал `PB-14.3` в своей ветке (не слитой); то же с `PB-17.1`/`PB-15.3` и с обычным `new` (`PB-544` оркестратора совпал с номером находки в чужой ветке). Столкновение ловит только `lint` при слиянии, и проигравший переименовывает файл руками — за заход трижды. Улика: `nextNumber`/`nextSub` в `lib/tasks.js` считают по `scanTasks`, а он читает только каталоги текущего дерева.

## Что сделать

- `new` при выборе следующего номера и `N.k` учитывает занятые номера из других worktree репозитория (`git worktree list --porcelain`, файлы `<docs>/backlog/**` и `<docs>/archive/*` на диске) и из всех локальных веток (`git ls-tree -r --name-only <branch> -- <docs>/backlog <docs>/archive`).
- Когда номер сдвинут чужим worktree или веткой — печатать, откуда взят занятый номер.
- Без git или вне репозитория — как раньше, по текущему дереву.
- Доки: справочник 01 и 02, README трекера в `docs/` и шаблонах ru/en («два параллельных заведения…»), CHANGELOG.

## Не входит

- Удалённые ветки (`origin/*`) и отдельные клоны — их файлы локально не видны; столкновение с ними по-прежнему ловит `lint` при слиянии.
- Флаг `--from N`: сканирование дёшево, явный номер не нужен.

## Проверки

- `test/commands.test.mjs`: задача, закоммиченная в другой ветке, и файл в другом worktree без коммита сдвигают номер `new` и sub-ID `new --parent`; вывод называет ветку или worktree.
