# 03. Lint gates

`lint` lists everything it finds and exits with code 1 when there are errors. Warnings are printed and do not fail it. Messages are in the project language (`lang`), the tool's own template checks included. A directory the walk cannot list is a refusal: `<path>: the directory is not readable (<code>) — lint cannot walk it; restore read access or move it out of the project`.

## Gates

| No. | Gate | What it catches | How to fix |
|---|---|---|---|
| 1 | Links | A broken local link, a missing anchor or an undeclared reference label in `docs/**` and root `*.md` — the extension in any case (`NOTE.MD` too). A root symlink is read when it resolves to a regular file inside the project; a link leading outside is not read; a symlink whose target the walk already covers is checked once, by the path without the link. Every form is read by one parser: inline — bare (balanced parentheses inside are legal: `foo(1).md`), with a title, in angle brackets; reference-style — full `[text][label]`, collapsed `[label][]` and shortcut `[label]` with a declaration, the first declaration of a label winning and labels compared case-insensitively; images; a badge `[![alt](img.png)](target.md)`, whose image and outer destination are both links; HTML `<a href="…">`; autolinks `<https://…>`, which are external. A full or collapsed reference whose label has no declaration is an error, `link [<text>] uses the label “<label>”, and there is no declaration “[<label>]: …”`; a shortcut `[x]` without a declaration is text. Code spans, fenced code blocks — also in a blockquote or a list item — and HTML comments hold no link, and a BOM at the start of a file hides neither a declaration nor a first-line fence; an indented code block (four spaces, no fence) is read as prose. Targets resolve by the [link rule](#link-rule), and a fragment must name an anchor of its target: `link <href>: <file> has no anchor “<fragment>” — no heading or id by that name`. Every error about a link ends with its line, `(line N)`. The target name is compared letter by letter with the directory listing: a target that differs from the file only in case (`readme.md` for `README.md`) is an error, `link target differs in case`, naming the real name, on every file system — Linux CI and web renderers are case-sensitive. The same gate reports a link to an existing directory whose text names a project task (`<prefix>-N[.k]` anywhere in the link text, in a code span too): inline `[<prefix>-N](../triage)` and reference-style — full `[<prefix>-N][f]`, collapsed `[<prefix>-N][]` and shortcut `[<prefix>-N]` with the declaration `[f]: ../triage` (labels compare case-insensitively). Such a link promises a card and delivers a directory, and it looks whole while broken; gate 6 does not see it, because the number exists. A directory link without a task id is allowed: `[templates/](../../templates/)` shows a directory, and nothing but the directory can show it. A link inside a code span or a fenced code block is an example and is not read. Gate 1 prints what it read to stdout, `gate 1: files N, links N, local N, anchors checked N`: the files of its set, the links of every form, the links with a local target (a same-file `#anchor` included, a use of a declaration counted once, at the declaration), and the fragments checked against a Markdown file. Markdown files with no link at all are an error, `gate 1 read nothing: …`: a walk that reads nothing must not look like a clean tree. Generated adapter outputs are not in this walk and not in its counts: their links are checked by the [adapter pass](#checks-outside-the-fourteen-gates) under the same rule | fix the path, and the case to match the file; point a fragment at an existing heading or id; declare the label or write the link inline; point a link that names a task at its file or journal line; move tasks with `archive`, which rewrites inline links and declarations at the start of a line itself; an HTML link, a badge's outer destination and a declaration in a blockquote or a list item are not rewritten yet — fix them by hand after the move |
| 2 | Numbers | A number used twice; a first line that is not the heading `# <prefix>-N · Title`; a first-line heading that names another number (compared as numbers: `<prefix>-007` in the heading and `<prefix>-7` in the file name are one number, leading zeros make no other number); a finding `N.k` without task `N`; in a status directory, a file whose name does not match the pattern, or a subdirectory — a symlink to a directory, and a directory named like a task file, included: commands of the current tree read no such directory as a task, neither in the status directories nor flat in `docs/backlog/`; a dangling symlink in a status directory | refile with a new number (`new`), fix the heading |
| 3 | Backlog layout | Any file directly in `docs/backlog/` other than `README.md` (dot files are ignored); a directory that is not a status; a missing status directory; a missing `docs/backlog/`; `docs/backlog/` or a status directory that is a regular file — `<path>: a file, expected a directory`. A symlink to a directory inside the project is a directory; a symlink leading out of the project is not followed and counts as a file | `mv N <status>` — it sees the flat file and recomputes its links; create the directory with a `.gitkeep`, or run `init` for a missing `docs/backlog/`; a file in place of a directory — remove or rename it and create the directory |
| 4 | Fields, sections and placeholders | In `queue/`: no integer Order, or one Order on two files. A known header field (RU/EN aliases counted) repeated in one file. In `active/`: no Taken date (`YYYY-MM-DD`). In `deferred/`: no Deferred section, an empty one or one still holding a `[TODO]` placeholder, or more than one such section. Section headings inside fenced examples are not sections. Scope missing, empty, or a value that is entirely a `[TODO…]` placeholder left by `new`, in `queue/`, `active/` or `deferred/`; in `minor/` the same is a warning, not an error, because the approver fills Scope when cutting batches. In `minor/`: no Cost field, a Cost that does not parse (`critical`, `major`, `minor`; a hypothesis is `major (hypothesis)` or its Russian form), or `major`/`critical` without the hypothesis mark — with evidence such a finding is fixed, not queued for a batch; no Evidence section, an empty one, or one holding a placeholder — the entry would go to a batch unreviewed. A standalone line that is a `[TODO…]` placeholder (a list marker `-`/`*`/`+`, a number `1.`/`1)` and a checkbox `[ ]`/`[x]` are stripped first; a table row is checked cell by cell), or a field whose value is entirely such a placeholder, in any markdown file under `docs/backlog/**` except `triage/`. `[TODO]` as part of an explanation is not a placeholder. A task just filed with `new <slug> --queue` fails this gate by design: the Scope placeholder is the reminder to pick a reference section, and until then the task is not ready for the queue. `triage/` is excluded whole: `new` puts a template card there, and nobody fills its blanks before triage, so every entry filed by the standard command would be red; the approver asks for evidence while triaging. `minor/` has no triage, so the Evidence section is required there, by `mv N minor` and by this gate | fix the field or section; delete a duplicate Deferred section, and do not duplicate the existing one through `mv` |
| 5 | Archive | A directory whose name does not match the pattern (a symlink to a directory inside the project is a task directory, a symlink leading out of the project is a stray file); a stray file in the archive — anything other than task directories, `README.md` and `LOG.md` (dot files are ignored); no `task.md` or `result.md`; a placeholder left in `result.md` — `[TODO` outside code, with code blocks and code spans blanked, so the placeholder form shown in code is an account of it and does not count, while the same form in prose does; a completed `result.md` that names no word of the outcome table ([01](01-layout.md#archive)) — completed, rejected, merged into `<prefix>-N`, or a Russian form — in its first paragraph or heading: a bare closing word ("Closed" or its Russian form), "done" and the `Outcome:` marker are not an outcome, folding would read them as completed, and with no word at all it would write `—`. `fold N` refuses on the same two predicates; the outcome refusal carries the same message ([02](02-cli.md)). In a batch's `minor/` subdirectory, anything other than entry files `<prefix>-N[.k]-<slug>.md` (dot files are ignored); `docs/archive` or a batch's `minor/` that is a regular file — `<path>: a file, expected a directory` | complete the result — this is the approver's reminder; name the outcome with a table word in the first paragraph: `**Closed DATE.** Rejected: …`; only `archive N.k --into M` puts files into a batch's `minor/`; a file in place of a directory — remove or rename it and restore the directory |
| 6 | Mentions | `<prefix>-N` or `<prefix>-N.k` in `docs/**` and `CHANGELOG.md` with no file behind it in the statuses or the archive (compared as numbers: `<prefix>-007` finds `<prefix>-7-*` and back); an entry in a batch's `minor/` counts as a file in the archive; code blocks are examples and do not count | fix the number or file the task |
| 7 | CHANGELOG | An entry title `- **…**` repeated within one section; code blocks are examples: a section heading or an entry inside a fence does not count | a repeated title is an edit of one entry: keep one revision |
| 8 | ADR | ADR not linked from `docs/README.md` — the link's href resolves by the [link rule](#link-rule); no `docs/README.md` index while ADRs exist; two files with one number; a file in `adr/` whose name does not match the pattern, `.MD` extension included — also when no correctly named ADR exists; `docs/adr` that is a regular file — `<path>: a file, expected a directory`, and `backslop adr` refuses with the same path | add the link as a row of the ADR table, or create the index; renumber; a file in place of `adr/` — remove or rename it and restore the directory |
| 9 | Triage review | A finding `N.k` lies in `triage/` while its task `N` is already in `archive/`: `lint` prints a warning for the approver and does not fail. A finding in `queue/`, `active/` or `deferred/` is already triaged and does not count | the approver triages the entry: `mv N.k queue`, merge it into another task, or close it with `archive N.k` |
| 10 | Quotes | In `docs/**` and root `*.md` — the gate 1 file set, with its root symlinks and `.MD`: a plain block `<!-- quote:<path> -->…<!-- /quote -->` checks its content, target and closing; `<!-- quote:before:<path> -->…<!-- /quote -->` marks a snapshot taken before an edit and does not fail on a content mismatch, but its target and closing are still required. Spaces after `quote:` and `before:` are allowed. A line that, without inline code, is entirely a marker (`^\s*<!--\s*/?quote\b.*-->\s*$`) but parses as neither an opening nor a closing marker, and a `<!-- /quote -->` with no open block, are errors with a line number; a marker in the middle of prose is prose. A quote path is tool syntax, not a link, and nothing renders it: `<!-- quote:/… -->` resolves from the project root, not from the repository root as gate 1 links do. The comparison is line by line, with whitespace at line edges trimmed on both sides and a wrapping fence around the quote dropped (fences inside the quote stay), so re-indented code does not break a quote. A form shown inside a code block or inline code is an example and does not count; `docs/archive/` is not checked: a quote in a closed task is a snapshot of its moment | reread the file and update a plain quote, or remove the block; for a snapshot, check the path and the closing; turn a quote of a place that its own task changes into `quote:before:` — who places the mark is said in the [operating rules](../backlog/README.md) |
| 11 | Release versions | Only in the tool's own repository (the same sign as template parity: its `templates/` is the running tool's directory). `package.json` that does not parse as JSON — an error with the parser's text; the other checks of this gate stop, the other gates run. No `version` field in `package.json` — nothing to compare with. `version` in `package.json` differs from the `backslop.json` stamp. `CHANGELOG.md` has no `## vX.Y.Z` section for that version. In `README.md` or `AGENTS.md`, a pin `github:Velklish/backslop#vX.Y.Z` (also with a `.git` suffix and without `v`: `….git#vX.Y.Z`, `…#X.Y.Z`) or `backslop@X.Y.Z` names another version. Code blocks count: an install command is an instruction, not an example | `npm run release -- X.Y.Z --bump`; in the prose of an install example, the generic form `#v<version>` has nothing to drift |
| 12 | Template placeholders | A placeholder `{{name}}` in `templates/**` with no key declared for its template group, and a declared key that no template of its group uses. Both language layers are checked: a name that diverged between ru and en would otherwise slip through. Only in the tool's own repository, by the same sign as template parity | add the pair whole: the name in both templates and the key in the caller's `vars`, plus the key in its group's declaration (see [Implementation notes](#implementation-notes)). A name without a key is a render-time refusal, so the reader never meets a literal `{{…}}` |
| 13 | Closed-task journal | A line of `<docs>/archive/LOG.md` that looks like an entry (starts with `- <a id=`) but does not parse; a line whose anchor does not match its number; a link to `LOG.md#<anchor>` with no journal entry behind the anchor, in `docs/**` and root `*.md` (the gate 1 set, with its root symlinks and `.MD`) — the path resolves by the [link rule](#link-rule), and the anchor is everything after `#`, including after a `?query`; a line revision not reachable from `HEAD` (absent from `git rev-list HEAD`), through which `show N` cannot find the body. Gate 1 leaves the anchors of journal links in its own file set to this check, whose message names the missing entry and the line: incoming links of closed tasks point at the journal. The adapter pass checks journal anchors itself, since this check does not walk adapter outputs. The fourth catches a commit that a squash or rebase dropped after folding — before the push, when `lint` runs on the final acceptance commit as the procedure says; [02 § fold](02-cli.md#fold) says what leaves such a revision | fix the journal line to the form of [01](01-layout.md#archive); point the link at an existing anchor — `backslop show N` shows the folded task's number; for an unreachable revision, bring the commit back into history or, when the body went into the acceptance commit message, replace the revision with `—`: `show N` finds the commit by its subject |
| 14 | Non-printable bytes | Only in the tool's own repository (the same sign as gates 11 and 12): a byte below `0x09` — tab excluded; NUL and SOH are the live cases — in a file tracked by git (`git ls-files`) under `lib/`, `bin/`, `test/`, `templates/`, `scripts/` or `docs/`. NUL makes a source file binary to `git` and `grep`: searching it finds nothing, and the silence reads like "not in the code"; git does not call bytes `0x01`–`0x08` binary, but they are invisible in an editor and in output, and the error calls them an invisible control byte. The error names the file, the byte offset and the line; there is no exception list — no file of these trees legitimately carries such a byte. In a consumer project the gate does not judge: its `docs/**` and `test/**` legitimately carry binary files, and git's text sign catches the wrong case — git itself calls a file with NUL binary | write the byte as an escape sequence (`\u0000`, `\x01`): the string is the same, and the file stays text |

## Link rule

One link rule serves gates 1, 8 and 13 and `seed --queue-reference`, and one parser reads their links:

- The target is the href up to the first `#` or `?`, decoded (`%2E` is a dot; a broken `%` escape is a broken link).
- A leading `/` resolves from the repository root, as on GitHub and GitLab — in a monorepo subproject too (`/pkg/a/docs/…`). Outside a repository it resolves from the project root, and a git failure while finding the root refuses `lint` with its cause. Any other path resolves from the file's directory.
- External addresses are not checked: any `<scheme>:`, case-insensitive (`https:`, `ftp:`, `tel:`, `HTTPS:`; a drive letter `C:/…` is a scheme too), and `//host`. A bare `#anchor` points into the same file.
- Footnotes `[^1]:` are not link declarations. A code fence closes only on a fence of the same character that is not shorter than the opening one; an unclosed fence runs to the end of the file.
- A declaration may stand in a blockquote or a list item (`> [l]: x.md`); a line that continues a quoted paragraph without `>` continues that paragraph and declares nothing.
- A fragment is checked for a local Markdown target (`.md` in any case) and for a same-file `#anchor`. It must name an anchor the target exposes: the slug of a heading outside code blocks and HTML comments — ATX or setext, also inside a blockquote or a list item — a repeated heading taking `-1`, `-2` in document order, or an explicit `id="…"` or `<a name="…">`. The fragment is URL-decoded and compared as written, then lowercased. Two fragments that the renderer resolves without a heading are not checked: `#top` in any case, the top of a page, and a source-view line `#L12` or `#L12-L20` after a `?plain=1` query.
- The slug is GitHub's, and gitlab.ati.st renders the same one: closing `#`s dropped, the lines of a setext heading joined with a space, a link, an image or an autolink reduced to its text, an HTML tag dropped (`Result<T, E>` keeps `<T, E>` as text), `_` and `*` emphasis unwrapped, the entities `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;`, `&nbsp;` and every numeric one decoded — another named entity keeps its letters (`&mdash;` gives `mdash`), where the renderer drops the character; then lowercase, punctuation dropped except `-` and `_`, each space a hyphen (`A — B` is `a--b`).
- A target's anchors are read from the target file, also outside the gate's file set, as long as it is inside the project. A target outside the project, a directory and a non-Markdown file (`code.js#L10`) keep their fragment unchecked.

## Checks outside the fourteen gates

These errors fail `lint` without a gate number:

- **Adapter outputs** of every selected adapter: the output file is present, is a file, and is owned (carries the generated marker); its links pass the gate 1 rule — target, anchor and label — and do not point to a directory while their text names a task. A foreign file without the marker at an owned path is an error — `init` does not overwrite it; remove or rename the file and rerun `init`, or deselect the adapter. A directory at an owned path is an error, since `init` refuses on it.
- **Claude stub.** The `claude` adapter is selected and `CLAUDE.md` is missing: `Claude stub is missing — run <cli> init`.
- **Template parity**, in the tool's own repository: the layers `templates/` and `templates/en/` agree in five ways — one set of files; one set of placeholders in each pair; skill frontmatter in both layers, with `name` equal to the directory name and a non-empty `description`; one sequence of heading levels outside code blocks; no Cyrillic letter in the English layer.
- **Live pins**: a stale or suffixed pin in a live file, or in `gates` and `probe` — see [Live-pin files](#live-pin-files).

## Live-pin files

The pin in `cli` is checked in every live file:

- `docs/**` and root `*.md`, except the root changelog `CHANGELOG.md` in any letter case, `docs/adr/**`, `<docs>/archive/<prefix>-N-*/`, task cards (`<prefix>-N[.k]-<slug>.md`, the extension in any case, the prefix as configured), and the entry lines of `<docs>/archive/LOG.md` (`- <a id=…`): an entry is a snapshot of its moment, while the journal header is live;
- every file named exactly `package.json` in the project, outside `.git`, `node_modules`, `.claude/worktrees` and a symlinked harness root (see [Markdown walk](#markdown-walk));
- `.yml` and `.yaml` files in `.github/workflows/`, `.github/actions/`, `.circleci/` and `.buildkite/`, and the root CI configs `.gitlab-ci.yml`, `.gitlab-ci.yaml`, `.travis.yml`, `.circleci.yml`, `azure-pipelines.yml`, `azure-pipelines.yaml`, `bitbucket-pipelines.yml`, `.drone.yml`, `appveyor.yml`, `buildspec.yml` and `Jenkinsfile`.

Rules:

- **A stale pin** in a live file is an error: the message names the file, the line and the expected pin. The `gates` and `probe` commands in `backslop.json` are checked the same way, and the error names the entry: `gates[i]` or `probe`.
- **A suffixed pin** (`#v0.1.0-rc.1`, `#v0.1.0x`, `#v0.1.0.1`) is another pin and an error in any of these places: `pin … has a suffix — it is not the cli pin …; upgrade leaves it, fix it by hand`.
- **`upgrade`** rewrites stale pins in this same set, except in a file behind a symlink on any path component and a file that is not UTF-8: it skips such a file with a warning, and the `lint` error names a manual edit as the cure for it instead of `upgrade`. A suffixed pin is not rewritten either.
- **Historical markdown** — the excluded files above — stays green.
- **A `cli` without a pin** (self-host, a global install, `npx backslop@latest`) has nothing to check against; in the tool's own repository gate 11 catches drift.
- **A bare `vX.Y.Z` in prose** next to the word backslop is not checked: it names history.

## Warnings

`lint` prints these and does not fail on them:

- a missing, empty or unfilled Scope in `minor/` (gate 4);
- a finding under a closed parent (gate 9);
- the layout version: `cli` in the `npx github:` form without a tag, `npx backslop` or `npx backslop@latest`; no `version` stamp in `backslop.json`; a stamp older than the tool; a stamp newer than the tool; a `cli` pin that differs from the stamp. The cure is `upgrade` in every case; for a stamp newer than the tool, update the installation or the pin;
- journal revision reachability (gate 13) that `lint` could not check: a shallow clone (`--depth`) or a project without git. This is a warning rather than green — the old commits are not in such a clone, and their absence says nothing about the line;
- non-printable bytes (gate 14) in the tool's repository when `git ls-files` failed: there is no list of tracked files to check.

## Markdown walk

- The gates and `archive` share one markdown walker. It skips `.git`, `node_modules` and `.claude/worktrees` (subagent working copies).
- The walk `mv`, `archive` and `fold` rewrite links by does not follow a link on a harness root either, on any component of `.claude/skills`, `.cursor/rules` or `.agents/skills`. Owned adapter outputs are left out of it: `mv`, `archive` and `fold` do not rewrite derived files.
- The link gate reads `docs/**` and root `*.md` and does not touch harness directories.
- `archive` and `mv` leave the outgoing root links (`/…`) of a moved file alone, and rewrite an incoming root link to it, which stays a root link.

## Implementation notes

- The gates live in [lib/lint.js](../../lib/lint.js), each marked with a `// N.` comment. The red probes of the gates are in [test/lint.test.mjs](../../test/lint.test.mjs), as mutations of a green project. The closed-parent check (gate 9) has its own probe, with exit code 0. Adding a gate step by step: [06 § Recipe: add a lint gate](06-module-map.md#recipe-add-a-lint-gate).
- Probes of the gates that switch on only in the tool's repository (template parity, gates 11, 12 and 14) run on a copy of the tool — `toolCopy` and `toolCli` in [test/helpers.mjs](../../test/helpers.mjs); for gate 14 the copy sets up a git index. The tool-repository sign is `isToolRepo` in [lib/templates.js](../../lib/templates.js), a realpath comparison of `templates/` with the running tool's directory.
- Gate 11's file list is `RELEASE_PIN_FILES` in `lib/lint.js`; gate 12's key declarations are `TEMPLATE_KEYS` in [lib/templates.js](../../lib/templates.js), one row per template group. The live-pin check is `lintProsePin`, over `livePinFiles` and `stalePins` in [lib/mdwalk.js](../../lib/mdwalk.js); the version warnings are `lintVersion`; the Scope check is `lintAreaField`.
- The gate 5 placeholder check and the `fold` refusal share one function, `hasResultTodo` in [lib/tasks.js](../../lib/tasks.js). Gate 4's line parser does not fit here: it does not read the template line `**Closed {{date}}.** [TODO: …]` as a placeholder, because the first colon stands inside the brackets and the bold label does not read as a field name. So the red probes run on each paragraph of both `result.md` templates separately, not on a bare `- [TODO]` line.
- Links are parsed by `linksOf` in [lib/links.js](../../lib/links.js); gate 1 checks a file with `checkLinks` and its anchors come from `anchorsOf`. `directoryLinks` takes every form with a link text from the same parser: for a reference-style link the declaration gives the target and the `[text][label]` link gives the text. The link text is read from the source, so a number in a code span inside the text stays a number.
- The walkers are in [lib/mdwalk.js](../../lib/mdwalk.js): `mdFiles` and `rootMarkdown` for the gates, `repoMarkdown` for `mv`, `archive` and `fold`, `livePinFiles` for the pin check and `upgrade`.
