# 03. Lint gates

`lint` lists everything it finds and exits with code 1 when there are errors. Warnings are printed and do not fail it. Messages are in the project language (`lang`), the tool's own template checks included. A directory the walk cannot list is a refusal: `<path>: the directory is not readable (<code>) — lint cannot walk it; restore read access or move it out of the project`.

## Gates

| No. | Gate | What it catches | How to fix |
|---|---|---|---|
| 1 | Links | A broken local link, a missing anchor, an undeclared reference label, a target that differs from the file name in case or in Unicode form, a link to a directory whose text names a project task, or Markdown files with no link at all, in `docs/**` and root `*.md`. The files, the link forms, the messages and the counts line are in [Gate 1 in detail](#gate-1-in-detail) | fix the path, and the case to match the file; point a fragment at an existing heading or id; declare the label or write the link inline; point a link that names a task at its file or journal line; move tasks with `mv`, `archive` or `fold`: they rewrite the local forms gate 1 reads — inline links and images, both badge destinations, HTML `<a href>` and reference declarations, including in a blockquote or a list item |
| 2 | Numbers | A number used twice; a first line that is not the heading `# <prefix>-N · Title`; a first-line heading that names another number (compared as numbers: `<prefix>-007` in the heading and `<prefix>-7` in the file name are one number, leading zeros make no other number); a finding `N.k` without task `N`; in a status directory, a file whose name does not match the pattern, or a subdirectory — a symlink to a directory, and a directory named like a task file, included: commands of the current tree read no such directory as a task, neither in the status directories nor flat in `docs/backlog/`; a dangling symlink in a status directory | refile with a new number (`new`), fix the heading |
| 3 | Backlog layout | Any file directly in `docs/backlog/` other than `README.md` (dot files are ignored); a directory that is not a status; a missing status directory; a missing `docs/backlog/`; `docs/backlog/` or a status directory that is a regular file — `<path>: a file, expected a directory`. A symlink to a directory inside the project is a directory; a symlink leading out of the project is not followed: under a status name the error says it is a symlink leading out, under any other name it counts as a file | `mv N <status>` — it finds the flat file and recomputes its links; create the directory with a `.gitkeep`, or run `init` for a missing `docs/backlog/`; a file in place of a directory — remove or rename it and create the directory |
| 4 | Fields, sections and placeholders | In `queue/`: no integer Order, or one Order on two files. An Order on a card outside `queue/` and a Previous order on a card in `queue/` are warnings, not errors: `mv` writes neither, they come from a move by hand, and no command reads a field in that place. A known header field (RU/EN aliases counted) repeated in one file. In `active/`: no Taken date (`YYYY-MM-DD`). In `deferred/`: no Deferred section, an empty one or one still holding a `[TODO]` placeholder, or more than one such section. Section headings inside fenced examples are not sections. Scope missing, empty, or a value that is entirely a `[TODO…]` placeholder left by `new`, in `queue/`, `active/` or `deferred/`; in `minor/` the same is a warning, not an error, because the approver fills Scope when cutting batches. In `minor/`: no Cost field, a Cost that does not parse (`critical`, `major`, `minor`; a hypothesis is `major (hypothesis)` or its Russian form), or `major`/`critical` without the hypothesis mark — with evidence such a finding is fixed, not queued for a batch; no Evidence section, an empty one, or one holding a placeholder — the entry would go to a batch unreviewed. A standalone line that is a `[TODO…]` placeholder (a list marker `-`/`*`/`+`, a number `1.`/`1)` and a checkbox `[ ]`/`[x]` are stripped first; a table row is checked cell by cell), or a field whose value is entirely such a placeholder, in any markdown file under `docs/backlog/**` except `triage/`. `[TODO]` as part of an explanation is not a placeholder. A task just filed with `new <slug> --queue` fails this gate by design: the Scope placeholder is the reminder to pick a reference section, and until then the task is not ready for the queue. `triage/` is excluded whole: `new` puts a template card there, and nobody fills its blanks before triage, so every entry filed by the standard command would be red; the approver asks for evidence while triaging. `minor/` has no triage, so the Evidence section is required there, by `mv N minor` and by this gate | fix the field or section; delete a duplicate Deferred section, and do not duplicate the existing one through `mv` |
| 5 | Archive | A directory whose name does not match the pattern (a symlink to a directory inside the project is a task directory, a symlink leading out of the project is a stray file); a stray file in the archive — anything other than task directories, `README.md` and `LOG.md` (dot files are ignored); no `task.md` or `result.md`; a placeholder left in `result.md` — `[TODO` outside code, with code blocks and code spans blanked, so the placeholder form shown in code is an account of it and does not count, while the same form in prose does; a completed `result.md` that names no word of the outcome table ([01](01-layout.md#archive)) — completed, rejected, merged into `<prefix>-N`, or a Russian form — in its first paragraph or heading: a bare closing word ("Closed" or its Russian form), "done" and the `Outcome:` marker are not an outcome, folding would read them as completed, and with no word at all it would write `—`. `fold N` refuses on the same two predicates; the outcome refusal carries the same message ([02](02-cli.md)). In a batch's `minor/` subdirectory, anything other than entry files `<prefix>-N[.k]-<slug>.md` (dot files are ignored); `docs/archive` or a batch's `minor/` that is a regular file — `<path>: a file, expected a directory` | complete the result — this is the approver's reminder; name the outcome with a table word in the first paragraph: `**Closed DATE.** Rejected: …`; only `archive N.k --into M` puts files into a batch's `minor/`; a file in place of a directory — remove or rename it and restore the directory |
| 6 | Mentions | `<prefix>-N` or `<prefix>-N.k` outside the [gate 15 set](#documentation-without-the-tracker) — in `<docs>/backlog/**`, `<docs>/archive/**` and the released sections of `CHANGELOG.md` — with no file behind it in the statuses or the archive (compared as numbers: `<prefix>-007` finds `<prefix>-7-*` and back); an entry in a batch's `minor/` counts as a file in the archive; code blocks are examples and do not count; while a status directory or an archive task directory leads out of the project, the number behind it is unknown and the gate reports nothing | fix the number or file the task |
| 7 | CHANGELOG | An entry title `- **…**` repeated within one section (a `**` inside a code span does not close the title); code blocks are examples: a section heading or an entry inside a fence does not count | a repeated title is an edit of one entry: keep one revision |
| 8 | ADR | ADR not linked from `docs/README.md` — the link's href resolves by the [link rule](#link-rule); no `docs/README.md` index while ADRs exist; two files with one number; a file in `adr/` whose name does not match the pattern, `.MD` extension included — also when no correctly named ADR exists; `docs/adr` that is a regular file — `<path>: a file, expected a directory`, and `backslop adr` refuses with the same path; an ADR without a [status line](#adr-status-line); a status whose first word is not `Proposed` or `Accepted` (`Superseded`, `Superseded in part`, `Deprecated`, `Rejected`); a status line that names another ADR, by an `ADR-NNN` token or a link to `adr-NNN-…` — a chain; an ADR linked from two table rows of the index; a row whose Status cell differs from the status word of its file; a `[TODO]` placeholder line left in an ADR (the line rule of gate 4, fenced code blocks skipped). A status error quotes the line | add the link as a row of the ADR table, or create the index; renumber; a file in place of `adr/` — remove or rename it and restore the directory; a replaced status or a chain — fold the decision into the ADR that governs the question now, then delete the replaced file; a second row — delete it; a Status cell — write the word of the file; a placeholder — write the line or remove it |
| 9 | Triage review | A finding `N.k` lies in `triage/` while its task `N` is already in `archive/`: `lint` prints a warning for the approver and does not fail. A finding in `queue/`, `active/` or `deferred/` is already triaged and does not count. A `Parent` field in a status directory whose number differs from the number in the file name (`<prefix>-5.1` with `Parent: <prefix>-6`) is a warning too; `<prefix>-5.2` with `Parent: <prefix>-5.1` agrees, and a `Parent` with no task number is not compared | the approver triages the entry: `mv N.k queue`, merge it into another task, or close it with `archive N.k`; fix the `Parent` field or the file name |
| 10 | Quotes | In `docs/**` and root `*.md` — the gate 1 file set, with its root symlinks and `.MD`: a plain block `<!-- quote:<path> -->…<!-- /quote -->` checks its content, target and closing; `<!-- quote:before:<path> -->…<!-- /quote -->` marks a snapshot taken before an edit and does not fail on a content mismatch, but its target and closing are still required. Spaces after `quote:` and `before:` are allowed. A line that, without inline code, is entirely a marker (`^\s*<!--\s*/?quote\b.*-->\s*$`) but parses as neither an opening nor a closing marker, and a `<!-- /quote -->` with no open block, are errors with a line number; a marker in the middle of prose is prose. A quote path is tool syntax, not a link, and nothing renders it: `<!-- quote:/… -->` resolves from the project root, not from the repository root as gate 1 links do. The comparison is line by line, with whitespace at line edges trimmed on both sides and a wrapping fence around the quote dropped (fences inside the quote stay), so re-indented code does not break a quote. A form shown inside a code block or inline code is an example and does not count; `docs/archive/` is not checked: a quote in a closed task is a snapshot of its moment | reread the file and update a plain quote, or remove the block; for a snapshot, check the path and the closing; turn a quote of a place that its own task changes into `quote:before:` — who places the mark is said in the [operating rules](../backlog/README.md) |
| 11 | Release versions | Only in the tool's own repository (the same sign as template parity: its `templates/` is the running tool's directory). `package.json` that does not parse as JSON — an error with the parser's text; the other checks of this gate stop, the other gates run. No `version` field in `package.json` — nothing to compare with. `version` in `package.json` differs from the `backslop.json` stamp. `CHANGELOG.md` has no `## vX.Y.Z` section for that version. In `README.md` or `AGENTS.md`, a pin `github:Velklish/backslop#vX.Y.Z` (also with a `.git` suffix and without `v`: `….git#vX.Y.Z`, `…#X.Y.Z`) or `backslop@X.Y.Z` names another version; a pin with a pre-release tail (`-rc.1`) is another version and is reported with its tail; a pin with another suffix (`x`, a fourth number) is another pin and this check does not read it, and in the tool's own repository, whose `cli` carries no pin, no other check reports it. Code blocks count: an install command is an instruction, not an example | `npm run release -- X.Y.Z --bump`; in the prose of an install example, the generic form `#v<version>` has nothing to drift |
| 12 | Template placeholders | A placeholder `{{name}}` in `templates/**` with no key declared for its template group, and a declared key that no template of its group uses. Both language layers are checked: a name that diverged between ru and en would otherwise slip through. Only in the tool's own repository, by the same sign as template parity | add the pair whole: the name in both templates and the key in the caller's `vars`, plus the key in its group's declaration (see [Implementation notes](#implementation-notes)). A name without a key is a render-time refusal, so the reader never meets a literal `{{…}}` |
| 13 | Closed-task journal | A line of `<docs>/archive/LOG.md` that looks like an entry (starts with `- <a id=`) but does not parse; a line whose anchor does not match its number; a link to `LOG.md#<anchor>` with no journal entry behind the anchor, in `docs/**` and root `*.md` (the gate 1 set, with its root symlinks and `.MD`) — the path resolves by the [link rule](#link-rule), and the anchor is everything after `#`, including after a `?query`; a line revision not reachable from `HEAD` (absent from `git rev-list HEAD`), through which `show N` cannot find the body. Gate 1 leaves the anchors of journal links in its own file set to this check, whose message names the missing entry and the line: incoming links of closed tasks point at the journal. The adapter pass checks journal anchors itself, since this check does not walk adapter outputs. The fourth catches a commit that a squash or rebase dropped after folding — before the push, when `lint` runs on the final acceptance commit as the procedure says; [02 § fold](02-cli.md#fold) says what leaves such a revision | fix the journal line to the form of [01](01-layout.md#archive); point the link at an existing anchor — `backslop show N` shows the folded task's number; for an unreachable revision, bring the commit back into history or, when the body went into the acceptance commit message, replace the revision with `—`: `show N` finds the commit by its subject |
| 14 | Non-printable bytes | Only in the tool's own repository (the same sign as gates 11 and 12): a byte below `0x09` — tab excluded; NUL and SOH are the live cases — in a file tracked by git (`git ls-files`) under `lib/`, `bin/`, `test/`, `templates/`, `scripts/` or `docs/`. NUL makes a source file binary to `git` and `grep`: searching it finds nothing, and the silence reads like "not in the code"; git does not call bytes `0x01`–`0x08` binary, but they are invisible in an editor and in output, and the error calls them an invisible control byte. The error names the file, the byte offset and the line; there is no exception list — no file of these trees legitimately carries such a byte. In a consumer project the gate does not judge: its `docs/**` and `test/**` legitimately carry binary files, and git's text sign catches the wrong case — git itself calls a file with NUL binary | write the byte as an escape sequence (`\u0000`, `\x01`): the string is the same, and the file stays text |
| 15 | Documentation without the tracker | In the [documentation set](#documentation-without-the-tracker) — root `README*.md`, every `.md` under `<docs>/` except `backlog/` and `archive/`, and the unreleased section of `CHANGELOG.md` — three classes of error, each naming the file, the line, the class and the token: a task id `<prefix>-N` or `<prefix>-N.k` anywhere, code included; a tracker link into `<docs>/backlog/` or `<docs>/archive/`; a tracker URL into the same repository's backlog or archive. A path to an output or a config file is not judged. A mention in the set is reported here once, not by gate 6 | write what the record says instead: the contract, the rationale, or the measurement itself with its version and date |

## Gate 1 in detail

- **Files.** `docs/**` and root `*.md`, the extension in any case (`NOTE.MD` too). A root symlink is read when it resolves to a regular file inside the project; a link leading outside is not read; a symlink whose target the walk already covers is checked once, by the path without the link. A status or archive directory that is a symlink leading out of the project is not read, as in gates 2, 4 and 6: gate 3 reports the link, and the links and quotes of the files behind it, the journal anchors among them, are not checked.
- **Forms.** Every form is read by one parser: inline — bare (balanced parentheses inside are legal: `foo(1).md`), with a title, in angle brackets; reference-style — full `[text][label]`, collapsed `[label][]` and shortcut `[label]` with a declaration, the first declaration of a label winning and labels compared case-insensitively; images; a badge `[![alt](img.png)](target.md)`, whose image and outer destination are both links; HTML `<a href="…">`; autolinks `<https://…>`, which are external.
- **Declarations.** A full or collapsed reference whose label has no declaration is an error, `link [<text>] uses the label “<label>”, and there is no declaration “[<label>]: …”`; a shortcut `[x]` without a declaration is text.
- **Code and comments.** Code spans, fenced code blocks — also in a blockquote or a list item — and HTML comments hold no link, and a BOM at the start of a file hides neither a declaration nor a first-line fence; an indented code block (four spaces, no fence) is read as prose.
- **Targets and fragments.** Targets resolve by the [link rule](#link-rule), and a fragment must name an anchor of its target: `link <href>: <file> has no anchor “<fragment>” — no heading or id by that name`. Every error about a link ends with its line, `(line N)`.
- **Case and Unicode form.** The target name is compared letter by letter with the directory listing: a target that differs from the file only in case (`readme.md` for `README.md`) is an error, `link target differs in case`, naming the real name, on every file system — Linux CI and web renderers are case-sensitive; a target that differs only in Unicode form (`é` as one character against `e` and a combining accent) is an error too, `link target differs in Unicode normalization`, naming the real name.
- **Directory links that name a task.** The same gate reports a link to an existing directory whose text names a project task (`<prefix>-N[.k]` anywhere in the link text, in a code span too): inline `[<prefix>-N](../triage)` and reference-style — full `[<prefix>-N][f]`, collapsed `[<prefix>-N][]` and shortcut `[<prefix>-N]` with the declaration `[f]: ../triage` (labels compare case-insensitively). Such a link promises a card and delivers a directory, and it looks whole while broken; gate 6 does not report it, because the number exists. A directory link without a task id is allowed: `[templates/](../../templates/)` shows a directory, and nothing but the directory can show it. A link inside a code span or a fenced code block is an example and is not read.
- **Counts.** Gate 1 prints what it read to stdout, `gate 1: files N, links N, local N, anchors checked N`: the files of its set, the links of every form, the links with a local target (a same-file `#anchor` included, a use of a declaration counted once, at the declaration), and the fragments checked against a Markdown file. Markdown files with no link at all are an error, `gate 1 read nothing: …`: a walk that reads nothing must not look like a clean tree.
- **Adapter outputs.** Generated adapter outputs are not in this walk and not in its counts: their links are checked by the [adapter pass](#checks-outside-the-fifteen-gates) under the same rule.

## Link rule

One link rule serves gates 1, 8, 13 and 15 and `seed --queue-reference`, and one parser reads their links:

- The target is the href up to the first `#` or `?`, decoded (`%2E` is a dot; a broken `%` escape is a broken link).
- A leading `/` resolves from the repository root, as on GitHub and GitLab — in a monorepo subproject too (`/pkg/a/docs/…`). Outside a repository it resolves from the project root, and a git failure while finding the root refuses `lint` with its cause. Any other path resolves from the file's directory.
- External addresses are not checked: any `<scheme>:`, case-insensitive (`https:`, `ftp:`, `tel:`, `HTTPS:`; a drive letter `C:/…` is a scheme too), and `//host`. A bare `#anchor` points into the same file.
- Footnotes `[^1]:` are not link declarations. A code fence closes only on a fence of the same character that is not shorter than the opening one; an unclosed fence runs to the end of the file.
- A declaration may stand in a blockquote or a list item (`> [l]: x.md`); a line that continues a quoted paragraph without `>` continues that paragraph and declares nothing.
- A fragment is checked for a local Markdown target (`.md` in any case) and for a same-file `#anchor`. It must name an anchor the target exposes: the slug of a heading outside code blocks and HTML comments — ATX or setext, also inside a blockquote or a list item — a repeated heading taking `-1`, `-2` in document order, or an explicit `id="…"` or `<a name="…">`. The fragment is URL-decoded and compared as written, then lowercased. Two fragments that the renderer resolves without a heading are not checked: `#top` in any case, the top of a page, and a source-view line `#L12` or `#L12-L20` after a `?plain=1` query.
- The slug is GitHub's, and gitlab.ati.st renders the same one: closing `#`s dropped, the lines of a setext heading joined with a space, a link, an image or an autolink reduced to its text, an HTML tag dropped (`Result<T, E>` keeps `<T, E>` as text), `_` and `*` emphasis unwrapped, the entities `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;`, `&nbsp;`, the entities of a fixed table (dashes, quotes, `&hellip;`, `&copy;`, `&reg;`, `&trade;`, arrows, currency signs and a few more) and every numeric one decoded — the character is dropped; any other named entity (`&le;`, `&minus;`, a letter one such as `&eacute;`) keeps its name as letters, because the full entity table is not carried. Of the table, `&mdash;`, `&hellip;` and `&copy;` were measured against gitlab.ati.st; the rest follows the same rule and is not measured; then lowercase, punctuation dropped except `-` and `_`, each space a hyphen (`A — B` is `a--b`).
- A target's anchors are read from the target file, also outside the gate's file set, as long as it is inside the project. A target outside the project, a directory and a non-Markdown file (`code.js#L10`) keep their fragment unchecked.

## Documentation without the tracker

Gate 15 holds project documentation to stand on its own: a task record leaves the tree at `fold`, and the history behind it may be out of the reader's reach.

- **The set.** Root `README*.md` (any letter case), every `.md` under `<docs>/` except `<docs>/backlog/` and `<docs>/archive/` — ADRs included — and, in `CHANGELOG.md`, the unreleased section only. The unreleased section is the first `## ` section whose title does not start with a version, and there is none when every section is versioned; the tags of the clone are not read, so a versioned top section is released whether or not its tag exists. Released sections are history and stay with gate 6.
- **Task id.** `<prefix>-N` or `<prefix>-N.k` with digits, whether or not a task file has that number, leading zeros included, anywhere in the file: prose, code spans and fenced blocks alike. A generic example writes `<prefix>-N`, which is not an id.
- **Tracker link.** A link in any form gate 1 reads whose target resolves by the [link rule](#link-rule) into `<docs>/backlog/` or `<docs>/archive/`, `LOG.md` and `LOG.md#…` included. The rendered operating rules, `<docs>/backlog/README.md` and `<docs>/archive/README.md`, with or without a fragment, are exempt: they stay in the tree, and the index of a fresh project links them.
- **Tracker URL.** An `http(s)://` address anywhere in the file whose host and repository path equal those of `git remote get-url origin` (the https and the scp form are read; letter case and a `.git` suffix are ignored) and whose path continues `/(blob|tree)/<ref>/…` on GitHub or `/-/(blob|tree)/<ref>/…` on GitLab into the backlog or the archive. A ref may hold slashes: the path is read after the ref that names a local branch, remote branch or tag, or a hex sha of 7 to 40 digits; when no split names one, every split is tried, so `…/blob/feature/x/docs/backlog/…` with an unknown ref is still refused, and a repository directory that holds its own `docs/backlog/` may then be refused too. Without an `origin` remote this class is skipped, and `lint` prints a note on stdout: `gate 15: no origin remote — tracker URLs into this repository were not checked`.
- **Gate 6** reads only what lies outside the set, so a mention inside it is reported once, by this gate.

## ADR status line

Gate 8 reads the status of every `adr-NNN-<slug>.md` in both languages:

- The status line is the first line outside a code fence that starts with `**Status:**` or its Russian label (the `Status` entry of `templates/i18n/ru.mjs`), also as a list item (`- **Status:** Accepted`). Both template layers write `**Status:**`.
- The status word is the first word after the label, and it is `Proposed` or `Accepted`; text after it is allowed (`Accepted (2026-09-01)`). The ADR directory holds current decisions only, so a replaced decision has no status of its own: it is folded into the ADR that governs the question now, and its file is deleted.
- A status line that names another ADR — an `ADR-NNN` token or a link to `adr-NNN-…`, in any case, with a number other than the file's own — marks a chain and is an error even after `Accepted`.
- In the index, a row is a table line of `docs/README.md` that links the ADR; a link in prose is not a row. One ADR has at most one row. When the table header has a `Status` cell or one with its Russian label, that column of the row equals the status word of the file; a table without that column is not compared. Two row forms are not seen: a table line without a leading `|`, and a row whose ADR link is reference-style (`[ADR-001][p]`); such a row is neither counted nor compared, while the link itself still satisfies the index check.

## Checks outside the fifteen gates

These errors fail `lint` without a gate number:

- **Adapter outputs** of every selected adapter: the output file is present, is a file, and is owned (carries the generated marker; a vendored skill's `LICENSE` stays verbatim and is owned through the marked `SOURCE.md` beside it, see [01](01-layout.md#adapter-ownership)); its links pass the gate 1 rule — target, anchor and label — and do not point to a directory while their text names a task. A foreign file without the marker at an owned path is an error — `init` does not overwrite it; remove or rename the file and rerun `init`, or deselect the adapter. A directory at an owned path is an error, since `init` refuses on it. An output that is absent is an error too, unless git ignores that path in this working tree (see [Absent outputs and git](#absent-outputs-and-git)), or the output belongs to a vendored skill that `init` did not lay out because of a foreign `LICENSE` or `SOURCE.md` — the foreign file is the error then.
- **Claude stub.** The `claude` adapter is selected and `CLAUDE.md` is missing: `Claude stub is missing — run <cli> init`. The same exception applies.
- <a id="absent-outputs-and-git"></a>**Absent outputs and git.** `init` gitignores the owned outputs and the stub, so a fresh `git worktree` of a project lacks them. One `git check-ignore` call per run asks which of the absent outputs and the stub git ignores in this working tree; those are skipped, silently: no warning, no note, and the exit code and the warning count do not change. An absent file that git does not ignore (tracked and deleted, or never ignored) is still an error. A present file is checked as before: a foreign file, a directory at an owned path and the links. The skip is not limited to linked worktrees: the same holds for a fresh `git clone` and for an output deleted in the main checkout, where `lint` does not report the file, so run `init` after cloning. Outside any git repository, such as a `git archive` copy unpacked outside every repository, or when git cannot run, no path counts as ignored and `lint` stays red there; a copy unpacked inside another repository's tree finds that repository and can go green. Lint a base commit in a `git worktree`.
- **Template parity**, in the tool's own repository (`templates/vendor/` is outside both layers and is not compared): the layers `templates/` and `templates/en/` agree in five ways — one set of files; one set of placeholders in each pair; skill frontmatter in both layers, with `name` equal to the directory name and a non-empty `description`; one sequence of heading levels outside code blocks; no Cyrillic letter in the English layer.
- **Live pins**: a stale or suffixed pin in a live file, or in `gates` and `probe` — see [Live-pin files](#live-pin-files).
- **Agent hook records** ([01 § Agent hook records](01-layout.md#agent-hook-records)), read from `<project>/.claude/settings.json`, `<project>/.cursor/hooks.json` and `<project>/.codex/hooks.json`:
  - a harness in `hooks` whose file lacks the start or the stop record with the project's `cli`: `the <event> agent hook record of <harness> is missing: expected “<command>” — run <cli> init`;
  - an owned record with another `cli`, in the file of a selected harness: `the agent hook record “<command>” runs another cli than this project’s <cli> — run <cli> init`;
  - any other difference from what `init` writes for a selected harness, such as a duplicate owned record or one under another event: `the agent hook records of <harness> differ from what init writes: a duplicate or a record under another event — run <cli> init`;
  - an owned record in the file of a harness that `hooks` does not select: `backslop agent hook records for <harness> sit here, but the hooks field of backslop.json does not select <harness> — run <cli> init`;
  - the same records reached through a symlink on the path: `backslop agent hook records for <harness> sit here, behind the symlink <link>, and the hooks field of backslop.json does not select <harness> — init does not remove records through a link: remove them by hand`;
  - the file of a selected harness that `init` refuses on — not valid JSON, `hooks` not an object, a symlink on its path: the refusal, followed by `— init refuses on it`. The file of an unselected harness in such a state is not read, except through a symlink: see the previous item.

## Live-pin files

The pin in `cli` is checked in every live file:

- `docs/**` and root `*.md`, except the root changelog `CHANGELOG.md` in any letter case, `docs/adr/**`, `<docs>/archive/<prefix>-N-*/`, task cards (`<prefix>-N[.k]-<slug>.md`, the extension in any case, the prefix as configured), and the entry lines of `<docs>/archive/LOG.md` (`- <a id=…`): an entry is a snapshot of its moment, while the journal header is live;
- every file named exactly `package.json` in the project, outside `.git`, `node_modules`, `.claude/worktrees` and a symlinked harness root (see [Markdown walk](#markdown-walk));
- `.yml` and `.yaml` files in `.github/workflows/`, `.github/actions/`, `.circleci/` and `.buildkite/`, and the root CI configs `.gitlab-ci.yml`, `.gitlab-ci.yaml`, `.travis.yml`, `.circleci.yml`, `azure-pipelines.yml`, `azure-pipelines.yaml`, `bitbucket-pipelines.yml`, `.drone.yml`, `appveyor.yml`, `buildspec.yml` and `Jenkinsfile`.

Rules:

- **A stale pin** in a live file is an error: the message names the file, the line and the expected pin. The `gates` and `probe` commands in `backslop.json` are checked the same way, and the error names the entry: `gates[i]` or `probe`.
- **A suffixed pin** (`#v0.1.0-rc.1`, `#v0.1.0x`, `#v0.1.0.1`) is another pin and an error in any of these places: `pin … has a suffix — it is not the cli pin …; upgrade leaves it, fix it by hand`.
- **`upgrade`** rewrites stale pins in this same set, except in a file behind a symlink on any path component and a file that is not UTF-8: it skips such a file with a warning, and the `lint` error names a manual edit as the cure for it instead of `upgrade`. A suffixed pin is not rewritten either.
- **Historical markdown** — the excluded files above — stays green.
- **A `cli` without a pin** (self-host, a global install, `npx backslop@latest`) has nothing to check against; in the tool's own repository gate 11 catches drift.
- **A bare `vX.Y.Z` in prose** next to the word backslop is not checked: it names history.

## Warnings

`lint` prints these and does not fail on them:

- a missing, empty or unfilled Scope in `minor/` (gate 4);
- an `Order` on a card outside `queue/` and a `Previous order` on a card in `queue/` (gate 4): `mv` removes the first when a card leaves `queue/` and the second when it enters, so delete the line;
- a finding under a closed parent, and a `Parent` field that names another number than the file name (gate 9);
- the layout version: `cli` in the `npx github:` form without a tag, `npx backslop` or `npx backslop@latest`; no `version` stamp in `backslop.json`; a stamp older than the tool; a stamp newer than the tool; a `cli` pin that differs from the stamp. The cure is `upgrade` in every case; for a stamp newer than the tool, update the installation or the pin;
- journal revision reachability (gate 13) that `lint` could not check: a shallow clone (`--depth`) or a project without git. This is a warning rather than green — the old commits are not in such a clone, and their absence says nothing about the line;
- non-printable bytes (gate 14) in the tool's repository when `git ls-files` failed: there is no list of tracked files to check.

## Markdown walk

- The gates and `archive` share one markdown walker. It skips `.git`, `node_modules` and `.claude/worktrees` (subagent working copies).
- The walk `mv`, `archive` and `fold` rewrite links by does not follow a link on a harness root either, on any component of `.claude/skills`, `.cursor/rules` or `.agents/skills`. Owned adapter outputs are left out of it: `mv`, `archive` and `fold` do not rewrite derived files.
- The link gate reads `docs/**` and root `*.md` and does not touch harness directories.
- `archive` and `mv` leave the outgoing root links (`/…`) of a moved file alone, and rewrite an incoming root link to it, which stays a root link.
- A directory reached through several symlinks is walked once, under the first path that reaches it. `mv`, `archive` and `fold` resolve the relative links of a file from its real place in the project, so a card listed only through a symlinked alias of its directory has its links to the moved task rewritten.

## Implementation notes

- The gates live in [lib/lint.js](../../lib/lint.js), each marked with a `// N.` comment. The red probes of the gates are in [test/lint.test.mjs](../../test/lint.test.mjs), as mutations of a green project. The closed-parent check (gate 9) has its own probe, with exit code 0. Adding a gate step by step: [06 § Recipe: add a lint gate](06-module-map.md#recipe-add-a-lint-gate).
- Probes of the gates that switch on only in the tool's repository (template parity, gates 11, 12 and 14) run on a copy of the tool — `toolCopy` and `toolCli` in [test/helpers.mjs](../../test/helpers.mjs); for gate 14 the copy sets up a git index. The tool-repository sign is `isToolRepo` in [lib/templates.js](../../lib/templates.js), a realpath comparison of `templates/` with the running tool's directory.
- Gate 11's file list is `RELEASE_PIN_FILES` in `lib/lint.js`; gate 12's key declarations are `TEMPLATE_KEYS` in [lib/templates.js](../../lib/templates.js), one row per template group. The live-pin check is `lintProsePin`, over `livePinFiles` and `stalePins` in [lib/mdwalk.js](../../lib/mdwalk.js); the version warnings are `lintVersion`; the Scope check is `lintAreaField`.
- The gate 5 placeholder check and the `fold` refusal share one function, `hasResultTodo` in [lib/tasks.js](../../lib/tasks.js). Gate 4's line parser does not fit here: it does not read the template line `**Closed {{date}}.** [TODO: …]` as a placeholder, because the first colon stands inside the brackets and the bold label does not read as a field name. So the red probes run on each paragraph of both `result.md` templates separately, not on a bare `- [TODO]` line.
- Gate 15 is `lintTrackerFreeDocs` over the set `trackerFreeSet` in `lib/lint.js`; it finds the unreleased section with `unreleasedSpan`, which calls `unreleasedIndex` of [lib/changelog-format.js](../../lib/changelog-format.js) with every version counted as released: only the first criterion of the `merge-changelog` rule applies and no tag is read. The exempt rules file is the constant `TRACKER_RULES`.
- Links are parsed by `linksOf` in [lib/links.js](../../lib/links.js); gate 1 checks a file with `checkLinks` and its anchors come from `anchorsOf`. `directoryLinks` takes every form with a link text from the same parser: for a reference-style link the declaration gives the target and the `[text][label]` link gives the text. The link text is read from the source, so a number in a code span inside the text stays a number.
- The walkers are in [lib/mdwalk.js](../../lib/mdwalk.js): `mdFiles` and `rootMarkdown` for the gates, `repoMarkdown` for `mv`, `archive` and `fold`, `livePinFiles` for the pin check and `upgrade`.
