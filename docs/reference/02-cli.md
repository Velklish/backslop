# 02. CLI и контракт для оркестратора

Точка входа — [bin/backslop.js](../../bin/backslop.js): первый аргумент — команда, модуль `lib/<команда>.js` экспортирует `run(argv, { cwd })`. Отказ, адресованный человеку, — `CliError`: печатается без стека, код возврата 1. Любое другое исключение — ошибка кода, со стеком. Вывод: `✔` — успех, `✖` — ошибка, `⚠` — предупреждение; цвет только на терминале.

Флаги разбирает `parseArgs` в строгом режиме через `parseCommandArgs` ([lib/util.js](../../lib/util.js)). Значение строкового флага, начинающееся с дефиса, принимается и через пробел (`--title "--strategy …"`): пара склеивается в `--title=…`, если значение не совпадает с именем флага этой команды; `--title --queue` — отказ с подсказкой формы `--title=…`, надёжная форма для любого значения — с «=». Справка называет это правило.

## Команды

| Команда | Что делает | Отказ (код 1) |
|---|---|---|
| `init [--dir docs] [--prefix BS] [--cli <команда>] [--lang ru\|en] [--tools <CSV\|none>]` | раскладка скелета: существующий файл `docs/` не трогается, правила ведения и архива тоже — их перерисовывает `migrate`; ADR процесса — `adr-001-process.md`, а в проекте со своими ADR — следующий свободный номер; см. [01](01-layout.md) | флаг `dir`/`prefix`/`cli` расходится с существующим конфигом; неизвестный `lang` или `tools`; проект инициализирован выше; symlink на корне выбранного adapter'а (до первой записи; корни невыбранных не проверяются); каталог на пути adapter output или файл на компоненте его пути; штамп новее инструмента; плохой префикс или путь; `--tools` не `none` в корне самого backslop — признак тот же, что у гейтов 11 и 12: `templates/` проекта и есть каталог запущенного инструмента (self-host держит `tools: []`, стенд с adapter'ом поднимают в своём каталоге); `AGENTS.md` или `.gitignore`, который `init` перепишет, не в UTF-8; метка блока отдельной строкой дважды или без пары — эти отказы случаются до первой записи |
| `new <slug> [--title "…"] [--queue [--top]] [--parent N[.M] [--minor --evidence "…" [--cost <уровень>] [--hypothesis]]]` | файл задачи из шаблона в `triage/`, с `--queue` — в очередь с порядком в конец или сверху; `--parent N` — находка `N.k`; `--minor` — minor-находка в `minor/` из шаблона `minor.md` с полями «Родитель» и «Цена» (`--cost`: `critical`, `major`, `minor`; по умолчанию `minor`; `major` и `critical` — только с `--hypothesis`, тогда с пометкой «гипотеза») и пустой «Областью» ([01](01-layout.md)); `--parent N.M` — находка под находкой, следующий свободный `N.k` и поле «Родитель» с точным номером родителя. Для находки в `triage/` `new` печатает поле «Улика»/`Evidence` отдельной строкой с заглушкой, которую нужно заполнить; в `minor/` заглушки нет — улику даёт обязательный `--evidence`, и без него команда отказывает до создания файла ([ADR-029](../adr/adr-029-minor-finding-requires-evidence.md)); «Область» подставляется ссылкой на `reference/README.md` с уже посчитанной от каталога статуса глубиной (в проекте без этого файла — текстом); раздел справочника выбирает и дописывает тот, кто заводит задачу. Номер — следующий свободный по текущему дереву, другим worktree и локальным веткам ([01](01-layout.md)); чужой номер, сдвинувший свой, называется в выводе, номер из текущего дерева — нет | отказ git при скане чужих номеров — кроме «репозитория нет» и «git не установлен»; плохой slug; родителя нет; `--top` без `--queue`; `--minor` без `--parent` или с `--queue`; `--cost`/`--hypothesis`/`--evidence` без `--minor`; `--cost` не из трёх уровней; `--cost major|critical` без `--hypothesis`; `--minor` без `--evidence` или с пустой уликой |
| `mv <N…> <triage\|queue\|active\|deferred\|minor> [--top \| --after M \| --restore] [--evidence "…"]` | `git mv` между каталогами; в `minor` требует улику — раздел «Улика» с текстом и без заглушки или `--evidence "…"` (только с одним номером), без неё отказ по всему пакету до первого переноса ([ADR-036](../adr/adr-036-mv-minor-requires-evidence.md)); карточку формы `task.md` переформовывает: разделы «Контекст», «Что сделать», «Не входит», «Проверки» из одних заглушек снимает, в разделах с текстом снимает строки-заглушки, «Контекст» с текстом без «Улики» переименовывает в «Улику», а `--evidence` пишет строку `Улика: …` на место первой заглушки раздела, иначе в его конец, иначе новым разделом; дописывает «Цена: minor», если поля нет, и стирает заглушку `[TODO…]` в «Области»; номеров может быть несколько за вызов — все резолвятся и проверяются до первого переноса, дальше перенос по одному в порядке аргументов, строка ok на каждый и одна сводка перенумерации очереди (файл, перенумерованный соседями пакета дважды, считается один раз); в `queue` ставит «Порядок» и снимает «Прежний порядок», из `queue` — снимает «Порядок» и кладёт его число в «Прежний порядок», откуда его берёт `--restore`; возврат в `queue` без `--restore` сохранённое число отбрасывает и говорит об этом строкой на каждую задачу, у которой оно было; `--restore` работает и на пакете — число берётся из шапки каждой задачи, и восстановленные встают между собой по возрастанию сохранённых чисел, при равных — по возрастанию номера, в любом порядке аргументов: пакет обрабатывается по убыванию сохранённых чисел, и каждая следующая задача встаёт не позже соседа по пакету, поставленного перед ней, — место позже него уступает месту прямо перед ним ([ADR-031](../adr/adr-031-restore-batch-keeps-order.md)); в `active` пишет «Взята», в `deferred` дописывает раздел «Отложено» только если его нет, а если раздел уже есть — оставляет файл как есть и печатает «раздел есть, проверь причину и условие возврата»; заголовок «Отложено» внутри fenced-примера разделом не считается; исходящие ссылки файла пересчитывает от старого каталога к новому, входящие переписывает по всему markdown репозитория; ссылка файла на самого себя — относительная и корневая — ведёт на его новое место. Файл, лежащий плоско в `docs/backlog/` (миграция чужого трекера), тоже переезжает — с пересчётом ссылок на выросшую глубину. Задача уже в `queue/` с `--top`/`--after M` — не переезд, а перестановка: меняется только «Порядок» | задачи нет; она в архиве; уже в этом статусе (в `queue/` — без `--top`/`--after`/`--restore`); `--after` не из очереди или на саму себя; номер назван в пакете дважды; `--top`/`--after` при нескольких номерах — место для пакета не определено одним числом, `--restore` этим не ограничен; два флага позиции сразу; `--restore` хотя бы у одной задачи вызова без «Прежнего порядка» или с нецелым его значением — отказ на весь вызов, поимённо и до первого переноса; в `minor` без улики хотя бы у одной задачи пакета — отказ поимённо, до первого переноса; `--evidence` не в `minor` или при нескольких номерах |
| `archive <N> [--dry-run] [--range <база>..HEAD]` \| `archive <N.k> --into <M> [--dry-run]` | `git mv` в `archive/<id>-<slug>/task.md`, перепись исходящих и входящих ссылок по всему markdown репозитория (ссылка карточки на саму себя становится `task.md`, корневая — `/<docs>/archive/<id>-<slug>/task.md`), заготовка `result.md`; `--into M` — закрытие minor-записи пачкой M: файл уезжает в `archive/<M>-<slug>/minor/` с той же переписью ссылок, своего `result.md` не получает, исход по записи называет `result.md` пачки; пачка закрывается первой — каталог незакрытой пачки в архиве читался бы вторым файлом её номера ([ADR-022](../adr/adr-022-cost-decides-finding-fate.md)); файл, лежащий плоско в `docs/backlog/`, тоже находится и переезжает в архив с тем же пересчётом ссылок. Файлы под `<docs>/` и `CHANGELOG.md`, которых коснулся ход задачи, печатаются всегда: выборка идёт по коммитам, чей **заголовок** начинается с `<prefix>-N:` (номер сравнивается числом, тело сообщения не считается — squash тащит туда чужие заголовки), а `--range` добавляет к ней коммиты диапазона. Карточки трекера (`<docs>/backlog`, `<docs>/archive`) из списка исключены; пути — от корня проекта и тогда, когда проект лежит в подкаталоге репозитория: префикс подкаталога команда срезает сама, потому что combined diff merge-коммита флаг `--relative` не учитывает. Merge-коммит добавляет только то, что изменил сам merge, — правку при слиянии (`--cc`); файлы ветки приходят через её коммиты: с `--range` — как часть диапазона, без него — только те, чей заголовок начинается с `<prefix>-N:`. Список — заготовка строки «Доки тем же ходом» для approver'а; в `result.md` команда не вписывает ничего |  задачи нет; уже в архиве; каталог занят; `--range` пуст или его ревизия не разбирается — отказ словами git, а не пустой список; `--range` без `..` — одна ревизия отдала бы всю историю до неё, отказ называет форму `<база>..HEAD`; с `--into`: запись не в `minor/`; пачки нет; пачка сама minor-запись; пачка ещё не закрыта; `--range` вместе с `--into` |
| `fold <N> [--dry-run]` | свернуть закрытую задачу в строку `<docs>/archive/LOG.md`: каталог задачи уходит из дерева, входящие ссылки переезжают на якорь строки — **вместе со старым якорем**, потому что `#контекст` исчезнувшего файла на строке журнала не значит ничего, — а `task.md` и `result.md` целиком уезжают в заготовку сообщения коммита. Каждая строка тела идёт в заготовку под меткой `> `, пустая — голым `>`: чистка сообщения git (`commit.cleanup=strip`, правка сообщения в редакторе, `--amend`) снимает строки на `#`, а с ними заголовки постановки и результата; метку снимает `show`. Вложение — любой файл каталога, кроме `task.md`, `result.md` и записей пачки в `minor/`, на любой глубине; файл, который git игнорирует (`.gitignore`, `info/exclude`, `core.excludesFile` — например `.DS_Store`), вложением не считается, если git не игнорирует сам каталог задачи (`git check-ignore -q -- <каталог>/`): в каталоге, игнорируемом целиком, и вне репозитория считается каждый файл. Вложение в заготовку не едет, поэтому `fold N` отказывает, пока хоть одно вложение не лежит в `HEAD` в том виде, что на диске: несохранённое вложение свёртка не удаляет. Переписываются ссылки на сам каталог, `task.md`, `result.md` и записи пачки, в том числе корневые — `/docs/archive/…` резолвится от корня проекта, как у гейта 1, и остаётся корневой — и на каталог с завершающим слэшем. Ссылку в свёрнутый каталог мимо них вести не на что: отчёт называет такие ссылки отдельным числом «ссылок в свёрнутое без переписи» и перечнем `файл: цель`, а гейт 1 `lint` в `docs/**` и корневых `*.md` видит их битыми. Заготовка идёт в **stdout**, отчёт — в **stderr**: `fold N \| git commit -F -` работает без чистки вывода. Дата закрытия и исход строки вычитываются из `result.md`: первый абзац, а без него — заголовок, скобками `(<исход> ГГГГ-ММ-ДД)` или формой `— результат: <исход>` (дату несут только скобки); исход — первое по позиции слово словаря, раскладка слов на три исхода — [01](01-layout.md#архив). Поле коммита в строке остаётся `—`, если тела ещё нет в истории; тогда `show N` ищет коммит по разделу тела в сообщении, а без него — по заголовку. Последняя строка отчёта и вступление заготовки говорят, какой это случай: в поле `—` — коммит с заготовкой обязателен, она единственное хранилище тела; строка назвала ревизию — заготовка лишь копия и не обязательна, тело достаёт `show N`, пока squash или `reset --soft` не выбросили эту ревизию из истории ([ADR-033](../adr/adr-033-fold-draft-mandatory-only-without-revision.md)). Каталог, закоммиченный между `archive N` и `fold N`, даёт строке ревизию этого коммита, и squash перед пушем уносит её из истории — поэтому между ними не коммитят. Заготовка ложится вне рабочего дерева — `fold N > "$(git rev-parse --git-dir)/BACKSLOP_DRAFT"`, иначе `git add -A` унёс бы её в коммит задачи, — и итоговый коммит приёмки несёт её сообщением: `git add -A`, `git reset --soft <база>`, `git commit --cleanup=verbatim -F "$(git rev-parse --git-dir)/BACKSLOP_DRAFT"` — `--cleanup=verbatim` не даёт git чистить сообщение вовсе, то же называет последняя строка отчёта; subject можно заменить на `<prefix>-N: закрыта — …`, тело остаётся. `fixup` поверх коммита worker'а заготовку выбрасывает, и после свёртки squash не делается. Ревизию, которой нет в истории `HEAD`, ловит гейт 13 `lint` ([03](03-lint.md)) — поэтому `lint` идёт на итоговом коммите, до пуша. Запись пачки уходит вместе с пачкой и получает свою строку с исходом «пачкой M» ([ADR-026](../adr/adr-026-archive-folds-to-log.md)); записи идут по номеру числом (`1.2` раньше `1.10`), а не файл в `minor/` — каталог, битую ссылку — `fold` не читает: его называет гейт 5 `lint`. Журнал с CRLF остаётся CRLF: дописанные строки берут перевод строки файла | задачи нет; она уже свёрнута; она не в архиве; `result.md` отсутствует, пуст или остался заглушкой — `[TODO` вне кода, тот же разбор, что у гейта 5 ([03](03-lint.md)); показанное в код-спане или блоке кода заглушкой не считается; `result.md` не называет исход словом словаря ни в первом абзаце, ни в заголовке — тот же предикат и текст, что у гейта 5 ([ADR-037](../adr/adr-037-result-outcome-word-under-gate.md)), массовая свёртка на такой записи не отказывает и читает голое «Закрыта» и маркер «Исход:» «выполнена»; нет `task.md`; вложение каталога не лежит в `HEAD` или расходится с ним — отказ называет файлы: «закоммить каталог сначала или убери эти файлы»; `--embed-missing` вместе с номером; номеров больше одного |
| `fold [--older-than <дата>] [--embed-missing] [--dry-run]` | свернуть накопленный архив: те же каталоги, но тело каждой задачи берётся из истории, и строка журнала называет ревизию, из которой его достаёт `show`: последний коммит, тронувший каталог тела (`git log -1 -- <каталог>/`), — `result.md`, дописанный после архивации, тоже; до удаления каждый файл каталога из ревизии сверяется с ней по блобу (`git hash-object`, [ADR-034](../adr/adr-034-fold-checks-body-blobs-against-revision.md)); файл под `.gitignore` в ревизию не попадает и уходит вместе с каталогом. Семьдесят семь тел в одно сообщение коммита не помещаются, поэтому заготовка перечисляет задачи и ревизии, а не тела; последняя строка отчёта так и говорит — тел в заготовке нет, их достаёт `show N` по ревизии строки, а у строк с `—`, чьё тело ушло с каталогом без `--embed-missing`, — что тело не сохранено нигде; коммит заготовки ради тел требует только `--embed-missing`, когда тела в ней есть. Вступление заготовки обещает тело в истории, только когда ревизию назвала каждая строка; иначе оно называет задачи строк с `—` и говорит, ниже их тела или потеряны. Тело, унесённое `--embed-missing`, идёт разделами `--- <каталог>/task.md ---` под той же меткой `> `, что у `fold N`, и `show N` находит его по разделу. Вложений `--embed-missing` не уносит: каталог без тела в истории, при котором лежит вложение, не сохранённое в `HEAD` (правило игнорируемых файлов — то же, что у `fold N`; каталог, игнорируемый целиком, считает каждый файл), — отказ до первой записи с перечнем файлов, как у прочих отказов массовой формы, а не пропуск каталога. Строки журнала и перечень заготовки идут в порядке дат закрытия — тех же, что встают в строки, — равные даты по номеру. Каталог с незакоммиченной правкой ревизии не получает: последний коммит каталога несёт тогда другую редакцию; то же — файл, который расходится с ревизией, хотя `git status` его правки не видит (`assume-unchanged`, `skip-worktree`). Блоб, закоммиченный с CRLF до `core.autocrlf=true|input`, `hash-object` видит другим; такой файл без флага в `git ls-files -v` сверяется второй раз — `git diff --quiet <ревизия> -- <файл>` — и проходит, если git зовёт его неизменным. Нечего сворачивать — строка «сворачивать нечего» уходит в stderr, stdout пуст, и `fold > "$(git rev-parse --git-dir)/BACKSLOP_DRAFT"` не закоммитит её сообщением. `--older-than` берёт только задачи с датой закрытия строго раньше названной (дата читается из `result.md` — первый абзац, а без него скобки заголовка; её нет — дата коммита ревизии тела; нет и ревизии — запись считается закрытой сегодня и не берётся). Сторона `--theirs` без секции невыпущенного читается пустой, и отчёт говорит об этом строкой «у theirs нет секции невыпущенного — записи theirs не читались»; код возврата от этого не меняется. Структура секции — пара «заголовок `### …` + жирная подгруппа»: подгруппа — строка `**…**` с первой колонки, а с отступом такая строка остаётся телом записи; буллет верхнего уровня без жирного заголовка — свой блок, опознаётся текстом и по `--base` не снимается. Разбор обратим, и раскладка стороны `--ours` не меняется: аддитивное слияние даёт против неё только добавления ([ADR-024](../adr/adr-024-changelog-merge-keeps-layout.md)). Односторонняя запись `--theirs` встаёт за ближайшей предшествующей ей у `--theirs` записью, уже лежащей в результате; такой нет — первой в контейнере, а если общей записи в контейнере нет вовсе — в конец: конвенция «новое сверху», спор за одно место — в пользу `--theirs`. Односторонний контейнер `--theirs` остаётся под своим заголовком: подгруппа встаёт за последним контейнером своего `### …`, а заголовок, которого у `--ours` нет, приезжает со своими подгруппами и встаёт за группой ближайшего предшествующего ему у `--theirs` контейнера, который уже лежит в результате, — верхняя группа без заголовка тоже считается; такого нет — в конец секции. Записи и подгруппы до первого `### …` — верхняя группа секции: записи без заголовка встают в её начало, подгруппа — за последним контейнером без заголовка, а без такого — тоже в начало. Каждое такое размещение отчёт называет строкой: «заголовок … добавлен перед …», «заголовок … добавлен в конец ## …», «подгруппа … добавлена под …», «записи без заголовка добавлены в начало ## …». Совпавший заголовок с одинаковым телом — одна запись; с разошедшимися телами — обе под меткой `<!-- backslop:conflict …  -->`, выбор за агентом, **код возврата 1**. Метка опознаётся строкой, начинающейся с неё, и только в сливаемой секции невыпущенного: имя метки, набранное прозой в код-спане, стоит в CHANGELOG любого проекта, который про неё написал, и меткой не считается. Односторонний буллет без жирного заголовка называется в отчёте своей строкой и в счёт записей не входит. Повтор блока внутри одной стороны называется отдельной строкой всегда и по обеим сторонам: второе вхождение в результат не попадает, и промолчать о пропавшей строке нельзя. `--base` снимает запись, которой сторона лишилась относительно базы; **без `--base` односторонняя запись сохраняется, а пометка о ней уходит в отчёт, а не в файл** — снятие от новизны без базы не отличить. Результат — в stdout или в `--out`, недостающие каталоги которого создаются; относительный `--out` отсчитывается от текущего каталога, и строка отчёта «записано:» называет путь от него же; переводы строк результата — как у существующего файла `--out`, а без него — как у редакции `--ours`: CHANGELOG.md, выписанный с `core.autocrlf=true`, остаётся CRLF, хотя его blob — LF. Отчёт (счёт записей, односторонние, помеченные пары, размещённые заголовки и подгруппы) — всегда в stderr | нет `--ours` или `--theirs`; пустой `--base`; ревизия или список тегов не читается; у стороны `--ours` нет секции невыпущенного — ни заголовка без номера версии, ни верхней секции с версией без тега; секция невыпущенного входной редакции несёт незакрытую метку `<!-- backslop:conflict`; результат не прошёл самопроверку — заголовок размножился, запись встала чаще одного раза (двух под меткой конфликта), аддитивное слияние потеряло строку `--ours` — либо от повтора блока у `--ours`, и тогда отказ называет повтор. Отказ по этому инварианту возможен только когда `--base` ничего не снял: слияние со снятой записью аддитивным не считается, и снятый повтор там уходит строкой отчёта, а не отказом; `--out` не записывается — каталог на месте файла, файл на месте каталога в пути, иной отказ файловой системы: отказ называет путь и код ошибки |
| `version`, `help` | версия из `package.json`; справка — также `--help` у любой команды | — |

Мутационную пробу шаг 4 managed-блока требует только там, где есть чем её гнать: команду берёт поле `probe` в `backslop.json` ([01](01-layout.md)) — непустая однострочная команда без обратной кавычки и без меток `backslop:start`/`backslop:end`: шаблон ставит значение в код-спан, кавычка внутри его закрывает; перевод строки развалил бы блок, а метка оборвала бы его границу, которую `init` ищет по сырому тексту. Поле объявлено — шаг называет команду; поля нет — предложения про пробу в блоке нет вовсе, потому что правило, которое нечем исполнить, дороже отсутствия правила. Выкинутое требование `init` называет строкой вывода («probe в backslop.json не объявлен…»): молчание не отличить от забытого поля. Свою пробу репозиторий без поля описывает разделом вне managed-блока — такой раздел переживает `init` ([ADR-021](../adr/adr-021-probe-command-field.md)).

Текст нумерованных шагов managed-блока `AGENTS.md` можно адаптировать в проекте через `agents.stepOverrides` в `backslop.json`: ключ — строковый номер от `"1"` до `"7"`, значение полностью заменяет текст этого шага при `init`, а номер и остальные шаги сохраняются. Значение должно быть непустой строкой без переводов строк и символа `<`; такой конфиг `init` отклоняет до записи managed-блока. Всё, что проверку прошло, подставляется экранированным: вся ASCII-пунктуация CommonMark уходит под обратную косую, и значение остаётся текстом, а не разметкой — определение ссылки `[label]: /target` в нём не открывается, соседний шаг ссылкой не становится и цель ссылки за пределами блока не меняется. Скобки без определения ссылки остаются законным значением. Список экранируемого полон по построению, а не по перечню: спека объявляет экранируемым любой символ ASCII-пунктуации, а открыть конструкцию markdown нечем, кроме символа из этого класса ([ADR-020](../adr/adr-020-agents-step-overrides.md)). Граница worker'а остаётся под управлением шаблона. Сам блок по-прежнему переписывается из шаблона между маркерами.

Пункт о границах в самом брифе уточняет: approver закрывает задачи и правит текст файлов в каталогах статусов и архиве, а worker присылает формулировку в результате; исключение — новая находка: worker заводит её отдельным файлом через `new --parent N[.M]` в своей ветке, но уже созданные карточки не правит; перенос файлов между этими местами worker не делает.

Даты, которые ставят команды («Создана», «Взята», «Отложена», «Закрыта»), — календарная дата машины по её часовому поясу, не UTC ([lib/util.js](../../lib/util.js), `today`). Файл вне индекса git (или репозитория нет) `mv` и `archive` переносят обычным переименованием и предупреждают. Два файла с одним номером — отказ с обоими путями: молча взять первый значило бы двигать не ту задачу. Место в очереди `mv` считает до переноса, поэтому отказ `--after` файл не трогает; тем же принципом все отказы, видимые до переноса, случаются до первого переноса: половина перенесённого пакета оставила бы каталоги в состоянии, которое ниоткуда не прочитать. Отказ самой файловой операции на середине пакета так не отменяется — атомарна проверка, а не перенос. Порядок каждому номеру считается заново, когда до него дошла очередь, — иначе весь пакет получил бы один «Порядок». Файлы задач читаются без BOM, переводы строк сохраняются какими были. Длинный вывод (`status --json`) доезжает до читателя целиком: код возврата ставится через `exitCode`, закрытый читателем пайп — тихий выход.

`upgrade` обновляет только вверх: пин и штамп на последнем теге — «уже на vX», цель ниже текущей — отказ, как и цель старше 0.2.0 (у неё нет `migrate`). `--to` нужен, чтобы выбрать не последний тег или повторить обновление на ту же версию после сбоя. Формы `cli` с пином — `npx [флаги] github:owner/repo[#vX.Y.Z]` и `npx [флаги] backslop@X.Y.Z`; флаги npx сохраняются. `npx backslop` и `npx backslop@latest` — та же npm-форма с `pin: null`: `lint` предупреждает, `upgrade` пина не выведет из registry. GitHub-форма даёт источник тегов; npm-форма — нет, и без поля `source` `upgrade` отказывает. `cli` не в этих формах (глобальная установка, репозиторий инструмента) — пин не трогается, команды новой версии запускаются тем же `cli`; без поля `source` в этом случае — отказ. Всё, что зависит от формата, делает новая версия: `upgrade` может идти из старой. Команды новой версии исполняются оболочкой из строки `cli` как есть — тот же уровень доверия к `backslop.json`, что у `gates`. `init` и `migrate` отказывают, когда штамп новее их самих: понижение версии не поддерживается. Обратный перекос — запись `MIGRATIONS` со `since` выше версии инструмента — рантаймом не ловится: такая миграция печатается должной и исполняется заново при каждом запуске, а отметиться применённой не может, потому что штамп не пишется при равенстве версий. Цена перекоса — не лишняя строка в выводе, а повторный проход по файлам проекта, и `upgrade` зовёт `migrate` каждый раз: тело миграции обязано быть идемпотентным. Сторожит её тест [test/version.test.mjs](../../test/version.test.mjs): оба числа приезжают из одного пакета и расходятся только в dev-дереве инструмента, между коммитом миграции и бампом.

Ловушка адресности закрыта наполовину: на пустом наборе изменённых путей каждая запись с областью пропускается. Там, где прогон объявил себя приёмкой флагом `--require-clean`, это отказ, и считается он по набору, а не по форме флагов: пустой набор бывает и с названной базой — `--base HEAD` или `--base origin/main` на уже влитой ветке дают чистое дерево и пустой дифф. Непустой набор, не задевший областей, отказа не даёт: там пропуск честный. Без `--require-clean` пустой набор остаётся честным ответом по выбранному источнику — ничего не тронуто. Прогон приёмки на проекте с областями идёт с `--base`, иначе он подтверждает только записи без области; числа в итоге это показывают, молчаливого зелёного здесь нет.

`upgrade` переписывает пин в `backslop.json`, поле `gates` и живых файлах: markdown из `docs/**` и корневые `*.md` с историческими исключениями, каждый файл с именем `package.json` и известные CI-файлы. Старый пин в живом файле — ошибка `lint`; исторические записи остаются зелёными. `--pin-only` меняет только конфигурацию и гейты; после ручных `migrate` и `init` повторный полный `upgrade` чинит живые пины, даже если новый тег не появился.

Бамп версии — отдельный ход до релиза: `npm run release -- X.Y.Z --bump` пишет `version` в `package.json`, переименовывает верхнюю секцию `CHANGELOG.md` в `## vX.Y.Z — <дата>` и ставит штамп `backslop.json` вызовом `init`; все проверки идут до первой записи, коммитов скрипт не делает — дифф смотрит и коммитит агент. До тега секция `## vX.Y.Z — <дата>` остаётся для `merge-changelog` секцией невыпущенного: пока над ней нет заголовка без номера версии, записи track'ов, принятых после бампа, сливаются в неё. Рассинхрон этих трёх чисел ловит одиннадцатый гейт `lint` ([03](03-lint.md)).

Релиз самого пакета — `npm run release -- X.Y.Z` ([scripts/release.mjs](../../scripts/release.mjs)): чистое дерево на `main`, совпадение версии и тега, `git fetch` и fast-forward от `origin/main` (локальный `main` может быть впереди), `npm test`, `lint`, `pack --dry-run`, локальный тег, `git push --atomic --dry-run`, затем `npm publish` и atomic push `main` и тега. `--no-publish` снимает только шаг `npm publish` — тег и atomic push остаются: публикация в npm не планируется (владелец отклонил [BS-2.1](../archive/LOG.md#bs-2.1) 2026-09-24), поэтому это и есть штатный релизный путь, и отчёт скрипта в этом случае говорит «npm publish не запускался». `--bump` и `--no-publish` вместе — отказ: бамп до релиза не доходит и ничего не публикует. Рабочие копии субагентов `.claude/worktrees/` игнорируются и чистоту release-preflight не нарушают. Acceptance-тест ([test/release.test.mjs](../../test/release.test.mjs)) собирает tarball настоящим `npm pack` и сверяет его состав с полем `files`: каждый отслеживаемый git файл под `bin`, `lib`, `templates` и корневые `README.md`, `README.ru.md`, `LICENSE`, `CHANGELOG.md` упакован, сверх них — только `package.json`. Сбой после тега печатает состояние и следующую команду. Default `cli` до первой публикации остаётся GitHub-формой ([ADR-007](../adr/adr-007-npm-pin.md)).

Порядок при постановке в очередь ([lib/tasks.js](../../lib/tasks.js), `placeInQueue`): в конец — максимум плюс 10; `--top` — середина между нулём и первым; `--after M` — середина между M и следующей; `--restore` — сохранённое число, если оно свободно, иначе место перед тем, кто его занял. Целого места нет — вся очередь перенумеровывается шагом 10 с сохранением порядка, команда об этом сообщает. `--restore` возвращает место, а не гарантирует его: ранг абсолютный ([ADR-002](../adr/adr-002-status-is-directory.md)), и очередь могла перенумероваться целиком. Команда отдельной строкой говорит, встала задача на сохранённое число, на ближайшее свободное или перед соседом по пакету. В пакете место каждой считается заново, когда до неё дошла очередь, и задано убыванием сохранённых чисел ([ADR-027](../adr/adr-027-previous-order-restores-place.md)). Относительный порядок возвращённых задач флаг гарантирует: место каждой следующей ограничено соседом, поставленным предыдущим шагом, — число свободно, но позади соседа, или занято задачей позади него, и задача встаёт прямо перед соседом, с серединой разрыва или перенумерацией, как у занятого числа ([ADR-031](../adr/adr-031-restore-batch-keeps-order.md)). Перестановка задачи, уже стоящей в очереди, считается так же, только без неё самой среди соседей; файл остаётся на месте, ссылки не переписываются.

## `status --json`

```json
{
  "prefix": "BS",
  "docs": "docs",
  "active":   [{ "id": "BS-2", "title": "…", "file": "docs/backlog/active/BS-2-x.md", "created": "2026-09-03", "taken": "2026-09-04" }],
  "queue":    [{ "id": "BS-1", "title": "…", "file": "docs/backlog/queue/BS-1-y.md", "created": "2026-09-03", "order": 10 }],
  "deferred": [{ "id": "BS-3", "title": "…", "file": "docs/backlog/deferred/BS-3-z.md", "created": "2026-09-01", "deferred": "- **Отложена:** 2026-09-02" }],
  "triage":   [{ "id": "BS-2.1", "title": "…", "file": "docs/backlog/triage/BS-2.1-w.md", "created": "2026-09-04" }],
  "minor":    [{ "id": "BS-2.2", "title": "…", "file": "docs/backlog/minor/BS-2.2-v.md", "created": "2026-09-05", "area": "[01. Раскладка](../../reference/01-layout.md)", "cost": "major (гипотеза)" }],
  "archive": 12
}
```

Очередь отсортирована по порядку, затем по номеру; задача без порядка идёт в конец с `order: null`. `deferred` — первая непустая строка раздела «Отложено». `minor` отсортирован по «Области» как по строке, записи без области — в конце с `area: null`; `cost` — значение поля «Цена» как записано, `null` без него. Пути — от корня проекта в posix-форме.

## Что стабильно

Оркестратор любого harness работает с backslop через файлы и CLI; другого API нет. Стабильное:

- каталоги статусов и архив; имя файла `<prefix>-N[.k]-<slug>.md`; форма строки `<docs>/archive/LOG.md` и её якорь `#<номер в нижнем регистре>`; русские и английские поля шапки и разделы задачи, включая совместимые `Scope`/`Area`;
- поля `backslop.json`: `prefix`, `docs`, `cli`, `gates`, `probe`, `version`, `source`, `lang`, `tools`; обе формы записи `gates` — строка и `{ command, when }`; формы пина `npx github:owner/repo#vX.Y.Z` и `npx backslop@X.Y.Z`;
- команды `status --json`, `mv`, `new --parent N[.M]`, `new --parent N[.M] --minor --evidence "…"`, `archive`, `archive N.k --into M`, `fold`, `show` и их коды возврата — ими оркестратор читает очередь, раздаёт, закрывает и сворачивает задачи;
- worker командами статусов не пользуется: его единственная запись — файл находки `new <slug> --parent N[.M]` (с `--minor --evidence "…"` для minor и гипотез) в своей ветке; при `--parent N.M` `new` выдаёт следующий свободный `N.k` и записывает поле `Parent`; команда видит номера соседних worktree и локальных веток;
- транспорт worker'ов — слот «Как поднять worker'а» в скилле `backslop-batch`; новый транспорт — страница с вариантом для этого слота, в CLI ничего не меняется.

Изменение любого пункта — новым ADR.
