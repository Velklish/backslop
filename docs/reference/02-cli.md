# 02. CLI и контракт для оркестратора

Точка входа — [bin/backslop.js](../../bin/backslop.js): первый аргумент — команда, модуль `lib/<команда>.js` экспортирует `run(argv, { cwd })`. Отказ, адресованный человеку, — `CliError`: печатается без стека, код возврата 1. Любое другое исключение — ошибка кода, со стеком. Вывод: `✔` — успех, `✖` — ошибка, `⚠` — предупреждение; цвет только на терминале.

## Команды

| Команда | Что делает | Отказ (код 1) |
|---|---|---|
| `init [--dir docs] [--prefix BS] [--cli <команда>]` | раскладка скелета; см. [01](01-layout.md) | флаг расходится с существующим конфигом; проект инициализирован выше; штамп новее инструмента; плохой префикс или путь |
| `new <slug> [--title "…"] [--queue [--top]] [--parent N]` | файл задачи из шаблона в `triage/`, с `--queue` — в очередь с порядком в конец или сверху; `--parent N` — находка `N.k` | плохой slug; родителя нет; `--top` без `--queue` |
| `mv <N> <triage\|queue\|active\|deferred> [--top \| --after M]` | `git mv` между каталогами; в `queue` ставит «Порядок», из `queue` снимает; в `active` пишет «Взята»; в `deferred` дописывает раздел «Отложено»; входящие ссылки на файл переписывает по всему markdown репозитория | задачи нет; она в архиве; уже в этом статусе; `--after` не из очереди |
| `archive <N> [--dry-run]` | `git mv` в `archive/<id>-<slug>/task.md`, перепись ссылок по всему markdown репозитория, заготовка `result.md` | задачи нет; уже в архиве; каталог занят |
| `adr <slug> [--title "…"]` | `docs/adr/adr-NNN-<slug>.md` из шаблона со следующим номером | плохой slug |
| `status [--json]` | сводка по каталогам | — |
| `lint` | восемь гейтов, см. [03](03-lint.md) | найдены ошибки |
| `upgrade [--to X.Y.Z] [--dry-run] [--pin-only]` | теги `vX.Y.Z` из `source` или из формы `cli`; пробный `<новый cli> version`; пин в `cli` и `gates`; затем `<новый cli> migrate`, `<новый cli> init`, `<новый cli> changelog --since <старая> --to <новая>` (без `--since`, если старой нет) | нет ни источника, ни формы `npx github:`; тега `--to` нет в источнике; цель старше 0.2.0 или ниже текущей; ls-remote или пробный запуск отказали — пин не тронут; сбой после пина — отказ называет, чем довести |
| `migrate [--dry-run]` | миграции из списка `MIGRATIONS` для штампа ниже их версии, затем штамп; список пока пуст | штамп новее инструмента |
| `changelog [--since X.Y.Z] [--to X.Y.Z]` | секции CHANGELOG backslop с версией строго после `since` и не позже `to` (по умолчанию — версия инструмента) | версия не по форме |
| `version`, `help` | версия из `package.json`; справка — также `--help` у любой команды | — |

Файл вне индекса git (или репозитория нет) `mv` и `archive` переносят обычным переименованием и предупреждают. Два файла с одним номером — отказ с обоими путями: молча взять первый значило бы двигать не ту задачу. Место в очереди `mv` считает до переноса, поэтому отказ `--after` файл не трогает. Файлы задач читаются без BOM, переводы строк сохраняются какими были. Длинный вывод (`status --json`) доезжает до читателя целиком: код возврата ставится через `exitCode`, закрытый читателем пайп — тихий выход.

`upgrade` обновляет только вверх: пин и штамп на последнем теге — «уже на vX», цель ниже текущей — отказ, как и цель старше 0.2.0 (у неё нет `migrate`). `--to` нужен, чтобы выбрать не последний тег или повторить обновление на ту же версию после сбоя. Форма `cli` — `npx [флаги] github:owner/repo[#vX.Y.Z]`; флаги npx сохраняются. `cli` не в этой форме (глобальная установка, репозиторий инструмента) — пин не трогается, команды новой версии запускаются тем же `cli`; без поля `source` в этом случае — отказ. Всё, что зависит от формата, делает новая версия: `upgrade` может идти из старой. Команды новой версии исполняются оболочкой из строки `cli` как есть — тот же уровень доверия к `backslop.json`, что у `gates`. `init` и `migrate` отказывают, когда штамп новее их самих: понижение версии не поддерживается.

Порядок при постановке в очередь ([lib/tasks.js](../../lib/tasks.js), `placeInQueue`): в конец — максимум плюс 10; `--top` — середина между нулём и первым; `--after M` — середина между M и следующей. Целого места нет — вся очередь перенумеровывается шагом 10 с сохранением порядка, команда об этом сообщает.

## `status --json`

```json
{
  "prefix": "BS",
  "docs": "docs",
  "active":   [{ "id": "BS-2", "title": "…", "file": "docs/backlog/active/BS-2-x.md", "created": "2026-09-03", "taken": "2026-09-04" }],
  "queue":    [{ "id": "BS-1", "title": "…", "file": "docs/backlog/queue/BS-1-y.md", "created": "2026-09-03", "order": 10 }],
  "deferred": [{ "id": "BS-3", "title": "…", "file": "docs/backlog/deferred/BS-3-z.md", "created": "2026-09-01", "deferred": "- **Отложена:** 2026-09-02" }],
  "triage":   [{ "id": "BS-2.1", "title": "…", "file": "docs/backlog/triage/BS-2.1-w.md", "created": "2026-09-04" }],
  "archive": 12
}
```

Очередь отсортирована по порядку, затем по номеру; задача без порядка идёт в конец с `order: null`. `deferred` — первая непустая строка раздела «Отложено». Пути — от корня проекта в posix-форме.

## Что стабильно

Оркестратор любого harness работает с backslop через файлы и CLI; другого API нет. Стабильное:

- каталоги статусов и архив; имя файла `<prefix>-N[.k]-<slug>.md`; поля шапки и разделы задачи;
- поля `backslop.json`: `prefix`, `docs`, `cli`, `gates`, `version`, `source`; форма пина `npx github:owner/repo#vX.Y.Z`;
- команды `status --json`, `mv`, `new --parent`, `archive` и их коды возврата — ими оркестратор читает очередь, раздаёт и закрывает задачи;
- worker командами статусов не пользуется: его единственная запись — файл находки `new <slug> --parent N` в своей ветке; sub-ID не требует координации;
- транспорт worker'ов — слот «Как поднять worker'а» в скилле `backslop-batch`; новый транспорт — страница с вариантом для этого слота, в CLI ничего не меняется.

Изменение любого пункта — новым ADR.
