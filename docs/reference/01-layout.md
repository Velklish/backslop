# 01. Раскладка и форматы

## Что кладёт `init`

```
<проект>/
  backslop.json                    конфиг: prefix, docs, cli (с пином), gates, probe, version, lang, tools
  AGENTS.md                        блок между <!-- backslop:start --> и <!-- backslop:end -->
  .gitignore                       блок между # backslop:start и # backslop:end; только при выбранных adapters
  docs/README.md                   индекс документации и таблица ADR
  docs/ROADMAP.md  docs/GLOSSARY.md  docs/reference/README.md
  docs/adr/adr-001-process.md      ADR процесса: решение вести задачи и решения по backslop; в проекте со своими ADR — следующий свободный номер
  docs/backlog/README.md           правила ведения; списка задач нет
  docs/backlog/{triage,queue,active,deferred,minor}/.gitkeep
  docs/archive/README.md  docs/archive/LOG.md   правила архива и журнал закрытых задач
```

Adapters — только если выбраны в `tools` ([lib/adapters.js](../../lib/adapters.js), [ADR-006](../adr/adr-006-adapter-ownership.md)):

| Adapter | Куда пишет |
|---|---|
| `claude` | `.claude/skills/backslop-*` и stub `CLAUDE.md` (`@AGENTS.md`), если файла не было |
| `cursor` | `.cursor/rules/backslop-*.mdc` и namespaced `references/` |
| `codex` | `.agents/skills/backslop-*` |

Owned outputs — локальный generated результат, и в git им делать нечего ([ADR-012](../adr/adr-012-owned-outputs-gitignore.md)): `init` держит для них блок в `.gitignore` между `# backslop:start` и `# backslop:end` — строка `<корень harness>/backslop-*` на каждый выбранный adapter и `/CLAUDE.md`, когда на диске лежит именно наш stub, а не пользовательский файл. Чужие строки файла сохраняются, заменяется только содержимое между маркерами. Проект без выбранных adapters `.gitignore` не получает: генерировать нечего, и заводить файл там, где его не было, `init` не станет; снятие всех adapters оставляет пустой блок с объяснением.

Состав adapters записан один раз — [lib/adapters-registry.js](../../lib/adapters-registry.js): `id`, корень каталога и имя canonical-скилла. Из него выводятся список `tools`, owned-пути, legacy-набор и признак adapter-пути; отдельной копии тройки путей в коде нет.

Правила идемпотентности ([lib/init.js](../../lib/init.js)): конфиг создаётся один раз, и флаги `dir`/`prefix`/`cli`, расходящиеся с ним, — отказ; `--lang` и `--tools` на повторном `init` меняют конфиг. Файлы `docs/` создаются только отсутствующие; выбранные adapter outputs переписываются, снятые чистятся по предикату владения — маркер в файле или legacy-путь, а не совпадение с текущим шаблоном; чужой файл без маркера на пути adapter output остаётся и называется предупреждением — и при снятии, и при записи: выбранный adapter переписывает только owned файлы (маркер или legacy-путь), а чужой на своём пути не трогает ([ADR-015](../adr/adr-015-adapter-write-preserves-foreign.md)), и `lint` такой файл у выбранного adapter'а красит; блок в `AGENTS.md` заменяется между маркерами, а без маркеров дописывается в конец; штамп `version` переставляется на версию инструмента, пин в `cli` при этом не трогается — расхождение называется предупреждением. Запуск в подкаталоге уже инициализированного проекта отказывает и называет корень. Корни выбранных adapter'ов — `.claude/skills`, `.cursor/rules`, `.agents/skills` по составу `tools` — проверяются на symlink до первой записи: бракуется symlink на любой компоненте пути под корнем проекта, в том числе на самом `.claude`, куда бы ссылка ни вела — внутрь проекта или наружу. Корни невыбранных adapter'ов не проверяются и не чистятся: backslop в них не пишет и ничего не снимает, и общий harness-каталог ссылкой у проекта без этого adapter'а — законная раскладка ([ADR-016](../adr/adr-016-selected-adapter-roots-symlink.md)). Отказ случается, пока на диске нет ни конфига, ни скелета; лечение — обычный каталог на месте компоненты либо снятие adapter'а: `--tools` без него или `--tools none`, если других adapters нет (повторный `init` без флага `--tools` состав не меняет и не лечит). За ссылку на корне harness — на любой его компоненте, `.claude` или `.claude/skills` — не заходит и обход markdown: `mv` и `archive` файлы за ней не читают и не переписывают; гейт ссылок `lint` ходит по `<docs>/**` и корневым `*.md` и harness-каталогов не касается. Каталог на пути adapter output выбранного adapter'а и файл на компоненте этого пути — отказ словами при записи (`owned adapter output не является файлом`, `файл вместо каталога`): писать некуда, а владение по legacy-пути до предиката не доходит. Self-host репозитория держит `tools: []`: обычный `init` не создаёт harness-файлов и не делает tracked tree грязным.

Имя проекта для заголовков — `name` из `package.json` без scope, иначе имя каталога.

## `backslop.json`

| Поле | Умолчание | Смысл |
|---|---|---|
| `prefix` | `BS` | префикс номеров: 2–6 заглавных латинских букв или цифр, первая буква |
| `docs` | `docs` | каталог документации относительно корня; уезжает в managed-блок — см. «Значения, которые уезжают в блок» ниже |
| `cli` | `npx github:Velklish/backslop#v<версия>` | как звать backslop из этого проекта; подставляется в скиллы и блок AGENTS.md — см. «Значения, которые уезжают в блок» ниже. Форма `npx github:owner/repo#vX.Y.Z` несёт пин, из неё `upgrade` выводит источник релизов |
| `gates` | `["<cli> lint"]` | команды, которые должны быть зелёными до сдачи; гонит их `backslop gates` ([02](02-cli.md)), и скиллы зовут именно её. Запись — строка-команда (гоняется всегда) либо объект `{ "command": "<команда>", "when": ["<glob>", …] }`: команда с областью запускается, только когда набор изменённых путей задел хоть один образец. `when` — непустой список непустых образцов; пустой отвергается, потому что команда не запускалась бы никогда. Образец сверяется с путём целиком и от корня проекта (в монорепе префикс каталога проекта с пути снимается, путь вне проекта из набора уходит): `*` и `?` не переходят `/`, `**` переходит, `**/` ловит и корень, поэтому каталог задаётся как `docs/**`, а не `docs` — голое имя каталога не сойдётся ни с одним путём и гейт не запустится никогда ([ADR-023](../adr/adr-023-gates-scope-when.md)) |
| `probe` | нет | команда мутационной пробы проекта: непустая строка, уезжающая в managed-блок — см. «Значения, которые уезжают в блок» ниже. Объявлена — шаг 4 блока `AGENTS.md` называет её; поля нет — требования пробы в блоке нет вовсе, и `init` говорит об этом строкой вывода. Умолчания нет: команда пробы у каждого репозитория своя, и выдуманная хуже отсутствующей ([ADR-021](../adr/adr-021-probe-command-field.md)) |
| `version` | версия инструмента | штамп: какая версия делала раскладку; ставят `init` и `migrate`, читают `lint` и `upgrade` |
| `source` | нет | откуда `upgrade` берёт теги релизов: git-адрес или путь; без поля — из GitHub-формы `cli`; npm-пин источника не даёт |
| `lang` | `ru` | язык новых файлов и генерируемых artifacts: `ru` или `en`; старый конфиг без поля читается как `ru` |
| `tools` | `[]` | выбранные adapters: уникальный список `claude`, `cursor`, `codex`; старый конфиг без поля и с `.claude/skills/backslop-task/SKILL.md` сохраняет `["claude"]`, без этой улики — пустой список ([ADR-008](../adr/adr-008-legacy-claude-adapter.md)) |
| `agents.stepOverrides` | нет | объект переопределений блока `AGENTS.md`: ключи — строковые номера шагов `"1"`…`"7"`, значения — непустой однострочный текст без переводов строк и символа `<`; `init` заменяет текст указанного шага внутри managed-блока, сохраняя номер, остальные шаги и границу worker'а. Значение подставляется **экранированным**: вся ASCII-пунктуация CommonMark (32 символа, от `!` до `~`) уходит под обратную косую, поэтому оно остаётся текстом и разметкой не становится — в частности, определение ссылки `[label]: /target`, у которого область всего документа, в нём не открывается. Скобки без определения ссылки остаются законным значением: экранирование не отвергает, а обезвреживает ([ADR-020](../adr/adr-020-agents-step-overrides.md)) |

**Значения, которые уезжают в блок.** Класс — поля, чьё значение шаблон подставляет внутрь managed-блока `AGENTS.md`: `prefix`, `docs`, `cli` и `probe`. Форма у них там одна: без переводов строк, без обратной кавычки, без меток `backslop:start` и `backslop:end`. Вторая строка встала бы в блоке отдельным абзацем, кавычка закрыла бы код-спан, в который шаблон ставит значение, а метка оборвала бы границу блока — `init` ищет её по сырому тексту и берёт первое вхождение, поэтому следующий запуск дописал бы свежий блок перед хвостом старого и растил файл с каждым разом. Запреты приняты [ADR-021](../adr/adr-021-probe-command-field.md) для `probe` и распространены на весь класс: проверка на все поля одна — `validateBlockValue` в [lib/config.js](../../lib/config.js). Отдельная копия запретов у каждого поля переживает появление следующего и оставляет его открытым — так `cli` и остался без запрета меток, когда его получил `probe`.

В списке проверяемых `prefix` нет: `PREFIX_RE` не пропускает ни метку, ни кавычку, ни перевод строки, и вызов был бы недостижимым кодом. Условие держит проверка в `test/config.test.mjs` — ослабнет regex, и покраснеет она, а не чужой `AGENTS.md`. Символ `<` в запрет не входит: закрыть код-спан им нечем (ADR-021). Флаги `--dir` и `--cli` первого `init` проверяются тем же местом: конфига ещё нет, и `loadConfig` его не читает.

Корень проекта — ближайший каталог с `backslop.json` вверх от текущего ([lib/config.js](../../lib/config.js)).

## Файл задачи

Имя — `<prefix>-N-<slug>.md` или `<prefix>-N.k-<slug>.md` для находки; slug — латиница в нижнем регистре, цифры, дефисы между словами. Каталог — статус. Русские и английские имена полей и разделов читаются вместе в одном бэклоге; новые файлы пишет слой `lang`.

```
# BS-1 · Заголовок

- **Порядок / Order:** 10               только в queue/; целое, шаг 10, меньше — раньше
- **Прежний порядок / Previous order:** 20   вне queue/; ранг, с которым задача ушла из очереди
- **Область / Scope / Area:** [раздел](../../reference/01-layout.md)
- **Создана / Created:** 2026-09-03
- **Взята / Taken:** 2026-09-04         ставит mv … active
- **Зависимости / Dependencies:** нет
- **Родитель / Parent:** BS-12.3       только у находки, созданной с `--parent N.M`; ребёнок получает следующий свободный `N.k`; в `minor/` — всегда
- **Цена / Cost:** minor              ставится в `minor/`, при уходе из него остаётся как есть: `critical`, `major` или `minor`; гипотеза — с пометкой, `major (гипотеза)` / `major (hypothesis)`

## Контекст / Context
## Что сделать / Work to do
## Не входит / Out of scope
## Проверки / Verification
## Отложено / Deferred                  только в deferred/: Отложена, Причина, Условие возврата
```

Поле шапки — строка `- **Имя:** значение` между заголовком и первым разделом `## `; порядок полей произвольный, «Порядок» команды ставят первым ([lib/tasks.js](../../lib/tasks.js), `setField`). «Область» новая задача получает от `new` ссылкой на `reference/README.md` с посчитанной глубиной пути; в проекте без этого файла заглушка остаётся текстом `[TODO: раздел reference/]` — битая ссылка красила бы гейт 1. Конкретный раздел выбирает тот, кто заводит задачу. «Область» разобранной задачи — заполненная ссылка на раздел справочника: в `queue/`, `active/` и `deferred/` пустое поле и оставленная `new` заглушка `[TODO]` красят `lint` (гейт 4, [03](03-lint.md)); в `triage/` поле не проверяется — запись там лежит без разбора. «Прежний порядок» ставит `mv` при уходе из `queue/` и снимает при возвращении туда. Активного «Порядка» вне очереди нет, а число, с которым задача ушла, нужно `mv N queue --restore` ([02](02-cli.md)). Поля разные, и гейт обязательности «Порядка» в `queue/` сохранённое число за него не считает. Каждое известное поле, включая его RU/EN-алиасы, должно встречаться в файле один раз: чтение и запись берут первое вхождение по порядку строк, `setField` схлопывает остальные, а `removeField` удаляет все. Заголовок первой строки обязан называть тот же номер, что имя файла.

Префикс, совпадающий с обычным словом (`API`, `RFC`, `HTTP`), даёт ложные срабатывания гейта упоминаний на строках вида `API-2.0` — выбирай префикс, которого нет в текстах проекта.

Номер выдаёт `new`: максимум по всем каталогам статусов и архиву плюс один; sub-ID находки — максимум `k` среди файлов `N.*` плюс один. Счётчика в файлах нет. Считаются не только файлы текущего дерева, но и занятые номера других worktree репозитория (по диску, включая незакоммиченные: `git worktree list --porcelain`) и всех локальных веток (`git ls-tree -r --name-only <ветка> -- <docs>/backlog <docs>/archive`) — [lib/tasks.js](../../lib/tasks.js), `foreignTaskIds`; когда чужой номер сдвинул свой, команда называет источник. Клон и удалённая ветка локально не видны — столкновение с ними ловит `lint` после слияния. Без git — по текущему дереву.

## Файл minor

`new <slug> --parent N --minor --evidence "…"` кладёт в `minor/` файл из [templates/minor.md](../../templates/minor.md): заголовок `# <id> · <title>`, поля «Область», «Создана», «Родитель», «Цена» и раздел «Улика» с текстом флага `--evidence`. Заведённая этой командой карточка заглушек `[TODO]` не несёт: без улики `new` отказывает до создания файла ([ADR-029](../adr/adr-029-minor-finding-requires-evidence.md)). Вторая дверь в `minor/` — `mv N.k minor` — переносит файл, не меняя его формы, и карточка из `triage/`, собранная по `task.md`, приносит туда заглушки «Что сделать», «Не входит» и «Проверки» вместе с заглушкой улики. Разделов «Что сделать», «Не входит», «Проверки» нет — это запись под пачку, а не постановка. «Область» пустая: её заполняет approver при резке пачек, и `lint` на пустую или незаполненную область в `minor/` только предупреждает. «Цена» по умолчанию `minor`; `--cost major|critical` принимается только с `--hypothesis` и записывается с пометкой гипотезы. `mv N minor` карточки из другого статуса дописывает «Цена: minor», если поля нет, и стирает заглушку области от `new` ([ADR-022](../adr/adr-022-cost-decides-finding-fate.md)).

## Архив

Архив держит две формы записи, и они живут рядом сколько угодно долго ([ADR-026](../adr/adr-026-archive-folds-to-log.md)).

**Каталог** — `docs/archive/<id>-<slug>/task.md`: постановка как была, с переписанными по новой глубине ссылками; `result.md` — из шаблона [templates/result.md](../../templates/result.md): дата закрытия, исход, что сделано, чем проверено, какие доки поправлены. Так кладёт `archive N`. Пока в `result.md` остаётся заглушка `[TODO` вне кода, `lint` красный; форма заглушки, показанная в код-спане, заглушкой не считается ([03](03-lint.md)).

**Строка журнала** — `docs/archive/LOG.md`: так задача выглядит после `fold N`. Каталога в дереве не остаётся, тело уезжает в сообщение коммита свёртки. Форма строки:

```
- <a id="bs-12"></a>`BS-12-slug` · 2026-09-05 · выполнена · `a1b2c3d4e5` · Заголовок задачи
```

Поля слева направо: якорь (номер в нижнем регистре — на него ведут входящие ссылки), номер со slug, дата закрытия, исход, коммит, заголовок. Заголовок стоит последним потому, что он единственный может содержать разделитель `·`; всё до него разбирается одним проходом без обратного хода. Якорь ставится явным `<a id>`, а не выводится из заголовка: он должен совпадать с номером, и это сверяет гейт 13 ([03](03-lint.md)).

Дата закрытия и исход вычитываются из двух мест `result.md`: первого абзаца — туда их кладёт шаблон — и скобок заголовка формой `(<исход> ГГГГ-ММ-ДД)`, как закрывали старые архивы: `# BL-005 — результат (снята с плана 2026-08-13)`. Первый абзац сильнее заголовка: дата — первая дата абзаца, а без неё — дата из скобок; исход — слово абзаца, а без него — слово скобок. Дальше абзаца файл не читается: «отклонена» в разделе «Проверки» — рассказ о ходе работы, а не исход. Даты нет ни там, ни там — строка получает дату свёртки.

Раскладка слов на три исхода журнала; обе языковые формы читаются всегда, пишется форма `lang`:

| Исход в строке | Слова в `result.md` |
|---|---|
| `слита в <номер>` / `merged into <номер>` | «слита в», «merged into»; между словом и «в» допустимы дата и разметка — `**Слита 2026-09-03 в** BL-470`, `**слита** в BL-172`. Номер — первый номер проекта после формы |
| `отклонена` / `rejected` | «отклонена», «rejected», «снята с плана»; голое «снята» — только первым словом абзаца или скобок: «Снята: 2026-08-26. Беспредметна» — исход, а «заглушка снята» посреди прозы — рассказ |
| `выполнена` / `completed` | «выполнена», «completed»; голые «закрыта», «closed», «done» — только когда ни абзац, ни скобки не назвали исхода словами выше: шаблон начинает абзац с `**Закрыта ДАТА.**`, и у старых архивов это единственное слово исхода |

Внутри одного места порядок проверки — сверху вниз: «Слита в BS-14. Выполнена там» — слияние. Голые слова ищутся целыми, а не частью другого: «abandoned» не несёт «done», «disclosed» — «closed». В поле стоит `—`, только когда ни абзац, ни скобки не несут ни одного слова таблицы, голого «закрыта» тоже: исхода, которого `result.md` не назвал, команда не выдумывает. Поэтому исход, отличный от выполненного, называется словом таблицы: «**Закрыта 2026-09-24.** Отказ: беспредметна» — это голое «Закрыта» шаблона и `выполнена`, а «**Закрыта 2026-09-24.** Отклонена: беспредметна» — `отклонена`. Запись, закрытая пачкой, получает исход `пачкой <номер пачки>` — он построен командой, а не вычитан, и по нему же читается обратно: `status` считает архивом закрытые задачи, а не пункты пачек.

Коммит — ревизия, из которой достаётся тело. `fold` массовой формой берёт её у последнего коммита, тронувшего путь тела, и проверяет `git cat-file` до удаления. Ревизии нет — причин три, и ответ у них разный: без git-репозитория и на незакоммиченном каталоге массовая свёртка **отказывает** (посмотреть в историю было нечем, и удалять нечем страховать), а доказанное отсутствие тела уносит каталог с собой либо, с `--embed-missing`, кладёт тело в заготовку сообщения. `fold N` тело кладёт в заготовку сообщения коммита, и в поле стоит `—`, пока каталог не закоммичен: коммита с телом ещё нет. Каталог, закоммиченный между `archive N` и `fold N`, получает в поле ревизию этого коммита — и squash перед пушем уносит её из истории; поэтому между ними не коммитят, а итоговый коммит приёмки несёт заготовку сообщением ([02](02-cli.md), `fold`). Строка назвала ревизию — `show N` читает её; в поле `—` — ищет коммит по заголовку `<prefix>-N:`, тем же признаком, которым `archive` и `tracks` узнают коммиты задачи. Ревизию, которой нет в истории `HEAD`, красит гейт 13 ([03](03-lint.md)).

Номера закрытых задач читаются из обоих источников: `scanTasks` и `foreignTaskIds` ([lib/tasks.js](../../lib/tasks.js)) берут и каталоги `archive/*/`, и строки журнала — в текущем дереве, в других worktree и в деревьях локальных веток. Имён файлов у свёрнутой задачи нет вовсе, и без чтения содержимого журнала соседней ветки её номер выдался бы второй раз.

Механическую половину строки «Доки тем же ходом» `archive` печатает: файлы под `<docs>/` и `CHANGELOG.md`, которых коснулись коммиты диапазона `--range` и коммиты с номером задачи в заголовке (`<prefix>-N: …`); пути — от корня проекта, merge-коммит считается по тому, что изменил сам merge. Список только печатается — что из него попадёт в `result.md`, решает approver; «Исход» и «Проверки» не подставляются вовсе, это его суждение по существу задачи.

Закрытие задачи не закрывает её находки: находка `N.k`, оставшаяся в `triage/` после переезда задачи `N` в архив, красит `lint` (гейт 9, [03](03-lint.md)). Запись из `minor/` закрывается пачкой: `archive N.k --into M` кладёт её файл в `docs/archive/<M>-<slug>/minor/` как есть, без своего `result.md`; исход по записям — строкой в `result.md` пачки. Такие записи остаются известными `lint` и нумерации: упоминание `N.k` зелёное, следующая находка под `N` получает следующий свободный номер, а `status` в счёте архива их не считает — там закрытые задачи.

## ADR

`docs/adr/adr-NNN-<slug>.md`, номер трёхзначный, следующий — по максимуму существующих ([lib/adr.js](../../lib/adr.js)). Шаблон [templates/adr.md](../../templates/adr.md): Status, Date, Deciders, Context, Варианты, Decision, Consequences. Каждый ADR — строка в таблице `docs/README.md`; принятый не правится, а заменяется новым с пометкой в старом.

## Шаблоны — источник

Всё, что `init` кладёт в проект, лежит в [templates/](../../templates/): `docs/**` — скелет документации, `skills/**` — скиллы, `agents-section.md` — блок AGENTS.md, `task.md`, `result.md`, `adr.md` — заготовки команд. Английский слой — `templates/en/` с тем же составом, подстановками, контрактом фронтматтера скиллов и числом заголовков, без кириллицы; `lint` репозитория инструмента краснеет при расхождении ([lib/templates.js](../../lib/templates.js), `templateParity`, подробности — [03](03-lint.md)). Значение `description` во фронтматтере скиллов стоит в двойных кавычках: плоский скаляр с «: » внутри как YAML-мэппинг не разбирается, и гейт фронтматтера у потребителя краснел бы на каждом `init`. Кавычки снимает `splitFrontmatter` ([lib/adapters.js](../../lib/adapters.js)) — Cursor кавычит значение заново сам, и без снятия в `.mdc` уехало бы двойное экранирование. Форму держит `npm test`, а не парность: `frontmatterField` построчный и к этому дефекту слеп. Подстановки `{{prefix}}`, `{{docs}}`, `{{cli}}`, `{{project}}`, `{{date}}`; неизвестная подстановка остаётся в тексте как есть, чтобы дыра была видна. Предложение про мутационную пробу живёт отдельным шаблоном `agents-probe.md` — так текст правила остаётся в `templates/`, а не в коде. Подстановка `{{probeRule}}` берёт его в трёх местах: шаг 4 managed-блока, тот же шаг скилла `backslop-task` и пункт про пробу в брифе. Подставляется он, только когда в конфиге объявлено поле `probe`.

Owned adapter output помечается `<!-- backslop:generated -->` в начале файла или сразу после YAML-фронтматтера — ровно туда кладёт `markGenerated` ([lib/adapter-ownership.js](../../lib/adapter-ownership.js)). Цитата маркера в теле docs владением не считается. Кроме маркера владение ограничено путями `.claude/skills/`, `.cursor/rules/`, `.agents/skills/` и фиксированным legacy-набором; под корнем маркер признаётся по любому пути, не только у `backslop-*`; снятие такого файла молчаливое, как у любого owned: закоммиченный виден в `git status` (блок `.gitignore` его не прячет), незакоммиченный уходит без следа. Снятие adapter'а идёт по тому же предикату `isOwnedAdapterFile`: кандидатов называют маркер, состав текущих шаблонов и legacy-набор, но удаляется только признанный owned — файл без маркера на пути шаблона переживает `init`, а legacy-путь, выпавший из шаблонов, снимается, в том числе у выбранного adapter'а. Разойтись эти множества могут только сменой состава `templates/skills/**`: сегодня он совпадает с legacy-набором файл в файл, поэтому разница предиката и совпадения с шаблоном на текущем дереве не наблюдается. Generated файлы не входят в `repoMarkdown`: `mv` и `archive` их ссылки не переписывают.
