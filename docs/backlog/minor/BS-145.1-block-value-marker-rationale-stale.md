# BS-145.1 · Reference and the refusal text justify the block-value marker ban by a raw-text bound search init no longer does

- **Scope:** [01. Layout](../../reference/01-layout.md) § backslop.json
- **Created:** 2026-09-28
- **Parent:** BS-145
- **Cost:** minor

## Evidence

Finding discovered while working on BS-145.

Evidence: docs/reference/01-layout.md, section on values that go into the block, says init finds the block marker in raw text and takes the first occurrence, so a marker inside a value would make the next run append a fresh block; docs/reference/02-cli.md (probe paragraph) and the validateBlockValue refusal in lib/config.js say the bounds are found in raw text. readManaged in lib/init.js recognises a marker only when it stands alone on its line (line.trim() === open), and 01-layout.md's idempotence rules say the same. Reproduced on the ADR consolidation branch: an AGENTS.md with an inline `<!-- backslop:end -->` in prose above the block, then init -> rc=0, 'AGENTS.md: backslop block unchanged', one backslop:start in the file. The ban itself still holds in code; only the stated reason is stale.
