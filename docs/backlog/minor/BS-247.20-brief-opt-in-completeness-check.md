# BS-247.20 · Decide and add an opt-in mechanical completeness check for generated briefs

- **Scope:** [02. CLI](../../reference/02-cli.md)
- **Created:** 2026-10-22
- **Parent:** BS-247
- **Cost:** minor

## Context

Before dispatching a generated brief, the batch instructions require the orchestrator to rescan its stdout for unresolved placeholders. Placeholder presence is deterministic and could be checked by the existing `brief` command. This is a confirmed automation opportunity, not a defect in the documented default draft behavior.

Evidence was inspected at source HEAD `44e74a32ff6a6b6c946321b3614b1881a2ccedfe`. The proposed public CLI option below has not been approved or implemented.

## Evidence

- `templates/en/skills/backslop-batch/SKILL.md:59` says "`brief` exits 0 even with stubs: check the output for `[TODO` before sending it"; the twin is at `templates/skills/backslop-batch/SKILL.md:59`.
- `lib/brief.js:50-60` supplies placeholders for missing track/entry/autonomy/handover; `:101-105` supplies the neighbour placeholder; `:74` returns 0.
- `test/brief.test.mjs:57-85` intentionally protects a bare draft, exit 0 and filled-slot rendering. `test/templates.test.mjs:374-380` protects the manual instruction rather than the completeness of a particular rendered brief.

The current success code cannot distinguish a draft from a mechanically complete brief. The audit did not observe an erroneous worker dispatch, and machine validation cannot decide the content of human choices.

## Work to do

1. First make the required ADR and public CLI contract decision. A candidate minimal interface is opt-in `brief --require-complete`; its exact name/diagnostic remains a decision, not an accepted fact.
2. If approved, validate the fully rendered brief before presenting it as ready output. Opt-in output containing unresolved slots or a `[TODO` marker must fail clearly with nonzero status and identify the remaining placeholders. A complete opt-in brief must retain the ordinary brief's text and exit 0.
3. Preserve ordinary incomplete `brief` output and exit 0. Do not make a breaking default change.
4. Implement through `lib/brief.js`, EN help in `bin/backslop.js`, EN/RU help/messages in `templates/i18n/ru.mjs`, existing brief tests and both batch skill locale sources. Update the CLI reference, README/CHANGELOG and required ADR under repository rules.
5. Replace the batch instruction's manual mechanical scan with the approved opt-in command while retaining the orchestrator's responsibility for meaningful entry, autonomy, neighbour and handover decisions.

Acceptance after contract approval: opt-in incomplete fails and stdout is not presented as a ready brief; opt-in complete returns 0 with unchanged content; default incomplete still returns its previous draft with exit 0. Cover EN/RU, omission of each required slot and a placeholder supplied inside an explicit value. State that this proves marker completeness, not semantic readiness.

## Out of scope

Do not dispatch workers, infer permissions, invent values, add a global dispatch tool or a new hook. Do not treat the proposed flag as already approved, and do not remove the useful draft mode.
