# BS-192.42 · lint gate 10 names the code fence as the first quoted line

- **Scope:** [03. Lint gates](../../reference/03-lint.md)
- **Created:** 2026-10-02
- **Parent:** BS-192
- **Cost:** minor

## Evidence

Finding discovered while working on BS-192.

Evidence: lib/lint.js, in `lintQuotes`, the branch that prints `quote no longer matches {href}: “{first}”` — a quote body wrapped in a code fence fails with `quote no longer matches <file>` followed by the opening fence line of the block: the message takes the first non-blank line of the body, which is the fence, so the reader cannot tell which statement changed. Reproduction on this branch: change one quoted line of docs/reference/06-module-map.md and run `node bin/backslop.js lint`; exit 1 with the message above. After: skip a wrapping fence line when choosing the line to print (the comparison already drops it, in `quoted`, the `FENCE_LINE.test(needle[0])` branch). Check: a test in test/lint.test.mjs that mutates a fenced quote and asserts the message holds the quoted text, not the fence; it fails on the old code.
