# BS-78.2 · Отказ git, оборванного сигналом, в gates, upgrade, merge-changelog и lint всё ещё печатает «код null»

- **Область:** [02. Команды](../../reference/02-cli.md)
- **Создана:** 2026-09-24
- **Родитель:** BS-78.1
- **Цена:** minor

## Улика

Находка при работе над BS-78.1.

Улика: сайты ниже читают stderr и error, но не signal — git, оборванный сигналом без error (SIGKILL извне), даёт в отказе «код null» / «null» / «git null». gitCause (lib/util.js) этот случай называет: вердикт «git: отказ без кода возврата называет причину — ошибку запуска или сигнал, а не «код null»» в test/fold.test.mjs, gitCause({ status: null, signal: 'SIGKILL', stderr: '' }) → «оборван сигналом SIGKILL». Эти сайты его не зовут; ENOBUFS, ETIMEDOUT и ENOENT они уже называют через error.message — предположительно цена minor. fold (bodyRev, git rm) и show переведены на gitCause пачкой BS-79.

<!-- quote:/lib/gates.js -->
```js
    const why = (r.stderr ?? '').trim() || (r.error ? r.error.message : `${r.status}`);
```
<!-- /quote -->

<!-- quote:/lib/upgrade.js -->
```js
    const why = (r.stderr ?? '').trim() || (r.error ? r.error.message : tr(lang, `код ${r.status}`, `code ${r.status}`));
```
<!-- /quote -->

