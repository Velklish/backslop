# BS-247.5 · Assert full URL order in the mixed external-links test

- **Scope:** [04. Finding verification protocol](../../reference/04-verification.md)
- **Created:** 2026-10-22
- **Parent:** BS-247
- **Cost:** minor

## Context

Audit finding PQA-005. `test/links-external.test.mjs:121–135`, especially `:129–131`, checks `r.out.trimEnd().split('\n').map(l => l.split(' ')[0])` against status-class prefixes. This drops URLs, allowing /ok and /moved, /missing and /gone, or same-class unverified URLs to exchange places undetected. `docs/reference/02-cli.md:346–347` promises document order and serial requests; `lib/links.js:737–745,774–779` currently preserves it. The blind spot is in assertions, not a proven production ordering defect.

Audit snapshot: `44e74a32ff6a6b6c946321b3614b1881a2ccedfe`. Commands below ran from the Backslop repository root unless another cwd is stated. On that unchanged snapshot, `node bin/backslop.js gates` exited 0: gates 2/2, tests 1240/1240, failures 0, skipped 0. This is a pre-change baseline; all implementation and post-fix checks below are notRun.

## Work to do

In this existing combined test, retain exit/class/summary and `state.maxInFlight === 1` assertions and additionally compare each result row's full URL with paths plus RESET. Check request order through existing `seen`, accounting for redirect /moved -> /ok. RESET currently destroys its socket before seen.push, so do not require a nonexistent seen entry. Preserve single-URL parameterized tests, JSON ordering and dedup tests: they cover different boundaries and do not check same-class URL order.

## Out of scope

No production behavior changes, increased timeouts, fixed sleeps, shared ports or deletions of useful surrounding cases.

## Evidence

A network-free in-memory probe executed with `node --input-type=module` from stdin (exit 0, 5 assertions) built output for this order:

```js
[['ok',200,'/moved'],['ok',200,'/ok'],['dead',410,'/gone'],['dead',404,'/missing'],['unverified',500,'/broken'],['unverified',429,'/limited'],['unverified',403,'/forbidden'],['unverified','UND_ERR_SOCKET','/reset']]
```

It appended the unchanged summary `links: 8 urls, 2 dead, 4 unverified`, set maxInFlight to 1, and confirmed that existing class/summary/concurrency assertions accept these three same-class inversions. It then asserted that the row URL sequence differs from `['/ok','/moved','/missing','/gone','/forbidden','/limited','/broken','/reset']`; a full-URL `deepEqual` correctly throws ERR_ASSERTION (caught by assert.throws). This was an assertion-sensitivity demonstration, not a failed product test.
