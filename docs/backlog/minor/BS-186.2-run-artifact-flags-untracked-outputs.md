# BS-186.2 · Gate 15 run-artifact class flags documented output and config locations that are untracked by design

- **Scope:** [03. Lint gates](../../reference/03-lint.md) § Documentation without the tracker
- **Created:** 2026-10-02
- **Parent:** BS-186
- **Cost:** major (hypothesis)

## Evidence

Finding discovered while working on BS-186.

Evidence: Hypothesis, not measured on a consumer project. Class 4 judges any documented path ending in .json, .jsonl, .txt or .log that holds a slash and names no tracked file. At bf64440 it reported 8 errors in this repository, all harness config locations and none a run capture: docs/GLOSSARY.md:57 and docs/reference/01-layout.md:304 named .claude/settings.json, .cursor/hooks.json and .codex/hooks.json; 01-layout.md:315 named .codex/hooks.json and .cursor/hooks.json (this branch rewrote them as <project>/.claude/settings.json, which the placeholder skip accepts). The same rule fires on documented output paths that are ignored by design: on 4d56943, a fresh init --lang en project with one committed docs/note.md naming coverage/coverage-final.json, logs/app.log, dist/stats.json and .vscode/settings.json in code spans gave lint exit 1 with 4 run-artifact errors, one per path. The hint to write the measurement does not fit such paths, and the check cannot be switched off (no baseline, strict for every project), so a consumer that documents them turns red on upgrade. Open: an exemption rule (promptobus kept a list of product locations) or the placeholder spelling as the documented cure, decided before release.
