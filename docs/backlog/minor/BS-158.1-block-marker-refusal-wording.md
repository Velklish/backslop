# BS-158.1 · Block-value marker refusal says block bounds are found in raw text

- **Scope:** [01. Layout](../../reference/01-layout.md) § Values that land in the block
- **Created:** 2026-09-29
- **Parent:** BS-158
- **Cost:** minor

## Evidence

Finding discovered while working on BS-158.

Evidence: lib/config.js validateBlockValue refuses a backslop:start/end marker with the text 'it sits inside the block, and the block bounds are found in raw text' (RU: 'границы блока ищутся по сырому тексту'), but init reads the AGENTS.md block with readManaged (lib/init.js, the loop over text.split('\n')), which counts a marker only when line.trim() equals it; block values are single-line, so a marker inside a value cannot be read as a bound. The refusal is right, its reason is stale. Verified by reading the code at ca6b511; not reproduced by a run, because validateBlockValue refuses the value before init writes it.
