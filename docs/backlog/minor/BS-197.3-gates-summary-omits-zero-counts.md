# BS-197.3 · gates-summary-omits-zero-counts

- **Scope:** [02. CLI](../../reference/02-cli.md) § gates
- **Created:** 2026-10-01
- **Parent:** BS-197
- **Cost:** minor

## Evidence

Finding discovered while working on BS-197.

Evidence: backslop-task step 'Report' on main (templates/en/skills/backslop-task/SKILL.md, rendered at cb3bb26) says to give 'not run N' and 'out of scope K' as two numbers and to take them from the summary line of gates or its --json; lib/gates.js on cb3bb26 builds the summary tail only when non-zero ('const tail = skipped ? ... : ""' and 'const why = outOfScope ? ... : ""'), so a run with nothing skipped prints only 'gates 2, green 2'. In the BS-197 runs, reports wrote 'not run 0 (out of scope 0)' that the tool never printed (graders flagged it in eval task-gates-base-committed round 1, new version, prompt "I'm the worker on APP-1 (branch app-1-words, everything is committed). Before I send my result to the orchestrator, run the project gates and give me the exact gate line for my report."; and in eval task-take-first round 3, both versions, prompt "hey, can you grab whatever's at the top of the backlog queue and get it done? I'll review the diff myself before anything gets closed out, so take it as far as it can go before that."); the value was right, but derived, not read. The skill already allows --json, which always carries skipped and outOfScope (lib/gates.js, the printJson call in run). Fix either side: print both numbers in the summary always, require --json for these two numbers, or state in the skill that an absent tail means zero.
