# BS-65.1 · Непечатаемый байт в исходнике не краснит ни один гейт, а греп по файлу молчит

- **Область:** [02-cli](../../reference/02-cli.md)
- **Создана:** 2026-09-22
- **Родитель:** BS-65
- **Цена:** minor

## Улика

Находка при работе над BS-65. В `lib/merge-changelog.js` уехали настоящие байты NUL (`0x00`) и SOH (`0x01`) — разделители ключей, написанные байтами вместо escape-последовательностей. Исходник стал бинарным для всего, что читает файл текстом.

Гейты этого не заметили. На коммите 2f037e8, где байты лежали в файле:

```
$ node bin/backslop.js gates --require-clean
✔ node bin/backslop.js lint — код 0
✔ npm test — код 0, tests 286 / pass 286 / fail 0
✔ гейтов 2, зелёных 2
  дерево: 2f037e86c9a3d4ddec1d7b03c766d4d89ef61a16, чисто

$ file lib/merge-changelog.js
lib/merge-changelog.js: data

$ grep -n 'HEADING' lib/merge-changelog.js
$ echo $?
1
```

Слово `HEADING` в том файле встречается трижды — `grep` с `LC_ALL=C` и флагом `-a` находит все три строки (19, 82, 152). Без флага он считает файл бинарным и молчит. Молчание грепа неотличимо от «такого в коде нет».

После починки (ae159d8, байты записаны escape-последовательностями, а не собой): `file` → `Java source, Unicode text, UTF-8 text`, `grep -n 'HEADING'` отдаёт три строки.

Цена — `minor`: код работал, тесты были зелёные, ничего не ломалось. Ломалась только находимость файла грепом, а поиск по коду в этом репозитории делают агенты грепом.

## Что сделать

Решить, нужен ли гейту `lint` отбой на непечатаемый байт в отслеживаемых текстовых файлах, и какой ценой обходов. Предположение, не проверено: дешёвая форма — проверка байтов `< 0x09` в `lib/**`, `bin/**`, `test/**` и `templates/**`; дорогая часть — список исключений для файлов, где такой байт законен.
