# BS-247.16 · Align the localization ADR with same-version migration of a previous complete CLI render

- **Scope:** [02. CLI](../../reference/02-cli.md)
- **Created:** 2026-10-22
- **Parent:** BS-247
- **Cost:** minor

## Context

The localization ADR excludes a supported same-version redraw case: an otherwise complete owned render containing one valid previous CLI command. ADR-048 and the implementation already support that case.

Evidence was inspected at source HEAD `44e74a32ff6a6b6c946321b3614b1881a2ccedfe`.

## Evidence

- `docs/adr/adr-051-localization.md:22`: "at the tool's own version only a file equal, pin aside, to the render of the other language or of the same one is redrawn".
- `lib/migrate.js:176-177` accepts `sameCliRender(cfg, ...)` and `sameCliRender(other, ...)` in addition to `samePinned`.
- `lib/migrate.js:217-234` matches the complete render using one valid previous `cli` across all command slots.
- `docs/adr/adr-048-version-pin-upgrade-migrate.md:31` already describes whole-command changes, including a pinned npx command changing to `npx --no-install backslop`, without a version bump.
- `test/migrate-cli.test.mjs:16` defines the same-version CLI-change scenario; `:43-50` checks four owned outputs, and `:53` retains the `0.20.0` stamp. An audit fixture dry-run using complete old renders listed all four paths, exit 0, and left their bytes unchanged.

The later CLI-change rule was not propagated to the restrictive "only" sentence in ADR-051.

## Work to do

1. Amend `docs/adr/adr-051-localization.md:22` so its same-version rule includes a complete render with one valid previous CLI.
2. Link to ADR-048 for the full rule instead of duplicating the migration algorithm. Point to the canonical owned set if ROLES and the journal header need clarification.
3. Add a narrow documentation guard in existing `test/doc-facts.test.mjs`, or an existing live-quote mechanism, that rejects the old pin-only restriction and protects the same-version previous-CLI-render rule.

Acceptance: ADR-051 no longer excludes changes accepted by `sameCliRender`; a CLI change does not imply a version bump; arbitrary local edits still do not qualify as untouched renders. The targeted documentation guard fails with the old pin-only sentence and passes with the corrected previous-CLI-render rule.

## Out of scope

Do not change migration behavior, loosen `validateBlockValue` or full-render matching, redraw committed approval prose or journal entries, or overwrite arbitrary manual edits.
