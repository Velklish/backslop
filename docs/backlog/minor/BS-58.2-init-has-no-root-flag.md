# BS-58.2 · init берёт корень из cwd — флага рабочего каталога у команды нет

- **Область:** [02. Команды](../../reference/02-cli.md) § `init`
- **Создана:** 2026-09-22
- **Родитель:** BS-58.1
- **Цена:** minor

## Улика

Находка при работе над BS-58.1: проверка карточки просит поднять стенд и прогнать на нём
`init --tools claude` с объявленной пробой и без неё. Корень проекта `init` берёт из cwd, и
флага рабочего каталога у него нет — `grep -n "root\|dir" bin/backslop.js` даёт `--dir`, но
это каталог документации внутри проекта, а не корень.

Цена находки: агент, поднимающий стенд из корня репозитория инструмента, правит сам
репозиторий. `node bin/backslop.js init --tools claude` в корне self-host отработал с кодом 0
и оставил `tools: ["claude"]` в `backslop.json`, дописанный блок в `.gitignore`, созданные
`CLAUDE.md` и `.claude/skills/`. Откат ручной: `git checkout -- .gitignore backslop.json`,
`rm -rf .claude CLAUDE.md`.

Обходится вызовом с явным cwd — `spawnSync(node, [bin, 'init', …], { cwd: стенд })`, как это
делают тесты через `cli()` из `test/helpers.mjs`. Остальные команды берут корень так же, так
что предмет не в `init`, а в отсутствии общего флага корня у CLI.

Предположение о лечении, не проверено: сквозной `--root <путь>` у всех команд, либо отказ
`init --tools`, когда cwd — корень самого backslop (`package.json` с `"name": "backslop"`).
Второе уже, но закрывает ровно наблюдавшийся случай.
