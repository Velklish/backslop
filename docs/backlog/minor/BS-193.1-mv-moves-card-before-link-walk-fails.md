- **Parent:** BS-193
- **Cost:** minor

## Evidence

Finding discovered while working on BS-193.

Evidence: Measured at 0991c03 in a throwaway project without git: card BS-1 in triage/, chmod 000 src/locked (a directory the link walk cannot list); 'mv 1 queue' -> rc=1, stderr '✖ src/locked: каталог не читается (EACCES) …' after the warning 'файл не в индексе git — перенесён без git mv'; a second 'mv 1 queue' then answers 'BS-1 is already in queue/', so the card was renamed and the incoming links were never rewritten (relocateTask in lib/tasks.js renames first, then walks repoMarkdown). Not measured: the same with git mv in a repository, and archive/fold.

Extension, measured at 4d2a254 in a throwaway git project (one queue card, committed; mkdir src/locked; chmod 000 src/locked): 'archive 1' -> rc=1, stderr '✖ src/locked: the directory is not readable (EACCES) — links in it cannot be updated; …'; the card is already in docs/archive/BS-1-a/ and queue/ is empty; a rerun says 'BS-1 is already archived'. Read, not measured: fold removes the task directories and appends the journal line before rewriteLinks walks (lib/fold.js, removeDirs and the appendLogLines write come before the rewriteLinks call), so a failed walk leaves a folded journal and no rewritten links. The wording 'links in it cannot be updated' (wordUnreadable in the repoMarkdown walk, lib/mdwalk.js) misstates the outcome for all three commands: the card has already moved and no incoming link was rewritten. A fix has to walk (or check readability) before the move, or word what state the tree is left in.
