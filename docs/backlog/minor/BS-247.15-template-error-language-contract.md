# BS-247.15 · Document the selected language and English default of missing-template-key errors

- **Scope:** [06. Module map](../../reference/06-module-map.md)
- **Created:** 2026-10-22
- **Parent:** BS-247
- **Cost:** minor

## Context

The template module recipe says its missing-key Error is always Russian, while rendering selects the supplied language and defaults to English. The old statement can cause callers or tests to expect the wrong diagnostic language.

Evidence was inspected at source HEAD `44e74a32ff6a6b6c946321b3614b1881a2ccedfe`.

## Evidence

- `docs/reference/06-module-map.md:174`: "printed in Russian in every project".
- `lib/templates.js:48` declares `export function renderTemplate(rel, vars, lang = 'en')`.
- At `lib/templates.js:52`, the missing-key branch throws an `Error` using `msg(lang, ...)`; `renderProjectTemplate` passes `cfg.lang` at `:61`.
- The audit called `renderTemplate('en/agents-probe.md', {})` and asserted the English message `en/agents-probe.md: placeholder {{probe}} is given no key probe`, with no Cyrillic characters; the bounded probe exited 0.

The prose retained an earlier internal-error language contract.

## Work to do

1. Update `docs/reference/06-module-map.md:174` to describe the passed language and English default accurately.
2. Retain the distinction between an ordinary programming `Error` and a user-facing `CliError`.
3. Use a narrow existing documentation guard to reject the old "Russian in every project" assertion.

Acceptance: the page agrees with `lang = 'en'` and with project rendering through `cfg.lang`; an old-text regression is caught without changing rendering behavior.

## Out of scope

Do not alter language selection to match the obsolete prose. Preserve missing-key validation, frontmatter JSON escaping and the guarantee that unresolved literal placeholders do not leak into successful output.
