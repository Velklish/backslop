# BS-178.1 · Lint rejects a percent-encoded hash in an existing filename

- **Scope:** [Link rule](../../reference/03-lint.md#link-rule)
- **Created:** 2026-10-03
- **Parent:** BS-178
- **Cost:** minor

## Context

Found during BS-178 (third round of edge-case correctness testing).

Reproduced by the finder 2/2 in fresh projects; blind reproduction from this card's text alone by an independent verifier (worker:v178, claude-sonnet-5-5, 2026-10-03): reproduced 2/2 (lint exit 1, broken link topic%23one.md#heading).

## Evidence

Finding discovered while working on BS-178.

Evidence: lib/links.js:453; node <worktree>/bin/backslop.js lint reports broken link topic%23one.md#heading, exit 1, although docs/topic#one.md exists and contains the heading. Reproduced twice in fresh projects with repro/encoded-reserved.sh; outputs: repro/evidence/encoded-reserved-1.txt and encoded-reserved-2.txt. Counter-argument: decodeURI deliberately preserves URI delimiters, and BS-89 selected that function. Checked docs/reference/03-lint.md:41 and the completed card: the target is already separated from query/fragment and is promised decoded, with no reserved-filename exception. The preserved %23 is therefore looked up as a literal percent sign. No open duplicate; BS-89 fixed other encodings and is related, not evidence that this case previously passed. Proposed fix: decode escaped filename characters after splitting the suffix, and keep query/anchor handling separate. Include `respell`, `rewriteIncomingLinks` and `rewriteMovedLinks` in the change: `encodeURI` leaves a literal hash unchanged, so changing only the normalizer could rewrite an encoded filename into a fragment. Preserve encoded filename characters on both incoming and outgoing rewrites. Add regression checks for `mv`/`archive` of a card whose outgoing link names a file containing a hash, and for incoming-link rewrites when the moved file path contains a hash; the task slug itself must still obey the existing slug grammar.

### Self-contained reproduction

Run this POSIX shell snippet with Node and git installed. Export BACKSLOP_SOURCE as the absolute path to a backslop checkout. It builds a fresh project under TMPDIR, or /tmp when unset; no previous script or fixture is needed.

````sh
#!/bin/sh
set -eu
BS_REPRO_CLI="${BACKSLOP_SOURCE:?set BACKSLOP_SOURCE to a backslop checkout}/bin/backslop.js"
BS_REPRO_ROOT=$(mktemp -d "${TMPDIR:-/tmp}/bs-card.XXXXXX")
export GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1
export GIT_AUTHOR_NAME=QA GIT_AUTHOR_EMAIL=qa@example.invalid
export GIT_COMMITTER_NAME=QA GIT_COMMITTER_EMAIL=qa@example.invalid
git init -q -b main "$BS_REPRO_ROOT"
bs() { (cd "$BS_REPRO_ROOT" && node "$BS_REPRO_CLI" "$@"); }
bs init --lang en --tools none --hooks none --cli "node $BS_REPRO_CLI"
printf '# Heading\n' > "$BS_REPRO_ROOT/docs/topic#one.md"
printf '[existing file](topic%%23one.md#heading)\n' > "$BS_REPRO_ROOT/docs/links.md"
set +e
set -x
bs lint
BS_REPRO_RC=$?
printf 'lint exit=%s\n' "$BS_REPRO_RC"
````

Expected: lint exits 0 because the filename exists and the fragment names its Heading heading. Actual on the reviewed tree: lint exits 1 and prints `docs/links.md: broken link topic%23one.md#heading (line 1)`, followed by `lint: errors 1`. The literal fixture filename is `docs/topic#one.md`; its entire body is `# Heading` plus a newline.

The saved script and output paths above are relative to the reproduction archive root and are secondary evidence; this card contains the complete fixture and command.
