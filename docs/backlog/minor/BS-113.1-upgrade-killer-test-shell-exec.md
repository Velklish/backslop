# BS-113.1 · The upgrade signal test assumes /bin/sh -c execs its last command

- **Scope:** [02. CLI](../../reference/02-cli.md) § upgrade
- **Created:** 2026-09-26
- **Parent:** BS-113
- **Cost:** minor (hypothesis)

## Evidence

Finding discovered while working on BS-113.

Evidence: Unverified assumption, no Linux run here. test/upgrade.test.mjs 'upgrade: a step killed by a signal names the signal, not an exit code' runs cli 'sh "<tmp>/killer.sh"' whose script is 'kill -KILL $$'. On macOS (/bin/sh = bash 3.2) the outer 'sh -c' execs the inner sh, so spawnSync sees signal SIGKILL and the test passes (c4d5f60, rc=0). A /bin/sh that forks the last command instead (older dash) would see the inner shell die and exit 137 itself: the outcome would read 'code 137' and the assertion on 'killed by signal SIGKILL' would fail. Candidate fix: make the cli itself the killer (cli: 'kill -KILL $$ #') so no inner shell exists.
