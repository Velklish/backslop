## Context

The delayed pipe-read test has a useful local timeout, but its comment calls the desired CLI exit behavior a regression and asserts a specific hang without runtime evidence. The task is a narrow comment correction, not a demonstrated runtime or timeout fix.

Evidence was inspected at source HEAD `44e74a32ff6a6b6c946321b3614b1881a2ccedfe`.

## Evidence

- `test/review.test.mjs:94-95` says a direct test gets no npm timeout and continues: "an `exitCode instead of process.exit` regression (bin/backslop.js) would hang the test, not fail it".
- `bin/backslop.js:111-114` intentionally uses `process.exitCode` so stdout can finish draining through a pipe.
- The test `status --json arrives whole through a pipe that is read late` protects complete output with a delayed reader. An independent read-only review of the test, CLI and package scripts confirmed the inaccurate comment; no hang reproduction was supplied.

Swapping the words `process.exit` and `exitCode` would still retain the unsupported causal hang claim.

```js

```

Acceptance: the comment states only the verifiable reason for a local timeout, does not label `exitCode` a regression and does not assert an unproved hang. The delayed pipe-read regression test remains intact.
