# BS-173.2 · The push --dry-run refusal offers a rerun without deleting the local tag

- **Scope:** [02. CLI](../../reference/02-cli.md) § Release (repository script)
- **Created:** 2026-09-29
- **Parent:** BS-173
- **Cost:** minor

## Evidence

Finding discovered while working on BS-173.

Evidence: Throwaway clone of b82dd2b with a local bare origin and remote.origin.pushurl set to a missing path: npm run release -- 0.13.0 --no-publish gave rc=1 with 'next: устрани отказ push или откати тег — git tag -d v0.13.0 — и повтори release' (scripts/release.mjs, the push --dry-run catch). After the push was fixed with HEAD unchanged (pushurl unset), the rerun without git tag -d gave rc=1 'release: локальный тег v0.13.0 уже существует'. After git tag -d, the rerun gave rc=0. The 'or' in next: presents fixing the push alone as enough, but a rerun always needs the tag deleted first.
