# BS-186.3 · Gate 15 reads a released versioned top CHANGELOG section as unreleased when the clone has no matching tag

- **Order:** 1075
- **Scope:** [03. Lint gates](../../reference/03-lint.md) § Documentation without the tracker
- **Created:** 2026-10-02
- **Dependencies:** none

## Context

Finding discovered while working on BS-186.
Evidence: gate 15 finds the unreleased CHANGELOG section by the rule of `merge-changelog`: with no unversioned section, the versioned top section is unreleased while `git tag --list` has neither `vX.Y.Z` nor `X.Y.Z` for it (`unreleasedIndex` and `taggedVersions` in `lib/changelog-format.js` at 4d56943). Measured on 4d56943: the test `lint: 15. a versioned top CHANGELOG section without its tag is unreleased and goes to gate 15` in `test/lint.test.mjs` passes, a top section `## v0.2.0 — 2026-10-01` with an unknown task id and no tag gives a gate 15 task-id error, and the same tree with `git tag v0.2.0` gives the gate 6 error instead. Assumption, not measured: a CI checkout that fetches no tags (a depth-1 clone) or a project that tags in another scheme (`release-1.2.0`, `pkg@1.2.0`) has no such tag, so a released top section that names task ids turns gate 15 red there while it is green on a clone with tags; under a foreign tag scheme it stays red. The card prescribes the `merge-changelog` rule, so the rule was not changed.
Quote a file inside a “<!-- quote:path --> … <!-- /quote -->” block rather than by line number: numbers drift silently, the block is guarded by lint. If unverified, state it as an assumption.

## Owner decision

Owner decision (2026-10-02): gate 15 treats only the section without a version (`## Unreleased`) as unreleased. A versioned top section is released, whatever tags the clone has. It goes before the release v0.14.0.

Consequence: both cases of the Evidence, a clone without tags and a foreign tag scheme, no longer reach gate 15. Between `release --bump` and the tag the renamed section is no longer read by gate 15; its text was checked while it was `## Unreleased`. Gate 15 first ships in v0.14.0.

## Work to do

- `unreleasedSpan` in `lib/lint.js`: the unreleased section of gate 15 is the first `## ` section whose title does not start with a version, and none when every section is versioned. Gate 15 no longer calls `taggedVersions`, so it never runs `git tag --list`.
- `docs/reference/03-lint.md`: § Documentation without the tracker (the bullet "The set") and the implementation note on gate 15 (the bullet that names `unreleasedIndex` and `taggedVersions`) state the new rule and no longer say that gate 15 shares the unreleased-section rule with `merge-changelog`.
- `CHANGELOG.md`: the Unreleased entry of gate 15 names the unreleased section as the one without a version.
- Keep the rule of `merge-changelog` and `unreleasedIndex` as they are.

## Out of scope

- The unreleased-section rule of `merge-changelog` itself.

## Verification

- A probe in `test/lint.test.mjs` for the chosen rule: a repository without tags whose top section is versioned (`## v0.2.0 — 2026-10-01`) and names an unknown task id gives the gate 6 error, not a gate 15 error; the same tree with `## Unreleased` as the title gives the gate 15 error. The test `lint: 15. a versioned top CHANGELOG section without its tag is unreleased and goes to gate 15` goes away, as its premise is reversed; the case with a tag keeps its verdict.
- A second case in the same file: a versioned top section above an unversioned one, with the task id in the unversioned one, still gives the gate 15 error.
- A check that fails on the old text: the probe above turns red against the old `unreleasedSpan`, and a `quote:` block or a test holds the new sentence of `docs/reference/03-lint.md`.
