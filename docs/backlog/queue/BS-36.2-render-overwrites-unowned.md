# BS-36.2 · `renderAdapters` перезаписывает чужой файл без маркера на пути owned output — предикат владения выровнен только на снятии

- **Порядок:** 50
- **Область:** `lib/adapters.js`, `docs/adr/adr-006-adapter-ownership.md`, [01-layout](../../reference/01-layout.md)
- **Создана:** 2026-09-09
- **Зависимости:** нет

## Контекст

Находка при работе над BS-36. Та задача свела **снятие** adapter'а к предикату `isOwnedAdapterFile`: чужой файл без маркера на пути текущего шаблона больше не стирается молча, а называется предупреждением `init` (`lib/adapters.js:181-190`). Запись осталась прежней.

`renderAdapters` для выбранного adapter'а пишет каждый файл шаблона безусловно: `lib/adapters.js:107` — `write(root, adapterRel(tool, rel), markGenerated(text), cfg.lang)`. `write` (`lib/adapters.js:59-64`) проверяет только путь (`ownedPath`: выход за корень и symlink) и делает `writeFileSync` поверх того, что лежало. Владение содержимым не читается — файл без маркера `<!-- backslop:generated -->` по пути owned output перезаписывается без предупреждения и без следа.

Получается несимметрично: тот же файл, который при `init --tools none` теперь сохраняется и называется вслух, при `init --tools claude` затирается молча.

ADR-006 («Decision», «Consequences») говорит о владении применительно к снятию — «Снятие adapter удаляет только backslop-owned пути»; про запись поверх чужого файла на owned-пути там ничего нет, то есть контракта на этот случай сегодня просто не существует.

Улик реального вреда нет: чтобы файл оказался на пути owned output без маркера, его должен положить человек или чужой генератор — ровно тот сценарий, который BS-36 признала достойным предупреждения на снятии.

## Что сделать

- Решить контракт записи и записать его в ADR (правка ADR-006 не годится — принятый не правится, а заменяется):
  - либо запись поверх не-owned файла — отказ или предупреждение с сохранением файла, симметрично снятию;
  - либо перезапись остаётся штатной, и тогда это должно быть сказано вслух в ADR и в `reference/01`, а не подразумеваться.
- По выбранному варианту — правка `renderAdapters`/`write` и проба в `test/init.test.mjs`: файл без маркера на пути owned output ведёт себя при `init --tools <adapter>` так, как решено.

## Не входит

- Само правило владения (маркер плюс legacy-набор) — оно задано ADR-006; предмет только в том, что запись его не спрашивает.
- Поведение снятия — закрыто BS-36.

## Проверки

- Один и тот же чужой файл на owned-пути обрабатывается записью и снятием по одному правилу; расхождение покрыто тестом.
- `npm test` и `node bin/backslop.js lint` зелёные.
