**1. The mechanism as implemented.** verified — read, plus `init` runs in a throwaway project: without `probe` -> rc=0 and the note on stdout; `probe: "npm run probe <!-- backslop:end -->"` -> rc=1 `✖ backslop.json: probe — значение без меток backslop:start и backslop:end: …`. Targeted run `node --test --test-name-pattern='probe|проб' test/config.test.mjs test/init.test.mjs test/brief.test.mjs test/templates.test.mjs; echo rc=$?` -> tests 7, pass 7, `rc=0`.
- `probe` is optional, a non-empty command string, no default; a non-string or whitespace-only value is refused (`validateProbe` lib/config.js:184-190); set by editing backslop.json, no CLI flag; `saveConfig` keeps its position (lib/config.js:232).
- Values substituted into the managed block form one class: `prefix`, `docs`, `cli`, `probe`. `docs`, `cli` and `probe` pass one check, `validateBlockValue` (lib/config.js:144-154), called from `loadConfig` (:119, :121, :189) and for first-run `--dir`/`--cli` before a config exists (lib/init.js:76-77); `prefix` is held by `PREFIX_RE` (lib/config.js:38). The check refuses any line break `\r \n U+2028 U+2029` (lib/config.js:18), a backtick (the templates put the value in a code span) and the substrings `backslop:start`/`backslop:end` (block bounds are found by raw `indexOf`, lib/init.js:292-293). `<` is allowed because the value sits in a code span; test/templates.test.mjs:41 pins that `{{probe}}` is the only code span of templates/agents-probe.md.
- The sentence lives in templates/agents-probe.md (en twin templates/en/agents-probe.md), rendered with the trimmed value into `probeRule = ' ' + rendered.trim()` or `''` without `probe` (lib/init.js:111-113 and lib/brief.js:151-153 at 6f6318e; the BS-118 (`command-module-exports`) card moved the expression into one `probeRule(cfg)` in lib/templates.js). `{{probeRule}}` is substituted in exactly three places in both layers: step 4 of the block (templates/agents-section.md:13), step 4 of the `backslop-task` skill (templates/skills/backslop-task/SKILL.md:26), the probe item of the brief (templates/brief.md:36); keys in `TEMPLATE_KEYS` (lib/templates.js:16, :17, :22). agents-probe.md is never copied into a project (init copies only templates/docs/**, lib/init.js:132-143).
- Without `probe`: `init` prints a note on stdout (lib/init.js:125-129); `brief` writes its note to stderr so stdout stays a clean brief (lib/brief.js:73-77).

**2. Stale or missing statements.** verified — read.
- adr-021:43 quotes the note as "the block has no mutation-probe requirement"; the code prints "neither the block nor the skill carries a mutation-probe requirement" (lib/init.js:127-128) and a live `init` prints the code's text. The new ADR states the rule without quoting the message.
- The value-form check was extended from `probe` to `docs` and `cli` (lib/config.js:119, :121; lib/init.js:76-77; test `config: docs и cli проверяются тем же запретом, что и probe`, test/config.test.mjs:140) but no ADR says so: `grep -rln validateBlockValue docs/adr/` -> no output, rc=1; only docs/reference/01-layout.md:51 and CHANGELOG.md:50 record it. The new ADR defines the class.

**3. Gap: overriding step 4 silently drops the declared probe command from the block.** verified — reproduced. backslop.json with `probe: "npm run probe"` and `agents: { stepOverrides: { "4": "Run gates yourself." } }`: `node <repo>/bin/backslop.js init > out 2>&1; echo rc=$?` -> `rc=0`; `grep -c probe out` -> `0`; AGENTS.md step 4 reads `4. Run gates yourself\.`; `grep -c 'npm run probe' AGENTS.md .claude/skills/backslop-task/SKILL.md` -> `AGENTS.md:0`, `SKILL.md:1`. The override replaces the whole step by design (`applyStepOverrides`, lib/init.js:221-246, applied at :124 after `probeRule` was rendered into the step), but the missing-probe note fires only on `!cfg.probe` (lib/init.js:125), so the loss is silent, against the rule that a dropped requirement is named aloud. No test combines `probe` with an override of step 4. **Decision taken by this card:** `init` prints a note when `probe` is set and `agents.stepOverrides` has key `"4"`. Rejected: only documenting it (the loss stays silent); appending `probeRule` after the override (breaks "an override replaces the whole step").
