# BS-184.1 · mv, archive and fold do not rewrite HTML links and badge destinations

- **Order:** 974
- **Scope:** [02. CLI](../../reference/02-cli.md) § mv
- **Created:** 2026-09-30
- **Dependencies:** none

## Context

Finding discovered while working on BS-184.
Evidence: a fresh `init --lang en --tools none` project, a card from `new alpha --queue`, and `docs/ROADMAP.md` with the line `<a href="backlog/queue/<card>.md">html</a> [![b](../triage/img.png)](backlog/queue/<card>.md) [inline](../triage/backlog/queue/<card>.md)`, committed. `mv 1 active` → rc 0, `task links updated: docs/ROADMAP.md`, and only the inline link now points at `active/`; `lint` → rc 1 with `broken link backlog/queue/<card>.md (line 3)` twice, the HTML link and the badge's outer destination. Cause, read from the code: `mapHrefs` in `lib/links.js` rewrites `LINK_PARTS` (inline links; its `[^\]]*` text stops at the badge's inner image) and `REF_PARTS` declarations only, while the gate parser `linksOf` reads HTML links and badges. Assumption, not run: `archive` and `fold` lose the same links, since `rewriteIncomingLinks` and `rewriteFoldedLinks` go through the same `mapHrefs`. The same holds for a declaration behind `>` or a list marker, which gate 1 now reads: `docs/ROADMAP.md` with `See [quoted][q] and [listed][l].`, `> [q]: backlog/queue/<card>.md` and `- [l]: backlog/queue/<card>.md`, committed; `mv 1 active` → rc 0 and both declarations keep `queue/`; `lint` → rc 1 with `broken link backlog/queue/<card>.md (line 5)` and `(line 7)`. Cause, read from the code: `REF_PARTS` in `mapHrefs` matches a declaration only at `^ {0,3}\[`.
Quote a file inside a “<!-- quote:path --> … <!-- /quote -->” block rather than by line number: numbers drift silently, the block is guarded by lint. If unverified, state it as an assumption.

## Work to do

- The link rewriting of `mv`, `archive` and `fold` (`mapHrefs` in `lib/links.js`, used by `rewriteIncomingLinks`, `rewriteFoldedLinks` and `rewriteMovedLinks`) rewrites every local destination that gate 1 reads through `linksOf`: an HTML `<a href>`, both destinations of a badge, and reference declarations behind `>` or a list marker, besides the inline links and line-start declarations it rewrites today. Each form keeps its syntax; only the path changes, and a fragment stays as it is.
- Take the positions from the parser instead of a second set of patterns, so the forms gate 1 reads and the forms the rewriters update cannot drift apart again.
- Tests: the two repros of the context for `mv`, and the same forms for `archive` (incoming links) and `fold` (links onto the journal line), each with a red probe on the current code.
- Documentation: the fix column of gate 1 in `docs/reference/03-lint.md` stops saying these forms are fixed by hand; the `mv`, `archive` and `fold` sections of `docs/reference/02-cli.md` name the forms they rewrite; a CHANGELOG entry under `## Unreleased`.

## Out of scope

- Named HTML entities in heading slugs (BS-184.2).
