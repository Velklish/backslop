## Work to do

- Create the ADR: `node bin/backslop.js adr version-pin-upgrade-migrate --title "Version pin, upgrade and migrate"`. Context: an untagged `npx github:` spec follows the head of main, so every template change would silently change every project; upgrading must be one deliberate command that also moves every place a project runs the tool from (config, gates, docs, manifests, CI), must leave historical records untouched, and must be performed by the new version because only it knows its file format and templates; rules the AGENTS.md block points to must reach consumers with each upgrade, even when an older version starts it.
- Decision: one bullet per rule of 'Rules to record', checked against current code after the dependency cards; drop any sentence about targets below 0.2.0 or the 0.9.0 migration; state the floating-cli rule as the code implements it after BS-84 (`upgrade-completes-pinned-consumers`).
- Options, one line each: no pin (every project follows main); auto-update on every run (updating becomes a side effect); upgrade performed by the old version (it does not know the new format); a flag on init or an env var to redraw the rules pair (a second, forgettable path); a one-shot versioned migration for the rules pair (later rule changes would not reach consumers).
- Consequences: updating is a deliberate command, never a side effect; the old version runs upgrade, the new one migrate and init; historical records keep their old pins and stay green; a committed local edit to the rules pair is lost on the next upgrade by design — project rules belong outside the pair; running init of a new version without migrate restamps and skips migrations and the rules rewrite, so every recipe runs migrate before init; migrate without the following init can leave links to skeleton files init has not created yet (lint gate 1 reports them); this repository (cli without a release source) is not updated through upgrade, and its rules pair equals the templates by test (test/templates.test.mjs:141); network is needed on every npx run (npm behaviour, cited above).
