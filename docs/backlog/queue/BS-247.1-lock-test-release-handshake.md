# BS-247.1 · Keep the real lock holder alive until the waiter confirms contention

## Context

Evidence: `test/new-lock.test.mjs:112-119` at source `44e74a32ff6a6b6c946321b3614b1881a2ccedfe`; the source snapshot and recorded checks below establish the audit claim. Follow the repository verification protocol before implementation.

Audit finding PQA-001. `test/new-lock.test.mjs:95–105` starts a child that calls `withNumberingLock`, writes `held\n`, then waits only `holdMs` using `Atomics.wait`. At `:112–119` the parent calls `holder(f.root, 500)`, awaits `h.held`, asserts `existsSync(f.lockPath)` with message `the holder owns the lock`, and launches the waiter CLI. Production releases the lock in `finally` (`lib/lock.js:141–148`). A parent continuation delayed over 500 ms can resume after the child releases a correctly held lock. Another allowed interleaving lets the test pass without the waiter ever meeting contention. This is a confirmed unsafe synchronization protocol, not an observed natural flake or measured CI flake rate.

Audit snapshot: `44e74a32ff6a6b6c946321b3614b1881a2ccedfe`. Commands below ran from the Backslop repository root unless another cwd is stated. On that unchanged snapshot, `node bin/backslop.js gates` exited 0: gates 2/2, tests 1240/1240, failures 0, skipped 0. This is a pre-change baseline; all implementation and post-fix checks below are notRun.

## Work to do

- Change only this test's process fixture to retain the lock until an explicit release command from the parent, rather than a time budget. A child can synchronously await a byte on stdin inside `withNumberingLock`.
- After receiving `held`, start the waiter and obtain a separate marker that it encountered contention before releasing the holder. An existing `lockIo.sleep` seam in a test subprocess wrapper can emit that marker on its first sleep and then delegate to the original sleep; no production flag is needed.
- Preserve the real subprocess boundary, next number `BS-2`, successful exit, and removed lock. Fake-clock unit coverage does not replace this integration test.
- In `finally`, terminate and await every child before fixture cleanup. Preserve the adjacent killed-holder scenario (`:125–143`): the lock must exist at the moment SIGKILL is sent.

## Out of scope

Do not increase a timeout as the fix, change lock allocation semantics, or report the documented over-one-minute holder/takeover limit in ADR-050 as a newly found race. Do not add a stress benchmark or production test flag.
