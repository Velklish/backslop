## Context

Five Russian ADRs describe how backslop renders its skills into harness directories: docs/adr/adr-006-adapter-ownership.md, adr-008-legacy-claude-adapter.md, adr-012-owned-outputs-gitignore.md, adr-015-adapter-write-preserves-foreign.md and adr-016-selected-adapter-roots-symlink.md. They carry task numbers, consumer measurements and edit notes, and three sentences no longer match the code. This card writes one English ADR with the rules as the code implements them, deletes the five files and removes every link to them.

Line numbers below are at base commit 6f6318e (v0.11.0), where `npm test` passes 450 tests and `node bin/backslop.js lint` exits 0. The cards named under Dependencies change some of the cited code; read the code on the commit you start from and cite file:line from that commit, not from this card.

Dependencies change this topic: the BS-107 (`marker-only-adapter-ownership`) card deletes the legacy path set (lib/adapter-ownership.js:6-14, :34-36) and the tools inference for a config without `tools` (lib/config.js:103-108); the BS-96 (`fs-shape-refusals-not-stacks`) card makes cleanup skip an unselected adapter whose candidate path has a symlink component or whose root is not a directory. The ADR records the rules after both.

**Rules to record** (verified — each read at 6f6318e against the cited lines; the behaviour of init and lint was reproduced in throwaway projects):
- Registry: exactly three adapters with one root each — claude `.claude/skills`, cursor `.cursor/rules`, codex `.agents/skills`; every other module derives ids and roots from it (lib/adapters-registry.js:4-17).
- Selection: `tools` in backslop.json is a list of unique registry ids, default `[]` (lib/config.js:33, :126-127). `init --tools a,b` sets it, `--tools none` empties it, unknown/empty/duplicate ids are refused, stored order is registry order (lib/init.js:203-211); on an existing config the flag replaces the field (lib/init.js:63).
- Rendering: for each selected adapter every file of templates/skills/** (per lang) is written under the adapter root (lib/adapter-ownership.js:28-32, lib/adapters.js:100-126); Cursor turns `<skill>/SKILL.md` into `<skill>.mdc` with frontmatter `description` + `alwaysApply: false` and rewrites relative links (lib/adapter-ownership.js:20-26, lib/adapters.js:62-96). Each rendered file gets `<!-- backslop:generated -->` as its first line or right after the YAML frontmatter (lib/adapter-ownership.js:42-46).
- Ownership predicate (after the BS-107 (`marker-only-adapter-ownership`) card): a file is owned when it lies under an adapter root and is a regular file whose first line, after optional frontmatter, is the marker, CRLF tolerated (lib/adapter-ownership.js:18, :38-40, :48-59). A quoted marker in the body does not count (test/adapter-ownership.test.mjs:27).
- Claude stub: with claude selected and no CLAUDE.md, init writes `@AGENTS.md\n`; a CLAUDE.md that links to AGENTS.md or contains `@AGENTS.md` is accepted; any other file is kept and init warns (lib/adapters.js:237-262). The AGENTS.md block calls the skills only when an adapter is selected (templates/en/agents-section.md:6).
- Write: a non-owned file at an output path is left as is and named in an init warning (lib/adapters.js:117-120, :127-129, lib/init.js:193); a directory at the output path, or a file on a path component, is a refusal (lib/adapters.js:114-116, :55-58); lint reports the same not-a-file case (lib/lint.js:231-233) and a foreign file without marker (lib/lint.js:238-242).
- Removal: candidates are marked files under the root and the current template paths (lib/adapters.js:189-201); the selected adapter keeps its current paths (:213); a non-owned candidate is kept and named (:218-221, :231-234); an owned one is unlinked and empty parents pruned (:144-152, :222). CLAUDE.md is removed only when claude is not selected and the file equals the stub (:225-230).
- Path safety: a path that escapes the project or has a symlink component is refused before ownership is read (lib/adapters.js:22-31, :110, :136, :217). Roots of selected adapters are checked before the first write of init, and the refusal names the remedy (lib/adapters.js:35-46, lib/init.js:96). An unselected adapter whose root has a symlink component is skipped entirely (lib/adapters.js:210).
- Self-host: in the backslop repository itself init with a non-empty `--tools` is refused (lib/init.js:86-92); the repo keeps `tools: []` and a hand-written .gitignore in the same glob form (.gitignore:7-11).
- Link walks: every command that rewrites links (mv and archive via lib/tasks.js:604, fold via lib/fold.js:325) walks `repoMarkdown`, which excludes owned adapter files and stops at a harness root with a symlink component (lib/mdwalk.js:80-94). Lint gate 1 reads only docs/** and root *.md (lib/lint.js:199-209); adapter outputs have their own lint pass (lib/lint.js:221-252).
- Ignore block: init keeps in .gitignore a block between `# backslop:start` and `# backslop:end` with `<adapter root>/backslop-*` per selected adapter and `/CLAUDE.md` only when CLAUDE.md is exactly the stub (lib/init.js:18-19, :248-257); the block is created only when there is something to ignore or a block exists, text outside the markers is kept, an unpaired marker is a refusal (lib/init.js:259-271, :286-303). Lint does not check the git index.

## Work to do

- Create the ADR: `node bin/backslop.js adr harness-adapters --title "Harness adapters: selection, ownership and path safety of generated outputs"`. Context: skills ship as templates and are rendered into the directories each harness reads; harness directories also hold user files and other tools' skills, so the tool renders only what the project selected, recognises what it owns, never overwrites or deletes what it does not own and never follows a link out of the project; rendered files are derived, so committing them or keeping a hand-written ignore list per project drifts.
- Decision: one bullet per rule of the 'Rules to record' list above, checked against the current code; the ownership predicate is marker-only and a config without `tools` reads as `[]` (after the BS-107 (`marker-only-adapter-ownership`) card); state the unselected-adapter rule as 'owned outputs of an unselected adapter are removed unless its root path has a symlink component, then the adapter is skipped entirely'.
- Options, one line each: render all three adapters always (a project that does not use a harness gets its directory); accept a link whose realpath stays inside the project (a second ownership criterion); check symlinks on all three roots (a project with a shared harness directory could never run init); commit rendered files (a second copy that drifts); a hand-written ignore list per project (drifts).
