# BS-23 · Цитата живого файла в карточке бэклога ничем не сторожится и рвётся молча — `lint` проверяет существование ссылки, но не содержимое цитаты

- **Порядок:** 110
- **Область:** `lib/lint.js`, `lib/mdwalk.js`, `lib/links.js`, `templates/task.md`, `templates/en/task.md`, [reference/03](../../reference/03-lint.md)
- **Создана:** 2026-09-06
- **Зависимости:** нет

## Контекст

Два подтверждённых сегодня живых случая в очереди ati-agents. (1) docs/backlog/queue/BL-531-reference-verdict-count-drifted.md:7 цитирует: «`docs/reference/10-validation.md` на `main` утверждает: «Восемь файлов и 295 вердиктов»» и предписывает повторить замер в `cli/packages/promptobus`. Сегодня `grep -rn` по репозиторию (без `.git`/`.claude`) находит эту фразу ровно один раз — в самой карточке; `docs/reference/10-validation.md` этого больше не утверждает (раздел «Набор самого package» теперь говорит: «Набор ядра шины уехал вместе с пакетом `promptobus` в его репозиторий… Число файлов `npm test` механизма от этого не обязано совпасть с прежним 68/68»), а каталога `cli/packages/promptobus` не существует вовсе — пакет переехал в отдельный репозиторий promptobus. Постановка мертва с обеих сторон, и агент, взявший карточку, узнаёт об этом только перечитав два файла. (2) docs/backlog/queue/BL-542.2-golden-tools-fixture-unguarded.md:16-17 цитирует `cli/scripts/release-gates.mjs:56` и `:401`; сегодня те же строки (объявление `GOLDEN_TOOLS` и её чтение) — `:60` и `:478` (подтверждено `grep -n GOLDEN_TOOLS`).

Что уже есть и чего нет: гейт ссылок (`lintLinks`, backslop lib/lint.js:71) проверяет существование файла, на который ведёт ссылка markdown, — не содержимое цитаты и не номер строки внутри. `grep -rn quote lib/ bin/` в backslop пуст — механизма сверки цитаты с текстом файла нет вовсе. Готовая модель для парной разметки (открывающий/закрывающий комментарий) есть в другом репозитории — `CONTRACT_PAIR`/`lintContractQuotes` в ati-agents cli/lib/lint.js:556 и :647, — но оттуда переносим только разбор пары комментариев: там сверка идёт с фиксированным реестром `CONTRACT_VALUES` и порогом `quoteThreshold`, которых у произвольной цитаты файла нет.

## Что сделать

- Девятый гейт `lint`: блок `<!-- quote:<путь> -->…<!-- /quote -->` в markdown, содержимое которого обязано быть подстрокой названного файла (по строкам, с отброшенными ведущими пробелами каждой — иначе переотступ рвёт цитату кода без изменения смысла); файла нет — тот же класс ошибки, что у битой ссылки; текст разошёлся — ошибка с именем файла и первой строкой цитаты.
- Обход `mdwalk` для этого гейта исключает `docs/archive/`: цитата в закрытой задаче — снимок момента, красить её нельзя (то же основание, что уже применено к гейту ссылок).
- Красная проба в test/lint.test.mjs по конвенции проекта.
- templates/task.md и templates/en/task.md: улика с номером строки заменяется цитатой кода, обёрнутой в блок.
- Строка в таблице docs/reference/03-lint.md и запись в CHANGELOG.

## Не входит

- Решение, что именно достойно цитаты, — остаётся автору карточки; гейт сторожит только уже обёрнутое.
- Перенос реестра `CONTRACT_VALUES`/`quoteThreshold` из ati-agents — у произвольной цитаты файла нет фиксированного реестра для сверки, только содержимое самого файла.
- Ретроактивная правка существующих карточек (BL-531, BL-542.2) под новый блок — задача того, кто следующим возьмёт эти карточки.

## Проверки

- Фикстура с блоком `<!-- quote:… -->`, чей текст есть в целевом файле, — `lint` чист; изменение целевого файла (или самой цитаты) красит гейт с именем файла и первой строкой цитаты.
- Блок цитаты внутри `docs/archive/**` не красится никогда, даже разойдясь с файлом.
- `node bin/backslop.js lint` на самом репозитории backslop остаётся зелёным.
