**Rules to record** (verified — read at 6f6318e; single and bulk fold were run live in throwaway projects):
- Folding is a separate command; `archive N` is unchanged and refuses on an archived or folded task, pointing to fold (lib/archive.js:23-24, :42-44). There is no unfold command (`grep -rn unfold lib bin` → only a message).
- A folded task is one line in `<docs>/archive/LOG.md`: `- <a id="<lowercase id>"></a>`<id>-<slug>` · <date> · <outcome> · `<rev10>`|— · <title>` (lib/log.js:15-17, :23-31, :56-65); lines are appended, a blank line separates prose from the first entry (lib/log.js:202-208). Date = first date of the first paragraph of result.md, else the heading `(… YYYY-MM-DD)`, else the revision commit date, else today (lib/fold.js:202, lib/log.js:144-146). Bulk lines are ordered by date, then number (lib/fold.js:48).
- Directories and journal lines are read together: `scanTasks` adds journal records as archive, folded (lib/tasks.js:162, :168-190); `foreignTaskIds` reads LOG.md of other worktrees and local branches so `new` never reuses a folded number (lib/tasks.js:313-314, :329-330). A batch entry keeps its own line with outcome 'batch <M>' (lib/log.js:83-87, lib/fold.js:222-230, lib/tasks.js:188-189).
- Incoming links to the folded directory, task.md, result.md and minor entry files are rewritten to `LOG.md#<anchor>`; links deeper into the directory are reported, not rewritten (lib/fold.js:212-221, :315-340).
- Body revision = the last commit that touched the directory (`git log -1 -- <dir>/`), accepted only if the directory is clean under `git status --porcelain --untracked-files=all`, task.md, result.md and every minor entry exist in that tree, and each file's `git hash-object` equals its blob id (lib/fold.js:254-277; CRLF over an LF blob is equal, test/fold.test.mjs:498).
- Four reasons for no revision — NO_GIT, DIRTY, ABSENT, DIVERGED (lib/fold.js:249-252). Bulk fold refuses NO_GIT, DIRTY and DIVERGED before any write and drops ABSENT bodies with a stderr note, or carries them into the draft with `--embed-missing` (lib/fold.js:52-61, :181-200, :296-309). Single fold also calls `bodyRev` (lib/fold.js:178), records the revision when the directory is committed, clean and blob-equal, writes `—` for any of the four reasons (:208), and always embeds the body in the draft (:281-291).
- Pre-write refusals: missing task.md or result.md, empty result.md, `[TODO]` left (lib/fold.js:167-171); single fold also refuses a task that is not archived, already folded, or a batch entry (:127-134), and a result.md that names no outcome (:172-174).
- Outcome: the first dictionary word by position in the first paragraph, else the heading note (lib/log.js:124-140, :150-156). Dictionary exactly as `OUTCOME_FORMS` defines it (lib/log.js:71-75): merged (слита / слиянием / merged + into `<prefix>-N`), rejected (отклонена / отклонением / снята с плана / leading bare снята / rejected), completed (выполнена / completed); 'снята с плана' has no English form. One strict predicate with one refusal text serves lint gate 5 and single fold (lib/log.js:110-122, lib/lint.js:431, lib/fold.js:174). Bulk fold also accepts bare закрыта/closed/done or an `Исход:`/`Outcome:` marker as completed (`CLOSED_FORM`, lib/log.js:77-79, :99-106), else writes `—`; live: `**Outcome:** shipped.` → completed. The result.md template states the requirement (templates/result.md:3, templates/en/result.md:3).
- Order of writes: directories removed first (`git rm -r -f` on tracked ones, then leftovers), then the journal appended, then links rewritten (lib/fold.js:70-77, :344-365); `--dry-run` prints the draft and writes nothing (:63-66).
- Draft: stdout carries the commit message draft, diagnostics go to stderr (lib/fold.js:61, :79-91). The single draft subject is `<id>: <title>` (:283), which `show N` uses to find the commit for a `—` line (lib/show.js:30, :87-96). The draft is mandatory only for a `—` line (draftNoteOne, lib/fold.js:95-103); with a revision it calls the body 'a copy' (:284-290). The bulk note has three variants — bodies embedded (commit required), nothing dropped (the draft carries no bodies), some dropped (names the count of `—` lines) (lib/fold.js:106-122).
- `show N` prints the body files from the line's revision (task.md first), else the message of that commit, else refuses; it needs git (lib/show.js:20-68, :73-83).
- Upgrade never folds: the 0.10.0 migration only creates LOG.md from the template (lib/migrate.js:27-38).
- Lint gate 13 has four checks: the line parses, the anchor equals the lowercase id, a `LOG.md#anchor` link from docs/** or root *.md has an entry, the revision is reachable from HEAD — with a warning on a shallow clone, without git or on a git failure (lib/lint.js:443-510; tests test/lint.test.mjs:764, :783, :800, :820).
- Acceptance recipe (templates/skills/backslop-batch/SKILL.md:24, :111 and en twins): single-task acceptance runs archive N, result.md and fold N into the acceptance commit with the draft as message; a track of several tasks leaving as one commit archives only and folds in the next commit, where lines get revisions and no draft is required; a batch folds after its entries.
