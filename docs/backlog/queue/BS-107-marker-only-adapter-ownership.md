# BS-107 · Make adapter ownership marker-only, drop the legacy tools inference, simplify cleanup

- **Order:** 250
- **Scope:** [01. Layout](../../reference/01-layout.md) § What init lays down
- **Created:** 2026-09-25
- **Dependencies:** BS-106, BS-96

## Context

All evidence below was taken at commit 6f6318e (v0.11.0), where `npm test` runs 450 tests (450 pass, rc=0) and `node bin/backslop.js lint` exits 0. "Removal probe" means: the change was applied in a throwaway clone at that commit, then the full suite and lint were run.

Support floor: no consumer runs a version below 0.9.0, so migrations and legacy paths needed only by older versions are dead code. Two legacy mechanisms from before the generated marker existed are dead under that floor.

**1. `LEGACY_ADAPTER_RELS`: unmarked files at 21 adapter paths count as owned.** verified — history, a live repro and a removal probe (every red test is listed below).
- lib/adapter-ownership.js:6 lists `LEGACY_SOURCES` (the canonical skill plus six batch and seed skill files). :34-35 multiplies them over every adapter: `TOOLS.flatMap((id) => LEGACY_SOURCES.map((rel) => adapterRel(id, rel)))`. `node -e "import('./lib/adapter-ownership.js').then(m=>{const a=[...m.LEGACY_ADAPTER_RELS];console.log(a.length,a.filter(r=>!r.startsWith('.claude/')).length)})"` prints `21 14`. :58 is `isOwnedAdapterFile(rel, file) { return LEGACY_ADAPTER_RELS.has(rel) || (isAdapterRel(rel) && hasGeneratedMarker(file)); }`. lib/adapters.js imports the set at :6 and adds every legacy path to the cleanup candidates at :197-199.
- History: `git grep -n -e '\.cursor' -e codex -e "'\.agents'" v0.2.0 -- lib bin` gives rc=1 with no output, and `git show v0.2.0:lib/init.js | grep -n claude` prints `90:  const skillsRoot = path.join(root, '.claude', 'skills');`. The cursor and codex adapters and `GENERATED_MARKER` arrived in the same commit, first tagged v0.3.0 (`git tag --contains 4a5418d --sort=v:refname | head -1` prints `v0.3.0`). So the 14 cursor and codex entries were never written unmarked by any release. The 7 claude entries matter only for installs of v0.2.0 or older, which the 0.9.0 floor excludes.
- Harm today, reproduced live. In a throwaway project after `init --tools none`, run `mkdir -p .cursor/rules; printf 'my own cursor rule, no marker\n' > .cursor/rules/backslop-task.mdc; node <repo>/bin/backslop.js init --tools cursor > init2.out 2>&1; echo rc=$?`. The result is rc=0, and the file now starts with `---` / `description: "Цикл одной задачи бэклога backslop …` / `alwaysApply: false`: the user's content is overwritten. `grep -i marker init2.out` prints nothing, so there is no foreign-file warning. With marker-only ownership, the foreign-file path (`foreign.push(outRel)` at lib/adapters.js:118 on install, `foreign.push(rel)` at :219 on cleanup) takes over.
- Removal probe: dropping the set and the loop turned 6 tests red. Three of them are expected: test/init.test.mjs:589-619, test/init.test.mjs:769-791 and test/init.test.mjs:467-480 (which belongs to part 2). The other three use fixtures that are unmarked files at legacy paths, and pass once the marker is added: test/adapter-ownership.test.mjs:41 (plus :49, where a missing file at a legacy path is no longer owned), test/commands.test.mjs:720 (fixture at :724) and test/mdwalk.test.mjs:15 (fixture at :24). After the removal, the `adapterRootRel` import at lib/adapters.js:8 and the `prefix` local in `cleanupCandidates` (:192) are unused.

**2. Inferring `tools` for a config without the field.** verified — history and a removal probe. lib/config.js:103-108:
```
const legacyTools = raw.tools === undefined
  && existsSync(path.join(root, ...ADAPTER_ROOTS.claude, ...CANONICAL_SKILL.split('/')))
  ? ['claude']
  : base.tools;
```
- `for t in v0.1.0 v0.2.0 v0.3.0 v0.9.0; do git show "$t:lib/config.js" | grep -c tools; done` prints 0, 0, 9 and 9. Since v0.3.0, the `saveConfig` key order includes `tools` (v0.3.0 :129, v0.9.0 :208). init writes `tools` on every run (lib/init.js:81 and :180), and every upgrade runs `<new cli> init` (lib/upgrade.js:163). A fresh init at 6f6318e writes `"tools": []`. So a config stamped 0.9.0 or later by the tool always has `tools`. The inference fires only for a hand-written config, or after `upgrade --pin-only` from a v0.2.0-or-older CLI without the follow-up init.
- Removal probe: replacing `legacyTools` with `base.tools` and dropping the `ADAPTER_ROOTS` and `CANONICAL_SKILL` imports from config.js turned red exactly test/config.test.mjs:15-23 ('legacy Claude output materializes missing tools as claude') and test/init.test.mjs:467-480. Lint stayed at rc=0.

**3. The cleanup path repeats checks already done on the same path** (verified — call sites and a removal probe, 450/450, lint rc=0):
- `removeFile` has one caller, `cleanupAdapters` at lib/adapters.js:222, which runs after `if (!lexists(file)) continue;` (:214) and `ownedPath(root, file, cfg.lang)` (:217). As a result, the ENOENT `return false` at :135 is reachable only in a race, the `if (removeFile(...))` at :222 is always true, and `ownedPath` at :136 repeats :217. `pruneEmpty` walks the ancestors of a file that was just unlinked, so `if (!existsSync(dir)) continue;` (:148) cannot fire, and `ownedPath` on each ancestor (:147) repeats the component check. At :226-228, `!lstatSync(claudeFile).isSymbolicLink() && lstatSync(claudeFile).isFile()` stats the file twice, and `lstat().isFile()` already excludes symlinks. The later `ownedPath` on root/CLAUDE.md checks only the CLAUDE.md component. Applying all of this kept 450/450 and lint rc=0, and left the `lang` parameter of `pruneEmpty` unused.
- **adapters.js: `text === CLAUDE_STUB ||` is redundant.** verified — call sites and a removal probe. `CLAUDE_STUB` is `'@AGENTS.md\n'` (lib/adapters.js:15), so `text === CLAUDE_STUB` implies `text.includes('@AGENTS.md')` in the condition at :253. `CLAUDE_STUB` itself is still used at :227, :242 and lib/init.js:253.

These docs still describe the legacy behaviour: docs/reference/01-layout.md:28 (says owned paths and the legacy set are derived from the registry), :30 and :48 (`tools`: "an old config without the field and with `.claude/skills/backslop-task/SKILL.md` keeps `[\"claude\"]`"); docs/GLOSSARY.md:24 (the owned-output definition includes "a path from the legacy set"); code comments at lib/lint.js:229-230, lib/adapters.js:112-113, lib/adapters-registry.js:19-20 and lib/init.js:179; and the ADRs on adapter ownership, the legacy Claude adapter and foreign files (adr-006, adr-008 and adr-015 at 6f6318e; the BS-144 (`adr-harness-adapters`) card replaces them later).

Record the outcome of each step in the result (reproduced / not reproduced / sanctioned by <file:line>).
- **`hasGeneratedMarker` rejects a BOM-prefixed file or a marker without a trailing newline** — unverified — run the check first. Observed: lib/adapter-ownership.js:18 `GENERATED_AT = /^(?:---\r?\n[\s\S]*?\r?\n---\r?\n)?<!-- backslop:generated -->\r?\n/` is anchored at `^` on `readFileSync(file, 'utf8')`, which keeps U+FEFF; a probe returned `false` for a BOM + marker file, for `isOwnedAdapterFile('.claude/skills/other/SKILL.md', …)`, and for a marker with no trailing newline. At 6f6318e no CLI effect was known, because all seven shipped skill files are owned by path through the legacy list (lib/adapter-ownership.js:6-14); once this card removes that list, every adapter file is owned only through `hasGeneratedMarker`, so the case becomes load-bearing.
