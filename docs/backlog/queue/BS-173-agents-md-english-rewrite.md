## Context

The hand-written part of `AGENTS.md` (the lines above `<!-- backslop:start -->`) is five Russian paragraphs. They mix rules with production artifacts: owner-decision dates, a rejected task described as deferred, rationale narration and a stale debt claim. They restate steps of the managed block, and they miss the invariants a contributor needs. The release procedure is described in two places that disagree. This card rewrites that part as plain English rules and makes it the single owner of the release procedure. The managed block is rendered by `init` from `templates/en/agents-section.md` and is not edited by hand here.

Evidence. Every item is verified at v0.11.0 (commit 6f6318e):

1. **Artifacts in the release paragraph.** verified — `sed -n 13p AGENTS.md`, a grep of `docs/archive/LOG.md` and `ls docs/backlog/deferred/`. `AGENTS.md:13` carries an owner-decision date ("решение владельца 2026-09-24") and the number of the npm-publish task. It says the npm-publish form turns on "when the task returns by its condition", but the journal records that task as rejected ("отклонена"), and `docs/backlog/deferred/` holds only `.gitkeep`. The same kind of note in the comment at `scripts/release.mjs:85` is rewritten by BS-127 (`release-script-messages-windows`).
2. **The release procedure is duplicated, and the copies conflict.** verified — `AGENTS.md:13` and `docs/reference/02-cli.md:45-47` both describe `npm run release -- X.Y.Z --bump` and the preflight chain. `02-cli.md:47` ("default `cli` until the first publication") implies a future npm publish, while `AGENTS.md:13` says publishing is not planned. The code sequence (`scripts/release.mjs:92-126`) is: `npm test`, `npm run lint`, `pack --dry-run`, a dirty-tree check, a local tag, `push --atomic --dry-run`, an optional `npm publish`, then `push --atomic`. This repo's `gates` are exactly lint and `npm test`.
3. **`--bump` refuses a released top section.** verified — at 6f6318e, evidence below. In a clone, `npm run release -- 0.12.0 --bump` gave rc=1 and `release: CHANGELOG.md: верхняя секция «## v0.11.0 — 2026-09-24» уже выпущена — нечего переименовывать в v0.12.0` (`scripts/release.mjs:56`). After an `## Unreleased` heading with one entry was added, the same command gave rc=0 (`«## Unreleased» → «## v0.12.0 — …»`). The concept of an unreleased section is defined at `02-cli.md:28`. The release paragraphs never say to open that section before the bump, or to open it again afterwards.
4. **The claim "all checks before the first write" is false.** verified — `release.mjs:59-63` writes `package.json` and `CHANGELOG.md`, then runs `init`, which can still refuse. The script's own comment at `:60` says so. `02-cli.md:45` claims all checks come before the first write. `init` also re-renders the managed block and the adapters.
5. **Recovery after a failure past the tag is incomplete.** verified — in a clone whose bare origin rejects pushes in `pre-receive`:
   - `node scripts/release.mjs 0.12.0 --no-publish` gave rc=1 with `state: npm publish не запускался (--no-publish); локальный тег v0.12.0 создан; atomic push не подтверждён` and `next: git push --atomic origin main v0.12.0`.
   - A rerun gave rc=1 with `локальный тег v0.12.0 уже существует` (`:96`).
   - The `push --dry-run` failure message (`:113`) gave the command in prose only; BS-127 (`release-script-messages-windows`) added the literal `git tag -d <tag>` to its `next:` line.
   - No doc covers a fix that needs a new commit. In that case the printed `git push` would publish the tag on the stale commit.
6. **Contributor invariants are missing.** verified — at 6f6318e, evidence below. "No dependencies" and the `TEMPLATE_KEYS` registry are already documented (`README.md:9`, `03-lint.md:18`). Two rules are written nowhere:
   - every user-facing message goes through `tr(lang, ru, en)` (`lib/i18n.js:1-3`, used across `lib/`); `test/lint.test.mjs:71-81` asserts that an English project's lint stderr contains no Cyrillic;
   - paths are printed through `toPosix`, and Windows-incompatible tests are skipped with `skip: process.platform === 'win32'` (present in 8 test files).

   `grep -rnE "toPosix|i18n|tr\(lang|bilingual" README.md AGENTS.md docs/reference docs/GLOSSARY.md templates` gave rc=1.
7. **The comment rule carries artifacts.** verified — at 6f6318e, evidence below. `AGENTS.md:11` has "(решение владельца, 2026-09-12)" and the rationale sentence "Причина измеримая, а не стилевая…". Its gate scope is delegated to ADR links, and those links will not survive ADR consolidation.
8. **The debt-snapshot claim is stale.** verified — `cat test/fixtures/comment-sweep-pending.json` printed `{}` at 6f6318e, and the BS-140 (`comment-length-templates-tests`) card removed the list since. `AGENTS.md:11` still said the accumulated debt lives in that snapshot and can only shrink (the BS-150 (`comments-gate-adr`) card removed that sentence).
9. **"The gate holds the rule" overstates the gate.** verified — at 6f6318e, evidence below. `test/comment-length.test.mjs` checks only `LIMIT = 2` and `WIDTH = 100` (`:12-13`). The ban on origin notes in comments is held by the author and the reviewer. Such comments still exist: `grep -rnE '^\s*(//|\*|/\*).*\bBS-[0-9]' lib bin scripts test` gives 29 lines, many of them format examples. The existing minor entry `comment-origin-task-numbers-left` in `docs/backlog/minor/` tracks the real ones.
10. **The branch rule contradicts practice.** verified — at 6f6318e, evidence below. `git log --format=%s v0.10.0..v0.11.0` lists 35 commits, and 23 of them start with a task id. The others are filing commits (`BS: …`) and release commits (`Релиз vX.Y.Z: бамп версии …`), and one task shipped as two commits. `git branch -r` shows only `origin/main`. `AGENTS.md:9` says "no branches", while the managed block lets a worker edit "only its branch or worktree", and `.gitignore` ignores `.claude/worktrees/`.
11. **The hand-written part restates the block.** verified — `AGENTS.md:5` (docs in the same change) and `:9` (one commit per task) restate block steps 3 and 7. `:7` is a real self-host delta (this repo's gates, no `probe` field) and stays.
12. **Dead sentences.** verified — `:13` describes a hypothetical npm-publish mode and gives a rationale ("this is the regular path, not a bypass of the script"). `:5` says editing generated skills is useless, but `tools: []` means none are generated here.

## Work to do

- Rewrite everything above `<!-- backslop:start -->` in English as short headed rule lists; no task numbers, decision dates, owner-decision notes, run ids, rationale narration or ADR citations. Sections: **Repository** (what lives in `bin/`, `lib/`, `templates/`, `test/`, `docs/`; the backlog runs on `node bin/backslop.js`; a pointer to `docs/reference/README.md`; the BS-176 (`orchestrator-contract-reference`) and BS-177 (`lib-module-map-reference`) cards add pointers to their pages).
- **Templates are the source**: process rules change in `templates/skills/**` or `templates/docs/**`, the English twin under `templates/en/` with the same file set; the rendered pair `docs/backlog/README.md` + `docs/archive/README.md` is updated in the same commit from the template of this repo's `lang`; other `docs/` files are project content; `tools: []`, so no adapter outputs exist here (drop the generated-skills sentence, evidence item 12).
- **Contributor invariants** (evidence item 6): Node >= 20 standard library only, no dependencies; every user-facing message via `tr(cfg.lang, ru, en)`, JSON output language-neutral; printed paths via `toPosix`; Windows is supported — a test that cannot run on win32 carries `skip: process.platform === 'win32'` and says why; a new `{{placeholder}}` is declared in `TEMPLATE_KEYS`; new commands, lint gates and migrations are added as the module-map page describes (that card adds the link). **Contract changes** (replaces the `:5` sentence): an ADR is needed when a stable output or field listed in docs/reference/02-cli.md § What is stable changes, or a new machine-readable output is promised as stable; any other command change needs the reference and a CHANGELOG entry (the BS-176 (`orchestrator-contract-reference`) card later points this line at its page).
- **Gates**: keep the `:7` content (`node bin/backslop.js gates` runs lint and `npm test`; confirm a lint gate with a red probe in `test/lint.test.mjs`; no `probe` field — break the code by hand after committing). **Commits and branches** (evidence item 10): `origin` has only `main`, no merge requests; workers may use local branches or worktrees; each task reaches `origin` as one acceptance commit; non-task commits use `BS: …` (filing, owner decisions) or the one release form `Release vX.Y.Z: version bump`. Drop the clauses that restate block steps 3 and 7 (evidence item 11).
- **Comments** (evidence items 7-9): at most two lines and at most 100 code points per line in `lib/`, `test/`, `bin/`, `scripts/`; a nuance that does not fit goes to docs with a short pointer; no origin notes (task numbers, dates, review remarks); `test/comment-length.test.mjs` checks only length and width, origin notes are held by author and reviewer; there is no debt list: every block over the limit fails wherever it is.
- **Release** (single owner; evidence items 2-5): (1) new entries go under an unversioned top heading `## Unreleased`; (2) `npm run release -- X.Y.Z --bump` renames it to `## vX.Y.Z — <date>`, writes `version` in `package.json` and runs `init` for the stamp; it refuses when the top section is already versioned; checks on `package.json` and `CHANGELOG.md` run before writing, `init` runs last — if it refuses, both files stay bumped with the old stamp: `git checkout -- package.json CHANGELOG.md`; (3) review and commit; (4) `npm run release -- X.Y.Z --no-publish` from a clean `main` (version equals the argument, fast-forward from `origin/main`, `npm test`, `npm run lint`, `pack --dry-run` leaves the tree clean, local tag, `push --atomic --dry-run`, atomic push of `main` and the tag); the tool is not published to npm, never run it without `--no-publish`; (5) after a failure past the tag follow the script's `next:` line; if the fix changes HEAD: `git tag -d vX.Y.Z`, fix, rerun; (6) open a new `## Unreleased` before the next entry.
- Replace the release paragraphs in `docs/reference/02-cli.md:45-47` with one line pointing to `AGENTS.md` § Release (drop the "until the first publication" wording); the BS-160 (`cli-reference-english`) card already replaced them with a link, so check the wording only.
