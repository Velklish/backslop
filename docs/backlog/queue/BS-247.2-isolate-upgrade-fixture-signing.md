## Context

Evidence: `test/upgrade.test.mjs:31-43` at source `44e74a32ff6a6b6c946321b3614b1881a2ccedfe`; the source snapshot and recorded checks below establish the audit claim. Follow the repository verification protocol before implementation.

Audit finding PQA-002. Three constructors in `test/upgrade.test.mjs` omit local `commit.gpgsign=false`: `releasesRepo` (`:31–43`), relative-source fixture (`:268–271`), and `switchedToEn` (`:775–783`). The first two discard Git command results. With global commit signing enabled and no available signing program, they silently fail commit/tag and produce misleading release assertions; the third reports the Git failure through checked `gitAll`. Existing `makeProject` (`test/helpers.mjs:40–43`) and `roadmapConsumer` (`upgrade.test.mjs:1465`) already disable signing in their ephemeral repositories. This is a reproduced config-dependent fixture failure; no load-sensitive natural flake is claimed.

Audit snapshot: `44e74a32ff6a6b6c946321b3614b1881a2ccedfe`. Commands below ran from the Backslop repository root unless another cwd is stated. On that unchanged snapshot, `node bin/backslop.js gates` exited 0: gates 2/2, tests 1240/1240, failures 0, skipped 0. This is a pre-change baseline; all implementation and post-fix checks below are notRun.

## Work to do

- Replace the two unchecked local `g()` call paths with the already imported checked `run(dir, args)`, or equivalent status checks that preserve cwd/args and stderr cause. `test/helpers.mjs:50–55` is the existing contract.

```js
function releasesRepo(tags) {
  const dir = realpathSync(mkdtempSync(path.join(os.tmpdir(), 'backslop-src-')));
  const g = (...a) => spawnSync('git', ['-C', dir, ...a], { encoding: 'utf8' });
  g('init', '-q', '-b', 'main');
  g('config', 'user.email', 'test@example.com');
  g('config', 'user.name', 'test');
  for (const tag of tags) {
    writeFileSync(path.join(dir, 'release.txt'), `${tag}\n`);
    g('add', '-A');
    g('commit', '-qm', tag);
    g('tag', tag);
  }
  return dir;
```
