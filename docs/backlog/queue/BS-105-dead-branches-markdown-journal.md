# BS-105 · Remove never-passed parameters and unreachable branches in links, lint, log, changelog

- **Order:** 230
- **Scope:** [Reference](../../reference/README.md)
- **Created:** 2026-09-25
- **Dependencies:** BS-104, BS-89, BS-87, BS-91

## Context

All evidence below was taken at commit 6f6318e (v0.11.0), where `npm test` runs 450 tests (450 pass, rc=0) and `node bin/backslop.js lint` exits 0. "Removal probe" means: the change was applied in a throwaway clone at that commit, then the full suite and lint were run.

Most entries below were checked with an instrumented clone: probes logged each branch in question while the full suite ran (`PROBE_LOG=$T/probe.log npm test` gave rc=0 and 450/450). The rest were checked by reading every call site and running a removal probe. All are verified.

- **links.js: `root = null` never arrives.** verified — call sites, instrumentation (zero `root === null` hits) and a removal probe (450/450, lint rc=0). `brokenLinks(file, root = null)` is at lib/links.js:88 and `directoryLinks(file, root = null)` at :113; the fallback `path.join(root ?? path.parse(file).root, …)` is at :107. Every caller passes a root: lib/lint.js:206 `brokenLinks(abs, root)`, :214 `directoryLinks(file, root)`, :249 `brokenLinks(file, root)`, and test/links.test.mjs:175, :188, :221 and :239 pass `sb`. lintLinks already dereferences `root` at lib/lint.js:202 (`readdirSync(root, …)`), so null would fail before reaching links.js.
- **mdwalk: the `out` parameter of `mdFiles` is never passed.** verified — call sites, instrumentation and a probe (450/450, lint rc=0). lib/mdwalk.js:75-76 is `export function mdFiles(dir, rel, out = []) { return srcFiles(dir, rel, ['.md'], out); }`. All 8 call sites pass two arguments: lib/lint.js:201, :313, :468, :516 and :595, lib/mdwalk.js:102, and test/mdwalk.test.mjs:43 and :83. The wrapper itself stays.
- **mdwalk: de-duplication in `livePinFiles` never fires.** verified — reasoning, instrumentation (zero hits for `seen.has(rel)` being true) and a probe that replaced it with a plain push (450/450, lint rc=0). The block is lib/mdwalk.js:126-142: `const seen = new Set(...)`, `add` returns early on `seen.has(rel)`. Its four sources cannot overlap: `liveMarkdown` yields only `*.md`, the second source only the basename `package.json`, `CI_ROOT_FILES` (:114-118) are fixed root names without .md or .json, and `CI_DIRS` (:119-124) yield `.yml`/`.yaml` files under distinct directories. `srcFiles` yields each path once.
- **log: the `lang` parameter of `namedResultOutcome` is never passed, and callers only test truthiness.** verified — grep and a probe (450/450, lint rc=0). The definition is lib/log.js:110, `namedResultOutcome(text, prefix, lang = 'ru')`. The production callers, lib/fold.js:174 and lib/lint.js:431, both pass two arguments and negate the result. Only test/tasks.test.mjs:316 reads the rendered string, `'слита в BL-604'`, and :313 in the same test asserts that same rendering through `outcomeFromResult` on the same input. The probe only dropped `lang`. The boolean-predicate form chosen below was not probed, so run the suite after the change.
- **log: fallbacks for outcomes no production caller produces.** verified — call sites and a probe. `renderOutcome` ends in `return UNKNOWN` at lib/log.js:94, but its callers pass only the kinds handled at :90-93: lib/log.js:105 passes `'completed'`, :134 passes a key of `OUTCOME_FORMS` (merged, rejected or completed), and lib/fold.js:226 passes `'batched'`. `formatLogLine` falls back with `outcome || UNKNOWN` at :60, but both production callers (lib/fold.js:207 and :226) always pass a non-empty outcome; only test/tasks.test.mjs:201 passes `outcome: ''`. The probe replaced :94 with a throw and dropped `|| UNKNOWN`; that turned red only the test at test/tasks.test.mjs:201, which passes again with `outcome: '—'` (450/450, lint rc=0). The `commit` and `title` fallbacks at :61-62 are reachable (lib/fold.js:208 passes commit null, :201 passes title null) and stay.
- **changelog: the `to == null` branch of `changelogSince` is reachable only from a test.** verified — call sites and a probe. In `run()`, `to` is `TOOL_VERSION` when `--to` is absent (lib/changelog.js:42), and an invalid `--to` throws (:44), so the guard `to ? … : true` at :32 is never taken in production. Removing it turned red only the test at test/upgrade.test.mjs:104-109, which calls `changelogSince(text, '0.1.0', null)` and failed with `Error: версия не разбирается: «null»`. It passes again once it uses a version instead of null (450/450, lint rc=0). The function and its export stay: `run()` uses it, and the unit test checks the real section filter.
- **merge-changelog: two branches of `checkInvariants` cannot fire.** verified — read, a mutation probe and fuzzing. The entry-count loop is at lib/merge-changelog.js:186-197 and the `else if (lost.length)` arm at :213-217. `parseSection` (:89-94) turns every line that matches the entry form into a block, and titled blocks are de-duplicated by title through `seen` (:269, :294). Only `conflictEntry` (:106-113) emits a second line with the same title, so the count never exceeds its limit. Every ours line is emitted, and a skip on `seen` is reported as `duplicatesOurs` by `repeatedBlocks` (:117-127). The code's own comment at :208-209 calls that arm the only reachable path. The mutation probe replaced both `fails.push` calls with `throw new Error('REACHED-…')`: `node --test test/merge-changelog.test.mjs` gave rc=0 with 31 pass and 0 REACHED. A fuzz run of 200000 random ours/theirs/base unreleased sections gave `{"ok":162079,"cliErrors":37921,"reached":{}}`. Deleting both branches kept 450/450 and lint rc=0, and left `entryKey` (:168) unused. The self-check stays through the reachable `duplicatesOurs` arm.
- **log: the first-paragraph outcome loop is copied.** verified — in a clone at base, `outcomeFromResult` was rebuilt on `namedResultOutcome`. test/tasks.test.mjs and test/fold.test.mjs passed 53/53, and the full suite passed 450/450. `outcomeFromResult` (lib/log.js:99-106) and `namedResultOutcome` (lib/log.js:110-116) run the same loop over `[firstParagraph(text), headingNote(text).words]` calling `namedOutcome`. One of the two loops is redundant: `outcomeFromResult` only adds the `CLOSED_FORM` fallback.

- lib/mdwalk.js:75-76: remove the `out` parameter, giving `mdFiles(dir, rel) { return srcFiles(dir, rel, ['.md']); }`.
- lib/mdwalk.js:126-142: replace the `seen`/`add` closure in `livePinFiles` with plain `files.push(...)`.
- lib/log.js:110: replace `namedResultOutcome(text, prefix, lang = 'ru')` with a boolean predicate `hasNamedOutcome(text, prefix)`. Update lib/fold.js:174 and lib/lint.js:431, which only negate it, and rewrite test/tasks.test.mjs:306 and :316 to assert false and true. The rendered string stays covered by :313.
- lib/log.js:94: replace the final `return UNKNOWN` of `renderOutcome` with `throw new Error(`unknown outcome kind: ${kind}`)`. lib/log.js:60: drop `|| UNKNOWN` on `outcome` and keep the `commit`/`title` fallbacks at :61-62. test/tasks.test.mjs:201: pass `outcome: '—'` instead of `''`.
- lib/changelog.js:32: drop the `to ? … : true` guard in `changelogSince`, and make test/upgrade.test.mjs:107-109 pass a version (for example `'9.9.9'`) instead of `null`, with the same expected sections.
- lib/merge-changelog.js: delete the entry-count loop with its comment (:186-197), the `else if (lost.length)` arm (:213-217) and the now-unused `entryKey` (:168). Reword the comment at :208-209 so that it no longer calls the remaining arm 'the only reachable path' in contrast to a deleted one.
- lib/log.js: share one first-paragraph/heading-note scan on top of the `hasNamedOutcome` change above: add a module-private `namedOutcomeText(text, prefix, lang)` that returns the rendered outcome or null, make `hasNamedOutcome` return `namedOutcomeText(...) !== null`, and make `outcomeFromResult` return `namedOutcomeText(...) ?? ([firstParagraph(text), headingNote(text).words].some((b) => CLOSED_FORM.test(b)) ? renderOutcome('completed', null, lang) : UNKNOWN)`.
