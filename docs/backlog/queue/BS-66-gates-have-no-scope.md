# BS-66 · Гейты не знают, что тронуто: правка одних доков платит полным набором, и пропустить его нечем

- **Порядок:** 15
- **Область:** [Гейты](../../reference/README.md), `lib/gates.js`, `lib/config.js`, `backslop.json`
- **Создана:** 2026-09-22
- **Зависимости:** нет

## Контекст

`gates` — плоский список команд: раннер исполняет `cfg.gates` по порядку и не спрашивает, что
изменилось (`lib/gates.js`, цикл по списку плюс снимок дерева; отсечки по путям в файле нет ни
одной). Состав списка тот же и для брифа worker'у (`lib/brief.js:124`), и для приёмки.

Отсюда цена, которая платится не за риск, а за ритуал. Замер 2026-09-22, правка в promptobus,
где менялись только тела карточек, `result.md` и каталоги статусов: `npm test` прогнан целиком —
70/70 файлов, код 0, и ни один из них не мог покраснеть от текста карточки. Числа соседей того же
дня: `npm test` в ati-agents — 51 976 мс по собственному отчёту раннера, `bun run test:ui` в
diffalanche — 79 748 мс. При десятке текстовых коммитов за прогон это десятки минут, потраченные
на подтверждение того, что markdown не ломает тесты.

Обратная сторона такая же настоящая: набор ловит не только правку кода. `backslop lint` краснеет
ровно на текстовых изменениях, `audit`/`pins` потребителя — тоже. То есть «докам гейты не нужны»
неверно: нужна не отмена, а адресность.

Механика для этого в инструменте уже наполовину есть: раннер умеет докладывать незапущенное
отдельным числом — `skipped` в JSON и хвост «не запущено N» в человеческом выводе
(`lib/gates.js:118-123`). Значит пропуск можно назвать пропуском, а не покрасить зелёным.

## Что сделать

- Дать записи `gates` необязательную область: вместо строки — объект `{ command, when: [<glob>…] }`,
  строка остаётся формой «гоняется всегда». Обратная совместимость обязательна: список из строк
  ведёт себя как сегодня.
- Считать изменённый набор путей и гонять только те команды, чья область его задевает. Источник
  набора назвать явно и в отчёте: грязное дерево (`git status --porcelain`) и/или дифф к базе.
- Пропущенное показывать как пропущенное — числом `skipped` и строкой с причиной, никогда не
  добавляя к «зелёным». Молчаливый пропуск читается как покрытие, которого не было.
- Поведение без области и без git оставить прежним: гоним всё.

## Развилка владельца

Чем задаётся изменённый набор — грязным деревом, диффом к базе (`--base <ref>`) или обоими.
Гейты сдаются на чистом дереве, то есть к моменту прогона правка уже в коммите и `git status`
пуст: без `--base` адресность работала бы только до коммита. Решение меняет и контракт команды,
и текст брифа.

## Не входит

- Кэш результатов гейтов между прогонами: это другая задача и другой риск (устаревший зелёный).
- Списки гейтов в самих репозиториях-потребителях: они правятся у себя после появления формы.

## Проверки

- Набор `node --test`: список из строк ведёт себя как прежде; команда с `when`, чья область не
  задета, не запускается и попадает в `skipped`, а не в зелёные; команда с `when`, чья область
  задета, запускается.
- Мутационная проба: убрать фильтр по области — тест «не запущено 1» краснеет; вернуть — зелёный.
  Вторая проба, на прицел: команда без `when` при любом наборе путей остаётся запущенной.
- Живой прогон в потребителе: правка одного `.md` в promptobus — `npm test` в `skipped`, `backslop
  lint` и `audit` запущены, итог печатает «гейтов N, зелёных M, не запущено K».
