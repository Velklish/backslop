# BS-197.2 · lint is red in a fresh git worktree: generated adapter outputs are gitignored

- **Order:** 1015
- **Scope:** [01. Layout](../../reference/01-layout.md) § Adapter ownership
- **Created:** 2026-10-01
- **Dependencies:** none
- **Cost:** major

## Context

Finding discovered while working on BS-197.
Evidence: in a project made by `init --lang en --tools claude`, `.gitignore` lists `.claude/skills/backslop-*` and `/CLAUDE.md`, so `git worktree add` gives a tree without them, and `lint` in that worktree reports each as missing: at `cb3bb26` `node <main>/bin/backslop.js lint` exits 1 with "✖ lint: errors 9" (8 × "generated output for adapter claude is missing", 1 × "Claude stub is missing"); at `806779d` (v0.12.0) it exits 1 with "errors 8". The main checkout of the same project exits 0. So the first `gates` run of every worker or approver in a fresh worktree is red for a reason that is not its change. In the BS-197 runs a fresh worktree hit this in 3 of 32 runs, across both versions: eval `task-take-first` round 1 (old) and round 2 (new), prompt "hey, can you grab whatever's at the top of the backlog queue and get it done? I'll review the diff myself before anything gets closed out, so take it as far as it can go before that."; and eval `task-red-first-gate` (old), prompt "Worker on APP-1 here, all my changes are committed on app-1-slug. Run the gates and tell me exactly where the branch stands — don't fix anything yet, I want the full picture before I decide what to change.", in the worktree it made to lint the base commit. Each agent copied the files from the main checkout and reported the workaround. The new-version run of `task-red-first-gate` hit the same 9 errors in a `git archive` copy of the base, which is not a worktree and is not counted above. Not a regression: v0.12.0 has the same failure.

## Work to do

- Decide how lint treats a worktree: skip the adapter-output and stub checks when the files are absent and gitignored, or name `init` in the worktree as a documented step in `backslop-batch` and `backslop-task`.
- A `git archive` copy has no git, so an "absent and gitignored" rule cannot decide it; if lint on such a copy should be green, that needs its own rule, or the skills name a worktree plus `init` as the way to lint a base commit.

## Out of scope

- What the adapter outputs contain.

## Verification

- `git add -A && git commit -qm init && git worktree add ../wt -b wt && cd ../wt && backslop lint` in a fresh `init` project exits 0, or the documented step makes it exit 0.
