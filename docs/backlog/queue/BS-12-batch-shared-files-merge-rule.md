# BS-12 · backslop-batch: правило слияния общих файлов track'ов вместо -X theirs и владение находками до слияния

- **Порядок:** 40
- **Область:** [templates/skills/backslop-batch](../../../templates/skills/backslop-batch/SKILL.md)
- **Создана:** 2026-09-05
- **Зависимости:** [BS-11](../../archive/BS-11-new-numbers-across-worktrees/task.md)

## Контекст

Наблюдение оркестратора 2026-09-05 в external/promptobus (15 track'ов, 33 задачи): ветки worker'ов сливались `git cherry-pick -n -X theirs`, и стратегия дважды теряла hunk'и соседнего track'а в общих файлах — CHANGELOG `[Unreleased]`, справочник, разделённый по `###`-секциям, регэксп-список `DRIVER_PRIVATE`, список префиксов `SUITE_PREFIXES` — и один раз продублировала хвост файла. Спас самописный скрипт, возвращавший после `-X theirs` недостающие пункты CHANGELOG (по заголовку `- **…**`) и секции справочника (по `###`) из HEAD. Улика: раздел «Слияние и приёмка» в `templates/skills/backslop-batch/SKILL.md` описывает только склейку CHANGELOG и не запрещает стратегию `-X theirs`. Связанное: столкновения номеров находок между оркестратором и worker'ами (BS-11).

## Что сделать

- В разделе «Слияние и приёмка» (ru и en): общие для track'ов файлы сливать по секциям и пунктам, а не стратегией `-X theirs`/`-X ours`; CHANGELOG — объединение пунктов по заголовку `- **…**`; документы — объединение секций по заголовкам; списки в коде — руками, с проверкой, что имена обеих сторон на месте; после слияния `git diff HEAD <голова worker'а> -- <файлы worker'а>` пуст.
- Правило владения находками: находки worker'а нумеруются `new --parent N` в ветке worker'а; оркестратор не заводит находок с тем же родителем, пока ветка не слита.

## Не входит

- Инструмент слияния в CLI.

## Проверки

- `node bin/backslop.js lint` зелёный: равенство шаблонов ru/en.
