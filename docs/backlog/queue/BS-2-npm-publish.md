# BS-2 · Публикация пакета в npm

- **Порядок:** 20
- **Область:** [reference/02](../../reference/02-cli.md)
- **Создана:** 2026-09-03
- **Зависимости:** первый живой прогон на чужом проекте — публиковать раньше отзывов значит раскатывать ошибки

## Контекст

Доставка идёт через `npx github:Velklish/backslop` ([ADR-003](../../adr/adr-003-node-stdlib-npx.md)): без реестра, но с клоном при первом запуске и без пина версии. Публикация в npm даёт короткую команду `npx backslop init`, точную версию в проектах и `npm view` для проверки свежести.

## Что сделать

- Аккаунт npm и токен публикации у владельца; имя `backslop` свободно (проверено 2026-09-03: `npm view backslop` — 404).
- Скрипт релиза: проверка чистого дерева, `npm test`, `lint`, тег `vX.Y.Z`, `npm publish`; чеклист — в `AGENTS.md` репозитория.
- Умолчание поля `cli` — `npx backslop@<мажор>`; `github:` остаётся как запасной путь в README.
- Запись в CHANGELOG на версию.

## Не входит

- Автоматизация релиза в CI: раннера у репозитория нет.

## Проверки

- `npx backslop@<версия> init` в пустом каталоге раскладывает те же файлы, что `npx github:…`.
- `npm view backslop version` печатает опубликованную версию.
