# BS-70 · Приёмка зовёт merge-changelog в том состоянии, которое создаёт бамп, и получает отказ на штатном ходу

- **Порядок:** 100
- **Область:** [02. CLI](../../reference/02-cli.md)
- **Создана:** 2026-09-22
- **Зависимости:** нет

## Контекст

Найдено заходом 2026-09-22; предмет — не разбор файла, а порядок бампа относительно приёмки.

`merge-changelog` сливает только первую секцию невыпущенного — заголовок `## …` без номера версии (`lib/merge-changelog.js`, `unreleasedIndex`). После `npm run release -- X.Y.Z --bump` такой секции в файле нет: скрипт переименовывает её в `## vX.Y.Z — <дата>`. Команда отказывает внятно, кодом 1 и словами «нет секции невыпущенного», — тихой неприменимости здесь нет.

Дорого другое. Скилл `backslop-batch` предписывает закрывать конфликт CHANGELOG при слиянии track'ов именно этой командой. В заходе 2026-09-22 бамп пришлось сделать **до** работы (миграция требовала своей версии в `MIGRATIONS`), и все четыре слияния пошли мимо команды: конфликт разбирался руками. То есть штатный ход приёмки упёрся в штатное же состояние репозитория, и обошли его без единого красного сигнала.

## Что сделать

- Решить, где стоит бамп относительно приёмки: всегда после закрытия всех задач захода, либо команда учится сливать и в секцию версии, которая ещё не выпущена (тег не поставлен).
- Если остаётся первое — сказать это явно там, где живёт рецепт приёмки: `templates/skills/backslop-batch/SKILL.md` и правила репозитория.

## Не входит

- Разбор записей и инварианты самой команды: закрыты в [BS-65](../../archive/BS-65-merge-changelog-returns-a-broken-file-with-exit-zero/task.md).

## Проверки

- Прогон команды на репозитории сразу после `--bump`: поведение совпадает с тем, что обещает справочник.
- Рецепт приёмки в скилле не предписывает ход, который на штатном состоянии репозитория отказывает.
