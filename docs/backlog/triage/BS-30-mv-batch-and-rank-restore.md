# BS-30 · `mv` не умеет несколько номеров разом, а «Порядок» стирается при уходе из очереди — вернуть задачу на прежнее место можно только по памяти оркестратора

- **Область:** [reference/02](../../reference/02-cli.md), `lib/mv.js`, `lib/tasks.js`, `templates/skills/backslop-batch/SKILL.md`, `test/commands.test.mjs`, `test/lint.test.mjs`
- **Создана:** 2026-09-06
- **Зависимости:** нет

## Контекст

Проверено на текущем HEAD. `lib/mv.js:23` — `const [rawId, target] = positionals;`: команда принимает ровно один номер задачи за вызов. Раздача track'а из N задач в работу — N отдельных вызовов, это же и предписывает `templates/skills/backslop-batch/SKILL.md:32`: «Роздал брифы — переведи розданные задачи в работу: `backslop mv N active` на каждую».

Там же, `SKILL.md:32`, вторая половина той же строки называет вторую дыру: «Заход кончился, а работу ты не принял — верни в очередь: `backslop mv N queue --top` или `--after M`, **чтобы место не потерялось**» — то есть текст скилла уже признаёт риск и перекладывает его на память оркестратора. В коде это подтверждается `lib/mv.js:60-61`: `if (placed) text = setField(text, FIELD_ORDER, String(placed.rank), cfg.lang); else text = removeField(text, FIELD_ORDER);` — при переводе НЕ в `queue` (`target !== 'queue'`, `placed` остаётся `null`) поле «Порядок» безусловно снимается, и прежний ранг нигде не сохраняется — ни в файле задачи, ни где-либо ещё.

`placeInQueue` (`lib/tasks.js:397`) уже умеет разрешать коллизию ранга перенумерацией соседей шагом 10 — эта логика используется сегодня только для `--top`/`--after`, для восстановления по сохранённому рангу её никто не вызывает. Единственная близкая закрытая задача — `BS-10` (`docs/archive/BS-10-mv-within-queue/task.md`, `result.md`) — решает перестановку задачи, уже стоящей в `queue/`, а не сохранение ранга при уходе из неё и не пакетный `mv`; в `result.md` этой задачи дыра не упомянута.

## Что сделать

- `lib/mv.js`: `run()` принимает список номеров вместо одного (`backslop mv N1 N2 N3 … <статус>`), применяет существующую логику по кругу к каждому и печатает сводку успех/отказ по каждому номеру отдельно, не прерываясь на первом отказе. Резка на track'и остаётся решением оркестратора — команда не понимает, что такое track.
- При уходе из `queue/` (место `lib/mv.js:61`, где сегодня `removeField(text, FIELD_ORDER)`) — записывать текущий ранг в отдельное поле шапки (например, «Прежний порядок / Previous order»), не путая его с активным «Порядком» очереди, чтобы `lint` (гейт 4, поля статусов) не пришлось разрешать «Порядок» на не-queue статусах.
- Флаг `backslop mv N queue --restore`: ставит задачу на сохранённый ранг через `placeInQueue` (`lib/tasks.js:397`), с тем же поведением при занятом ранге (перенумерация шагом 10), что уже есть у `--top`/`--after`.
- Обновить `templates/skills/backslop-batch/SKILL.md` (и англ. слой `templates/en/skills/backslop-batch/SKILL.md`) — убрать формулировку «чтобы место не потерялось», заменить на `--restore`; упомянуть пакетный `mv` в шаге перевода в работу.
- Обновить `docs/reference/02-cli.md`: строка `mv` в таблице команд — множественные номера и флаг `--restore`.
- Запись в `CHANGELOG.md`.

## Не входит

- Само решение, резать ли track на отдельные вызовы или как их группировать, — остаётся оркестратором; команда `mv` не приобретает понятия track'а.
- Изменение семантики `--top`/`--after` для обычной перестановки — она не трогается, `--restore` добавляется как третий, отдельный вариант позиции.
