## Контекст

Находка при работе над BS-64, метка major: штатная команда инструмента рождает красный гейт.
BS-64 закрыл этот дефект для `triage/`; в `minor/` он остался. `lintBacklogTodos`
(`lib/lint.js`) пропускает в `minor/` одну строку — «Область» (`areaLine`), — а строку
«Улика», которую `new` пишет сам, красит.

Замер на экспорте дерева `a74dc1a` (`git archive`, вне репозитория), команды подряд:

```
node bin/backslop.js lint                                        → код 0, «lint: ошибок нет»
node bin/backslop.js new minor-evidence-probe --parent 64 --minor → код 0
node bin/backslop.js lint                                        → код 1
✖ docs/backlog/minor/BS-64.1-minor-evidence-probe.md: строка 11: осталась заглушка [TODO]
⚠ docs/backlog/minor/BS-64.1-minor-evidence-probe.md: «Область» пуста: назови раздел справочника
```

Строку 11 пишет `lib/new.js` (ветка `context` для находки), заголовок раздела — шаблон
`templates/minor.md`. Предупреждение о пустой «Области» здесь по замыслу: её заполняет
approver при резке пачек. Красит гейт именно заглушка улики.

**Зачем:** правило бэклога отправляет находку без улики в `minor/` штатной командой, и эта
же команда оставляет проект с красным гейтом до разбора пачки. Автор находки либо правит
файл руками сразу после команды, либо несёт красный гейт в отчёт.

## Что сделать

- Решить, где чинить: исключить строку «Улика» в `minor/` так же, как исключена «Область», либо снять гейт заглушек с `minor/` целиком, как BS-64 снял его с `triage/`. Второе шире и согласуется с тем, что `minor/` ждёт пачки, а не разбора; первое точечнее. Красная проба на выбранный вариант.
