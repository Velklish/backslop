## Контекст

Эта запись — то же самое отсутствие синхронизации прозы с пином, что и находка AT-D-13 этого прогона (улика там — ati-agents, здесь — promptobus): механизм дефекта идентичен, объект правки — тот же код backslop (lib/upgrade.js, lib/lint.js). При разборе triage предмет один, и решение — сливать эту запись в AT-D-13 или вести отдельно — принимает approver по правилу дублей (docs/backlog/README.md: «слить дубль в существующую задачу, уточнить формулировку»). Ниже — самостоятельная улика, которая не покрыта фикстурами AT-D-13.

Замер сегодня в promptobus (backslop.json: cli = npx github:Velklish/backslop#v0.4.0, version = 0.4.0; package.json version = 0.5.0 — версия самого promptobus, к пину backslop отношения не имеет): docs/guides/contributing.md:3 — «This repository is run entirely through backslop `v0.3.0`», при этом на строках 6-7 того же файла команды уже даны с `#v0.4.0` — расхождение есть даже внутри одного файла. docs/archive/README.md:7 (promptobus) — тот же устаревший пин #v0.3.0 в живой, не архивной по содержанию инструкции.

Механизм: lib/upgrade.js:37-38 (rewriteGates) переписывает пин только в cli и gates; lib/lint.js:55-69 (lintVersion) сверяет пин с версией внутри backslop.json и не читает markdown. npx github:Velklish/backslop#v0.4.0 lint в promptobus сегодня — «lint: no errors». docs/adr/adr-004-version-pin-upgrade.md о синхронизации прозы ничего не говорит — расхождение не решение, а пробел.

## Что сделать

- Тот же код меняется, что и в AT-D-13 (lib/upgrade.js — прогон замены по docs/**, lib/lint.js — предупреждение о расхождении); отдельного изменения promptobus эта находка не требует.
- Если запись остаётся отдельной (решение approver'а), verification добавляет фикстуру вида «версия названа прозой на одной строке, пин командой — на соседней» (contributing.md:3 vs :6-7) — этот случай не совпадает с примером AT-D-13, где расхождение — только в самом пине.

## Не входит

- Слияние с AT-D-13 — решение approver'а при разборе triage, не фиксируется здесь заранее.
