# BS-32 · Уборка захода держится на памяти оркестратора: перечень worktree/веток и то, что из них влито, не печатает ни одна команда

- **Область:** [reference/02](../../reference/02-cli.md), `lib/tasks.js`, `bin/backslop.js`, `templates/skills/backslop-batch/SKILL.md`
- **Создана:** 2026-09-06
- **Зависимости:** нет
- **Взята:** 2026-09-09

## Контекст

Проверено на текущем HEAD. `templates/skills/backslop-batch/SKILL.md`, раздел «Слияние и приёмка», пункт 5 (строка 111): «Тем же ходом убери за собой: `git worktree remove <путь>`, `git branch -D <ветка>`, закрой сессии worker'а и reviewer'а тем способом, который дал harness». Раздел «Конец захода» (строка 115): «Итог владельцу: что закрыто, что осталось, где развилки. Проверь, что живых сессий и worktree захода не осталось» — обе проверки идут по памяти оркестратора о путях и ветках, заведённых с начала захода; ни `backslop lint`, ни `backslop status` их не печатают. `COMMANDS` в `bin/backslop.js:12` команды для этого нет.

Пункт 3 того же раздела (строка 109, мерило `git diff HEAD <голова worker'а> -- <файлы worker'а>`) сюда не входит: это ровно формулировка, которую внесла закрытая задача `BS-12` (`docs/archive/BS-12-batch-shared-files-merge-rule/task.md`, раздел «Не входит»: «Инструмент слияния в CLI») — то есть автоматизация именно этого мерила уже сознательно оставлена ручной при разработке этого раздела, и сюда не переоткрывается.

Механика для нового наблюдения уже есть в коде: `foreignTaskIds` (`lib/tasks.js:178-217`) вызывает `git worktree list --porcelain` (строка 209) и разбирает блоки на путь и ветку (строки 212-217) для другой задачи (счёт занятых номеров, `BS-11`) — тот же обходчик переиспользуется для нового наблюдения. Задачи про команду уборки/списка track'ов нет ни в одном каталоге бэклога backslop и не в архиве.

## Что сделать

- Новая команда `backslop tracks [--json]`: по `git worktree list --porcelain` (переиспользуя обходчик `foreignTaskIds`, `lib/tasks.js:178-217`) для каждого worktree и локальной ветки с коммитами `{{prefix}}-N:` печатает путь, ветку, влита ли она в `HEAD` (`git merge-base --is-ancestor <ветка> HEAD`), список коммитов `{{prefix}}-N:`, которых нет в `HEAD` (`git log <ветка> --not HEAD --grep '^{{prefix}}-'`), и есть ли незакоммиченная работа в этом worktree (`git status --porcelain` внутри него).
- Команда только печатает картину — удалять worktree/ветку или нет решает оркестратор своей командой `git worktree remove`/`git branch -D`, как и сегодня; `tracks` не получает `--cleanup` или автоудаление.
- Обновить раздел «Конец захода» в `templates/skills/backslop-batch/SKILL.md` (и англ. слой) — заменить «проверь по памяти» на «`backslop tracks` печатает список; убедись, что он пуст».
- Добавить строку `tracks` в таблицу команд `docs/reference/02-cli.md`.
- Запись в `CHANGELOG.md`.

## Не входит

- Мерило `git diff HEAD <голова worker'а>` из пункта 3 раздела «Слияние и приёмка» — сознательно оставлено ручным задачей `BS-12`, эта задача его не переоткрывает.
- Автоматическое удаление worktree/веток (`--cleanup`) — команда только наблюдает, действие остаётся явными командами git в руках оркестратора.

## Проверки

- `node bin/backslop.js tracks` в тестовом репозитории с двумя worktree — одним слитым (все коммиты `BS-N:` есть в `HEAD`, дерево чистое) и одним нет — печатает для первого «влит, ничего не осталось», для второго путь, ветку и список неслитых коммитов.
- `--json`: та же информация в машиночитаемой форме, поле на worktree с незакоммиченными изменениями отмечено отдельно.
- Репозиторий без лишних worktree — пустой список, код возврата 0.
