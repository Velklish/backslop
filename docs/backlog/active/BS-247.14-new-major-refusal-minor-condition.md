# BS-247.14 · Limit the documented major-cost refusal to minor-mode hypotheses

## Context

Evidence: `docs/reference/02-cli.md:105-105` at source `44e74a32ff6a6b6c946321b3614b1881a2ccedfe`; the source snapshot and recorded checks below establish the audit claim. Follow the repository verification protocol before implementation.

The CLI reference incorrectly lists major/critical cost without a hypothesis as an unconditional refusal. Confirmed findings with a parent and without `--minor` are allowed to carry that cost; adding `--hypothesis` to such a normal card is itself forbidden.

Evidence was inspected at source HEAD `44e74a32ff6a6b6c946321b3614b1881a2ccedfe`.

## Evidence

- `docs/reference/02-cli.md:105` lists "`--cost major|critical` without `--hypothesis`" as a refusal.
- The same page at `:90` correctly says "`--cost critical|major` with `--parent` and without `--minor` writes that level into the Cost field of the task card".
- `lib/new.js:43` guards this refusal with `values.minor && level !== 'minor' && !values.hypothesis`; `:38` separately forbids `--hypothesis` without `--minor`.
- An isolated audit fixture ran `new confirmed --parent 1 --cost major` without `--hypothesis`: exit 0, with `**Cost:** major` in the generated card. This was a baseline behavior probe, not a post-fix check.

The mode condition was dropped while summarizing flag validation.

## Work to do

1. In `docs/reference/02-cli.md:105`, explicitly scope the refusal to `--minor --cost major|critical` without `--hypothesis`.
2. Protect the distinction with the narrowest suitable existing doc-fact assertion or live quote; the old broad refusal must make that check fail.

Acceptance: the reference permits a confirmed `--parent N --cost major|critical` card without `--minor` or a hypothesis; the expensive `--minor` case still requires a hypothesis.

## Out of scope

Do not change code validation, add `--hypothesis` to normal finding cards, weaken the hypothesis requirement in `minor/`, or alter card templates and routing.
