# BS-65 · `merge-changelog` отдаёт структурно битый файл и выходит с нулём

- **Область:** [02-cli](../../reference/02-cli.md)
- **Создана:** 2026-09-22
- **Зависимости:** нет
- **Взята:** 2026-09-22

## Контекст

Команда объявлена в правилах репозитория-потребителя как **единственный законный** способ разрешать конфликт CHANGELOG: «resolve it with `merge-changelog`, never by hand-picking lines». Поэтому её вывод принимают не глядя, а `exit 0` это поощряет.

Живой вход, `external/diffalanche`, 2026-09-21, слияние ветки в main:

```
npx github:Velklish/backslop#v0.9.0 merge-changelog \
  --ours 8db629b --theirs e495e97 --base ed81928 --out <tmp>
→ exit 0
stderr: entries: ours 54, theirs 48, merged 55
stderr: ⚠ bodies differ under one heading — both revisions kept under the
        <!-- backslop:conflict mark, decide yourself: A window shows the task
        its address names.
```

Что в файле на самом деле:

1. **Дубль примерно семидесяти строк.** В секции `Unreleased` два заголовка `### Changed` вместо одного. `grep -c 'A window shows the task'`: у `ours` 1, у `theirs` 1, у слитого — **3**.
2. **Предупреждение о расхождении тел — ложное.** Для этой записи `base`, `ours` и `theirs` совпадают текстуально: `diff` по всем трём срезам даёт пустые обе пары. Похоже, разбор спотыкается о буллеты без жирного заголовка и затягивает хвост секции в «тело» записи.
3. **Переразметка всего файла.** Пустых строк было 44, стало 95, при нуле удалённых строк содержания. То есть в коммит задачи въезжает косметическая правка всего CHANGELOG.
4. **Запись переезжает.** Автор поставил её первой в `### Fixed` — конвенция файла «новое сверху». Тул кладёт её последней в секции.

Варианты с опущенным `--base` и с переставленными местами `ours`/`theirs` дают то же самое.

**Верное слияние для этого входа существует и проверяется в одну строку.** Объединение обеих вставок целиком даёт против `main` `+16 / −0`, и шестнадцать совпадает с `git diff --stat ed81928 e495e97 -- CHANGELOG.md` → `1 file changed, 16 insertions(+)`. Аддитивный файл, слитый аддитивно, без единого удаления.

Обе приёмки того прогона пошли мимо команды, объединяя стороны руками с этой проверкой. Второй раз конфликт пришёл двумя коммитами из восьми, и оба разрешились так же: `16 0` и `20 0`.

**Цена — не сам дефект, а `exit 0` рядом с ним.** Поймано только потому, что приёмщик прочитал вывод, а не код возврата. Правило репозитория при этом велит доверять команде и не править руками.

## Что сделать

- Разобраться с разбором записи: почему буллет без жирного заголовка утягивает в тело хвост секции, и почему заголовок `### Changed` дублируется вместо слияния.
- Не выходить нулём, когда в результате остались метки `<!-- backslop:conflict`. Незакрытый конфликт — это не успех, и вызывающий не обязан искать метку глазами.
- Проверять собственный вывод перед записью: количество заголовков одного уровня в секции не растёт, число вхождений записи не превышает суммы по сторонам, число удалённых строк содержания равно нулю для аддитивного слияния.
- Сохранять позицию записи в секции. Конвенция «новое сверху» есть у всех известных потребителей.
- Пока это не сделано — снять из шаблона `AGENTS.md` формулировку, которая объявляет команду единственным законным способом.

## Что вне задачи

- Поведение при настоящем расхождении тел одной записи. Здесь тела совпадали, и предупреждение было ложным; настоящий случай — отдельный разговор.

## Проверка

- На входе выше команда даёт `+16 / −0` против `main`, один `### Changed` в `Unreleased`, одно вхождение записи и запись первой в своей секции.
- При настоящем неразрешённом конфликте команда выходит ненулём и называет метку.
