# BS-31 · Бриф worker'у оркестратор набирает вручную, хотя семь из восьми обязательных пунктов — данные с диска и неизменный текст

- **Область:** [reference/02](../../reference/02-cli.md), `lib/tasks.js`, `lib/config.js`, `lib/templates.js`, `templates/skills/backslop-batch/SKILL.md`, `templates/brief.md`, `templates/en/brief.md`
- **Создана:** 2026-09-06
- **Зависимости:** нет
- **Взята:** 2026-09-09

## Контекст

Проверено на текущем HEAD. `templates/skills/backslop-batch/SKILL.md`, раздел «Бриф», строка 48 — «Первая строка — заголовок track'а в 2–5 слов…», обязательные пункты — строки 50-57: номера задач с постановкой; границы правки; критерий готовности; явная просьба закоммитить с префиксом; запрет каталогов статусов и `archive/` с причиной; находки файлом (`backslop new <slug> --parent N`); порядок мутационной пробы; состав результата.

Из восьми пунктов только «границы правки» — решение оркестратора по конкретному заходу. Остальные семь либо читаются с диска (постановки задач — `scanTasks`, `lib/tasks.js`; `gates` и `prefix` — поля `backslop.json`, читает `lib/config.js:24-26`), либо представляют собой неизменный по формулировке абзац (критерий готовности «гейты из `backslop.json` зелёные, доки поправлены тем же ходом», запрет каталогов статусов, порядок мутационной пробы, состав результата, просьба закоммитить с префиксом, приём находок через `--parent`).

Команды `backslop brief` в CLI нет: `COMMANDS` в `bin/backslop.js:12` — `['init', 'new', 'mv', 'archive', 'adr', 'status', 'lint', 'upgrade', 'migrate', 'changelog']`; `node bin/backslop.js help` её не показывает; `grep -rniE '\bbrief\b' lib/ bin/` не находит реализации — только упоминания в `README.md`, `GLOSSARY.md` и самом `SKILL.md`. `renderProjectTemplate` (`lib/templates.js`) уже используется ровно для этого паттерна — рендер шаблона с подстановками — в `new.js`, `archive.js`, `adr.js`; задачи про команду `brief` нет ни в одном каталоге бэклога backslop (`queue/active/triage` пусты, `deferred/` — только `BS-2.1`) и не в архиве.

## Что сделать

- Новая команда `backslop brief <N…> [--track "<заголовок>"] [--neighbour "test/=tests"] [--measurements]`: рендерит текст брифа из `templates/brief.md` (и `templates/en/brief.md`, parity проверяет `lint`) через `renderProjectTemplate` — подставляет заголовок track'а, номера и тела задач (`scanTasks`), `gates` и `prefix` из `backslop.json`, неизменные разделы текста списком выше.
- Флаг `--neighbour "путь=track"` (повторяемый) подставляет в раздел «границы правки» имена соседних track'ов и их пути — единственное, что раньше требовало решения оркестратора вручную, здесь остаётся текстовым аргументом, не автоматическим выводом.
- Команда только печатает текст брифа (в stdout) — куда его отправить (промпт субагента, первое сообщение сессии, шина) решает оркестратор.
- Обновить раздел «Бриф» в `templates/skills/backslop-batch/SKILL.md` (и `templates/en/skills/backslop-batch/SKILL.md`) — заменить перечень обязательных пунктов на отсылку к команде и описание оставшихся оркестратору решений (границы, соседи).
- Добавить строку `brief` в таблицу команд `docs/reference/02-cli.md`.
- Запись в `CHANGELOG.md`.

## Не входит

- Выбор модели и уровня усилий исполнителя, решение о резке track'ов — остаются оркестратором, команда их не читает и не выводит.
- Автоматическая отправка брифа исполнителю (субагенту, сессии, шине) — команда только формирует текст.

## Проверки

- `node bin/backslop.js brief 3 4 --track "миграция конфигов"` на подставном проекте: вывод содержит заголовок track'а, постановки задач 3 и 4 из их файлов, текущие `gates` и `prefix` из `backslop.json`, все семь неизменных пунктов.
- `node bin/backslop.js lint`: равенство `templates/brief.md` и `templates/en/brief.md` (`templateParity`) зелёное; сломанная copy другого языка — красное.
- Тест на несуществующий номер задачи в `brief` — отказ с этим номером, а не пустой рендер.
