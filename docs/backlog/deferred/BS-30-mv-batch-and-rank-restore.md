# BS-30 · «Порядок» стирается при уходе задачи из очереди — вернуть её на прежнее место можно только по памяти оркестратора

- **Область:** [reference/02](../../reference/02-cli.md), `lib/mv.js`, `lib/tasks.js`, `templates/skills/backslop-batch/SKILL.md`, `test/commands.test.mjs`, `test/lint.test.mjs`
- **Создана:** 2026-09-06
- **Зависимости:** нет

## Контекст

Проверено на текущем HEAD. `lib/mv.js:60-61` — `if (placed) text = setField(text, FIELD_ORDER, String(placed.rank), cfg.lang); else text = removeField(text, FIELD_ORDER);`: при переводе НЕ в `queue` (`target !== 'queue'`, `placed` остаётся `null`) поле «Порядок» снимается безусловно, и прежний ранг нигде не сохраняется — ни в файле задачи, ни где-либо ещё.

Текст скилла эту дыру уже признаёт и перекладывает на память оркестратора: `templates/skills/backslop-batch/SKILL.md:32` — «Заход кончился, а работу ты не принял — верни в очередь: `backslop mv N queue --top` или `--after M`, **чтобы место не потерялось**».

`placeInQueue` (`lib/tasks.js:397`) уже умеет разрешать коллизию ранга перенумерацией соседей шагом 10 — сегодня эта логика зовётся только из `--top`/`--after`, для восстановления по сохранённому рангу её никто не вызывает.

Контрдовод, из-за которого запись отложена (он же — «Не входит» BS-26): ранг по ADR-002 (Consequences) — абсолютное целое, которое очередь перенумеровывает шагом 10, когда целого места нет. Сохранённое число поэтому не гарантирует того же места после следующего захода, а новое поле шапки по ADR-002 тянет за собой `lint`, `migrate` и весь комплект справочников — ради приоритета, который оркестратор при возврате назначает заново (`--top` для незакрытой работы).

## Что сделать

- При уходе из `queue/` (место `lib/mv.js:61`, где сегодня `removeField(text, FIELD_ORDER)`) — записывать текущий ранг в отдельное поле шапки («Прежний порядок» / «Previous order»), не путая его с активным «Порядком» очереди, чтобы гейт полей статусов не пришлось разрешать «Порядок» на не-queue статусах.
- Флаг `backslop mv N queue --restore`: ставит задачу на сохранённый ранг через `placeInQueue` (`lib/tasks.js:397`), с тем же поведением при занятом ранге (перенумерация шагом 10), что уже есть у `--top`/`--after`.
- `templates/skills/backslop-batch/SKILL.md` и англ. слой `templates/en/…` — убрать «чтобы место не потерялось», заменить на `--restore`.
- `docs/reference/02-cli.md` — флаг `--restore` в строке `mv`; `docs/reference/01-layout.md` — новое поле шапки; `CHANGELOG.md` — запись.

## Не входит

- Пакетный `mv` несколькими номерами за вызов — вторая половина исходной записи, вынесена в [BS-26](../active/BS-26-mv-single-id-per-call.md) как самостоятельная задача.
- Изменение семантики `--top`/`--after` — `--restore` добавляется третьим, отдельным вариантом позиции.

## Проверки

- `test/commands.test.mjs`: `mv N active` из `queue/` с «Порядком» 30, затем `mv N queue --restore` — файл снова получает «Порядок» 30 (или ближайшее свободное место с перенумерацией, если 30 занято).
- Красная проба в `test/lint.test.mjs`: новое поле «Прежний порядок» вне `queue/` не путается с гейтом обязательности «Порядка» в `queue/`.

## Отложено

- **Отложена:** 2026-09-06
- **Причина:** ранг по ADR-002 — абсолютное целое, которое очередь сама перенумеровывает шагом 10, поэтому сохранённое число не значит того же места после следующего захода; новое поле шапки тянет за собой `lint`, `migrate` и справочники ради приоритета, который оркестратор при возврате всё равно назначает заново (`--top`).
- **Условие возврата:** живой заход, в котором потерянное место стоило работы — задача вернулась в очередь не туда и была взята не в свой черёд; либо решение отказаться от абсолютного ранга в пользу порядкового списка, после которого восстановление места перестаёт быть догадкой.
