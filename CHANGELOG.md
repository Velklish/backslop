# Changelog

## Unreleased

- **The `init` message for an existing `docs/README.md` asks for a link to the ADR** — it said to add a row to the table, otherwise `lint` fails, but gate 8 checks that the ADR is linked from `docs/README.md`; a row in the table is now named as the usual place for the link, not as the condition.
- **The `backslop-writer` audit files a Blocking card with `--cost critical` and a High card with `--cost major`** — the filing table gave `new <slug> --parent N` without a cost, so the card showed a dash instead of its label.
- **The acceptance recipe in the `backslop-task` skill carries the attachment branch** — the skill restated step 5 of the `AGENTS.md` block without it, so an approver who followed the skill alone ran `fold` over a task directory with an attachment and met the refusal. The skill now squashes first with the directory in the tree, folds, and commits the draft as a second commit; the task reaches the main branch as two commits.
- **`init --hooks` uses a declared local backslop dependency without per-event GitHub resolution** — when the project-root `package.json` lists `backslop` in `devDependencies`, a new config and its hook records use `npx --no-install backslop`; otherwise they keep the pinned GitHub npx command, regardless of a global install. With the local command, `init` warns if the package is absent or its installed version differs from the tool: an older installation points to the declared dependency spec, and a newer one prompts use of that version without recommending a downgrade. It refuses before writes without the declaration, including on a first explicit `--cli` run. The local command has no release pin; `upgrade` keeps it, requires an explicit `source`, and refuses before migration if hook records use it without the declaration.
- **The `backslop-writer` audit treats a statement about another product as an assumption** — step 3 of the audit mode called every statement the document makes that the code cannot confirm a confirmed Blocking finding, while the filing rules call a finding the writer cannot verify an assumption. A statement about how another product behaves fits both. The skill now files it as a `--hypothesis` entry with a cost, in both template layers.
- **The `docs/README.md` template and the `backslop-seed` ADR backfill reference say `lint` fails without the link** — they said it fails without a table row, but gate 8 only checks that the ADR is linked from `docs/README.md`; an ADR linked outside the table passes. Both template layers now name the link and keep the advice to add a row.
- **The `backslop-writer` description and the README name the closing of a run with workers** — they called it the closing of a batch, but a batch is a card that closes minor entries, so the sentence named the wrong event. The skill description and the README now say a run with workers closes, in both template layers; the mode name batch close is unchanged.
- **The take commit has one owner: the `AGENTS.md` block, and step 4 of `backslop-batch` follows it** — the block squashed the take commit into the acceptance commit, while step 4 of the skill set the recipe's base to main's head before the integration, so a one-task batch ended in one commit or in two depending on the text the reader followed. Both texts, in both template layers, now say the same: a take commit that took one task is squashed into that task's acceptance commit, with `reset --soft` onto the commit before it, when no commit follows it; otherwise it stays a commit of its own and the acceptance commit says so. A take commit that took several tasks stays a commit of its own, and the `reset --soft` goes to main's head before the integration, never to the shared take commit, which would replace the earlier acceptances above it and lose their drafts. The acceptance of one task never absorbs the take of another. The base of `gates --base` is unchanged.
- **Hook messages, the `hook` usage line, the `AGENTS.md` hook sentence and the `backslop-batch` launch line say what backslop prints, not what a harness does** — they described what another program does with backslop's output. The note after repeated errors now reads `lint errors in changed files were reported {limit} times in a row; the hook now exits 0, the errors stay:`, the `hook` usage line names the stream and the exit code of each harness, the hook sentence says the stop hook runs `lint` and prints its errors in the files the session changed, the `CLAUDE.md` warning says that the `@AGENTS.md` import line is missing, and the launch line asks for a subagent started in its own worktree and branch. Russian entries and twins follow.
- **`status` shows the Reason of a deferred card** — `status` and `status --json` printed the first line of the Deferred section, which `mv` fills with the date line, so a deferred card read `- **Deferred:** <date>`. They now show the text of the Reason line without its list marker and label, in either language; an empty or `[TODO]` Reason gives `null` in `status --json` and no text after the title, and a section without a Reason line shows its first non-empty line that is not a field line, never `- **Deferred:** <date>`.
- **The acceptance recipe in the `backslop-task` skill commits the draft with `--cleanup=verbatim`** — step 4 gave `git commit -F` over the `fold` draft, while the block, the hint of `fold` and the `02-cli` reference name the flag. The skill now gives the same command in both languages.
- **The `backslop-batch` skill no longer lists the mutation probe among the fixed brief sections** — the brief carries the probe only when `probe` is declared, yet the skill listed it as fixed and its review-choice table named a probe result. The sentence now names the probe bullet and its result item only with `probe` declared, and the table speaks of what the worker broke by hand and what turned red.
- **The Russian `backslop-seed` adr-backfill reference keeps one voice per sentence** — the pointer to the owner-talk wording joined an impersonal clause and an imperative with a comma; it is now a parenthesis, as in the English text.
- **A value substituted into a JSON-quoted frontmatter value is escaped** — a placeholder inside `name: "…"` or `description: "…"` of a skill template took its value raw, so a `cli` with a quote or a backslash, such as `node "C:\Users\me\backslop.js"`, made `init` refuse with `the frontmatter description is not a valid JSON string` or wrote a malformed description. The value is now JSON-escaped there and stays raw everywhere else.
- **The acceptance recipe in the `AGENTS.md` block commits the draft with `--cleanup=verbatim`** — step 5 gave `git commit -F` over the `fold` draft, while `fold` itself and the `02-cli` reference name `--cleanup=verbatim`, which stops git from stripping lines of the message. The block template of both languages now carries the flag; a project takes it with the next `init`.
- **`lint` gate 10 names the first quoted line, not the code fence** — for a quote wrapped in a code fence, `quote no longer matches <file>` printed the opening fence line, so the reader could not tell which statement had changed. It now prints the first line of the quoted text.
- **`lint` does not call the outputs of a skipped vendored skill missing** — when `init` leaves a vendored skill out because its `LICENSE` or `SOURCE.md` at the output path is foreign, `lint` reported the foreign file and then every other output of that skill as missing, telling the reader to run `init`, which would not write them. It now reports the foreign file alone, with its remedy.
- **A dangling status link through a symlinked path prefix is no longer called a link out of the project** — on a system where the project lives under a symlinked prefix (`/var` → `/private/var` on macOS), an absolute link such as `docs/backlog/queue -> /var/…/docs/nowhere` was judged by its text against the real path of the project and warned about as leading out. The prefix is now resolved before the comparison.
- **An unreadable directory behind a status link is named, not `docs/backlog`** — with `docs/backlog/queue` linked to a directory under a locked directory inside the project, the refusal named `docs/backlog`, which is readable. It now follows the link and names the directory that denies the search.
- **`lint` gates 2, 4 and 6 do not read behind a status directory symlinked out of the project** — with such a link, gate 3 was joined by gate 2 (the names behind the link), gate 4 (`[TODO]` placeholders in its cards) and gate 6, which called every mention of a number behind the link a missing task, in every card of the project. Gates 2 and 4 no longer read behind the link, and gate 6 reports nothing while a status or archive directory leads out, because the number may sit behind it.
- **`mv`, `archive` and `fold` rewrite the links of a card listed through a symlinked alias of its directory** — with a symlink such as `aa-alias` to `docs/backlog` that sorts before `docs`, the link walk listed the cards of the backlog only under the alias, resolved their relative links from the alias path and left a link to the moved task as it was, with no message. The links of a file are now resolved from its real place in the project.
- **`lint` gates 1, 10 and 13 do not read behind a status directory symlinked out of the project either** — with `docs/backlog/queue` linked to a directory outside the project, gate 1, the check of links to journal lines and gate 10 still walked through the link, so a card behind it with a broken relative link, a journal anchor with no entry or a stale quote was reported besides the error of gate 3. They now skip the files behind such a link, as gates 2, 4 and 6 do.
- **`lint` gate 3 calls a status directory symlinked out of the project a symlink** — the error read `file is outside a status directory` and advised moving a task into a status directory, which does not fit a link that is itself the status directory. It now says that the symlink leads out of the project, that the tasks in it are not read, and that the link should point inside the project or become a directory.
- **`init` words an unreadable `docs` or skeleton directory before it writes** — with `docs/backlog` unreadable, `init` ended in a `node:fs` stack on the first file it tried to write into it. It now refuses before the first write, naming the directory and its error code as the other commands do.
- **An archive task directory symlinked out of the project is no longer read** — `lint` gate 5 calls such a directory a stray file, but `status`, `show` and the number scan read the task through the link. They now skip it as they skip a status directory: `status`, `show`, `brief`, `mv`, `archive` and `fold` print a warning naming it, and `new` refuses, because the number behind the link is not seen.
- **`init` refuses a bad adapter output path and a `CLAUDE.md` directory before it writes anything** — a symlink or a directory on an owned output path of a selected adapter, a file where its path needs a directory, and `CLAUDE.md` that is a directory or a dangling symlink with `claude` selected were found after `backslop.json` and the docs skeleton were already on disk, and a directory ended in an `EISDIR` stack. All of them now stop `init` before the first write, with the words of the refusals that were there before.
- **`lint` gate 8 says an ADR is not linked, not that it has no row** — the check tests that the ADR file is among the links of `docs/README.md`, but the message read `no row in README.md — the ADR table is maintained manually`. It now reads `not linked from README.md — the ADR index is maintained manually`, in both languages.
- **`upgrade` pins a floating `cli` inside backticks** — in a `gates` or `probe` command such as ``x=`npx github:me/proj lint` ``, the floating form was left as written, while the same form inside `$(…)` or quotes was pinned. A backtick now bounds the form like a quote does.
- **`help` names lint gate 12 "template placeholders"** — the `lint` line of `help` listed the gate by its old name, "template slots"; it now says "template placeholders", the name `docs/reference/03-lint.md` and the glossary use.
- **Upgrade: `lint` gate 8 fails on a `[TODO]` line left in an ADR** — an ADR made by `adr` carries `[TODO…]` lines in Deciders and in its four sections, and one committed with them passed every gate once it was linked from the index. Gate 8 now reports each such line with its number, by the line rule of gate 4; fenced code, a code span and a `[TODO]` inside a sentence are text. `init` itself left `**Deciders:** [TODO: project owner]` in `docs/adr/adr-001-process.md` (the Russian layer has the same line in Russian) and now writes `**Deciders:** the project owner`. Affects projects: an existing project whose `adr-001-process.md` still carries that placeholder turns `lint` red on upgrade until its owner replaces that one line with a name, and any other ADR with a placeholder line does too: write the line or delete the ADR.
- **Upgrade: `lint` gate 4 warns about an Order outside `queue/` and a Previous order inside it** — a card moved out of `queue/` by hand kept its `Order`, and a card moved in by hand kept its `Previous order`; nothing reported either, though `mv` removes the first on leaving and the second on entering. Both are warnings and do not fail `lint`: delete the line.
- **Upgrade: `lint` gate 9 warns about a Parent field that names another number than the file name** — a finding `<prefix>-5.1` whose `Parent` is `<prefix>-6` was accepted, though the field and the file name disagree on the task the finding belongs to. The warning does not fail `lint`; a finding of a finding (`<prefix>-5.2` with `Parent: <prefix>-5.1`) agrees. A card with a wrong `Parent` gets the warning after `upgrade`: fix the field or the file name.
- **`lint` gate 11 reports a pin with a pre-release tail whole and does not read other tails as the plain pin** — in the tool's own `README.md` and `AGENTS.md`, `#v0.1.0-rc.1`, `#v0.1.0x` and `backslop@0.1.0.1` were compared as `0.1.0` and printed as `0.1.0`. A pin with a tail now has an end boundary, as the pin of the `cli` field has: a pre-release tail (`-rc.1`) makes another version and is reported with its tail, while a suffix such as `x` or a fourth number is not read. In the tool's own repository, whose `cli` carries no pin, nothing reports a suffix of the second kind in these files; in a project with a pinned `cli`, the pin check of that field still does.
- **A `**` inside a code span no longer ends a CHANGELOG entry title** — `lint` gate 7 and `merge-changelog` read the title of `- **`when`: `**/` …**` as `` `when`: ` ``, so two different entries with such a prefix looked like one: gate 7 reported a repeated title and `merge-changelog` took them for the same entry. A code span is now read whole.
- **`upgrade` leaves a pin in a `LOG.md` journal entry that follows a leading BOM** — an entry on the first line of a `LOG.md` that starts with a byte order mark was not recognised as a journal entry by `upgrade`, so its pin was rewritten, though the entry is a record of its moment and `lint` already skipped it. The BOM no longer hides the entry, and the file keeps its BOM.
- **`lint` gate 1 reads the slug of a heading with a punctuation or symbol entity as the renderer does** — `## A &mdash; B` has the id `a--b` on gitlab.ati.st, and gate 1 computed `a-mdash-b`, so a link to the rendered id was reported as a missing anchor. A fixed table of entities (dashes, quotes, `&hellip;`, `&copy;`, `&reg;`, `&trade;`, arrows, currency signs and a few more) is now decoded before the slug drops them; `&mdash;`, `&hellip;` and `&copy;` were measured against the renderer, the rest follows the same rule unmeasured. Any other named entity (`&le;`, `&minus;`, a letter one such as `&eacute;`) is still read by its name.
- **`lint` gate 1 refuses a link that differs from its file only in Unicode normalization** — a link written with `é` as one character to a file named with `e` and a combining accent (or the reverse) resolved on a normalization-insensitive file system such as macOS APFS and passed, and failed on Linux. It now fails everywhere with `link target differs in Unicode normalization: <real name>`.
- **Internal errors follow the project language** — the refusal of a template placeholder without a key and the refusal of a version that does not parse printed Russian text only, even in an `en` project. They now print in the project language, and in English when the call has no language: no Russian text appears in an `en` project, nor in a call without a language.
- **The `fold` refusal over an unsaved attachment no longer asks for a commit** — the acceptance recipe forbids a commit between `archive` and `fold`, and the refusal told the approver to make one. It now says to move the files out of the task directory and link them from `result.md`, then fold again.
- **A status directory symlinked out of the project is no longer read** — `lint` gate 3 already treated such a directory as a file, but `status`, `show`, `mv` and the number scan read the tasks through the link. They now skip the directory, and `status`, `show`, `brief`, `mv`, `archive` and `fold` print a warning naming it. `new` refuses while any status directory leads out, because a number taken behind the link would be given out again, and `mv` refuses it as a destination. A link to a directory inside the project is still a directory, and a dangling link counts as out only when its text points outside the project. `lint` gate 2 still reads the names behind the link.
- **Commands word an unreadable `docs/backlog` and an unreadable status directory of another worktree** — with `docs/backlog` unsearchable, `status` printed an empty backlog and exited 0, `show`, `brief` and `fold` said the task did not exist, and `mv`, `archive` and `new` ended in a Node stack trace. They now refuse with `<path>: the directory is not readable (<code>) — …`, as for any other unreadable directory. `new` does the same when a status directory of another worktree cannot be listed.
- **The refusal of a `backslop:start` or `backslop:end` marker in a block value gives the right reason** — the text said the block bounds are found in raw text, but `init` counts a marker only on a line of its own. The refusal now says that a marker in the value would copy a block boundary into the block text.
- **`mv` with several numbers no longer calls them a batch** — the refusals for `--top`/`--after` with several numbers and for a number named twice, and the note about a saved position that falls behind a neighbour, speak of the call instead; `batch` names only the card that closes minor entries. The `mv` section of the CLI reference and the queue-order decision say the same.
- **`init --hooks` writes the agent hook records of the `claude`, `cursor` and `codex` harnesses** — a new `hooks` field of `backslop.json` lists the harnesses (`claude`, `cursor`, `codex`) whose project hook files carry backslop's start and stop records, which run `<cli> hook session-start` and `<cli> hook stop`. `init --hooks <list>` sets it, and a first `init` selects none. `init` writes the records into `<project>/.claude/settings.json`, `<project>/.cursor/hooks.json` and `<project>/.codex/hooks.json`, keeps every foreign key and hook in those files, rewrites its own records when `cli` changes, removes them when a harness is dropped, and refuses a file that is not valid JSON before the first write; the files in your home directory are never written. `lint` reports a missing record, a record with another `cli`, a duplicate or a record under another event (the file differs from what `init` writes), and a record of an unselected harness; owned records of an unselected harness behind a symlink are reported too, to be removed by hand, since `init` does not write through a link. With hooks selected, the `AGENTS.md` block gains one sentence about the stop hook and `lint` errors.
- **`mv`, `archive` and `fold` refuse over an unreadable directory before they change anything** — the link walk ran after the card had moved (or the archive directory had gone and the journal line was written), so a directory it could not list left the card in its new place with no incoming link rewritten, and a repeat answered `already in` or `already archived`. The walk now runs first: the refusal names the directory as before, the tree is untouched, and the repeat works once the directory is readable.
- **The `backslop-task` report step says what an absent part of the `gates` summary means** — `gates` prints `, not run N` and ` (out of scope K)` only when the number is not zero, and reports in a run wrote `not run 0 (out of scope 0)` as if the tool had printed it. Both layers of the skill now say that an absent part means 0 and that the report says 0; the summary line itself is unchanged.
- **`tracks --json` keeps the status column of a `dirty` item** — the items were the `git status --porcelain` lines trimmed at both ends, so the leading space of an unstaged change was lost (`M a.txt`) and a fixed-column porcelain parser misread the two status letters. An item is now the line as git prints it (` M a.txt`), as `tree.dirty` of `gates --json` already was; the text listing prints the same lines.
- **`merge-changelog` keeps one blank line between merged entries when the section ends the file** — with no released section below, the blank line that ended the unreleased section stayed attached to the last entry of a side, so an entry of the other side placed after it was separated by two blank lines. The last entry of a side now keeps one trailing blank line when another entry or a `###` heading follows it in the result.
- **`lint` skips a missing adapter output that git ignores** — a fresh `git worktree` of a project lacks the gitignored adapter outputs and `CLAUDE.md`, and `lint` there named each one missing, so the first `gates` run was red for a reason that was not the worker's change. An output or the Claude stub that is absent and ignored by git in that working tree is now skipped, with one `git check-ignore` call per run. A present file is checked as before, an absent file that git does not ignore is still an error, and outside any git repository, such as a `git archive` copy unpacked outside every repository, nothing changes: `lint` stays red there. The same holds for a fresh clone and for an output deleted in the main checkout: `lint` no longer reports it there, so run `init` after cloning. The `backslop-batch` and `backslop-task` skills name a `git worktree` as the way to lint a base commit.
- **`hook` reports the `lint` errors in the files a session changed** — a new command for the agent hook records: `hook session-start --harness <claude|cursor|codex>` records the start commit of the session under `backslop/hooks/` in the git directory of the working tree, and `hook stop --harness …` runs `lint` in the same process when the session changed a file and prints the errors in those files. The changed set is every path that differs between the start commit and the working tree, plus untracked files git does not ignore; an error in another file, an error without a file and every warning are never reported. For `claude` and `codex` the errors go to stderr with exit 2, for `cursor` into a `followup_message` on stdout with exit 0. The errors are reported at most three times in a row whatever they are, then the stop prints a note naming them instead; only a stop without errors resets the count. Outside a git repository, without `backslop.json`, with unreadable input or on an error of its own, `hook` exits 0 with one note.
- **Upgrade: a documentation fix carries a check red on the old text, and the writer pass runs at release and at batch close** — step 3 of the `AGENTS.md` block gains two sentences: a documentation fix carries a check that fails on the old text (a `quote:` block, a test or a lint rule), and documentation does not cite tasks but states the contract, the rationale or the measurement. The Skills line names `backslop-writer`, `backslop-techdoc` and `backslop-humanizer`, and a sentence outside the numbered steps, under the same adapter condition, tells the agent to run the `backslop-writer` pass in release mode over the diff since the previous tag before a release commit. The `backslop-batch` skill gains a closing step after every track is accepted and before the last push of the run: the writer pass in batch-close mode over the run's range, filed as a task of its own whose `result.md` holds the ledger, with commits that carry the task prefix, reviewed like any piece, and findings filed under that task. The `backslop-task` skill names the regression check for a documentation fix and points to `backslop-writer` for style; the backlog README and the brief state the same rule. `migrate` redraws the backlog README and `init` redraws the block; a project with an `agents.stepOverrides` entry for step 3 should review its override, because the override replaces the two new sentences along with the rest of the step.
- **`links --external` checks the external links of the documents** — a new command requests every `http` and `https` link of the files gate 1 reads, one at a time, and prints `<class> <status or error> <url>` for each, then `links: N urls, D dead, U unverified`; `--json` prints one document instead. An address is `ok` on 2xx and 3xx, `unverified` on 401, 403, 408, 429, a 5xx or no answer, and `dead` on 404, 410 and every other status; the exit code is 0 when all are `ok`, 1 with a dead one, 2 with unverified ones only. The command stays out of `gates` and `lint`: a network answer is not reproducible. There are no retries and no authentication.
- **Upgrade: `lint` fails on task ids and tracker links in project documentation** — a new gate 15 reads the project documentation: root `README*.md`, every `.md` under `docs/` except `backlog/` and `archive/` (ADRs included), and the unreleased section of `CHANGELOG.md`, the first `## ` section whose title does not start with a version (`## Unreleased`); a section whose title starts with a version is released, whatever tags the clone has. It fails on a task id `<prefix>-N` anywhere in those files, code included; on a link into `docs/backlog/` or `docs/archive/`, `LOG.md#…` included (the two rules files `backlog/README.md` and `archive/README.md` stay linkable); and on an address into the same repository's backlog or archive, read from the `origin` remote on GitHub and GitLab. Each error names the file, the line, the class and the token, and says what to write instead: the contract, the rationale, or the measurement with its version and date. Gate 6 now checks mentions only outside that set: the backlog, the archive and released changelog sections. A project whose documentation carries task ids or tracker links turns red on upgrade until its own migration task clears them.
- **`backslop-writer` audits documentation** — a new audit mode runs under a task of its own and writes the upstream audit report (`Score`, `Shippable`, `Blocking`, `Findings`) for each document into the task result. Every finding is filed by severity: Blocking as a `critical` card, High as a `major` card, Medium and Low as `minor` entries, one per document and rule, and each record names the check the fix adds, one that fails on the old text. A document with `Shippable: no` holds the release pass until its Blocking findings are closed: a card by `archive`, a hypothesis entry by the batch that closes it. The audit edits no document, and `lint` computes no score.
- **Upgrade: ADRs hold current decisions only, and `lint` gate 8 reads ADR statuses** — gate 8 now fails on an ADR without a `**Status:**` line (the list-item form `- **Status:**` and the Russian label count), on a status word other than `Proposed` or `Accepted` (`Superseded`, `Superseded in part`, `Deprecated`, `Rejected`), on a status line that names another ADR by `ADR-NNN` or by a link to `adr-NNN-…`, on an ADR listed in two table rows of `docs/README.md`, and on a row whose Status cell differs from the status word of its file. The index principle in the `docs/README.md` template and step 3 of the `AGENTS.md` block now say that a new decision on a question already decided rewrites that question's ADR in place, an ADR that governs nothing is deleted, and a chain of ADRs on one question folds into its highest number; the `backslop-task` skill gains a "Changing a decision" section, and the `backslop-seed` ADR backfill records a decision that changed as the one that governs now, in one ADR. `migrate` does not redraw your `docs/README.md`: replace your copy of the first principle ("An accepted decision is not edited; it is superseded") with the new text, then fold each chain of ADRs into its highest number and delete the replaced files before upgrading, or `lint` turns red.
- **The managed block tells how to talk to the owner and the skills point to it** — the `AGENTS.md` block gains a "Talking to the owner" item: a message to the owner is read without the queue, the run or the agent's context open; a question says what is asked, why, and what each answer changes; it uses no term or abbreviation the agent coined (worker slugs, "piece", review codes), and a new definition is used only after the owner confirms it; a task is named by its number and its title, never by the number alone — the title goes at the first mention in a message, in every heading and in every table row, and later mentions in the same paragraph may use the number alone, and each list item counts as a paragraph. `backslop-task`, `backslop-batch`, `backslop-seed` and its ADR-backfill and glossary references link to that item where they report to the owner or ask them, and do not restate it. Re-run `init` to refresh the block and the skills.
- **`mv`, `archive` and `fold` rewrite every local link form gate 1 reads** — task moves now update HTML `<a href>` links, both destinations of a badge, and reference declarations inside a blockquote or list item, as well as inline links and line-start declarations. The rewrite uses the same parser positions as `lint`, matches the complete written filename including literal backticks, and keeps the written syntax; `mv` and `archive` preserve the `#…`/`?…` tail, while `fold` points matching task links at the archive journal anchor.
- **The adapters lay out `backslop-writer`, and `backslop.json` accepts writer scope** — every selected adapter now writes the `backslop-writer` skill for the technical-writer pass. The pass has release and batch-close modes, currency and style ledgers, project-rule precedence over `backslop-techdoc` and `backslop-humanizer`, and language rules for `lang: en` and `lang: ru`. - **`new` counts numbers across all worktrees and local branches** — files in other worktrees and the trees of local branches take numbers and finding sub-IDs, and the output names the worktree or branch that moved yours.
- **`mv N queue --top | --after M` reorders a queued task** — only Order changes, and neighbours are renumbered by 10 when there is no free place; `lint` reports two queue files with the same Order.
