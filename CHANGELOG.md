# Changelog

## v0.9.0 — 2026-09-18

- **Пятый каталог статуса `minor/` — minor-находки и гипотезы ждут пачки, а не разбора** — `new <slug> --parent N --minor [--cost <уровень>] [--hypothesis]` кладёт туда файл из нового шаблона `minor.md` с полями «Родитель» и «Цена» и разделом «Улика»; `major` и `critical` принимаются только гипотезой, с уликой такая находка чинится сейчас. «Область» у minor пустая и заполняется при резке пачек: `lint` на неё предупреждает, а на отсутствующую или неразбираемую «Цену» и на `major` без пометки гипотезы — краснеет. `mv N minor` дописывает «Цена: minor» и стирает заглушку области. `status` печатает секцию `Minor` по областям, `status --json` отдаёт `minor` с `area` и `cost`. Первая миграция `migrate` — каталог `docs/backlog/minor/` для проектов со штампом ниже 0.9.0; проект без штампа считается старше любой миграции. Решение — [ADR-022](docs/adr/adr-022-cost-decides-finding-fate.md) (BS-61).
- **`archive N.k --into M` закрывает minor-запись пачкой без своего `result.md`** — файл уезжает в `docs/archive/<M>-<slug>/minor/` с той же переписью ссылок, что у обычного закрытия; исход по записи называет `result.md` пачки. Пачка закрывается первой: каталог незакрытой пачки в архиве читался бы вторым файлом её номера. Отказы: запись не в `minor/`, пачки нет, пачка сама minor-запись, `--range` вместе с `--into`. Закрытые так записи остаются известными упоминаниям, нумерации находок и гейту архива, который в `minor/` пачки пускает только файлы записей; счёт архива в `status` считает задачи, не записи (BS-62).
- **Цена находки решает её судьбу — правило в шаблонах и скиллах** — backlog README, блок `AGENTS.md`, бриф, `backslop-task` и `backslop-batch` (ru и en) ведут находку по метке: `critical` чинится сейчас (в чужих файлах — сообщением оркестратору сразу), `major` в области текущей задачи чинится сейчас, `major` вне её — карточка в `triage/`, `minor` и гипотеза — `minor/`; без метки approver находку не принимает. Пачки minor режутся перед заходом по области — той, которую заход трогает, или с десятью и больше записями; владелец заказывает пачку в любой момент. Архивный README описывает `minor/` пачки. Решение — [ADR-022](docs/adr/adr-022-cost-decides-finding-fate.md) (BS-60).
- **Значение `agents.stepOverrides` подставляется экранированным и остаётся текстом** — вся ASCII-пунктуация CommonMark уходит под обратную косую при сборке блока, поэтому значение вида `[policy]: /changed` больше не становится определением ссылки с областью всего документа: текст шага остаётся видимым, соседний шаг ссылкой не становится, цель ссылки за пределами блока не меняется. Шестого запрета в перечне не добавлено — список экранируемого полон по построению, а не по перечню; скобки без определения ссылки остаются законным значением. Цена пути названа в [ADR-020](docs/adr/adr-020-agents-step-overrides.md): markdown-разметка внутри значения перестаёт действовать (BS-57).
- **Шаг 4 блока `AGENTS.md` называет команду мутационной пробы или не требует её вовсе** — команду берёт новое поле `probe` в `backslop.json`. Объявлено — шаг называет её; поля нет — предложения про пробу в блоке нет, а `init` называет пропажу строкой вывода: правило, которое нечем исполнить, дороже отсутствия правила, но выкинуто оно должно быть вслух. Умолчания у поля нет — команда пробы у каждого репозитория своя. Значение — однострочная команда без обратной кавычки и без меток `backslop:start`/`backslop:end`: перевод строки развалил бы блок, кавычка закрыла бы код-спан, в который шаблон ставит значение, а метка оборвала бы сам блок — границы ищутся по сырому тексту, и следующий `init` дописывал бы хвост старого. `<` не запрещён намеренно: внутри код-спана он литерал, а метка блока — отдельный класс, который закрывает проверка формы, а не рендер (BS-58).

## v0.8.0 — 2026-09-13

- **`quote:before:<путь>` хранит снимок до правки без потери проверки блока** — расхождение содержимого такого блока не красит `lint`, но отсутствующая цель и незакрытый блок остаются ошибками; обычный `quote:<путь>` по-прежнему сторожит инвариант (BS-52).
- **Живые пины входят в один обход `upgrade` и `lint`** — `package.json` и известные CI-файлы обновляются вместе с живым markdown, а старый пин в живом файле становится ошибкой. Исторические markdown-файлы остаются зелёными (BS-53).
- **Шаги managed-блока `AGENTS.md` можно заменить настройкой проекта** — `agents.stepOverrides` в `backslop.json` принимает ключи `"1"`…`"7"`; значение полностью заменяет текст выбранного шага при `init` и должно быть непустой строкой без переводов строк и символа `<`. Это inline-текст без разметки, способной открыть блок или сырой HTML. Номер шага, остальные шаги и граница worker'а сохраняются (BS-54).
- **Бриф прямо закрепляет границу status/archive** — worker не правит текст существующих файлов в каталогах статусов и архиве, а присылает формулировку в результате; единственное исключение — новая находка, которую worker создаёт отдельным файлом через `new --parent N[.M]` в своей ветке; закрытие и перенос остаются ходами approver'а (BS-56).
- **`new --parent N.M` сохраняет связь с находкой без третьего уровня номера** — команда выдаёт следующий свободный `N.k` и пишет поле «Родитель». Находка под закрытым родителем остаётся в `triage/`, а `lint` предупреждает approver'а без красного гейта (BS-50).
- **`lint` не пропускает второй раздел и незаполненные заглушки бэклога** — в `deferred/` второй `## Отложено` красный, а заголовки разделов внутри fenced-примеров не считаются разделами: fenced-only пример не скрывает отсутствие настоящего «Отложено» и не мешает `mv N deferred` добавить его; отдельная строка или поле с целиком заглушечным значением вида `[TODO…]` в любом markdown-файле `docs/backlog/**` красны; `[TODO]` внутри пояснения не считается заглушкой. `mv N deferred` не дописывает уже существующий раздел и печатает «раздел есть, проверь причину и условие возврата» (BS-49).

## v0.7.0 — 2026-09-12

- **Бриф называет три решения оркестратора, и слот без ключа больше не уезжает читателю** — шаблон нёс семь подстановок, и решением оркестратора были две: заголовок track'а и границы правки. Ни границы самостоятельности, ни точки входа, ни формы результата среди слотов не было, а разбор 73 прогонов шины показал, что предмет вопросов участника постановочный: 30 % граница задачи, 25 % развилка решения, 24 % подтверждение необратимого шага. Теперь `brief` принимает `--entry`, `--autonomy` и `--handover`; без флага слот печатает `[TODO: …]` с объяснением, чего не хватает. Заодно закрыта механическая дыра: `renderTemplate` на имя без ключа отказывает, а не подставляет его буквально, и двенадцатый гейт `lint` сверяет пару «слот ↔ ключ» по реестру `TEMPLATE_KEYS` в обе стороны и в обоих языковых слоях ([ADR-018](docs/adr/adr-018-brief-decision-slots.md), BS-55).

- **Шаг гейтов в брифе идёт по пинованной версии, а не по запущенной** — блок «Критерий готовности» звал `<cli> gates` всегда, а раннер появился в v0.5.0: на проекте, пинованном ниже, требование неисполнимо, и worker дважды тратил ход на разбор `unknown command "gates"`. Теперь `brief` сверяет пин из `cli` с версией появления команды: пин не ниже — блок зовёт раннер; ниже — перечисляет команды поля `gates` по одной, требует код возврата у каждой и прямо запрещает выдумывать сводку «гейтов N, зелёных N». Пина нет вовсе (self-host, глобальная установка) — раннер считается доступным ([ADR-017](docs/adr/adr-017-gates-step-follows-the-pin.md), BS-51).

## v0.6.0 — 2026-09-09

- **`init` проверяет на symlink только корни выбранных adapter'ов** — три корня harness проверялись при любых `tools`, и проект с общим harness-каталогом ссылкой не проходил `init` никогда, даже с `tools: []`, где backslop туда не пишет ни одного файла; отказ советовал `--tools none` и сам же говорил, что он не поможет. Теперь ссылка — отказ только на корне выбранного adapter'а, куда бы она ни вела, и отказ называет лечение: обычный каталог или снятие adapter'а; корни невыбранных не проверяются и не чистятся, а обход markdown, по которому `mv` и `archive` переписывают ссылки, за ссылку на корне harness не заходит ([ADR-016](docs/adr/adr-016-selected-adapter-roots-symlink.md), BS-38.1).

- **Acceptance-тест релиза сверяет состав tarball** — после `npm pack` тест дёргал у установленного бинаря только `version`, `init` и `lint`, и выпадение `templates/` из поля `files` они бы не поймали: self-host без adapters шаблонов не рендерит. Теперь перечень `files[].path` из `npm pack --json` сверяется с отслеживаемыми git файлами: всё из `bin`, `lib`, `templates` и корневых файлов упаковано, лишнего нет, а поле `files` равно этому контракту (BS-47).

- **`archive` видит правку, сделанную самим merge-коммитом** — `git log --name-only` для merge-коммита не печатает файлов вовсе, и файл, изменённый только при слиянии (разрешение конфликта), выпадал из списка тронутых доков. Теперь выборка идёт с `--cc`: merge даёт ровно свою правку, а файлы ветки по-прежнему приходят через её коммиты, которые входят в диапазон. Для самого backslop без веток это безразлично, у потребителя с MR — нет (BS-33.2).

- **Пути тронутых доков — от корня проекта и на проекте внутри большего репозитория** — `archive N --range` держал пути от корня проекта на флаге `--relative`, но combined diff merge-коммита этот флаг не учитывает и печатает путь от toplevel git (`sub/docs/…`). Теперь префикс подкаталога команда срезает сама по `git rev-parse --show-prefix` и печатает не-ASCII имена как есть (`core.quotePath=false`), а не закавыченными восьмеричными последовательностями; проверено на проекте в подкаталоге с merge-коммитом и кириллическим именем дока (BS-33.1).

- **Разбор `git worktree list --porcelain` — один помощник** — `worktrees` в `lib/util.js` вместо двух копий разбора: внутри цикла `foreignTaskIds` (счёт номеров по чужим worktree у `new`) и в `tracks` (BS-32.1).

- **Оснастка тестов: копия инструмента — один helper** — `toolCopy` и `toolCli` в `test/helpers.mjs` вместо двух копий той же оснастки в `test/init.test.mjs` и `test/lint.test.mjs` (BS-48).

- **`init` не переписывает чужой файл на пути adapter output** — снятие adapter'а шло по предикату владения, а запись — нет: `renderAdapters` клал файл выбранного adapter'а поверх того, что лежало, и пользовательский файл без маркера на пути скилла терялся молча — тот самый, который `init --tools none` сохранял и называл вслух. Теперь запись читает то же правило: файл без маркера и вне legacy-набора остаётся, `init` называет его предупреждением, а `lint` красит его у выбранного adapter'а — скилл backslop на этом пути не установлен; каталог на owned-пути или файл на его компоненте — отказ словами, а не стек `EISDIR`/`ENOTDIR`, и `lint` красит каталог на owned-пути ([ADR-015](docs/adr/adr-015-adapter-write-preserves-foreign.md), BS-36.2).

- **Снятие adapter'а и предикат владения читают одно правило** — `markedFiles` брал под корнем harness только файлы, чей первый сегмент пути начинается на `backslop-`, а `isOwnedAdapterFile` признавал owned любой файл с маркером под корнем. Файл с маркером по пути вроде `.claude/skills/other/note.md` выпадал из `mv`, `archive` и `lint` как owned, но снятие его не видело, и он оставался в проекте навсегда. Теперь снятие идёт по маркеру без фильтра имени, как предикат (BS-36.1).

- **Каталог с именем файла задачи — диагностика `lint`, а не стек** — `scanTasks` читал каталог вида `docs/backlog/queue/BS-9-x.md` как файл задачи, и команда падала `EISDIR` со стеком раньше, чем гейт 2 доходил до своей ветви «каталог внутри каталога статуса». Теперь такой каталог задачей не считается ни в каталогах статусов, ни в плоском `docs/backlog/`, и `lint` печатает диагностику гейта; symlink на каталог получает ту же диагностику, битая ссылка — свою (BS-19.1).

## v0.5.0 — 2026-09-09

- **`tracks` — перечень worktree и веток захода** — новая команда печатает по каждому чужому worktree и по каждой ветке с коммитами задач мимо `HEAD`: путь, ветку, влита ли она в `HEAD`, неслитые коммиты `<prefix>-N` и незакоммиченное в дереве. Уборка захода держалась на памяти оркестратора: скилл `backslop-batch` требовал убрать worktree и ветки, но перечня не печатала ни одна команда. Команда только наблюдает — удаляют по-прежнему `git worktree remove` и `git branch -D` ([ADR-014](docs/adr/adr-014-tracks-observation-command.md), BS-32).

- **Красная проба у каждого гейта из перечисленных в справочнике** — пять ветвей `lint` (каталог внутри каталога статуса, отсутствующий каталог бэклога, посторонний файл в архиве, каталог архива без `task.md`, ADR при отсутствующем индексе документации) и четыре проверки формы `loadConfig` (`prefix`, `docs`, `cli`, `gates`) закрыты пробами: раньше все девять можно было вырезать, и `npm test` оставался зелёным. Правило AGENTS.md и текст [03-lint](docs/reference/03-lint.md) про красную пробу у каждого гейта стали фактом для этих ветвей (BS-19).

- **Дубли полей шапки схлопываются и ловятся lint** — чтение и запись выбирают первое вхождение поля по строкам, команды удаляют остальные RU/EN-алиасы, а гейт 4 сообщает номера строк дубля (BS-17).

- **Команда `seed` берёт на себя механику посева** — инвентаризацию источников гейтов и заведение задач «Справочник: …» скилл `backslop-seed` описывал как извлечение по улике, а CLI не давал для них ни одной команды. `seed --scan [--json]` печатает кандидатов в `gates` и подсистемы с путями-уликами; `seed --queue-reference` заводит задачи по строкам таблицы справочника, чьи разделы ещё не написаны, и не плодит дублей при повторе. Что из перечисленного настоящий гейт и настоящая подсистема, по-прежнему решают агент и владелец (BS-35).

- **Команда `brief` собирает бриф worker'у с диска** — из восьми обязательных пунктов брифа семь оркестратор набирал вручную при каждом заходе: постановки задач лежат в их файлах, `gates`, `prefix` и `cli` — в `backslop.json`, остальное — неизменный текст. `backslop brief <N…> [--track "…"] [--neighbour "путь=track"] [--measurements]` печатает готовый текст в stdout; решением оркестратора остаются границы правки — они задаются `--neighbour` (BS-31).

- **Гейт 10 сторожит цитату живого файла** — гейт ссылок проверял только существование цели, а текст под ссылкой уезжал молча, и постановка жила с цитатой, которой в файле уже нет. Блок `<!-- quote:<путь> -->…<!-- /quote -->` обязан найтись в названном файле: сверка построчная, ведущие пробелы и строки-фенсы отброшены. `docs/archive/` не проверяется — цитата в закрытой задаче снимок момента; форма, показанная внутри блока кода, остаётся примером (BS-23).

- **`new` подставляет в «Область» посчитанный путь до справочника** — было статичное `[TODO: раздел reference/]`, и число `../` до `reference/` агент считал вручную при каждом заведении задачи. Теперь команда кладёт рабочую ссылку на `reference/README.md`, посчитанную от каталога статуса, а раздел по-прежнему выбирает тот, кто заводит задачу (BS-34).

- **Гейт 4 проверяет «Область»** — поле было объявлено, но не читалось ни одним гейтом: задача уезжала в очередь вовсе без него, а заглушка `[TODO]` от `new` не ловилась ничем. Теперь пустая и незаполненная «Область» красит `lint` в `queue/`, `active/` и `deferred/`; `triage/` освобождён — запись там по определению лежит без разбора, а выбор раздела и есть разбор (BS-25).

- **`npm run release -- X.Y.Z --no-publish`** — релиз без шага `npm publish`: локальный тег и atomic push `main` и тега остаются. Публикация в npm отложена владельцем (BS-2.1), а единственный путь скрипта звал `npm publish` безусловно — и три тега после появления скрипта вышли мимо него. Теперь путь «тег и atomic push без публикации» штатный: `AGENTS.md` называет его формой релиза до закрытия BS-2.1, отказ после тега различает «опубликован» и «npm publish не запускался», а `--bump` вместе с `--no-publish` — отказ (BS-39).

- **`upgrade --pin-only` тоже пробует новую версию до записи пина** — раньше флаг пропускал пробный запуск, и проект оставался с пином и гейтами на команду, которая не поднимается: лечилось это правкой `backslop.json` руками, потому что сам backslop из проекта больше не звался. Инвариант, объявленный в шапке `lib/upgrade.js` и в справочнике («ls-remote или пробный запуск отказали — пин не тронут»), стал верным без оговорок; флаг по-прежнему сокращает хвост — `migrate`, `init` и выжимку CHANGELOG (BS-37).

- **`mv` принимает несколько номеров за вызов** — `backslop mv 1 2 3 active` переводит track захода одной командой вместо пяти вызовов и пяти аппрувов. Все номера резолвятся и проверяются до первого переноса: отказ по любому не оставляет пакет перенесённым наполовину; повтор номера в пакете — отказ; `--top` и `--after` при нескольких номерах — отказ, место для пакета не определено одним числом. Порядок каждому считается заново, когда до него дошла очередь (BS-26).

- **`upgrade` переставляет пин и в прозе, `lint` предупреждает о расхождении** — спека `cli` с любым номером версии (`github:owner/repo#vX.Y.Z`, `backslop@X.Y.Z`) в `docs/**` и корневых `*.md` переставляется на новый пин, поэтому чинится и проза, отставшая на две версии; `CHANGELOG.md`, `docs/adr/**`, архив и сами карточки задач остаются как были — они описывают момент, а не запуск. `lint` предупреждает о пине, разошедшемся с `cli`, называя файл, строку и ожидаемый пин; `cli` без пина и голый `vX.Y.Z` в прозе не проверяются. Раньше живая инструкция продолжала звать снятую версию (BS-24).

- **Закрытая задача с неразобранной находкой красит lint, `archive --range` печатает тронутые доки** — гейт 9 ловит находку `N.k`, оставшуюся в `triage/` после переезда задачи `N` в архив: прежде гейт 2 такую находку пропускал, родитель у неё был. `archive N [--range <база>..HEAD]` печатает файлы под `docs/` и `CHANGELOG.md`, изменённые коммитами диапазона и коммитами с номером задачи в заголовке, — механическая половина строки «Доки тем же ходом», исход и проверки по-прежнему пишет approver (BS-33).
- **`gates` — раннер гейтов из конфига** — `backslop gates` гонит команды поля `gates` по порядку, берёт код возврата у самой команды, а не у пайпа, и печатает «гейтов N, зелёных M» со снимком дерева (`HEAD`, чистота). `--keep-going` досчитывает после первого красного, `--require-clean` механически проверяет «неподвижное дерево» из шага 4 скилла задачи, `--dry-run` печатает состав, `--json` отдаёт то же для брифа и `result.md`. Раньше worker гонял гейты по одной, а число в отчёте держал в памяти (BS-14).

- **Релиз бампит версию, а рассинхрон версий красит `lint`** — `npm run release -- X.Y.Z --bump` пишет `version` в `package.json`, переименовывает верхнюю секцию `CHANGELOG.md` в `## vX.Y.Z — <дата>` и ставит штамп `backslop.json` вызовом `init`, проверки идут до первой записи; одиннадцатый гейт `lint` (только в репозитории инструмента) краснеет на расхождении `package.json` со штампом, на отсутствии секции CHANGELOG на выпускаемую версию и на пине `#vX.Y.Z` или `backslop@X.Y.Z` в `README.md`, `README.ru.md`, `AGENTS.md`, называющем не её. Примеры установки в README переведены на обобщённую форму `#v<версия>` — там пин держался на `#v0.2.0` три релиза спустя (BS-29).

- **`archive` использует общий перенос и находит flat task** — перепись исходящих и входящих ссылок вынесена в `relocateTask`, а файл прямо в `docs/backlog/` теперь архивируется так же, как задача из каталога статуса (BS-43).

- **`merge-changelog` — слияние двух редакций CHANGELOG командой** — правило слияния жило только прозой скилла `backslop-batch`, и приёмка track'а собирала файл из двух редакций руками: стратегия `-X ours`/`-X theirs` молча теряла записи соседнего track'а, а в заходе 2026-09-05 понадобился одноразовый скрипт. Теперь `merge-changelog --ours <ref> --theirs <ref> [--base <ref>] [--out <файл>]` объединяет записи секции невыпущенного по заголовку `- **…**`, сохраняет жирные подгруппы и их порядок, снимает по `--base` запись, которой сторона лишилась, и оставляет обе редакции под меткой `<!-- backslop:conflict … -->`, когда тела одного заголовка разошлись ([ADR-013](docs/adr/adr-013-changelog-merge.md)) (BS-22).

- **`init` держит блок `.gitignore` для owned outputs** — правило «generated не коммитится» действовало с ADR-006, но нигде не было записано и ничем не поддерживалось: три проекта на backslop завели три разных `.gitignore` руками, один держал правило вне git вовсе. Теперь `init` пишет блок между `# backslop:start` и `# backslop:end` — строка `<корень harness>/backslop-*` на каждый выбранный adapter и `/CLAUDE.md`, когда на диске лежит наш stub, а не пользовательский файл. Чужие строки сохраняются; проект без adapters `.gitignore` не получает ([ADR-012](docs/adr/adr-012-owned-outputs-gitignore.md)) (BS-20).

- **Гейт парности шаблонов смотрит и содержание** — сравнивались только состав файлов и подстановки, поэтому пустой `description` в EN-скилле проезжал в `.cursor/rules/*.mdc` строкой `description: ""`, а пропавший раздел и кириллица в английском слое проходили `lint` зелёным. Добавлены три механические сверки без перевода текста: контракт фронтматтера скиллов (`name` и `description` непусты в обоих слоях, `name` равен имени каталога), число и уровень заголовков вне блоков кода, отсутствие кириллицы в `templates/en/` (BS-40).

- **Состав adapters — один источник** — тройка корней и имя canonical-скилла были записаны независимо в шести и более местах; теперь они лежат в `lib/adapters-registry.js`, а `TOOLS`, owned-пути, legacy-набор, `isAdapterRel` и улика legacy-конфига выводятся из него. Признак «репозиторий инструмента» для гейта парности шаблонов — тождество `templates/` проекта с каталогом, из которого рендерит запущенный CLI, а не файл `templates/skills/backslop-task/SKILL.md`: переименование скилла выключало гейт молча (BS-42).

- **`init` проверяет корни harness на symlink до первой записи** — раньше отказ приходил после `saveConfig` и скелета `docs/`, и проект с общим `.claude` оставался с конфигом, красным `lint` и советом запустить ту же падающую команду; `--tools none` из этого состояния не выводил. Теперь пути `.claude/skills`, `.cursor/rules`, `.agents/skills` — вместе с каждой их родительской компонентой — проверяются до записи и при любых `tools`, а отказ называет причину и лечение (BS-38).

- **Снятие adapter'а идёт по предикату владения** — `cleanupAdapters` удалял файл за одно совпадение пути с текущим шаблоном, поэтому чужой файл без маркера на таком пути стирался молча, а legacy-путь, выпавший из состава шаблонов, снятие переживал. Теперь кандидатов называют маркер, шаблоны и legacy-набор вместе, а удаляет только `isOwnedAdapterFile`; чужой файл на owned-пути остаётся и назван предупреждением `init` (BS-36).

## v0.4.0 — 2026-09-05

- **`mv` из плоского `docs/backlog/`** — файл задачи, лежащий прямо в `docs/backlog/` (чужой трекер до раскладки по статусам), `mv` теперь находит и переносит в каталог статуса с пересчётом исходящих ссылок от старого каталога к новому, как `archive`; раньше такой файл переезжал `git mv` руками, и `../reference/…` внутри рвались. Тот же пересчёт между каталогами статусов чинит ссылку на соседнюю задачу прежнего каталога (`BS-1-a.md` → `../queue/BS-1-a.md`) (BS-9).
- **Даты команд — по местному времени машины** — `today()` брал дату по UTC, и `mv N active` в час ночи (UTC+3) ставил вчерашнюю «Взята»; теперь «Создана», «Взята», «Отложена» и «Закрыта» — календарная дата машины (BS-8).
- **`backslop-batch`: общие файлы track'ов сливаются по единицам структуры, не стратегией** — раздел «Слияние и приёмка» запрещает `-X theirs`/`-X ours` для файлов, общих для track'ов (стратегия молча теряет hunk'и соседа и дублирует хвост): CHANGELOG — объединение пунктов по заголовку `- **…**`, документы — объединение секций по заголовку, списки в коде — руками с проверкой имён обеих сторон; мерило — пустой дифф с головой worker'а по его файлам. Находки под задачей N до слияния заводит только worker её track'а (BS-12).
- **`--title` со значением, начинающимся с дефиса** — `new strategy-flag --title "--strategy on spawn …"` падал отказом `parseArgs` «argument is ambiguous». Теперь такое значение принимается через пробел, если не совпадает с именем флага команды; совпадающее (`--title --queue`) — отказ с подсказкой `--title=…`, и эту форму называет `help` (BS-13).
- **`new` считает номер по всем worktree и локальным веткам** — не только по текущему дереву: файлы других worktree репозитория (`git worktree list --porcelain`, включая незакоммиченные) и деревья всех локальных веток (`git ls-tree`) занимают номера и sub-ID находок; чужой номер, сдвинувший свой, называется в выводе с веткой или worktree. Раньше worker в worktree и оркестратор в основном дереве выдавали один `N.k`, и это ловил только `lint` при слиянии — за заход трижды (BS-11).
- **`mv N queue --top | --after M` переставляет задачу, уже стоящую в очереди** — раньше отвечала «уже в queue/» и ничего не делала, README предлагал править «Порядок» руками. Теперь файл остаётся на месте, меняется только «Порядок» (соседи перенумеровываются шагом 10, когда целого места нет); без флага положения — отказ с подсказкой; `--after` на саму себя — отказ. `lint` (гейт 4) краснеет на двух файлах очереди с одним «Порядком» (BS-10).
