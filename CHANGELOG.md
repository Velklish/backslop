# Changelog

## Unreleased

- **`init --hooks` installs the agent hooks of Claude Code, Cursor and Codex** — a new `hooks` field of `backslop.json` lists the harnesses (`claude`, `cursor`, `codex`) whose project hook files carry backslop's start and stop records, which run `<cli> hook session-start` and `<cli> hook stop`. `init --hooks <list>` sets it, and a first `init` selects none. `init` writes the records into `<project>/.claude/settings.json`, `<project>/.cursor/hooks.json` and `<project>/.codex/hooks.json`, keeps every foreign key and hook in those files, rewrites its own records when `cli` changes, removes them when a harness is dropped, and refuses a file that is not valid JSON before the first write; user-level hook files are never touched. `lint` reports a missing record, a record with another `cli`, a duplicate or a record under another event (the file differs from what `init` writes), and a record of an unselected harness; owned records of an unselected harness behind a symlink are reported too, to be removed by hand, since `init` does not write through a link. With hooks selected, the `AGENTS.md` block gains one sentence: the stop hook returns the turn on `lint` errors in the files the session changed, and the errors are fixed, not bypassed. A project that runs promptobus Codex or Cursor participants should not select those hooks yet, and `init` says so.
- **`mv`, `archive` and `fold` refuse over an unreadable directory before they change anything** — the link walk ran after the card had moved (or the archive directory had gone and the journal line was written), so a directory it could not list left the card in its new place with no incoming link rewritten, and a repeat answered “already in” or “already archived”. The walk now runs first: the refusal names the directory as before, the tree is untouched, and the repeat works once the directory is readable.
- **The `backslop-task` report step says what an absent part of the `gates` summary means** — `gates` prints `, not run N` and ` (out of scope K)` only when the number is not zero, and reports in a run wrote `not run 0 (out of scope 0)` as if the tool had printed it. Both layers of the skill now say that an absent part means 0 and that the report says 0; the summary line itself is unchanged.
- **`tracks --json` keeps the status column of a `dirty` item** — the items were the `git status --porcelain` lines trimmed at both ends, so the leading space of an unstaged change was lost (`M a.txt`) and a fixed-column porcelain parser misread the two status letters. An item is now the line as git prints it (` M a.txt`), as `tree.dirty` of `gates --json` already was; the text listing prints the same lines.
- **`merge-changelog` keeps one blank line between merged entries when the section ends the file** — with no released section below, the blank line that ended the unreleased section stayed attached to the last entry of a side, so an entry of the other side placed after it was separated by two blank lines. The last entry of a side now keeps one trailing blank line when another entry or a `###` heading follows it in the result.
- **`lint` skips a missing adapter output that git ignores** — a fresh `git worktree` of a project lacks the gitignored adapter outputs and `CLAUDE.md`, and `lint` there named each one missing, so the first `gates` run was red for a reason that was not the worker's change. An output or the Claude stub that is absent and ignored by git in that working tree is now skipped, with one `git check-ignore` call per run. A present file is checked as before, an absent file that git does not ignore is still an error, and outside any git repository, such as a `git archive` copy unpacked outside every repository, nothing changes: `lint` stays red there. The same holds for a fresh clone and for an output deleted in the main checkout: `lint` no longer reports it there, so run `init` after cloning. The `backslop-batch` and `backslop-task` skills name a `git worktree` as the way to lint a base commit.
- **`hook` returns the turn of a coding agent on `lint` errors in the files it changed** — a new command for the agent hook records of Claude Code, Cursor and Codex: `hook session-start --harness <claude|cursor|codex>` records the start commit of the session under `backslop/hooks/` in the git directory of the working tree, and `hook stop --harness …` runs `lint` in the same process when the session changed a file and returns the turn on the errors in those files. The changed set is every path that differs between the start commit and the working tree, plus untracked files git does not ignore; an error in another file, an error without a file and every warning never return the turn. Claude Code and Codex get exit 2 with the errors on stderr, Cursor a `followup_message` on stdout. The turn is returned at most three times in a row whatever the errors are, then the stop lets it end with a note naming them; only a stop without errors resets the count. The hook never breaks a session: outside a git repository, without `backslop.json`, with unreadable input or on an error of its own it exits 0 with one note.
- **Upgrade: a documentation fix carries a check red on the old text, and the writer pass runs at release and at batch close** — step 3 of the `AGENTS.md` block gains two sentences: a documentation fix carries a check that fails on the old text (a `quote:` block, a test or a lint rule), and documentation does not cite tasks but states the contract, the rationale or the measurement. The Skills line names `backslop-writer`, `backslop-techdoc` and `backslop-humanizer`, and a sentence outside the numbered steps, under the same adapter condition, tells the agent to run the `backslop-writer` pass in release mode over the diff since the previous tag before a release commit. The `backslop-batch` skill gains a closing step after every track is accepted and before the last push of the run: the writer pass in batch-close mode over the run's range, filed as a task of its own whose `result.md` holds the ledger, with commits that carry the task prefix, reviewed like any piece, and findings filed under that task. The `backslop-task` skill names the regression check for a documentation fix and points to `backslop-writer` for style; the backlog README and the brief state the same rule. `migrate` redraws the backlog README and `init` redraws the block; a project with an `agents.stepOverrides` entry for step 3 should review its override, because the override replaces the two new sentences along with the rest of the step.
- **`links --external` checks the external links of the documents** — a new command requests every `http` and `https` link of the files gate 1 reads, one at a time, and prints `<class> <status or error> <url>` for each, then `links: N urls, D dead, U unverified`; `--json` prints one document instead. An address is `ok` on 2xx and 3xx, `unverified` on 401, 403, 408, 429, a 5xx or no answer, and `dead` on 404, 410 and every other status; the exit code is 0 when all are `ok`, 1 with a dead one, 2 with unverified ones only. The command stays out of `gates` and `lint`: a network answer is not reproducible. There are no retries and no authentication.
- **Upgrade: `lint` fails on task ids and tracker links in project documentation** — a new gate 15 reads the project documentation: root `README*.md`, every `.md` under `docs/` except `backlog/` and `archive/` (ADRs included), and the unreleased section of `CHANGELOG.md`. It fails on a task id `<prefix>-N` anywhere in those files, code included; on a link into `docs/backlog/` or `docs/archive/`, `LOG.md#…` included (the two rules files `backlog/README.md` and `archive/README.md` stay linkable); on an address into the same repository's backlog or archive, read from the `origin` remote on GitHub and GitLab; and on a `.json`, `.jsonl`, `.txt` or `.log` path in a code span or a link that names no tracked file. Each error names the file, the line, the class and the token, and says what to write instead: the contract, the rationale, or the measurement with its version and date. Gate 6 now checks mentions only outside that set: the backlog, the archive and released changelog sections. A project whose documentation carries task ids or tracker links turns red on upgrade until its own migration task clears them.
- **`backslop-writer` audits documentation** — a new audit mode runs under a task of its own and writes the upstream audit report (`Score`, `Shippable`, `Blocking`, `Findings`) for each document into the task result. Every finding is filed by severity: Blocking as a `critical` card, High as a `major` card, Medium and Low as `minor` entries, one per document and rule, and each record names the check the fix adds, one that fails on the old text. A document with `Shippable: no` holds the release pass until its Blocking findings are closed: a card by `archive`, a hypothesis entry by the batch that closes it. The audit edits no document, and `lint` computes no score.
- **Upgrade: ADRs hold current decisions only, and `lint` gate 8 reads ADR statuses** — gate 8 now fails on an ADR without a `**Status:**` line (the list-item form `- **Status:**` and the Russian label count), on a status word other than `Proposed` or `Accepted` (`Superseded`, `Superseded in part`, `Deprecated`, `Rejected`), on a status line that names another ADR by `ADR-NNN` or by a link to `adr-NNN-…`, on an ADR listed in two table rows of `docs/README.md`, and on a row whose Status cell differs from the status word of its file. The index principle in the `docs/README.md` template and step 3 of the `AGENTS.md` block now say that a new decision on a question already decided rewrites that question's ADR in place, an ADR that governs nothing is deleted, and a chain of ADRs on one question folds into its highest number; the `backslop-task` skill gains a “Changing a decision” section, and the `backslop-seed` ADR backfill records a decision that changed as the one that governs now, in one ADR. `migrate` does not redraw your `docs/README.md`: replace your copy of the first principle (“An accepted decision is not edited; it is superseded”) with the new text, then fold each chain of ADRs into its highest number and delete the replaced files before upgrading, or `lint` turns red.
- **The managed block tells how to talk to the owner and the skills point to it** — the `AGENTS.md` block gains a “Talking to the owner” item: a message to the owner is read without the queue, the run or the agent's context open; a question says what is asked, why, and what each answer changes; it uses no term or abbreviation the agent coined (worker slugs, “piece”, review codes), and a new definition is used only after the owner confirms it; a task is named by its number and its title, never by the number alone — the title goes at the first mention in a message, in every heading and in every table row, and later mentions in the same paragraph may use the number alone, and each list item counts as a paragraph. `backslop-task`, `backslop-batch`, `backslop-seed` and its ADR-backfill and glossary references link to that item where they report to the owner or ask them, and do not restate it. Re-run `init` to refresh the block and the skills.
- **`mv`, `archive` and `fold` rewrite every local link form gate 1 reads** — task moves now update HTML `<a href>` links, both destinations of a badge, and reference declarations inside a blockquote or list item, as well as inline links and line-start declarations. The rewrite uses the same parser positions as `lint`, matches the complete written filename including literal backticks, and keeps the written syntax; `mv` and `archive` preserve the `#…`/`?…` tail, while `fold` points matching task links at the archive journal anchor.
- **The adapters lay out `backslop-writer`, and `backslop.json` accepts writer scope** — every selected adapter now writes the `backslop-writer` skill for the technical-writer pass. The pass has release and batch-close modes, currency and style ledgers, project-rule precedence over `backslop-techdoc` and `backslop-humanizer`, and language rules for `lang: en` and `lang: ru`. A project may add `writer.style` and `writer.currency` glob arrays to extend the pass scope; unknown keys and non-string glob values are refused by field name. `init` does not write the object.
- **The adapters lay out two third-party writing skills** — every selected adapter, in every language, now also writes `backslop-humanizer` (humanizer by Siqi Chen) and `backslop-techdoc` (technical-documentation by Wondel.ai), each with its MIT `LICENSE` verbatim and a `SOURCE.md` naming the upstream commit and the modifications. For `cursor`, each becomes a `.mdc` rule with its references beside it. `--tools none` removes them, a repeated `init` updates them, and `lint` checks their links; a `LICENSE` is owned through the marked `SOURCE.md` beside it, so an unmarked `LICENSE` of your own in such a directory is kept and named.
- **The `backslop-batch` skill links the backlog README instead of restating it and spells every command with the configured CLI** — the triage, minor-batch and `--restore` paragraphs keep only the orchestrator's timing and point to `docs/backlog/README.md`. The track title is described as the brief heading, the skill says that `brief` exits 0 even with `[TODO` stubs, and the end-of-run check reads `total` of `tracks --json` because `tracks` exits 0 either way. The measurements reference says that `--measurements` carries only a three-point summary, names the macOS-specific `\s` failure of `git grep -E`, gives a concrete call-counting rule and drops the list of `--require-clean` refusal causes. Every runnable command in the skills is written through the project's configured `cli`, and the alias sentence is gone.
- **The `backslop-batch` integration steps give a per-task command, a containment check and a CHANGELOG reference** — step 1 states the real reason a second `merge --squash` of one branch conflicts (a squash commit does not record the worker branch as a parent) and gives one command per task: `git cherry-pick -n <task commits>`, or `git merge --squash <last commit of the task>` for the first. Step 3 no longer asks for an empty diff against the worker head, which fails on a correct merge when another track changed a shared file: it checks that every line the worker added, and every line the main branch added, is present in HEAD. The `merge-changelog` details moved to a new `references/merge-changelog.md`, which says to delete the `<!-- backslop:conflict … -->` line and that a leftover mark passes `lint` but makes the next `merge-changelog` refuse. Step 4 links the `backslop-task` acceptance recipe instead of restating it and carries its Windows note.
- **The `backslop-task` skill points to the `AGENTS.md` block instead of restating it** — “Task flow” opens with a pointer to steps 1–7 and keeps only what the block does not say. Step 4 of the skill and of the block names `gates --require-clean --base <base>` for a committed branch (without `--base` only uncommitted paths count and scoped gates are skipped), and the skill adds that gates stop at the first red unless `--keep-going` and that only the “out of scope” part of “not run N” is path filtering. The incident history and the “Real failures” section are gone, the English and Russian texts no longer drift apart, every runnable command in the skill uses the configured `cli`, and step 5 of the block and the skill say to run the `BACKSLOP_DRAFT` recipe in Git Bash on Windows. The `probeFailure` template key and `probe/failure.md` are removed with the section.
- **Probe text renders only when `probe` is declared** — without the field, the `backslop-task` skill, the brief and the `result.md` stub no longer ask for a mutation probe (the block already dropped it). With the field, the brief states "commit first" once, in the sentence that carries the command. The `result.md` stub written by `archive` names the project's `cli` in `<cli> gates` instead of a bare `backslop gates`.
- **Upgrade: `lint` checks heading anchors and every Markdown link form** — gate 1 now fails on a missing anchor (in another Markdown file or a same-file `#anchor`, by GitHub's heading slug, `-1`, `-2` for a repeated heading, or an explicit `id`), on a reference link whose label has no declaration, and on a broken HTML `<a href>` link or badge destination; links in code are still not read, and links inside HTML comments no longer count for gates 1, 8 and 13 — an ADR row inside a comment no longer satisfies gate 8. Upgrading can turn a project red: fix the fragment, the label or the path. Every error about a link names its line, `lint` prints what gate 1 read, and Markdown files without a single link are an error.
- **The backlog and archive rules state each rule once and describe both meanings of a `—` commit** — the “How it gets there” column of the backlog README keeps only commands; the triage exemption and the deferred rule each live in one bullet, the batch order in “Triage cadence”, and the draft-commit rule only in the archive README; the archive README and the journal header now say that a bulk fold drops a body missing from history unless `fold --embed-missing` puts it into the draft. `migrate` redraws the two READMEs on the next upgrade; the header of an existing `LOG.md` is not redrawn.
- **Template parity takes the English layer as the source** — `lint` in the tool's repository names a missing Russian twin of an English template and a Russian template without an English source, and on a placeholder or heading mismatch prints the English side as the expected one.
- **`README.ru.md` is no longer shipped** — the package carries one README, `README.md`, in English. It lists every command with a link to its reference section, says that `init` writes `lang: ru` unless `--lang` is given, describes closing a task through `fold` into the archive journal, and ends the update section with a post-upgrade checklist. The npm description is English too.
- **The glossary templates separate the Term and EN columns** — the English glossary now defines Term as the spelling in project prose and EN as the identifier in code only, and the `backslop-seed` glossary reference shows example rows where the two differ. The reference points to the glossary header for the column and `[?]` rules instead of restating them and no longer repeats the rule on proposing missing names.
- **The `backslop-seed` skill states the real end state and drops the roadmap** — Phase 4 no longer promises a green `lint`: right after `seed --queue-reference` it is red on the placeholder fields of the seeded tasks and on links to sections not written yet, and after Phase 3 only those links remain, so Phase 3 now tells the agent to fill every seeded `describe-<slug>` task and Phase 4 adds a `grep` for placeholder markers in the places `lint` does not check. The inventory marks which sources `seed --scan` reads and which are read by eye; ADRs migrated from another format are renamed to `adr-NNN-<slug>.md` (a foreign-named file already inside `docs/adr/` is renamed or moved out), take the next free numbers and stay `Proposed` until the owner accepts them; the survey and the fill steps no longer mention `ROADMAP.md`; every runnable command uses the configured `cli`.
- **The process ADR and the docs index stop restating the tool-owned READMEs** — the ADR written by `init` no longer lists the task layout, closed-task directories, skills and gates (it described directories that `fold` removes and skills a default project does not have); it states the decision, the version pin and links the backlog and archive READMEs and the backslop section of `AGENTS.md`. The docs index template drops the two principles the `AGENTS.md` block owns, and its archive row names the `LOG.md` journal. The hint printed when `docs/README.md` already exists no longer repeats the row text. Existing projects keep their copies.
- **The brief forbids a push and contact with the owner, and states one commit rule** — the worker brief gains a fixed line under "How to work": do not push, decision points go to the orchestrator and never to the owner directly. The commit bullet reads the same in both languages: commits per task, each prefixed with the task prefix, including review fixes and the task's `CHANGELOG.md` entry. The Russian brief also names "status directories" and "another track's files" the way the English one does.
- **The managed block tells a worker to commit and names the triage commit** — steps 1, 2, 4, 5 and 7 of the `AGENTS.md` block changed: step 4 tells the worker to commit to their branch with the task prefix before reporting; step 5 keeps one commit subject, `<prefix>-N: <what was done>`, and no longer carries the alternative `closed —` subject, the lint and push sentence or the worker-boundary sentence; step 7 commits the changes of the triage review as a separate commit with the subject `<prefix>: triage after <prefix>-N` after the acceptance commit, then `lint` on the final commit, then push; step 1 says a `major` finding outside the task is filed with `new <slug> --parent N[.M]` and its `Evidence:` line filled in, and a `major` or `critical` hypothesis takes `--minor --cost <level> --hypothesis --evidence`. The step 2 glossary rule names the owner as the addressee, the `Worker boundaries:` line allows new finding files through `new` and forbids `mv` and `archive` on existing task files, and the `status` sentence names the minor entries. The `backslop-task` skill states the same worker boundary and names the owner in the glossary rule; the brief carries the same finding routes. A project with `agents.stepOverrides` for steps 1, 2, 4, 5 or 7 should review its overrides.
- **An unreadable directory in the task scan, the link walk or the pin walk is worded** — a directory the task scan or the link and pin walks could not list stopped `status`, `mv`, `archive`, `fold`, `brief`, `show`, `new` and `upgrade` with an `EACCES` stack trace or a bare `<absolute path>: EACCES`. They now name the project-relative path, the reason and what the command could not do, in the wording `lint` already uses. `upgrade` keeps its “finish manually” hint when the pin walk fails after the pin was saved.
- **`tracks` names a locked worktree in its text listing** — a locked worktree showed only in `tracks --json` (`locked: true`), and the reader of the text listing learned it when `git worktree remove` refused. The text now adds a line for a locked worktree saying to run `git worktree unlock` first.
- **`mv … minor` reads a stub as gate 4 does** — `mv` counted only a bullet or a bare line as a `[TODO` placeholder, so a card with `1. [TODO: command]`, a task box or a table row with a placeholder cell moved to `minor/` and then failed `lint`. `mv` now applies the line rule of gate 4 in every section: a stub is cut from every section but “Evidence”, where it is replaced by the `--evidence` line or, without the flag, refused, and an all-placeholder table row there is cut. In a table row that also has a written cell only the placeholder cell is emptied, and the written cells stay.
- **`new` skips a status directory that is a file in another worktree** — `new` stopped with an `ENOTDIR` stack trace when another worktree held a file where a status directory, `archive/` or an archive `minor/` belongs. Such a path now counts as holding no tasks, as in the working tree itself.
- **`lint` and `new` refuse a file where `docs/backlog` or a status directory is expected** — `lint` stopped with an `ENOTDIR` stack trace when `docs/backlog` was a file, and `new` with `ENOTDIR` or `EEXIST` when `docs/backlog` or the status directory it writes into was one. `lint` now reports the path as “a file, expected a directory”, and `new` refuses with the same wording `mv` uses, before it writes anything.
- **`new` sees numbers taken on other branches whatever the `docs` spelling** — with `"docs": "./docs"` or `"docs": "docs/"` in `backslop.json`, `new` did not see a task number taken on another branch and handed it out again. The path is now compared the way git prints it.
- **A pin with a suffix is not the cli pin** — `upgrade` matched the version prefix of `#v0.1.0x` or `#v0.1.0-rc.1` as the pin `#v0.1.0` and rewrote it to `#v0.2.0x`, keeping the suffix. A pin of the project's `cli` now ends at its version and `upgrade` leaves a suffixed one as written; `lint` reports it in a gate, the probe or a live file as a pin with a suffix that is not the cli pin, to fix by hand, and `upgrade` does not say “already on” while one stays. The pin in prose that gate 11 reads in the tool repository is unchanged.
- **`upgrade` pins a floating cli inside a quoted gate command** — a gate such as `sh -c "npx github:me/proj lint"` kept the floating form after `upgrade` pinned `cli`, because only whitespace and shell operators counted as word boundaries. A single or double quote now bounds the form too, and the command moves like an unquoted one.

## v0.12.0 — 2026-09-29

- **`docs/ROADMAP.md` leaves the layout** — `init` no longer creates it. `upgrade` and `migrate` delete an untouched, unlinked copy with its row in `docs/README.md` and keep an edited or linked one with a warning.
- **Upgrade: add `lang` and `tools`, rename `Area:` to `Scope:`, lead release headings with a version** — a config missing either field is refused; `## Release 1.2.3` is no release. `lint` now reports a stub behind a `[TODO` field and an unmarked skill-path file; pins below 0.9.0 are unsupported.
- **Only the generated marker makes an adapter file backslop's** — an unmarked file at a skill path is foreign: `init` leaves it and warns. A leading BOM, or the marker on a last line without a newline, no longer makes a generated file foreign.
- **`lint` and `mv` read placeholders and links more precisely** — `lint` reports a placeholder behind a `[TODO` field name, `mv … minor` keeps a written Scope, and `mv`, `archive` and `fold` rewrite percent-encoded links.
- **Git failures and time caps are named, not guessed** — `show`, `archive --range`, `gates` and `fold` refuse with the git cause instead of reading a failure as no repository. An `upgrade` step that hits the time cap fails.
- **Line endings and BOMs survive rewrites** — `init` keeps the line endings of `AGENTS.md` and `.gitignore`, `migrate` keeps the BOM of the rules it redraws, adapter outputs are always LF, and a `package.json` with a BOM is read.
- **`lint` names an unreadable directory instead of crashing** — it refuses with the path from the project root and the error code, and `upgrade`, `archive`, `fold` and `mv` refuse on the same directories.
- **Stricter arguments and consistent messages** — an extra positional argument is refused, messages follow the project language (both outside a project), hints name the project `cli`, and routine reports go to stderr. `changelog` and `merge-changelog` accept an otherwise invalid config.

## v0.11.1 — 2026-09-25

- **`upgrade` finishes from a pinned project** — from v0.9.0–v0.11.0 it now finishes, checks the version the new `cli` runs, starts from the lower of pin and stamp, moves every pin in `gates` and `probe`, and pins a floating `cli`.
- **Commands refuse before they damage a file** — `init` refuses a non-UTF-8 `AGENTS.md`, `upgrade` skips non-UTF-8 and symlinked files, `migrate` refuses when git fails, block markers count only as whole lines, and `init`, `mv`, `new`, `adr` check paths first.
- **Links resolve as GitHub renders them** — `/…` starts at the repository root, `#` and `?` end the target, escapes decode, any URI scheme is external, and self-links follow `mv` and `archive`. `.MD` files and root symlinks are walked.
- **`seed` reads real repositories** — `seed --queue-reference` writes Scope in the project language, keeps rows sharing a basename apart; `seed --scan` lists only `bin/` scripts, reads YAML block scalars, skips linked worktrees, quotes .NET paths.
- **`fold` and `show` keep task bodies safe** — `fold N` refuses while git lacks an attachment, bodies survive git's message cleanup, CRLF stays CRLF, and `show N` finds bulk-embedded bodies.
- **`new`, `tracks` and `gates` handle monorepos and git failures** — `new` sees other branches' numbers in subdirectory projects, `tracks` names gone worktrees, `gates` judges only the project's tree, and git failures refuse.
- **Stricter config, flags and `merge-changelog`** — a blank gate, a non-string `prefix` and an unsafe `init --dir` are refused, a BOM in `backslop.json` is ignored, and `-h` can be a flag value. `merge-changelog` keeps theirs' headings and line endings; `--out` follows the current directory.
- **Upgrade: fix what `lint` newly reports** — case-only link mismatches, misnamed ADR files, malformed quote markers and placeholders in numbered items, task boxes and tables are now errors, and an unknown `lint` flag fails. Journal entry pins are history.

## v0.11.0 — 2026-09-24

- **Upgrade: keep local rules elsewhere and name outcomes** — `migrate` redraws `docs/backlog/README.md` and `docs/archive/README.md` on every upgrade, losing committed edits. `lint` now wants an outcome word in every unfolded `result.md` and a file, not a directory, behind a task link.
- **`result.md` must name its outcome** — gate 5 and `fold N` want completed, rejected or merged into `<prefix>-N` (or Russian forms) in the first paragraph or heading. A bare "Closed" fails; a placeholder quoted in code is not a stub.
- **`fold` reads outcomes and revisions more accurately** — the first outcome word decides, "merged into" needs a task id, and `Outcome:` reads as completed. Bulk `fold` records the last commit that touched the task directory and checks each file against it.
- **`fold` rewrites root and trailing-slash links** — a link into the folded directory that cannot be rewritten is listed. `fold N` asks to commit the draft only when the body is not in history, and the batch skill names `fold M`.
- **`show N` handles large commits** — it prints a body from the commit message without the diff, and every git call reads up to 256 MiB, so large output is no longer cut off.
- **`mv` requires evidence for `minor/` and restores batches in order** — `mv N minor` refuses without an Evidence section or `--evidence`. `mv <N…> queue --restore` goes by descending saved numbers; a task whose place falls behind a batch neighbour goes right before it, and a line says so.
- **`merge-changelog` works after a version bump** — the unreleased section is the first without a version, or else the top one without a tag, and the report names it per side; the blank line before the next section is kept.
- **Stricter link checks and clearer git failures** — the task link rule covers reference-style links, and the rules name `quote:before:` for a task's own code. `gates` counts a gate that fails to start as red, and git killed by a signal is named.
