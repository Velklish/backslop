# backslop — репозиторий инструмента

Здесь живёт сам backslop: CLI (`bin/`, `lib/`), шаблоны всего, что он кладёт в проекты (`templates/`), тесты (`test/`) и документация устройства (`docs/`). Свой бэклог репозиторий ведёт тем же инструментом — команда здесь `node bin/backslop.js`.

Правило одно на весь репозиторий: **шаблоны — источник, `docs/` и `.claude/` — результат.** Правило процесса меняется в `templates/skills/**` или `templates/docs/**`, после чего `node bin/backslop.js init` переписывает скиллы здесь; править `.claude/skills/backslop-*` напрямую бесполезно. Меняется поведение команды — тем же ходом справочник `docs/reference/`, README и CHANGELOG; меняется контракт (форматы файлов, команды, состав `status --json`) — новый ADR.

Гейты: `npm test` и `node bin/backslop.js lint` зелёные. Проверку гейта `lint` подтверждай красной пробой в `test/lint.test.mjs`.

## Задачи и решения — backslop

Трекер задач и журнал решений живут в `docs/` и ведутся командой `node bin/backslop.js` (конфиг — `backslop.json`, префикс задач — `BS`). Списка задач в файлах нет: очередь, работу, отложенное и triage печатает `node bin/backslop.js status`. Правила ведения — `docs/backlog/README.md`, термины — `docs/GLOSSARY.md`.

**Скиллы:** `backslop-task` — цикл одной задачи; `backslop-batch` — заход worker'ами по track'ам; `backslop-seed` — наполнение документации после установки.

**Процедура изменения.** Роли две: worker правит и проверяет (шаги 1–4), approver принимает и закрывает (5–7); одиночный агент совмещает обе и идёт по шагам подряд.

1. **Задача.** Возьми первую в очереди (`node bin/backslop.js status`) или заведи: `node bin/backslop.js new <slug> --title "…"` — в triage, с `--queue` — сразу в очередь. Мелочь без следа в трекере допустима, если правка исчерпывается одним заходом и не меняет контракт. Находка, которую этот заход не закроет, — сразу файл: `node bin/backslop.js new <slug> --parent N`, с уликой.
2. **Правка.** Реверс прежнего решения — чистым удалением, без зачёркиваний и пометок «отменено». Стиль существующего файла сохраняй. Термины — из глоссария; нужного нет — предложи, молча не выдумывай.
3. **Доки тем же ходом.** Незадокументированное изменение считается незавершённым: справочник `docs/reference/`, README затронутой подсистемы, CHANGELOG. Архитектурное решение — `node bin/backslop.js adr <slug>` и строка в таблицу `docs/README.md`.
4. **Гейты до отчёта.** Команды из `gates` в `backslop.json` зелёные. Правку теста проверяй мутационной пробой: сначала коммит, потом проба.
5. **Приёмка и архив** — approver'ом, одним ходом: ревью диффа, `node bin/backslop.js archive N`, дописать `result.md` (исход, что сделано, чем проверено), `node bin/backslop.js lint` зелёный. Worker свою работу принятой не объявляет и файлы задач между каталогами не двигает.
6. **Разбор triage** — сразу после закрытия: каждой записи ход — слить, уточнить, `node bin/backslop.js mv N queue`, `node bin/backslop.js mv N deferred` с условием возврата. К владельцу — только за отказом.
7. **Фиксация.** Коммит с номером задачи первым в сообщении: `BS-N: <что сделано>`.

Границы worker'а: правит только свою ветку или worktree, каталоги статусов и `docs/archive/` не трогает; закрытие и triage — approver.
