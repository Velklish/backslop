# backslop — репозиторий инструмента

Здесь живёт сам backslop: CLI (`bin/`, `lib/`), шаблоны всего, что он кладёт в проекты (`templates/`), тесты (`test/`) и документация устройства (`docs/`). Свой бэклог репозиторий ведёт тем же инструментом — команда здесь `node bin/backslop.js`.

Правило одно на весь репозиторий: **шаблоны — источник, adapter outputs — локальный generated результат.** Правило процесса меняется в `templates/skills/**` или `templates/docs/**`; английский близнец — в `templates/en/` с тем же составом. Правка процессного текста в `templates/docs/backlog/README.md` или `templates/docs/archive/README.md` тем же коммитом обновляет одноимённый файл в `docs/` этого репозитория: только эта пара рендерится из шаблона 1:1, а `GLOSSARY.md`, `README.md`, `ROADMAP.md` и `reference/README.md` осознанно наполнены проектным контентом и с шаблоном расходятся. Self-host держит `tools: []` в `backslop.json`, поэтому `init` здесь не создаёт `.claude/`, `.cursor/` и `.agents/skills/`. Править generated skills и rules напрямую бесполезно. Меняется поведение команды — тем же ходом справочник `docs/reference/`, README и CHANGELOG; меняется контракт (форматы файлов, команды, состав `status --json`) — новый ADR.

Гейты: `node bin/backslop.js gates` зелёный — он гонит `node bin/backslop.js lint` и `npm test` из поля `gates`. Проверку гейта `lint` подтверждай красной пробой в `test/lint.test.mjs`. Своей команды пробы у репозитория нет, поэтому нет и поля `probe` в `backslop.json`, а шаг 4 блока его не называет: порти код руками, сначала коммит, потом проба.

Фаза разработки: работа идёт прямо в `main`, без веток и MR; в `origin` каждая задача уезжает одним коммитом `BS-N: …` — промежуточные коммиты схлопываются перед пушем.

**Комментарии.** Код самодокументируем, и инлайн-комментарий длиннее двух строк не пишется (решение владельца, 2026-09-12). Строка комментария — не шире 100 знаков: абзац, сложенный в две длинные строки, — всё тот же абзац. Нюанс, не умещающийся в две строки, либо не пишется вовсе, либо уезжает в документацию — `docs/reference/`, README затронутой подсистемы или ADR, — а рядом с кодом остаётся короткий указатель, и только там, где без него нюанс не найти. Происхождение в комментарии не живёт: номер задачи, дата, «замечание ревью», пересказ строк под собой принадлежат git и трекеру. Причина измеримая, а не стилевая: этот код читают агенты, и абзац над функцией оплачивается токенами на каждом чтении файла. Правило держит гейт `test/comment-length.test.mjs` внутри `npm test`; накопленный долг вынесен снимком в `test/fixtures/comment-sweep-pending.json`, и этот список умеет только уменьшаться. Что гейт ловит, а что нет — [ADR-028](docs/adr/adr-028-two-line-comment-rule-and-its-gate.md), ширина — [ADR-038](docs/adr/adr-038-comment-line-width-under-gate.md).

**Релиз.** Публикация в npm не планируется (решение владельца 2026-09-24, BS-2.1 отклонена), default `cli` — GitHub-форма — и релиз идёт как `npm run release -- X.Y.Z --no-publish` из чистого `main`: версия в `package.json` совпадает с аргументом, локальный `main` — fast-forward от `origin/main`, гейты зелёные, `pack --dry-run` не пачкает дерево, локальный тег, `push --dry-run`, atomic push `main` и тега. Это штатный путь, а не обход скрипта: до BS-2.1 тег ставится только им. Без флага тот же скрипт делает и `npm publish` — эта форма включается, когда BS-2.1 вернётся по своему условию (владелец выбрал версию и подтвердил готовность npm auth и 2FA). Сбой после тега — смотри сообщение скрипта, не выдумывай следующий шаг. Версию бампит отдельный ход того же скрипта, до релиза и до коммита: `npm run release -- X.Y.Z --bump` пишет `version` в `package.json`, переименовывает верхнюю секцию `CHANGELOG.md` в `## vX.Y.Z — <дата>` и ставит штамп `backslop.json` вызовом `init`; дифф проверяет и коммитит агент. Рассинхрон этих чисел и устаревший пин в прозе README красит одиннадцатый гейт `lint`.

## Задачи и решения — backslop

Трекер задач и журнал решений живут в `docs/` и ведутся командой `node bin/backslop.js` (конфиг — `backslop.json`, префикс задач — `BS`). Списка задач в файлах нет: очередь, работу, отложенное и triage печатает `node bin/backslop.js status`. Правила ведения — `docs/backlog/README.md`, термины — `docs/GLOSSARY.md`. Версия раскладки — поле `version` в `backslop.json`; обновление backslop — `node bin/backslop.js upgrade`, по своему решению, а не по чужому коммиту.

**Скиллы (если выбран adapter):** `backslop-task` — цикл одной задачи; `backslop-batch` — заход worker'ами по track'ам; `backslop-seed` — наполнение документации после установки.

**Процедура изменения.** Роли две: worker правит и проверяет (шаги 1–4), approver принимает и закрывает (5–7); одиночный агент совмещает обе и идёт по шагам подряд.

1. **Задача.** Возьми первую в очереди (`node bin/backslop.js status`) или заведи: `node bin/backslop.js new <slug> --title "…"` — в triage, с `--queue` — сразу в очередь. Мелочь без следа в трекере допустима, если правка исчерпывается одним заходом и не меняет контракт. Находка идёт с меткой цены: `critical` чини сейчас, `major` в области текущей задачи чини сейчас, `major` вне её — сразу файл `node bin/backslop.js new <slug> --parent N[.M]` с уликой, `minor` и гипотезу — `node bin/backslop.js new <slug> --parent N[.M] --minor --evidence "…"`; без улики команда отказывает.
2. **Правка.** Реверс прежнего решения — чистым удалением, без зачёркиваний и пометок «отменено». Стиль существующего файла сохраняй. Термины — из глоссария; нужного нет — предложи, молча не выдумывай.
3. **Доки тем же ходом.** Незадокументированное изменение считается незавершённым: справочник `docs/reference/`, README затронутой подсистемы, CHANGELOG. Архитектурное решение — `node bin/backslop.js adr <slug>` и строка в таблицу `docs/README.md`.
4. **Гейты до отчёта.** `node bin/backslop.js gates` зелёный: команды из `gates` в `backslop.json`, код каждой и счёт «гейтов N, зелёных M». Запись с областью `when` на нетронутых путях пропускается: пропущенное идёт отдельным числом «не запущено N», к зелёным не прибавляется и называется в отчёте отдельной строкой.
5. **Приёмка и архив** — approver'ом, одним ходом: ревью диффа, `node bin/backslop.js archive N`, дописать `result.md` (исход, что сделано, чем проверено), `node bin/backslop.js fold N > "$(git rev-parse --git-dir)/BACKSLOP_DRAFT"` — каталог сворачивается в строку `docs/archive/LOG.md`, а тело задачи уезжает в заготовку сообщения коммита, которая ложится вне рабочего дерева. Между `archive N` и `fold N` не коммить: такой коммит станет ревизией строки журнала, и squash унесёт её из истории. Итоговый коммит приёмки несёт заготовку сообщением: `git add -A`, `git reset --soft <база>`, `git commit -F "$(git rev-parse --git-dir)/BACKSLOP_DRAFT"` — subject можно заменить на `BS-N: закрыта — …`, тело оставь; `fixup` поверх коммита worker'а заготовку выбрасывает. `node bin/backslop.js lint` зелёный на итоговом коммите, до пуша. Worker свою работу принятой не объявляет и файлы задач между каталогами не двигает.
6. **Разбор triage** — сразу после закрытия: каждой записи ход — слить, уточнить, `node bin/backslop.js mv N queue`, `node bin/backslop.js mv N deferred` с условием возврата. К владельцу — только за отказом.
7. **Фиксация.** Коммит с номером задачи первым в сообщении: `BS-N: <что сделано>`. В основную ветку задача уезжает одним коммитом: взятие и правки по ревью схлопываются в коммит приёмки из шага 5, а после свёртки squash не делается — он выбросил бы заготовку, единственное хранилище тела задачи.

Границы worker'а: правит только свою ветку или worktree, каталоги статусов и `docs/archive/` не трогает; закрытие и triage — approver.
