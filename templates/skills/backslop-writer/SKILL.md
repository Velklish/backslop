# backslop-writer — технический проход writer

Запускай этот проход, когда документацию нужно сверить с кодом. Это не механический гейт `lint`: это проход чтением, с уликами, правками и ledger. Режим audit — исключение по правкам: он не меняет ни одного документа и заводит то, что нашёл.

## Приоритет

Применяй первый источник, который отвечает:

1. Правила самого проекта: `AGENTS.md`, `{{docs}}/GLOSSARY.md`, руководство для контрибьюторов или по стилю, если оно есть.
2. `backslop-techdoc`.
3. `backslop-humanizer`.

Сначала загрузи этот скилл, затем по необходимости два скилла письма выше.

## Область

Документация, которую читают люди, проходит и проверку актуальности (currency), и проверку стиля:

- корневые `README*.md`;
- секция `Unreleased` файла `CHANGELOG.md`;
- `{{docs}}/**`, кроме `{{docs}}/backlog/**` и `{{docs}}/archive/**`;
- маски из `writer.style` в `backslop.json`.

ADR входят в область. Правка стиля в ADR не меняет решение; когда нужно изменить само решение, заведи задачу с уликой.

Маски из `writer.currency` задают область только для проверки актуальности. Используй их для мест, которые описывают поведение, но не являются прозой для читателей и могут устареть: исходник справки CLI, поставляемые скиллы и промпты.

Тексты для агентов освобождены от проверки стиля: скиллы, промпты, `AGENTS.md`, карточки бэклога и архив. В проверку актуальности они входят, только когда `writer.currency` их называет.

## Локальные правила

- Неодушевлённое подлежащее разрешено: "The command exits with code 2".
- Справочный текст сохраняет однородные предложения.
- Жирный шрифт — только для флага, строки интерфейса или заголовка в строке.
- Английский текст пиши без сокращённых форм вроде "don't".
- Не добавляй к процедуре хвост "What's next".
- Сохраняй стиль тире, который уже использует файл.
- Не меняй утверждение о поведении, пока не сверил его с кодом.

## Язык

Для `lang: en` применяй и `backslop-techdoc`, и `backslop-humanizer`.

Для `lang: ru` выполняй проверку актуальности и структурные правила `backslop-techdoc`. Его раздел "Non-English documents" пропускает правила `[EN]`. `backslop-humanizer` применяй только к английским фрагментам.

Переведённый README, например `README.ru.md`, проверяется как точный аналог исходного файла (faithful counterpart): его утверждения о фактах сверяются с оригиналом и с кодом, а исправляется только факт, который противоречит коду или оригиналу. Ничего не удаляй, не добавляй и не переписывай ради зеркала оригинала. Факт, который есть в оригинале, но отсутствует в переводе, этот проход не добавляет: запиши его в строку currency ledger и заведи задачу с уликой. Не переписывай перевод английскими скиллами.

## Режим release

Вход: `git diff <предыдущий тег>..HEAD`.

Выполни проверку актуальности и проверку стиля по всей области. Коммиты, меняющие поведение, ведут currency ledger, а паттерны `backslop-humanizer` ведут style ledger.

## Режим batch close

Вход: `<база захода>..HEAD`.

Выполни только проверку актуальности. Выбери из входа коммиты, меняющие поведение, затем проверь каждый документ и каждое настроенное место проверки актуальности, которое описывает изменённое поведение, даже если diff этого места не коснулся. Не правь стиль документации при закрытии пачки.

## Режим audit

Вход: документы для аудита или область документации выше. Запускай аудит отдельной задачей, а не внутри прохода release или batch close: он ничего не чинит, а только заводит находки.

Для каждого документа:

1. Загрузи `backslop-techdoc` и прочитай его `references/audit-checklist.md` до первой находки. Называй только те ID правил, которые прочитал там.
2. Сначала применяй правила самого проекта, как в разделе «Приоритет», и назови файл, который соблюдал, в строке `Local style guide` отчёта.
3. Прочитай документ как его читатель, затем сверь каждую команду, флаг и утверждение о поведении с кодом, и только потом оценивай стиль. Утверждение документа о самом проекте, которое код не подтверждает, — непроверяемый факт: подтверждённая находка Blocking самого документа, а не гипотеза. Утверждение о поведении другого продукта, которое не удалось проверить самому, — не этот случай: это предположение, его заводят записью `--hypothesis` с ценой по разделу «Заведение находок», а не подтверждённой находкой Blocking.
4. Напиши отчёт аудита, затем заведи каждую находку.

Документ `lang: ru` идёт по разделу «Non-English documents» чеклиста: пропущенные правила `[EN]` запиши в строку `Language`. Переведённый README проверяется как точный аналог (faithful counterpart), как в разделе «Язык»: факт, которого нет в переводе, — находка, а не переписывание.

Режим audit не ведёт ни currency ledger, ни style ledger: результат несут отчёт и заведённые записи.

## Отчёт аудита

Напиши по одному отчёту на документ в результат задачи, в формате исходного аудита: `backslop-techdoc`, раздел "Running the Audit, Rewrite, or Write". Формат здесь не пересказывай. Поля, на которые опирается этот скилл:

- `Score` — пройденные строки Quick Diagnostic из 10, без частичных баллов;
- `Shippable` — `yes` или `no`, решается только находками Blocking и никогда баллом: одна находка Blocking делает документ на 9/10 `no`;
- `Blocking` — неверные или непроверяемые факты, процедура, которую нельзя выполнить, информация, которую несёт только картинка; `none`, когда их нет;
- `Language` и `Local style guide` — пропущенные правила и соблюдённый файл;
- `Findings` — одна строка на срабатывание: место, ID и название правила, до, после, серьёзность (Blocking, High, Medium или Low).

Добавь в таблицу `Findings` колонку `Filed as` с записью, в которую ушла каждая находка. Находка без записи не закончена.

## Заведение находок

Каждая находка заводится, а серьёзность решает, куда. `N` — номер задачи аудита.

| Серьёзность | Метка цены | Запись |
|---|---|---|
| Blocking | `critical` | карточка, `{{cli}} new <slug> --parent N --cost critical`, с уликой; сразу поднимай её оркестратору, а когда его нет — владельцу, не дожидаясь результата задачи |
| High | `major` | карточка, `{{cli}} new <slug> --parent N --cost major`, с уликой в строке `Улика:` её раздела «Контекст» |
| Medium, Low | `minor` | запись, `{{cli}} new <slug> --parent N --minor --evidence "…"` |

- Улика — `file:line` документа и код, команда или вывод, которые опровергают или подтверждают утверждение. Находка, которую не удалось проверить самому (команду здесь не запустить, улика недоступна), — предположение; это не то же, что факт документа, который код не подтверждает: Blocking или High заводи как `{{cli}} new <slug> --parent N --minor --cost <level> --hypothesis --evidence "…"`.
- Срабатывания Medium и Low с общим документом и правилом — одна запись со всеми местами.
- Запись, цитирующая старый текст, берёт `<!-- quote:before:<path> -->`, а не обычный `quote`: правка меняет процитированные строки.
- Не чини находку в аудите, даже односложную.

## Регрессионная проверка

Каждая заведённая запись называет проверку, которая упадёт на старом тексте, и место, где она будет жить. Запись пишется до правки, поэтому проверки ещё нет: её добавляет правка. Карточка называет её в разделе «Проверки», запись minor — в тексте `--evidence`, после улики. Проверка — одно из:

- тест, который утверждает исправленное положение;
- правило `lint`;
- блок `<!-- quote:<path> -->` гейта 10 с исправленным текстом. Он охраняет, только когда лежит в документе, который не в архиве и не совпадает ни с цитируемым файлом, ни с записью: блок внутри своего же файла всегда находит собственное тело, а запись в архиве или после fold уже не проверяется.

Проверка, которая проходит и на старом тексте или не может упасть, проверкой не является.

## Блокировка релиза

Документ, в отчёте аудита которого `Shippable: no`, держит проход release, пока не закрыта каждая находка Blocking этого отчёта. Находка закрыта, когда её карточка в архиве (`{{cli}} archive N.k`), а для записи-гипотезы — когда пачка закрыла её (`{{cli}} archive N.k --into M`) после проверки или отклонения гипотезы. Пока хоть одна открыта, проход release называет в результате документ и открытые записи и не объявляет документацию готовой.

Записи бери из колонки `Filed as` отчёта, в результате задачи аудита (`{{cli}} show N` печатает его, когда задача свёрнута). `{{cli}} status` показывает открытые записи, но не отличает `critical` от `major`, поэтому по нему их не найти.

## Currency ledger

В результате задачи укажи одну строку на каждый коммит из входа, который меняет поведение.

Каждая строка содержит:

- коммит;
- что изменилось;
- место в документации, которое теперь описывает поведение, или причину, почему запись не нужна;
- улику из кода в форме `file:line`.

Если утверждение выглядит устаревшим, но код показывает, что поведение не менялось, запиши этот факт и оставь текст как есть.

## Style ledger

В режиме release укажи одну строку на каждый паттерн `backslop-humanizer`.

Каждая строка содержит:

- паттерн;
- найденные срабатывания;
- сделанные правки;
- оставленные срабатывания вместе с локальным или проектным правилом, которое их сохраняет.

Строка есть и без правок. Проход завершён, когда пройден каждый паттерн, а не когда каждый паттерн дал переписывание.

## Output

Сделай один коммит на группу документов: справочник, руководства, ADR, README и индекс, changelog.

Всё, что требует правки кода или решения, не исправляй этим проходом. Заведи задачу с уликой. Режим audit коммитит только заведённые им записи.

Ревьюер выборочно сверяет переписанные места с кодом: смысл не должен измениться, и не должно появиться новых непроверенных утверждений.
