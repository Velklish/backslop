# backslop-writer — технический проход writer

Запускай этот проход, когда документацию нужно сверить с кодом. Это не механический гейт `lint`: это проход чтением, с уликами, правками и ledger.

## Приоритет

Применяй первый источник, который отвечает:

1. Правила самого проекта: `AGENTS.md`, `{{docs}}/GLOSSARY.md`, руководство для контрибьюторов или по стилю, если оно есть.
2. `backslop-techdoc`.
3. `backslop-humanizer`.

Сначала загрузи этот скилл, затем по необходимости два скилла письма выше.

## Область

Документация, которую читают люди, проходит и проверку актуальности (currency), и проверку стиля:

- корневые `README*.md`;
- секция `Unreleased` файла `CHANGELOG.md`;
- `{{docs}}/**`, кроме `{{docs}}/backlog/**` и `{{docs}}/archive/**`;
- маски из `writer.style` в `backslop.json`.

ADR входят в область. Правка стиля в ADR не меняет решение; когда нужно изменить само решение, заведи задачу с уликой.

Маски из `writer.currency` задают область только для проверки актуальности. Используй их для мест, которые описывают поведение, но не являются прозой для читателей и могут устареть: исходник справки CLI, поставляемые скиллы и промпты.

Тексты для агентов освобождены от проверки стиля: скиллы, промпты, `AGENTS.md`, карточки бэклога и архив. В проверку актуальности они входят, только когда `writer.currency` их называет.

## Локальные правила

- Неодушевлённое подлежащее разрешено: "The command exits with code 2".
- Справочный текст сохраняет однородные предложения.
- Жирный шрифт — только для флага, строки интерфейса или заголовка в строке.
- Английский текст пиши без сокращённых форм вроде "don't".
- Не добавляй к процедуре хвост "What's next".
- Сохраняй стиль тире, который уже использует файл.
- Не меняй утверждение о поведении, пока не сверил его с кодом.

## Язык

Для `lang: en` применяй и `backslop-techdoc`, и `backslop-humanizer`.

Для `lang: ru` выполняй проверку актуальности и структурные правила `backslop-techdoc`. Его раздел "Non-English documents" пропускает правила `[EN]`. `backslop-humanizer` применяй только к английским фрагментам.

Переведённый README, например `README.ru.md`, проверяется как точный аналог исходного файла (faithful counterpart): его утверждения о фактах сверяются с оригиналом и с кодом, а исправляется только факт, который противоречит коду или оригиналу. Ничего не удаляй, не добавляй и не переписывай ради зеркала оригинала. Факт, который есть в оригинале, но отсутствует в переводе, этот проход не добавляет: запиши его в строку currency ledger и заведи задачу с уликой. Не переписывай перевод английскими скиллами.

## Режим release

Вход: `git diff <предыдущий тег>..HEAD`.

Выполни проверку актуальности и проверку стиля по всей области. Коммиты, меняющие поведение, ведут currency ledger, а паттерны `backslop-humanizer` ведут style ledger.

## Режим batch close

Вход: `<база захода>..HEAD`.

Выполни только проверку актуальности. Выбери из входа коммиты, меняющие поведение, затем проверь каждый документ и каждое настроенное место проверки актуальности, которое описывает изменённое поведение, даже если diff этого места не коснулся. Не правь стиль документации при закрытии пачки.

## Currency ledger

В результате задачи укажи одну строку на каждый коммит из входа, который меняет поведение.

Каждая строка содержит:

- коммит;
- что изменилось;
- место в документации, которое теперь описывает поведение, или причину, почему запись не нужна;
- улику из кода в форме `file:line`.

Если утверждение выглядит устаревшим, но код показывает, что поведение не менялось, запиши этот факт и оставь текст как есть.

## Style ledger

В режиме release укажи одну строку на каждый паттерн `backslop-humanizer`.

Каждая строка содержит:

- паттерн;
- найденные срабатывания;
- сделанные правки;
- оставленные срабатывания вместе с локальным или проектным правилом, которое их сохраняет.

Строка есть и без правок. Проход завершён, когда пройден каждый паттерн, а не когда каждый паттерн дал переписывание.

## Output

Сделай один коммит на группу документов: справочник, руководства, ADR, README и индекс, changelog.

Всё, что требует правки кода или решения, не исправляй этим проходом. Заведи задачу с уликой.

Ревьюер выборочно сверяет переписанные места с кодом: смысл не должен измениться, и не должно появиться новых непроверенных утверждений.
