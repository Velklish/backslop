# Backfill ADR: как записать решения, которые уже приняты

Читается в фазах 2–3 скилла `backslop-seed`. Первый ADR — про сам процесс — уже лежит после `{{cli}} init`; здесь про остальные.

## Сколько и какие

- **3–5 решений**, не вся история. Критерий: решение до сих пор ограничивает правки — сменить его дорого, и следующий читатель спросит «почему так». Фреймворк, хранилище, брокер, формат API, слоистость — обычные кандидаты. Мелкие выборы и умолчания инструментов — нет.
- Список кандидатов с уликами показывается владельцу **до записи**, инструментом опроса с множественным выбором, формулировку бери по пункту «Разговор с владельцем» секции backslop в AGENTS.md. Владелец — авторитет в том, было ли решение решением или стечением обстоятельств.
- Решение, чья мотивировка не восстанавливается, записывается только по слову владельца — и тогда честно: «причина утрачена; записано по состоянию кода на <дата>».

## Форма записи задним числом

- `{{cli}} adr <slug> --title "…"`, затем в файле:
  - **Status:** Accepted; **Date:** дата исходного решения по истории git (коммит, где выбор появился), не сегодняшняя;
  - **Deciders:** кто решал по словам владельца; неизвестно — «не установлено»;
  - в **Context** первой фразой: «Записано задним числом <сегодня>; решение действует с <дата>.»;
  - **Варианты** — только те альтернативы, о которых известно, что их рассматривали; неизвестно — «альтернативы не восстановлены»;
  - **Decision** — что выбрано, с уликой: манифест, конфиг, каталог;
  - **Consequences** — что решение до сих пор ограничивает: это самая полезная часть записи задним числом.
- Строка в таблицу `{{docs}}/README.md` тем же ходом — без неё `{{cli}} lint` красный.

## Чего не делать

- Не придумывать прошлое обоснование: если решение изменилось после принятия, записывай то, что действует сейчас, одним ADR на вопрос: прежний выбор и дата перемены идут в Context, а не во второй ADR и не в статус «заменён». Уже существующий ADR по этому вопросу переписывается на месте, как говорит раздел «Смена решения» скилла `backslop-task`.
- Не заводить ADR на будущее решение из этого скилла — открытый вопрос идёт файлом в `triage/`, а ADR появится, когда решение примут.

## ADR в другом формате

Нашлись ADR в другом каталоге или шаблоне — вопрос владельцу (формулируй по пункту «Разговор с владельцем» секции backslop в AGENTS.md): перенести в `{{docs}}/adr/` или оставить на месте и сослаться из индекса. Два параллельных журнала решений — худший вариант из трёх.

Оставить на месте можно только ADR вне `{{docs}}/adr/`. Файл с чужим именем, уже лежащий в нём (например `0001-use-pg.md`), остаться не может: `{{cli}} lint` отвергает там любое имя, кроме `adr-NNN-<slug>.md`, — переименуй его, как описано ниже, или вынеси из каталога.

Перенесённый файл переименовывается в `adr-NNN-<slug>.md`: нумерация видит только такую форму. Если в `{{docs}}/adr/` до `{{cli}} init` не было ни одного `adr-NNN-*.md`, номер 001 занят ADR процесса; иначе ADR процесса взял следующий свободный номер. Перенесённые ADR получают следующие свободные номера, а исходный номер и дату оставляют в тексте. Сохранить исходные номера можно, только сперва перенумеровав ADR процесса, — на это нужно согласие владельца (формулируй вопрос по пункту «Разговор с владельцем» секции backslop в AGENTS.md).

Перенесённый ADR коммитится без `[TODO]`, а его Status остаётся `Proposed`, пока владелец не принял решение, после чего — `Accepted`. Статус — строка `**Status:** Proposed` под заголовком, потом `**Status:** Accepted`: `{{cli}} lint` читает только эту форму, и заголовок `## Status` из другого шаблона или слово статуса вроде `Superseded` или `Deprecated` его красят. Перенесённый ADR, который заменил другой, сворачивается в тот, что действует сейчас, как говорит раздел «Смена решения» скилла `backslop-task`.
