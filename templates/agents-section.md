## Задачи и решения — backslop

Трекер задач и журнал решений живут в `{{docs}}/` и ведутся командой `{{cli}}` (конфиг — `backslop.json`, префикс задач — `{{prefix}}`). Списка задач в файлах нет: очередь, работу, отложенное и triage печатает `{{cli}} status`. Правила ведения — `{{docs}}/backlog/README.md`, термины — `{{docs}}/GLOSSARY.md`. Версия раскладки — поле `version` в `backslop.json`; обновление backslop — `{{cli}} upgrade`, по своему решению, а не по чужому коммиту.

**Скиллы (если выбран adapter):** `backslop-task` — цикл одной задачи; `backslop-batch` — заход worker'ами по track'ам; `backslop-seed` — наполнение документации после установки.

**Процедура изменения.** Роли две: worker правит и проверяет (шаги 1–4), approver принимает и закрывает (5–7); одиночный агент совмещает обе и идёт по шагам подряд.

1. **Задача.** Возьми первую в очереди (`{{cli}} status`) или заведи: `{{cli}} new <slug> --title "…"` — в triage, с `--queue` — сразу в очередь. Мелочь без следа в трекере допустима, если правка исчерпывается одним заходом и не меняет контракт. Находка идёт с меткой цены: `critical` чини сейчас, `major` в области текущей задачи чини сейчас, `major` вне её — сразу файл `{{cli}} new <slug> --parent N[.M]` с уликой, `minor` и гипотезу — `{{cli}} new <slug> --parent N[.M] --minor --evidence "…"`; без улики команда отказывает.
2. **Правка.** Реверс прежнего решения — чистым удалением, без зачёркиваний и пометок «отменено». Стиль существующего файла сохраняй. Термины — из глоссария; нужного нет — предложи, молча не выдумывай.
3. **Доки тем же ходом.** Незадокументированное изменение считается незавершённым: справочник `{{docs}}/reference/`, README затронутой подсистемы, CHANGELOG. Архитектурное решение — `{{cli}} adr <slug>` и строка в таблицу `{{docs}}/README.md`.
4. **Гейты до отчёта.** `{{cli}} gates` зелёный: команды из `gates` в `backslop.json`, код каждой и счёт «гейтов N, зелёных M». Запись с областью `when` на нетронутых путях пропускается: пропущенное идёт отдельным числом «не запущено N», к зелёным не прибавляется и называется в отчёте отдельной строкой.{{probeRule}}
5. **Приёмка и архив** — approver'ом, одним ходом: ревью диффа, `{{cli}} archive N`, дописать `result.md` (исход, что сделано, чем проверено), `{{cli}} fold N > "$(git rev-parse --git-dir)/BACKSLOP_DRAFT"` — каталог сворачивается в строку `{{docs}}/archive/LOG.md`, а тело задачи уезжает в заготовку сообщения коммита, которая ложится вне рабочего дерева. Между `archive N` и `fold N` не коммить: такой коммит станет ревизией строки журнала, и squash унесёт её из истории. Итоговый коммит приёмки несёт заготовку сообщением: `git add -A`, `git reset --soft <база>`, `git commit -F "$(git rev-parse --git-dir)/BACKSLOP_DRAFT"` — subject можно заменить на `{{prefix}}-N: закрыта — …`, тело оставь; `fixup` поверх коммита worker'а заготовку выбрасывает. `{{cli}} lint` зелёный на итоговом коммите, до пуша. Worker свою работу принятой не объявляет и файлы задач между каталогами не двигает.
6. **Разбор triage** — сразу после закрытия: каждой записи ход — слить, уточнить, `{{cli}} mv N queue`, `{{cli}} mv N deferred` с условием возврата. К владельцу — только за отказом.
7. **Фиксация.** Коммит с номером задачи первым в сообщении: `{{prefix}}-N: <что сделано>`. В основную ветку задача уезжает одним коммитом: взятие и правки по ревью схлопываются в коммит приёмки из шага 5, а после свёртки squash не делается — он выбросил бы заготовку, единственное хранилище тела задачи.

Границы worker'а: правит только свою ветку или worktree, каталоги статусов и `{{docs}}/archive/` не трогает; закрытие и triage — approver.
