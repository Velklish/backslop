# backslop

Бэклог для слопа: трекер задач и журнал решений файлами рядом с кодом, плюс скиллы процесса для агентов. Разворачивается в любой проект одной командой.

```bash
npx github:Velklish/backslop init
```

Нужны Node 20+ и git. Зависимостей у пакета нет.

[English version](README.md)

## Что это

Агенты производят много работы, и ей нужен трекер, который живёт в репозитории, читается агентом без внешних сервисов и не даёт конфликтов при параллельной работе в ветках. backslop держит всё файлами:

- **задача — файл** `BS-N-<slug>.md`; **статус — каталог**, в котором файл лежит: `triage/`, `queue/`, `active/`, `deferred/`, `minor/`; закрытые уезжают в `archive/` парой `task.md` + `result.md`;
- **приоритет — поле «Порядок»** в файле, а не строка общего списка; списка задач в git нет вовсе — сводку печатает `status`;
- **находка — файл** с номером `N.k`, который заводит нашедший в своей ветке без координации, а метка цены решает её ход: `critical` и `major` в области текущей задачи чинятся сейчас, `major` вне её становится карточкой, `minor` и гипотезы ждут пачки в `minor/`;
- **решения — ADR**, **термины — глоссарий**, **устройство — справочник** по подсистемам;
- **процесс — скиллы**: цикл одной задачи с ролями worker и approver, заход worker'ами по track'ам с брифами и гейтом ревью, наполнение документации после установки.

## Что появится в проекте

```
backslop.json                    prefix, docs, cli (с пином версии), gates, probe, version, lang, tools, agents.stepOverrides
AGENTS.md                        блок с процедурой изменения между <!-- backslop:start --> и <!-- backslop:end -->
docs/…                           скелет документации, бэклог, архив, первый ADR
```

Adapters пишутся только по выбору: `init --tools claude,cursor,codex`. Умолчание `tools` — пустой список. Legacy-конфиг без `tools` сохраняет Claude, если на диске есть прежний canonical `.claude/skills/backslop-task/SKILL.md`; без этой улики остаётся без adapter. Явные `tools: []` и `--tools none` всегда сильнее состояния диска.

Мутационную пробу шаг 4 managed-блока требует только там, где есть чем её гнать: команду берёт поле `probe` в `backslop.json` — непустая однострочная команда без обратной кавычки и без меток `backslop:start`/`backslop:end`: шаблон ставит значение в код-спан, а границы блока `init` ищет по сырому тексту. Поле объявлено — шаг называет команду; поля нет — предложения про пробу в блоке нет вовсе: правило, которое нечем исполнить, дороже отсутствия правила. Выкинутое требование `init` называет строкой вывода («probe в backslop.json не объявлен…»), а не выбрасывает молча. Репозиторий без поля описывает свою пробу разделом вне managed-блока — такой раздел переживает `init`.

Чтобы адаптировать нумерованный шаг managed-блока `AGENTS.md`, задай в `backslop.json` `agents.stepOverrides`: строковый ключ `"1"`…`"7"` заменяет текст этого шага при `init`, а его номер и остальные шаги остаются под управлением инструмента. Значение должно быть непустой строкой без переводов строк и символа `<`. Всё, что проверку прошло, подставляется экранированным: вся ASCII-пунктуация CommonMark уходит под обратную косую, и значение остаётся текстом, а не разметкой — определение ссылки `[label]: /target` с областью всего документа в нём не открывается. Скобки без определения ссылки остаются законным значением. `init` отклоняет такой конфиг до записи managed-блока. Граница worker'а остаётся под управлением шаблона.

| Adapter | Куда пишет |
|---|---|
| `claude` | `.claude/skills/backslop-*` и stub `CLAUDE.md` (`@AGENTS.md`), если файла не было |
| `cursor` | `.cursor/rules/backslop-*.mdc` и namespaced references |
| `codex` | `.agents/skills/backslop-*` |

Существующие файлы `docs/` повторный `init` не трогает; выбранные adapter outputs и блок в `AGENTS.md` обновляет. `--tools none` очищает список и удаляет только owned-файлы. Adapter outputs — generated и не коммитятся: `init` держит для них блок в `.gitignore` между `# backslop:start` и `# backslop:end` — строка `<корень harness>/backslop-*` на каждый выбранный adapter и `/CLAUDE.md`, когда на диске лежит наш stub. Свои строки файла сохраняются; проект без adapters `.gitignore` не получает. Флаги: `--dir <каталог>` вместо `docs`, `--prefix <KEY>` вместо `BS`, `--cli <команда>`, `--lang ru|en`.

Скелет готов — скажи агенту «заполни docs по backslop»: скилл `backslop-seed` прочитает репозиторий, задаст несколько вопросов и наполнит глоссарий, первые ADR и справочник, ничего не выдумывая без улики.

## Команды

| Команда | Что делает |
|---|---|
| `init [--dir docs] [--prefix BS] [--cli …] [--lang ru\|en] [--tools <CSV\|none>]` | разложить скелет; повторно — обновить выбранные adapters и блок AGENTS.md |
| `new <slug> [--title "…"] [--queue [--top]] [--parent N[.M] [--minor [--cost <уровень>] [--hypothesis]]]` | завести задачу в `triage/` или сразу в очередь; `--parent N` — находка `N.k`; `--parent N.M` — находка под находкой, следующий свободный `N.k` и поле «Родитель»; `--minor` кладёт находку в `minor/` с полем «Цена» (`major`/`critical` — только гипотезой); номер обходит занятые в других worktree и локальных ветках |
| `mv <N…> <triage\|queue\|active\|deferred\|minor> [--top \| --after M]` | сменить статус одной или нескольких задач за вызов: `git mv` плюс поля, которые статус ведёт за собой; в `minor/` дописывается «Цена», если поля нет; в `deferred/` существующий раздел не дублируется, команда печатает подсказку проверить причину и условие возврата; заголовок внутри fenced-примера существующим разделом не считается; задаче, уже стоящей в `queue/`, `--top` или `--after M` меняет только «Порядок» |
| `archive <N> [--dry-run]` | закрыть: переезд в `archive/`, перепись ссылок по репозиторию, заготовка `result.md`; `archive <N.k> --into <M>` закрывает minor-запись пачкой M: файл уезжает в `archive/<M>-<slug>/minor/` без своего `result.md`, пачка закрывается первой |
| `adr <slug> [--title "…"]` | новый ADR со следующим номером |
| `status [--json]` | в работе, очередь по порядку, отложено, triage, minor по областям; `--json` — для оркестраторов и скриптов |
| `upgrade [--to X.Y.Z] [--dry-run] [--pin-only]` | обновить проект: пин в `cli`, `gates` и живых файлах, `migrate` и `init` новой версией, выжимка CHANGELOG |
| `migrate [--dry-run]` | миграция формата файлов и штамп версии; пока форматы не менялись — только штамп |
| `changelog [--since X.Y.Z] [--to X.Y.Z]` | выжимка CHANGELOG backslop между версиями |
| `version`, `help` | версия и справка |
| `lint` | гейты трекера, adapter outputs и, в этом репозитории, равенство языковых шаблонов; отдельная строка-заглушка или поле, чьё значение целиком является заглушкой вида `[TODO…]`, в любом markdown-файле `docs/backlog/**` красит гейт, а `[TODO]` внутри пояснения не считается заглушкой; `quote:before:<путь>` хранит снимок до правки, обычный `quote:<путь>` сторожит инвариант |
| `gates [--keep-going] [--json] [--require-clean] [--dry-run]` | прогнать команды из `gates`: код каждой, «гейтов N, зелёных M», снимок дерева |

Без публикации в npm команда длинная, поэтому в проекте она записана в `backslop.json` полем `cli` и оттуда подставляется в скиллы и блок `AGENTS.md`. Установил глобально (`npm i -g github:Velklish/backslop#v<версия>`) — поменяй `cli` на `backslop`.

## Обновление

`init` записывает в `backslop.json` пин версии, которая делала раскладку: `cli` — `npx github:Velklish/backslop#v<версия>` с номером той версии, что его положила, `version` — штамп. Форма без тега тянет HEAD ветки `main` при каждом запуске, поэтому для `cli` проекта она не годится: поведение менялось бы чужим коммитом. Проект обновляется, когда решил сам:

```bash
npx github:Velklish/backslop upgrade
```

`upgrade` берёт последний тег из репозитория (или `--to X.Y.Z`), пробно запускает новую версию, переставляет пин в `cli`, `gates` и живых файлах: markdown из `docs/**` и корневых `*.md` с историческими исключениями, каждый файл `package.json` и известные файлы CI. Затем он запускает `migrate`, `init` и печатает выжимку CHANGELOG между версиями. Звать его можно и командой проекта — `<cli> upgrade` работает с любой версии не ниже 0.2.0, — и беспиновой формой выше: она всегда берёт свежий backslop, а обновляет проект всё равно на последний тег. `--dry-run` показывает план, `--pin-only` меняет только конфигурацию и гейты, без живых файлов; после ручных `migrate` и `init` повторный полный `upgrade` находит и чинит их даже без нового тега. Понижение версии не поддерживается: старая версия не знает формата файлов новой. `lint` предупреждает о версии раскладки, а старый пин в живом файле делает ошибкой; исторические файлы остаются зелёными.

Глобальная установка (`cli: "backslop"`) и npm-пин (`cli: "npx backslop@X.Y.Z"`) источника тегов не дают: укажи в `backslop.json` поле `source` — адрес репозитория с тегами релизов. `upgrade` переставит пин и раскладку; глобально установленный пакет обновляешь ты.

## Как идёт работа

1. Агент берёт первую задачу по `status` и переводит её в работу: `mv N active`.
2. Правит, обновляет документацию тем же ходом, гоняет гейты из `backslop.json` — среди них `lint`.
3. Approver принимает: `archive N`, дописывает `result.md` (пока в нём `[TODO]`, `lint` красный), разбирает `triage/` — каждой записи ход. Текст файлов задач в каталогах статусов и архиве также правит approver; worker присылает формулировку в результате. Единственное исключение — новая находка: worker создаёт её отдельным файлом через `new --parent N[.M]` в своей ветке; уже существующую карточку не правит.
4. Несколько задач в непересекающихся подсистемах — заход worker'ами по скиллу `backslop-batch`: track на подсистему, самодостаточный бриф, worker правит только свою ветку и статусы не трогает, reviewer поднимается на дифф контракта, приёмка — squash по задаче.

Граница ролей одна и та же в одиночной работе и под оркестрацией: worker свою работу принятой не объявляет, существующие файлы задач между каталогами не двигает, новую находку заводит `new --parent N[.M]` (с `--minor` для minor и гипотез) отдельным файлом в своей ветке, уже созданную карточку не правит.

## Для оркестраторов

Оркестратор любого harness — субагенты в worktree, отдельные сессии, шина — работает через файлы и CLI: `status --json` читает очередь, `mv` раздаёт, `archive` закрывает. Транспорт worker'ов — слот в `backslop-batch`; новый транспорт подключается страницей с вариантом для этого слота, в CLI ничего не меняется.

## Ограничения

- Скиллы появляются только для выбранных `tools`. Без `--tools` проект получает блок в `AGENTS.md` и `docs/`.
- Английский и русский слои шаблонов есть. Смена `lang` существующие docs не переводит.
- Публикация в npm подготовлена (пин `npx backslop@X.Y.Z` и `npm run release`), но default CLI остаётся на GitHub до первого релиза.
- Префикс, совпадающий с обычным словом (`API`, `RFC`), даёт ложные срабатывания гейта упоминаний на строках вида `API-2.0` — выбирай префикс, которого нет в текстах проекта.

## Разработка

```bash
npm test                      # node --test
node bin/backslop.js lint     # гейты на собственном docs/
```

Источник всего, что кладётся в проект, — `templates/`; `docs/` репозитория ведётся тем же инструментом. Устройство — в `docs/reference/`.
